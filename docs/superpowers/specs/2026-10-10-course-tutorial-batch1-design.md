# NoteFlow 首批教程文档设计

## 目标

基于 `00-course-blueprint.md`，完成 NoteFlow 全栈工程师课程的首批教程文档：

- 课程总 README；
- 教程项目结构说明；
- 统一单元写作模板；
- W1 两个完整教程单元：
  - Web 应用、浏览器和服务器是什么；
  - 终端、文件系统、Git 与开发环境。

本批次只实现教程文档，不实现 `labs/` 实验目录、实验源码、环境检查脚本或其他可执行项目文件。

## 范围边界

### 本批次包含

```text
web-fullstack-course/
├── README.md
├── 00-course-map/
│   ├── 01-course-structure.md
│   └── 02-week-one-checkpoint.md
├── 00-common/
│   ├── README.md
│   └── W01-web-foundations/
│       ├── 01-web-app-browser-server.md
│       └── 02-terminal-filesystem-git.md
├── templates/
│   └── unit-template.md
└── progress/
    └── README.md
```

根目录已有的课程蓝图、48 周路线图、NoteFlow 项目规格、技术版本基线和考核标准保持不变，作为教程设计的事实来源。

### 本批次不包含

- `web-fullstack-course/labs/`；
- 静态服务器、环境检查器或其他 Node.js 源文件；
- `package.json`、锁文件、构建配置和课程代码仓库；
- React、Vue、Node.js API、数据库和部署阶段的正文；
- 修改根目录总纲文件；
- 恢复或回退当前工作区中已存在的删除状态。

教程可以在代码块中给出最小示例、运行命令、预期输出和失败诊断，但这些示例不会在本批次写入独立源码文件。

## 学习体验设计

教程使用 NoteFlow 团队入职叙事，将每个知识单元组织成一个可交付任务：

```text
接到任务
  -> 先看结果
  -> 拆解运行机制
  -> 制造一个可控故障
  -> 用证据排查
  -> 接回 NoteFlow
  -> 提交验收记录
```

每个单元都要让学习者留下一个可见成果：

- U01：能解释一个页面从 URL 到显示的请求链，并完成公共首页草图的运行记录；
- U02：能建立可复现的学习工作区，完成第一次 Git 提交记录和环境诊断记录。

教程文字使用短段落、任务卡、结果表、ASCII 流程图和代码块组织信息。叙事用于建立上下文，概念解释必须回到准确术语、实际命令和可观察证据。

## 单元结构

每个单元严格包含蓝图规定的 13 个板块：

1. 任务背景；
2. 学习目标；
3. 预备知识；
4. 核心理论；
5. 标签、属性、API 或配置清单；
6. 最小可运行案例；
7. NoteFlow 集成案例；
8. 常见错误与排查路径；
9. 课后题；
10. 实践练习；
11. 阶段验收；
12. 常见问题；
13. 扩展阅读。

此外，每个单元必须包含：

- 任务卡；
- 单元成果清单；
- 文件位置；
- 从仓库根目录执行的命令；
- 预期结果；
- 失败诊断；
- “我现在能做到什么”；
- 上一单元、下一单元和课程入口导航。

代码示例必须注明文件路径。由于本批次不实现 `labs/`，示例会明确标注“教程内示例”，并说明未来实验目录应承载的职责，不把不存在的实验文件写成已交付能力。

## 文档职责

### `web-fullstack-course/README.md`

课程学习者入口，负责说明：

- 课程培养目标；
- NoteFlow 主线；
- 48 周阶段地图；
- 单元学习循环；
- 首周阅读顺序；
- 文档结构和模板；
- 版本与安全边界；
- 后续扩展规则。

不在此文件中重复全部理论正文。

### `web-fullstack-course/00-course-map/01-course-structure.md`

负责解释课程仓库的物理结构、阶段目录职责、单元命名规则、教程与实验的边界、后续单元如何接入，以及文档链接维护规则。

### `web-fullstack-course/00-course-map/02-week-one-checkpoint.md`

负责集中描述 W1 的学习顺序、成果物、时间分配、验收证据和常见卡点，作为两个单元之间的导航页。

### `web-fullstack-course/00-common/README.md`

负责 Web 与 HTML 阶段入口，说明 W1 的两个单元、阶段目标和阶段验收标准，并链接回课程总入口与 W1 checkpoint。

### `web-fullstack-course/templates/unit-template.md`

提供未来单元可复制的 Markdown 结构。模板可以包含字段说明，但不使用“待完成”“略”“自行补充”等正文占位表达。

### `web-fullstack-course/progress/README.md`

记录首批已交付文档、验收范围和后续扩展规则。它不伪造尚未实现的正文或实验文件。

## 验收标准

### 文档完整性

- 总 README、结构说明、W1 checkpoint、阶段 README、模板和两个教程文件均存在；
- 两个教程均包含完整 13 个固定板块；
- 两个教程均包含任务卡、代码位置、运行命令、预期结果、失败诊断、阶段验收和单元导航；
- 正文没有 `TODO`、`TBD`、`待完善`、`待实现`、`略` 等占位表达。

### 内容质量

- U01 覆盖浏览器、HTTP 服务器、文件系统、URL、请求/响应、状态码、资源请求和 `file://` 与 `http://` 的差异；
- U02 覆盖终端、路径、文件系统、标准输出/错误、退出状态、进程/PID/端口、Node.js/pnpm/Git 检查、Git 工作区/暂存区/仓库和安全提交；
- 两个单元均把理论回接到 NoteFlow，而不是孤立介绍命令或概念；
- 每个关键命令都有预期结果和失败时的诊断路径；
- 示例不包含真实凭据、真实个人信息或危险的破坏性命令。

### 链接与边界

- 教程内相对链接只指向本批次实际创建的文件或根目录已有总纲文件；
- 不创建、不引用不存在的 `labs/` 文件作为已完成交付物；
- 不修改根目录课程总纲；
- 不改变工作区中与本批次无关的既有改动。

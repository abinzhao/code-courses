# 移动端开发课程蓝图

> 状态：仅供方向评审，不包含移动端教程或应用实现。
> 技术快照：2026-10-11；实施启动时重新核验精确版本、设备支持和商店规则。

## 培养目标

面向已完成 Web 全栈主线、能独立使用 React/TypeScript、HTTP、测试和发布门禁的学习者。完成后
应能交付一个 iOS/Android 双端应用，解释平台差异、离线状态、权限、深链、生命周期、原生模块、
设备测试、签名和发布证据，而不是只让同一页面在模拟器中显示。

能力结果：

- 用共享领域契约实现双端等价业务；
- 遵循 iOS 与 Android 各自的导航、权限、输入和可访问性习惯；
- 在弱网、离线、后台恢复和进程重建后保持状态一致；
- 对相机、通知、定位和安全存储采用最小权限；
- 能从崩溃、日志、网络和性能证据定位问题；
- 生成可复现的本地构建、真机验收和商店候选记录。

## 前置知识

- 完成 Web 课程的 JavaScript/TypeScript、React、浏览器、工程化、后端与全栈交付；
- 熟悉整数分、UTC、运行时解析、Cookie/Token 边界、对象授权和幂等；
- 能运行 lint、双类型检查、单测、E2E、构建与回滚检查；
- 至少有一台目标真机；iOS 发布路径需要可运行目标 Xcode 的 Mac；
- 不要求先掌握 Swift/Kotlin，但原生边界模块会要求阅读两种语言的最小代码。

## 技术选型

| 方案 | 优势 | 主要成本 | 适合作为 |
|---|---|---|---|
| SwiftUI + Jetpack Compose | 平台能力、交互和调试最直接；Compose 是 Android 官方推荐的现代 UI 工具包，SwiftUI 是 Apple 官方声明式 UI 框架。[cite:2][cite:3] | 两套语言、工程和测试体系 | 平台深度路线 |
| React Native + Expo | 复用 React/TypeScript；React Native 官方建议新应用采用 Expo 一类框架。[cite:1] | 仍需理解原生生命周期、构建和模块兼容 | **默认主线** |
| Flutter | 单代码库和一致渲染工具链，官方定位为多平台应用框架。[cite:4] | 新增 Dart；平台外观需主动翻译 | 对照路线 |
| Compose Multiplatform | Kotlin 与 Compose 心智统一 | iOS 工具链、生态和平台适配仍需专项验证 | 高阶探索 |

### 推荐默认

采用 **React Native + Expo + TypeScript**，原因是与现有 React/TS 课程衔接最短，适合单人、低预算
迭代。课程必须使用 development build 和本地原生工程验证，不能把 Expo Go 成功当作最终构建
证据。云构建和远程更新属于可选外部服务；本地优先模式默认关闭，启用前单独评审代码、凭据和数据
边界。[cite:1][cite:5]

每个关键模块保留原生逃生口：Android 用 Kotlin/Compose，iOS 用 Swift/SwiftUI。共享业务规则，
不强制像素级克隆两个平台。

## 模块结构

1. 移动运行时、生命周期、前后台和进程重建；
2. 原生导航、深链、返回手势与 URL/通知入口；
3. 组件、主题、动态字体、暗色模式和平台适配；
4. 表单、键盘、焦点、触控目标和无障碍；
5. HTTP、运行时 parser、取消、重试、幂等和弱网；
6. 本地数据库、缓存、离线草稿、同步和冲突；
7. 身份、系统安全存储、会话撤销和生物识别边界；
8. 相机、图片、文件、通知、定位与最小权限；
9. 原生模块、桥接、后台任务和失败降级；
10. 单测、组件测试、设备 E2E、崩溃与性能；
11. 本地构建、签名、候选包、灰度、发布和回滚；
12. Capstone、真机答辩与独立修改。

## 连续项目

项目为“邻里集市移动端”：

- 浏览、搜索、详情、收藏、发布和预约；
- React Native 双端共享领域层，平台导航和权限适配分开；
- 本地缓存最近浏览，离线只保存明确标记的草稿；
- 恢复联网后使用幂等键与版本冲突流程；
- 图片选择先做本机压缩和元数据最小化；
- 推送只作为通知，最终状态回读 API；
- 不接入真实支付，不在客户端决定对象授权。

阶段版本：只读浏览 → 登录与写操作 → 离线草稿 → 原生能力 → 交付与恢复。

## 测试与发布证据

- iOS/Android 各一台真机，另记录模拟器/系统版本；
- 组件、领域、网络 parser、离线同步和权限拒绝测试；
- 深链冷启动、后台恢复、进程重建、弱网和无网路径；
- 动态字体、屏幕阅读器、键盘/开关控制和横竖屏；
- 崩溃日志、内存、启动、列表滚动和图片处理预算；
- 本地可复现构建、签名身份、依赖锁、制品摘要；
- 内测安装、升级、数据迁移、撤回和隐私清单；
- 商店提交只有真实审核记录才能标记通过。

## 验收标准

- 双端主路径功能等价，但交互符合各自平台；
- 数据契约、整数分、UTC、错误 code 和授权边界与 Web 主线一致；
- 离线草稿不显示为服务端成功，冲突不自动覆盖；
- 权限在使用时请求，拒绝后仍有可恢复路径；
- 真机完成登录、发布、预约冲突、退出和深链冷启动；
- 至少一个原生模块有双端实现、测试与降级；
- 依赖、构建、签名、候选包和已知缺口可由他人复核；
- 未运行的商店、设备、辅助技术和云服务不写成通过。

## 复用关系

| Web 能力 | 移动端复用 | 新增边界 |
|---|---|---|
| TypeScript 领域契约 | DTO、parser、状态机 | 原生生命周期与桥接 |
| React | 组件、Hook、状态边界 | 原生组件和导航 |
| 浏览器网络与存储 | HTTP、取消、离线思维 | 本地数据库、后台恢复 |
| 后端安全 | API、授权、幂等 | Token/系统安全存储 |
| 工程化 | 锁文件、测试、CI | 原生构建、签名、商店 |
| 无障碍 | 名称、状态、焦点 | Dynamic Type、VoiceOver、TalkBack |

## 建议周数

建议 **14 周，每周 18–22 小时**：

- 1–2：运行时、导航、平台 UI；
- 3–4：表单、网络、身份；
- 5–6：本地数据、离线与同步；
- 7–8：图片、权限、通知；
- 9–10：原生模块与后台；
- 11–12：测试、性能、真机矩阵；
- 13：构建、签名与候选发布；
- 14：Capstone、恢复演练和答辩。

全部平台深度练习另增加 4–6 个弹性周。

## 实施顺序

1. 冻结产品范围、设备矩阵、隐私边界和共享 API 契约；
2. 建立 React Native/Expo 本地构建基线与双端空壳；
3. 先完成只读主路径和运行时 parser；
4. 加入身份、写操作、错误恢复和对象授权证据；
5. 引入本地数据库、离线草稿和同步状态机；
6. 逐项接入权限与原生能力，每项都有拒绝路径；
7. 建立真机 E2E、性能、崩溃和无障碍门禁；
8. 完成签名、候选包、升级/回滚演练；
9. 由独立评审者复现后再进入教程编写计划。

## 风险与决策门

- Expo 模块不满足能力或平台版本时，先做最小原生模块验证再决定替换；
- 需要高度平台化体验时，允许局部或整模块转原生，不维持虚假共享率；
- 任何远程构建、分析、推送或崩溃服务都是外部数据边界，默认关闭；
- 精确 SDK/OS 最低版本在实施启动日重新核验，不由本蓝图长期固定。

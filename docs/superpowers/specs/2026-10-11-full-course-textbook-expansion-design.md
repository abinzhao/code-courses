# Full Course Textbook Expansion Design

> 设计日期：2026-10-11
> 适用范围：`web-fullstack-course/00-guide`、`02-css` 至 `09-fullstack`
> 质量基线：已完成的 `01-html`

## 1. 目标

把 HTML 之外的全部课程从“单层综合章”升级为可独立学习、可复现、可诊断、可验收的两层教材：

```text
卷 README
  ├── 稳定编号章入口
  │   ├── 详细教程 1
  │   ├── 详细教程 2
  │   ├── 详细教程 3
  │   └── 可选详细教程 4
  └── 分卷覆盖矩阵
```

现有编号文件路径保持不变，改为章入口。理论推导、完整代码、错误实验、邻里集市集成和练习验收进入同名目录下的详细教程。

完成后新增 202 篇详细教程和 8 个分卷覆盖矩阵。按根 README 现行统计口径，全书正文与覆盖矩阵从 106 篇增加到 316 篇。

学习路线、版本基线、项目契约、覆盖地图、教材结构、写作模板和周验收继续作为治理文档，不拆成教程目录。

## 3. 不做的事情

- 不在教材仓库中创建 `labs/`、应用源码工程、依赖目录、包清单或锁文件。
- 不新增真实支付、真实邮件、生产身份系统或云资源。
- 不把静态示例、内存状态、Mock API、教学数据库或本地代理描述成生产能力。
- 不为追求数量重复同一段理论或完整项目源码。
- 不修改已经完成的 HTML 正文，除非全书导航或交叉链接必须调整。
- 不把尚未执行的 Docker、HTTPS、托管 CI、真实数据库或屏幕阅读器检查写成通过。

## 4. 稳定路径与文件责任

每个现有编号文件继续承担稳定入口职责。例如：

```text
02-css/
├── 01-syntax-cascade-selectors.md
└── 01-syntax-cascade-selectors/
    ├── 01-rules-parsing-entry-points.md
    ├── 02-cascade-layers-specificity.md
    └── 03-selectors-pseudo-classes-inheritance.md
```

章入口只包含：

1. 本章任务、产出与必要前置；
2. 2 至 4 篇详细教程的学习顺序；
3. 依赖关系和建议投入时间；
4. 章级邻里集市综合任务；
5. 综合验收证据；
6. 上下章导航。

详细教程承担完整教学内容。分卷 README 负责卷级路线、运行约定、边界和最终验收。覆盖矩阵负责把知识点映射到具体教程，不承担正文。

## 5. 详细教程契约

每篇详细教程必须按以下顺序包含顶级章节：

```text
# 教程标题
## 任务卡
## 1. 任务背景
## 2. 学习目标
## 3. 预备知识
## 4. 核心理论
## 5. 元素、属性、API 或配置清单
## 6. 最小可运行案例
## 7. 邻里集市集成案例
## 8. 常见错误与排查路径
## 9. 课后题
## 10. 实践练习
## 11. 阶段验收
## 12. 常见问题
## 13. 扩展阅读
## 我现在能做到什么
## 单元导航
```

其中：

- CSS 教程的第 5 节列属性、值、选择器、规则或 DOM/CSSOM 接口。
- 浏览器教程列协议字段、Web API、事件、状态与安全边界。
- JavaScript / TypeScript 教程列语法、标准 API、类型工具与运行时边界。
- React / Vue 教程列组件 API、Hook/Composable、路由、状态和测试接口。
- 工程化教程列命令、配置键、文件角色和工具链版本。
- 后端与全栈教程列接口、DTO、SQL、配置、容器、代理、发布和运维契约。

每篇教程还必须包含：

- 一个能观察结果的最小案例；
- 一个从最小案例逐步扩展的过程；
- 一个邻里集市集成案例；
- 一个明确标注的错误示例；
- 一份“现象、证据、原因、修复、复验”记录；
- 文件位置、创建方式、运行命令、预期结果和失败证据；
- 基础、进阶、故障注入练习；
- 课后题答案或可判定答案标准；
- 官方资料与技术资料快照日期。

## 6. 连续项目与领域约束

全部教程继续使用邻里集市，不新造第二套业务：

- 价格存储与传输使用整数分。
- 持久化时间使用 UTC ISO 8601，显示时才本地化。
- 商品、用户、收藏、预约和版本冲突沿用 `00-guide/05-project-assessment.md`。
- React 与 Vue 使用同一业务复杂度和接口契约。
- 认证只证明身份；对象授权和 RBAC 必须由后端执行。
- CSRF、CORS、Cookie、CSP、代理和 TLS 分别说明职责，不能互相替代。
- 事务、缓存、队列、文件、容器和发布示例必须说明一致性与失败边界。
- 示例中的内存 API、Mock 数据和静态页面必须在界面或说明中显式标记。

## 7. 复用与避免重复

同一知识点只在一个卷中完整推导，其他卷通过前置链接复用：

- HTML 负责语义、表单默认行为和基础 DOM。
- CSS 负责视觉格式化与布局，不重复 HTML 语义。
- 浏览器卷负责平台运行机制，不重复 JavaScript 语法。
- JavaScript / TypeScript 负责语言和原生应用，不提前讲框架抽象。
- React 与 Vue 保持业务等价，但分别解释各自模型，不做逐行互译。
- 工程化负责工具链和质量门禁，不重复框架业务实现。
- 后端负责真实数据、权限和并发；全栈卷负责组合与交付。

完整项目源码只在承担综合项目职责的详细教程出现一次。其他教程引用文件路径和必要片段，避免两份完整源码漂移。

## 8. 覆盖矩阵

`02-css` 至 `09-fullstack` 各新增一个 `*-COVERAGE.md`。统一列：

```text
ID | 知识点 | 主要教程 | 理论 | 最小案例 | 项目案例 | 错误诊断 | 练习 | 验收
```

矩阵必须满足：

- 每个 ID 唯一；
- 每个主要教程链接存在；
- 每行六个证据维度均能在正文中定位；
- 不使用“待补充”“计划中”或模糊状态；
- 版本、兼容性、安全和人工验证边界单独成行；
- 现有 CSS 476 属性索引、HTML 115 元素口径和全书覆盖地图保持可追溯。

## 9. 技术基线

沿用 `00-guide/02-version-baseline.md` 的快照和已验证差异：

- Node.js 24 LTS；
- pnpm 12.10.1 为工程卷基线，框架历史验证使用的 pnpm 10.34.6 单独标注；
- TypeScript 7 主线与 TypeScript 6 旧编译器 API 兼容线分开；
- React 19.3、Vue 3.5.43、Vite 8、ESLint 10；
- NestJS 12.1.1、PostgreSQL 18；
- Chromium 是主要浏览器自动验证环境。

版本号必须来自现有版本基线、锁定示例或官方资料。不同历史验证快照不得合并成一个不存在的统一环境。

## 10. 验证策略

### 10.1 文档结构

- 预计 316 篇正文与覆盖矩阵；
- 202 篇新教程全部满足 13 节契约；
- 所有 README、章入口、详细教程、覆盖矩阵和全书地图相互可达；
- 零未闭合代码围栏、零相对断链、零占位标记、零空白错误。

### 10.2 示例静态验证

从 Markdown 机械提取明确标为完整文件的代码到 `/tmp`：

- HTML 使用解析器检查唯一 ID、片段和引用关系；
- CSS 使用支持当前语法的解析器或浏览器 CSSOM；
- JavaScript 使用目标 Node 版本执行 `--check`；
- JSON、JSONC、YAML、WebVTT、SQL、Dockerfile、Nginx 和 shell 使用对应解析器或可用工具；
- TypeScript、TSX、Vue SFC 和配置文件按分卷固定版本创建临时项目验证；
- 临时项目和缓存不得进入仓库。

### 10.3 运行时验证

按风险选择代表性而非伪造“全部已运行”：

- CSS、浏览器、DOM、React、Vue：Chromium 和键盘关键路径；
- JavaScript：Node 内置测试与故障注入；
- 工程化：类型、Lint、单元、集成、构建、预算和 E2E；
- 后端：能获得目标 PostgreSQL 环境时运行真实 HTTP/数据库测试，否则保留明确阻塞证据；
- 全栈：本地可用环境中的 Compose、代理、发布和恢复步骤；不可用的外部系统只做配置静态验证和手动清单。

### 10.4 人工缺口

必须显式记录但不得声称通过：

- Safari、Firefox、真实移动设备；
- VoiceOver、NVDA、JAWS；
- 真实第三方媒体、邮件、对象存储和支付；
- 生产域名、ACME、托管 CI、镜像仓库和云主机；
- 真实备份恢复时间与生产容量。

- 合并前结构和边界审查；
- 跨卷术语、版本和业务契约对账；
- 运行统一验证；
- 精确暂存与分卷提交；
- 最终独立复审和缺口修复。

## 12. 提交策略

- 先提交本设计和实施计划。
- 现有未跟踪课程文件按所在卷与新增教程一起提交，不建立掩盖原始状态的全书基线提交。
- 每个卷至少一个独立提交；大卷按 2 至 4 个章节分批提交。
- 不暂存其他卷的中间状态。
- 不推送远端、不部署、不创建云资源。

## 13. 完成标准

只有同时满足以下条件才可结束：

1. 202 篇详细教程和 8 个覆盖矩阵全部存在。
2. 66 个章入口全部连接其详细教程并有章级验收。
3. 每篇详细教程满足结构、案例、诊断、练习、答案和来源契约。
4. 全书导航和计数按同一口径更新。
5. 全量相对链接、结构、围栏、占位、空白和范围检查通过。
6. 可静态验证的代码与配置全部通过对应检查。
7. 代表性运行时与浏览器关键路径通过。
8. 无法验证的真实环境范围有明确原因和剩余风险。
9. 独立复审没有阻塞项。
10. 任务范围工作区干净，用户其他文件未被误提交。

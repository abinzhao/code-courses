# Web 全栈课程知识单元 01 设计

## 1. 目标

在重构后的 24 周 Web 全栈工程师课程中，创建第一个公共基础知识单元：

`前端全栈工程师培养课程/00-common/01-计算机如何运行Web程序.md`

该单元面向零基础或弱基础学员，用可观察的程序运行现象建立计算机基础心智模型。学员完成后应能解释一个 Web 程序从源码变为运行中进程的基本过程，并能使用系统工具收集 PID、进程状态、资源占用、端口和退出码等证据。

## 2. 内容边界

### 2.1 必须覆盖

1. CPU、内存、磁盘和网络的基本职责。
2. 源代码、可执行指令、运行时和进程之间的关系。
3. 操作系统在进程创建、资源分配和回收中的作用。
4. PID、父子进程、运行状态和退出码。
5. 栈、堆与内存占用的概念模型。
6. CPU 密集型任务和 I/O 密集型任务的差异。
7. 浏览器程序与 Node.js 程序运行位置和职责的差异。
8. 使用终端工具观察程序运行状态的基本方法。

### 2.2 暂不覆盖

1. CPU 指令集、汇编、寄存器和操作系统内核实现。
2. 线程调度、锁和并发控制细节。
3. JavaScript 事件循环、微任务和宏任务细节。
4. 文件系统路径与权限的完整规则。
5. TCP、DNS、HTTP 等网络协议细节。
6. 浏览器渲染流水线和多进程架构细节。

这些内容由后续独立知识单元承接，避免首个单元认知负荷过高。

## 3. 固定文档结构

知识单元正文必须且只能按以下六个一级教学部分组织：

1. `目标`
2. `技术栈`
3. `详细的理论知识讲解和示例伪代码`
4. `课后题`
5. `实践练习题`
6. `阶段验收作业`

标题之下允许使用三级标题拆分内容，但不得新增与六段结构并列的教学部分。

## 4. 各部分设计

### 4.1 目标

目标使用可观察行为描述，至少包括：

- 能画出源码、Node.js 运行时、操作系统和硬件资源之间的关系。
- 能解释启动、运行、等待 I/O 和退出四个基本阶段。
- 能根据 PID、CPU、内存、端口和退出码判断程序状态。
- 能区分浏览器中的前端代码与服务器上的 Node.js 代码运行位置。

### 4.2 技术栈

只使用本单元完成学习和验证所需工具：

- Node.js 当前 LTS。
- macOS 或 Linux 终端。
- `node`、`ps`、`top`、`lsof`、`kill`。
- 系统活动监视器作为图形化观察工具。

命令差异应明确标注平台，不假设所有系统参数完全一致。

### 4.3 详细的理论知识讲解和示例伪代码

理论按以下认知顺序展开：

1. 计算机资源模型。
2. 从源代码到进程。
3. 进程的生命周期。
4. 内存的概念模型。
5. CPU 密集型与 I/O 密集型任务。
6. 浏览器程序与 Node.js 程序的运行边界。
7. 通过系统证据观察程序。

每个概念都应包含：

- 通俗定义。
- 与 Web 开发的关系。
- 一个具体例子。
- 一个常见误解或边界说明。

核心伪代码应表达以下流程：

```text
读取启动命令
请求操作系统创建进程
操作系统分配 PID 和基础资源
Node.js 运行时加载入口模块
执行同步代码
等待文件、网络或定时器等 I/O
处理完成结果
返回退出码
操作系统回收资源
```

伪代码用于表达机制，不伪装成可直接运行的 JavaScript。

### 4.4 课后题

设置 8 至 10 题，覆盖三种能力：

- 概念理解：解释资源、运行时和进程。
- 过程推导：根据程序行为推断运行阶段。
- 故障判断：根据 CPU、内存、端口和退出码证据定位问题方向。

题目不得只要求背诵定义，至少三分之一需要结合场景分析。

### 4.5 实践练习题

设置三个递进练习：

1. 启动并观察一个持续运行的 Node.js 进程。
2. 分别制造 CPU 占用和 I/O 等待，比较系统表现。
3. 制造正常退出、异常退出和端口占用，记录证据并解释。

每个练习必须包含任务、步骤约束、提交物和验收标准。命令结果不得要求学员提交真实用户名、令牌或其他敏感信息。

### 4.6 阶段验收作业

作业名称为“Web 程序运行观察报告”，提交物包括：

- 一个可复现的 Node.js 观察脚本。
- 一份运行观察报告。
- 一张程序运行链路图。
- 正常退出与异常退出的证据。
- 对 CPU 密集型和 I/O 密集型现象的比较。
- 一份问题复盘。

验收采用 100 分制：

- 机制解释 30 分。
- 证据完整性 25 分。
- 实践可复现性 25 分。
- 安全与规范 10 分。
- 表达与复盘 10 分。

达到 70 分视为通过；若无法区分源代码、运行时和进程，或提交内容不可复现，则不得通过。

## 5. 写作与质量要求

- 使用中文教学，技术名词保留通用英文写法。
- 默认读者没有操作系统背景，不使用未经解释的专业术语。
- 理论必须服务于后续 Web 开发，不扩展为计算机组成原理课程。
- 示例命令需说明预期观察结果，而不只罗列命令。
- 不使用具体 Node.js 小版本作为长期固定基线。
- 不引入数据库、前端框架、后端框架或第三方依赖。
- 单元应可在约 12 至 15 小时内完成。

## 6. 完成标准

完成后的知识单元应满足：

1. 六段固定结构完整且顺序一致。
2. 所有目标都能在练习或验收作业中找到对应检查项。
3. 理论内容与暂不覆盖范围没有明显重叠。
4. 伪代码表达机制且不依赖具体框架。
5. 练习能够在 Node.js LTS 和常见 macOS/Linux 环境中完成。
6. 验收标准明确、可观察、可评分。

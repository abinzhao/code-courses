# Web 全栈教程现代化改造设计

> 设计日期：2026-10-11
> 适用范围：`web-fullstack-course/00-guide`、`02-css` 至 `09-fullstack`
> 既有基线：`01-html` 已完成 67 篇选择性物理拆分
> 状态：设计已确认，分批实施计划已生成

## 1. 背景

当前课程已经形成 50 周、10 卷、269 篇详细教程的 Web 全栈体系，并具备：

- 根目录、分卷 README、章入口、详细教程和覆盖矩阵五级导航；
- 邻里集市连续项目；
- 固定的 13 节详细教程契约；
- HTML、CSS、浏览器、JavaScript / TypeScript、React、Vue、工程化、后端和交付卷；
- 全书链接、锚点、围栏、覆盖 ID 和代表性运行验证。

HTML 卷已经从 24 篇综合教程选择性拆分为 67 篇聚焦教程。其余卷已有 202 篇详细教程，多数为 300–600 行，少量 Capstone 或综合教程达到 900–2480 行。

本轮不重新推翻已有教材，而是在保留有效知识、案例和验证证据的前提下，完成全书现代化、去过时、补闭环和必要的选择性拆分。

## 2. 目标

本轮必须达到以下结果：

1. `00-guide`、`02-css` 至 `09-fullstack` 的结构逻辑清晰、职责单一、学习路径连续。
2. Web 全栈核心知识域形成闭环，不依赖未解释的外部课程才能完成结业项目。
3. 所有过时、淘汰、停止支持或已被当前稳定方案替代的技术内容全部删除。
4. 技术主线采用审计日期可核验的 GA、LTS 或稳定版本。
5. 示例代码、配置、架构、测试、安全、无障碍、性能和运维方案符合当前通行最佳实践。
6. 每个知识点都有理论、最小案例、项目案例、错误诊断、练习和验收证据。
7. 全书完成统一静态检查、代表性运行验证和独立复审。
8. Web 全栈改造全部通过后，再提交移动端、小程序、AI Agent、浏览器插件四份蓝图，等待用户确认。

## 4. 选择性拆分规则

### 4.1 拆分触发条件

只有教程同时满足以下条件才物理拆分：

1. 正文明显超长，通常超过 900 个可见 Markdown 行；
2. 同时承担两个或更多可以独立学习、独立练习和独立验收的主题；
3. 包含多个完整项目、多个互不依赖的运行环境，或多个不同所有权的综合案例；
4. 拆分后能够减少重复，而不是复制同一套代码到多个文件。

### 4.2 不按长度机械拆分

以下文件即使较长也可以保留：

- 单一目标的 Capstone；
- 单一运行手册；
- 单一稳定索引；
- 一个不可分割的端到端验收流程；
- 拆分后会导致共享代码重复的完整项目。

### 4.3 拆分后的职责

每篇新教程必须：

- 只承担一个明确主题；
- 保持任务卡、`1..13`、能力总结和单元导航；
- 拥有独立最小案例、故障、练习和验收；
- 只引用完整项目 owner，不复制完整项目；
- 保持原覆盖 ID，不创建无必要的新编号；
- 更新章入口、README、覆盖矩阵和跨课导航。

## 5. 过时内容零保留规则

用户已明确要求不保留过时技术。本轮采用零保留规则。

### 5.1 删除对象

以下内容必须从正文、历史说明、错误示例、迁移章节、FAQ 和扩展阅读中删除：

- 已停止官方支持的运行时或框架主版本；
- 官方已废弃或删除的 API；
- 已被当前稳定配置体系替代的旧配置文件和命令；
- 已淘汰的脚手架、构建、测试或部署主线；
- 当前浏览器、Node 或框架不再推荐的实践；
- 只为兼容陈旧生态而保留、但不属于当前课程运行路径的方案；
- 对已过时技术的教学性历史回顾。

### 5.2 替换要求

删除过时内容时必须同时：

1. 找到当前稳定替代方案；
2. 更新理论、命令、完整代码、故障案例、练习和验收；
3. 更新覆盖矩阵和版本基线；
4. 删除旧技术名称和旧路径的残留引用；
5. 验证替代方案能够完成原有教学目标。

不能只做名词替换而保留旧架构。

### 5.3 正向表达

教程直接讲当前正确方案，不通过旧技术对照建立主线。需要解释设计原因时，从当前职责、约束和失败模式推导，不引用已淘汰方案。

## 6. 稳定版本策略

### 6.1 稳定的定义

本课程中的“最新稳定”定义为：

- 运行时：当前仍受官方支持、适合生产的 LTS；
- 数据库：当前受官方支持的稳定主版本；
- 框架和工具：官方 GA / stable release；
- 浏览器平台：Living Standard 或已进入目标浏览器稳定通道的机制；
- 不使用 alpha、beta、RC、nightly、canary 或仅存在于草案的主线能力。

“版本号更大”不能压过生产支持和生态兼容。

### 6.2 证据优先级

版本和兼容结论按以下顺序取证：

1. 官方版本页、支持表和迁移指南；
2. 官方发布说明和仓库 Release；
3. 官方包注册表元数据；
4. 官方兼容性数据；
5. 项目锁文件与真实命令输出。

第三方博客、搜索摘要和缓存页面不能单独决定课程版本。

### 6.3 版本落点

精确版本事实集中维护在：

- `00-guide/02-version-baseline.md`；
- 对应卷的运行条件；
- 完整工程或 Capstone 的锁定快照；
- `VALIDATION.md` 的真实验证环境。

README 和普通教程不重复维护容易漂移的全书精确版本表。

### 6.4 兼容组合

每组依赖必须同时满足：

- 运行时 engine；
- 框架 peer dependency；
- TypeScript / 类型工具兼容性；
- 构建工具插件兼容性；
- 测试运行器和浏览器驱动兼容性；
- ESM / CommonJS 边界；
- 目标数据库和客户端兼容性。

无法组成可验证稳定组合时，保留阻塞，不虚构版本。

## 8. 教学内容标准

### 8.1 每篇详细教程

继续使用固定结构：

```text
# 标题
## 任务卡
## 1. 任务背景
## 2. 学习目标
## 3. 预备知识
## 4. 核心理论
## 5. API / 属性 / 配置清单
## 6. 最小可运行案例
## 7. 邻里集市集成案例
## 8. 常见错误与排查路径
## 9. 课后题
## 10. 实践练习
## 11. 阶段验收
## 12. 常见问题
## 13. 扩展阅读
## 我现在能做到什么
## 单元导航
```

### 8.2 案例要求

每篇教程必须有：

- 文件路径；
- 创建方式；
- 运行命令；
- 正常结果；
- 失败输入；
- 证据位置；
- 修复动作；
- 同路径复验；
- 停止或清理方式；
- 未验证边界。

### 8.3 最佳实践

所有代码和架构必须遵守：

- 最小权限和默认拒绝；
- 服务端重新校验和授权；
- 整数分、UTC 和明确领域状态；
- 参数化查询和事务边界；
- 结构化错误和可恢复交互；
- 可访问名称、键盘、焦点、缩放和减少动效；
- 取消、超时、幂等、重试上限和优雅停机；
- 结构化日志、相关 ID 和敏感信息脱敏；
- 锁文件、可重复构建和负向质量门禁；
- 备份校验和隔离恢复。

每个批次必须按以下顺序：

1. 读取工作区状态和当前 Diff。
2. 建立该批文件与知识域清单。
3. 从官方来源核验稳定版本和过时项。
4. 标记保留、删除、替换、补充和拆分项。
5. 先更新版本或领域契约，再修改正文。
6. 只拆分满足门槛的教程。
7. 更新章入口、README 和覆盖矩阵。
8. 运行最小相关静态检查。
9. 运行代表性代码、浏览器或后端验证。
10. 审查最终 Diff，确认未覆盖用户改动。
11. 独立复审并修复阻塞项。
12. 更新 `VALIDATION.md` 的当前事实和未验证范围。

## 11. 验证策略

### 11.1 全书静态验证

- Markdown 文件数量与教程数量；
- 每篇教程的固定结构；
- 本地链接和锚点；
- 代码围栏闭合；
- 覆盖 ID 唯一性和双向反查；
- README、章入口和教程导航；
- 过时技术词表零命中；
- 未完成标记零命中；
- 尾随空白和意外文件；
- 50 周连续且唯一。

### 11.2 代码与配置验证

- HTML：解析、唯一 ID、引用关系；
- CSS：目标浏览器 CSSOM 或兼容解析器；
- JavaScript：目标 Node 的语法和测试；
- TypeScript / TSX：项目固定编译器与严格配置；
- Vue SFC：`vue-tsc`、测试和构建；
- JSON / JSONC / YAML / WebVTT / SQL：对应解析器；
- Dockerfile / Compose / Nginx / shell：可用工具或静态解析器；
- OpenAPI：结构和契约检查；
- 链接到外部官方资料的抽样可达性检查。

### 11.3 运行验证

- CSS、浏览器、React、Vue：Chromium 关键路径和键盘；
- JavaScript：Node 测试和故障注入；
- 工程化：格式、Lint、类型、测试、构建、预算和 E2E；
- 后端：真实 HTTP、数据库、事务和并发；环境缺失时保留阻塞；
- 全栈：容器、代理、TLS、发布、回滚和恢复；不可用时只报告静态范围。

### 11.4 禁止外推

未实际运行的环境不得写成通过，包括：

- Safari、Firefox 和真实移动设备；
- VoiceOver、NVDA、JAWS；
- 真实邮件、对象存储和支付；
- 托管 CI、镜像仓库、云主机和生产域名；
- 真实生产容量、RTO 和 RPO。

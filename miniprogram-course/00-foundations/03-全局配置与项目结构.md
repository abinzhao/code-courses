# 03-全局配置与项目结构

## 目标

完成本知识单元后，学员应能独立、规范地组织小程序工程结构，并通过全局配置驱动小程序的外观、页面注册与能力声明，而不是依赖开发者工具的默认值“凑合用”。

学员应能够：

1. 说清小程序从启动到找到首页的过程：微信如何依据 `app.json` 的 `pages` 字段确定入口页面。
2. 完整说出 `app.json` 中常用顶层字段的职责：`pages`、`window`、`tabBar`、`networkTimeout`、`permission`、`requiredPrivateInfos`、`subpackages`、`preloadRule`、`lazyCodeLoading`、`renderer`、`componentFramework`、`style`、`sitemapLocation`、`darkmode`。
3. 区分哪些配置属于“全局默认”，哪些可以在页面 `.json` 中被覆盖，理解“全局给默认、页面做个性化”的分层关系。
4. 为「逛吃指南」配置符合设计稿的导航栏、背景色、下拉刷新与触底距离。
5. 正确配置 `tabBar`：颜色、选中色、列表项的 `pagePath/text/iconPath/selectedIconPath`，理解 `custom` 自定义 tabBar 的适用场景。
6. 理解页面四件套（`.wxml/.wxss/.js/.json`）的协作关系，并按“页面、组件、工具、静态资源”建立清晰目录。
7. 说清 `project.config.json`、`project.private.config.json`、`sitemap.json` 各自的作用，区分团队共享配置与个人本地配置。
8. 通过 `permission` 与 `requiredPrivateInfos` 正确声明定位等敏感能力的用途，理解“配置声明”与“运行时授权”的区别。
9. 识别常见配置错误：页面未注册、tabBar 页面路径不匹配、图标文件缺失、JSON 尾逗号导致编译失败。
10. 建立后续分包、Skyline、组件化配置的索引，知道这些字段在课程后续由哪个单元深入。

本单元聚焦“全局配置与结构”。生命周期与路由跳转在 U04，模板语法在 U05，分包在 U26，Skyline 在 U28。

## 技术栈

本单元不引入后端或第三方 npm 包，使用 TypeScript 小程序原生项目。

| 工具或配置 | 用途 | 学习要求 |
|---|---|---|
| `app.json` | 全局配置 | 能配置页面、窗口、tabBar、权限 |
| 页面 `.json` | 单页配置 | 能覆盖窗口样式、注册页面级组件 |
| `app.js / app.ts` | 应用逻辑入口 | 知道其与 `app.json` 的分工 |
| `app.wxss` | 全局样式 | 知道全局样式与页面样式层级 |
| `project.config.json` | 项目/工具配置 | 能读懂 AppID、源码目录、编译设置 |
| `project.private.config.json` | 个人本地配置 | 理解其不入库、仅覆盖本机 |
| `sitemap.json` | 搜索索引 | 能配置页面是否可被检索 |
| 微信开发者工具 | 编辑与校验 | 能用详情面板、配置提示定位错误 |

配置约定：

- JSON 文件**不允许注释和尾逗号**（标准 JSON 语法），写错会直接编译报错。
- 所有尺寸、颜色以课程设计稿为准；路径统一使用相对路径、正斜杠 `/`。
- 配置字段随基础库演进，开课时以官方文档字段为准；本单元标注“后续单元”的字段先建立认知，不提前深挖。

## 详细的理论知识讲解和示例伪代码

### 1. 小程序如何找到入口

微信打开一个小程序时，先读取 `app.json`，其中 `pages` 字段是一个**有序的页面路径数组**：

```json
{
  "pages": [
    "pages/index/index",
    "pages/explore/explore",
    "pages/publish/publish",
    "pages/profile/profile",
    "pages/detail/detail"
  ]
}
```

关键规则：

- 数组中每一项对应一个页面，**路径不带文件后缀**，框架会自动找该目录下同名的四件套。
- **数组第一项就是小程序启动后的首页**。
- 所有要被打开的页面都必须在 `pages` 中注册（分包页面在 `subpackages` 中注册），未注册的页面无法跳转。
- 新增页面后必须把路径加入 `pages`，否则报“页面不存在”。

启动过程伪代码：

```text
读取 app.json
  → 取 pages[0] 作为入口页面
  → 加载 app.js（执行应用生命周期）
  → 加载 app.wxss
  → 渲染 pages/index/index 四件套
```

### 2. app.json 字段全景

`app.json` 是小程序的“总控制面板”，常用字段分类如下：

| 分类 | 字段 | 作用 |
|---|---|---|
| 页面注册 | `pages`、`subpackages` | 注册主包页面与分包页面 |
| 窗口外观 | `window` | 导航栏、背景、下拉刷新等全局默认 |
| 底部标签 | `tabBar` | 配置底部/顶部多 Tab |
| 网络 | `networkTimeout` | 各类网络请求超时时间 |
| 权限 | `permission`、`requiredPrivateInfos`、`requiredBackgroundModes` | 声明敏感能力用途与隐私接口 |
| 性能 | `lazyCodeLoading` | 按需注入，减小启动开销 |
| 渲染 | `renderer`、`rendererOptions`、`componentFramework` | 选择 WebView/Skyline 与组件框架 |
| 分包预取 | `preloadRule` | 进入某页面时预下载分包 |
| 主题 | `darkmode`、`themeLocation` | 深色模式与主题文件 |
| 其他 | `style`、`sitemapLocation`、`workers`、`useExtendedLib`、`entranceRenderLocation` | 样式版本、索引位置、多线程、扩展库等 |

下面逐项展开最常用部分。

### 3. window：全局窗口默认

`window` 配置所有页面的默认窗口表现，页面 `.json` 可覆盖其中大部分字段。

```json
{
  "window": {
    "navigationBarTitleText": "逛吃指南",
    "navigationBarBackgroundColor": "#ffffff",
    "navigationBarTextStyle": "black",
    "backgroundColor": "#f6f6f6",
    "backgroundTextStyle": "dark",
    "enablePullDownRefresh": false,
    "onReachBottomDistance": 50,
    "navigationStyle": "default"
  }
}
```

常用字段说明：

| 字段 | 取值 | 说明 |
|---|---|---|
| `navigationBarTitleText` | 字符串 | 导航栏标题，页面可改 |
| `navigationBarBackgroundColor` | 十六进制颜色 | 导航栏背景色 |
| `navigationBarTextStyle` | `black` / `white` | 导航栏标题/按钮颜色，仅这两值 |
| `backgroundColor` | 颜色 | 窗口下拉露出的背景色 |
| `backgroundTextStyle` | `dark` / `light` | 下拉 loading 的样式 |
| `enablePullDownRefresh` | 布尔 | 是否开启全局下拉刷新 |
| `onReachBottomDistance` | 数值（px） | 距底部多远触发触底事件 |
| `navigationStyle` | `default` / `custom` | `custom` 时只保留右上角胶囊，自定义导航 |
| `pageOrientation` | `portrait` / `landscape` / `auto` | 屏幕旋转方向 |
| `backgroundColorTop/Bottom` | 颜色 | iOS 顶部/底部窗口背景色 |

要点：

- `window` 给的是“默认值”，例如详情页想显示不同标题，在 `pages/detail/detail.json` 单独设置即可。
- 开启 `navigationStyle: custom` 后要自己处理状态栏高度与胶囊避让，这是 U07 适配单元的内容。

### 4. tabBar：底部多标签

#### 4.1 基础配置

`tabBar` 用于在多个一级页面之间快速切换，「逛吃指南」的首页、探索、发布、我的四个一级页面适合用 tabBar。

```json
{
  "tabBar": {
    "color": "#9a9a9a",
    "selectedColor": "#ff6a00",
    "backgroundColor": "#ffffff",
    "borderStyle": "black",
    "position": "bottom",
    "list": [
      {
        "pagePath": "pages/index/index",
        "text": "首页",
        "iconPath": "assets/tab/home.png",
        "selectedIconPath": "assets/tab/home-active.png"
      },
      {
        "pagePath": "pages/explore/explore",
        "text": "探索",
        "iconPath": "assets/tab/explore.png",
        "selectedIconPath": "assets/tab/explore-active.png"
      },
      {
        "pagePath": "pages/publish/publish",
        "text": "发布",
        "iconPath": "assets/tab/publish.png",
        "selectedIconPath": "assets/tab/publish-active.png"
      },
      {
        "pagePath": "pages/profile/profile",
        "text": "我的",
        "iconPath": "assets/tab/profile.png",
        "selectedIconPath": "assets/tab/profile-active.png"
      }
    ]
  }
}
```

字段规则：

- `list` 是数组，**最少 2 项、最多 5 项**。
- 每项 `pagePath` 必须是 `pages` 中已注册的页面。
- `text` 为标签文字；`iconPath/selectedIconPath` 为默认/选中图标，图片尺寸与体积有规范（建议小尺寸 png）。
- `color` 为未选中文字色，`selectedColor` 为选中文字色。
- `borderStyle` 仅支持 `black`/`white` 两档（控制顶部边线观感）。
- `position` 默认 `bottom`，设为 `top` 时不显示图标。

#### 4.2 tabBar 与路由的关系

- 切换 tabBar 页面必须使用 `wx.switchTab`，不能用 `wx.navigateTo`（U04 详解）。
- tabBar 页面在切换时不会被层层压入普通页面栈，有独立的切换逻辑。
- 从非 tabBar 页面想跳到某个 Tab，只能 `switchTab` 或 `reLaunch`。

#### 4.3 自定义 tabBar

当默认 tabBar 无法满足（如中间凸起的发布按钮、动态徽标、自定义动画），可设置：

```json
{ "tabBar": { "custom": true, "list": [] } }
```

并在根目录创建 `custom-tab-bar/` 组件自行渲染。自定义 tabBar 提高灵活度但需自己处理选中态与跳转，属于进阶内容，本课程在组件化阶段再实践，主线先用标准 tabBar。

### 5. networkTimeout 与网络相关

`networkTimeout` 统一设置各类网络 API 的超时（毫秒）：

```json
{
  "networkTimeout": {
    "request": 10000,
    "connectSocket": 10000,
    "uploadFile": 20000,
    "downloadFile": 20000
  }
}
```

- 超时后请求进入失败回调；具体请求也可在调用时单独覆盖超时。
- 网络请求的合法域名、封装在 U17 系统讲解；这里只配置超时基线。

### 6. 权限与隐私相关声明

#### 6.1 permission：能力用途说明

调用定位等能力时，需要在 `app.json` 的 `permission` 中向用户说明用途：

```json
{
  "permission": {
    "scope.userLocation": {
      "desc": "用于在地图上显示附近的探店门店"
    }
  }
}
```

- `desc` 会展示在系统授权弹窗中，文案应真实、具体。
- 这是“**配置层面的用途声明**”，真正发起定位时还要在运行时调用 `wx.getLocation` 触发授权（U21）。

#### 6.2 requiredPrivateInfos：隐私接口声明

部分隐私相关接口（如获取定位、选择位置等）需要在 `requiredPrivateInfos` 中声明：

```json
{
  "requiredPrivateInfos": ["getLocation", "chooseLocation"]
}
```

- 未声明而直接调用相关接口会失败或在审核中被拦。
- 配合“用户隐私保护指引”一并配置，是上线合规的必要项（U32 复审）。

#### 6.3 requiredBackgroundModes

需要在后台持续运行某些能力（如后台定位、后台音频）时声明：

```json
{ "requiredBackgroundModes": ["location"] }
```

本课程主线不强制后台常驻，仅在地图/硬件单元说明边界。

### 7. 性能与渲染相关配置

#### 7.1 lazyCodeLoading

按需注入可显著降低启动时注入的代码量：

```json
{ "lazyCodeLoading": "requiredComponents" }
```

- 开启后未被当前页面用到的组件/代码不立即注入，启动更快。
- 原理与收益在 U26/U27 用数据验证。

#### 7.2 renderer 与 componentFramework

```json
{
  "renderer": "webview",
  "componentFramework": "glass-easel"
}
```

- `renderer`：`webview`（默认、兼容性主线）或 `skyline`（进阶引擎，U28）。
- `componentFramework`：可指定新一代组件框架 `glass-easel`（U11 系统讲解）；默认随基础库演进。
- 这些可在全局配置，也可在单个页面 `.json` 覆盖，便于“个别页面试点 Skyline、其余保持 WebView”。

#### 7.3 style 与扩展库

- `"style": "v2"`：启用新版 WeUI 组件样式，按钮等控件使用更新的外观。
- `useExtendedLib`：可声明使用官方扩展库（如 WeUI），无需把库文件打进包内。
- `workers`：配置多线程 Worker 目录，用于把计算密集任务移出主线程（进阶）。

### 8. 页面级 .json

每个页面的 `.json` 只对当前页面生效，可：

- 覆盖 `window` 中的导航栏标题、颜色、背景、下拉刷新等；
- 通过 `usingComponents` 注册该页面用到的自定义组件或组件库组件；
- 单独指定 `renderer`、`disableScroll`、`componentPlaceholder` 等。

详情页示例：

```json
{
  "navigationBarTitleText": "探店详情",
  "enablePullDownRefresh": false,
  "usingComponents": {
    "note-card": "/components/note-card/note-card"
  }
}
```

首页示例（使用组件库）：

```json
{
  "navigationBarTitleText": "逛吃指南",
  "enablePullDownRefresh": true,
  "usingComponents": {
    "van-search": "@vant/weapp/search/index"
  }
}
```

分层关系一句话：**全局 window 是默认值，页面 json 是覆盖值，usingComponents 决定当前页能用哪些组件**。

### 9. 推荐项目结构

随业务增长，建议从一开始就建立清晰目录，而不是所有文件堆在根目录：

```text
guangchi-miniprogram/
├── miniprogram/
│   ├── app.ts
│   ├── app.json
│   ├── app.wxss
│   ├── pages/                  # 页面
│   │   ├── index/
│   │   ├── explore/
│   │   ├── publish/
│   │   ├── profile/
│   │   └── detail/
│   ├── components/             # 自定义组件
│   │   ├── note-card/
│   │   ├── empty/
│   │   └── rating/
│   ├── utils/                  # 纯逻辑工具
│   │   ├── request.ts
│   │   ├── format.ts
│   │   └── constants.ts
│   ├── assets/                 # 静态资源
│   │   ├── tab/                # tabBar 图标
│   │   └── images/
│   └── styles/                 # 公共样式（可选）
│       └── tokens.wxss
├── package.json                # npm 依赖（组件库等）
├── project.config.json
├── project.private.config.json
├── sitemap.json
└── tsconfig.json
```

组织原则：

- **pages 只放页面，components 只放可复用组件，utils 只放与界面无关的纯逻辑**。
- 组件也由四件套构成，但用 `Component` 而非 `Page`（U09 详解）。
- 静态图片放 `assets`，tabBar 图标路径与 `app.json` 完全对应。
- 分包页面后续放到独立分包目录（U26），不与主包混放。

### 10. project.config.json 与项目级配置

`project.config.json` 保存项目与开发者工具相关的团队共享设置：

```json
{
  "appid": "你的AppID",
  "compileType": "miniprogram",
  "miniprogramRoot": "miniprogram/",
  "projectname": "guangchi-miniprogram",
  "libVersion": "stable",
  "setting": {
    "es6": true,
    "enhance": true,
    "postcss": true,
    "minified": true,
    "urlCheck": true,
    "ignoreUploadUnusedFiles": true
  },
  "condition": {}
}
```

关键字段：

- `appid`：项目绑定的 AppID，与管理后台一致。
- `miniprogramRoot`：小程序源码所在目录（模板把源码放在 `miniprogram/` 时配置）。
- `libVersion`：调试基础库，`stable` 表示稳定版。
- `setting`：编译相关开关，如 ES6 转 ES5、增强编译、压缩、URL 合法性校验等。
- `packOptions`：可配置打包时忽略/包含的文件。

要点：`project.config.json` 应纳入版本管理，保证团队成员工具行为一致。

### 11. project.private.config.json（个人本地）

该文件用于保存**只在你本机生效**的个性化覆盖，例如个人的编译条件、本地 setting：

- 它会覆盖 `project.config.json` 中同名字段，但仅影响本机。
- 通常应加入 `.gitignore`，不提交到团队仓库，避免个人设置干扰他人。
- 不要把 AppSecret 等机密写在这里——它仍是普通文本文件，不是密钥管理方案。

### 12. sitemap.json：搜索索引

`sitemap.json` 控制小程序页面是否允许被微信搜索收录：

```json
{
  "desc": "关于本文件的更多信息，请参考官方文档。",
  "rules": [
    { "action": "allow", "page": "*" }
  ]
}
```

- `action: allow/disallow` 配合 `page` 指定允许或禁止索引的页面。
- 默认允许所有页面被索引；隐私页面可单独禁止。
- `app.json` 的 `sitemapLocation` 可指定该文件位置。

### 13. app.ts 与 app.wxss 的分工

- `app.ts`：通过 `App({})` 注册应用逻辑、全局数据与应用生命周期（U04 讲生命周期）。它**不负责声明页面和外观**，那是 `app.json` 的职责。
- `app.wxss`：所有页面共享的全局样式，如通用类、设计 Token；页面 `.wxss` 只作用于当前页。

最小示例：

```typescript
// app.ts
App({
  globalData: {
    appName: '逛吃指南'
  }
})
```

```css
/* app.wxss */
page {
  background: #f6f6f6;
}
```

注意：`app.json` 中写 `"pages"`，`app.ts` 中写逻辑，`app.wxss` 中写全局样式，三者职责不交叉。

### 14. 常见配置错误与排查

| 现象 | 可能原因 | 排查方向 |
|---|---|---|
| 编译报 JSON 解析错误 | 尾逗号、缺引号、写了注释 | 定位报错行，按标准 JSON 修正 |
| 跳转提示页面不存在 | 页面未在 `pages` 注册/路径拼错 | 核对 `pages` 与实际文件路径 |
| tabBar 不显示 | `list` 少于 2 项/路径不是注册页面 | 核对 list 与 pagePath |
| 图标不显示 | iconPath 文件缺失/路径错/体积过大 | 核对资源路径与文件是否存在 |
| 定位接口调用失败 | 未配 permission/requiredPrivateInfos | 补齐声明与隐私指引 |
| 全局样式没生效 | 写在页面 wxss/选择器不匹配 | 区分全局与页面样式层级 |
| 真机与工具表现不同 | 个人本地设置覆盖/基础库差异 | 对比 private 配置与基础库 |

排查原则：先看开发者工具 Console 的明确报错与文件/行号，再对照本单元字段表，不要靠“改改试试”。

# 04-生命周期与页面路由

## 目标

完成本知识单元后，学员应能理解应用与页面在双线程环境中的生命周期调度，熟练、正确地在页面间导航与传递数据，而不是只会 `wx.navigateTo` 一种跳转。

学员应能够：

1. 区分**应用生命周期**与**页面生命周期**，说出各自关键回调的触发时机与执行次数。
2. 完整描述一次页面首次加载的生命周期顺序：`onLoad → onShow → onReady`，并解释 `onReady` 与“节点可交互”的关系。
3. 说清在 `navigateTo`、`redirectTo`、`switchTab`、`reLaunch`、`navigateBack` 各操作下，原页面与目标页面分别触发哪些生命周期。
4. 正确使用五种路由 API，理解每种 API 对**页面栈**的影响，以及“页面栈最多 10 层”的限制。
5. 通过 URL query 在跳转时传参，在目标页 `onLoad(query)` 中接收，并处理参数类型与编码问题。
6. 使用 `EventChannel` 在页面间建立双向通信，实现“打开页 → 子页选择 → 回传给父页”等场景。
7. 使用 `getCurrentPages()` 获取页面栈实例，正确实现 `navigateBack` 时的数据回传。
8. 理解冷启动与热启动、`onLaunch` 与 `onShow` 的区别，以及启动参数中的 `scene`、`path`、`query`。
9. 为「逛吃指南」实现列表 → 详情 → 返回刷新、Tab 切换、跨页选择回填等真实导航流程。
10. 识别导航反模式：循环 navigateTo 导致栈溢出、对 tabBar 页用 navigateTo、返回后数据不刷新、重复注册页面。

本单元承接 U02 双线程与 U03 配置；分享相关生命周期（`onShareAppMessage` 等）在 U25 深入。

## 技术栈

本单元不引入后端或第三方依赖，使用 TypeScript 原生小程序与前面创建的五个页面。

| 工具或 API | 用途 | 学习要求 |
|---|---|---|
| `App({})` 中的生命周期 | 应用级调度 | 能写 onLaunch/onShow/onHide/onError 等 |
| `Page({})` 中的生命周期 | 页面级调度 | 能写 onLoad/onShow/onReady/onHide/onUnload |
| `wx.navigateTo` | 入栈跳转 | 理解栈+1、不可跳 tabBar |
| `wx.redirectTo` | 替换跳转 | 理解当前页卸载、栈不增 |
| `wx.switchTab` | Tab 跳转 | 理解仅用于 tabBar 页 |
| `wx.reLaunch` | 重启跳转 | 理解清空全部页面栈 |
| `wx.navigateBack` | 返回 | 会用 delta 多级返回 |
| `EventChannel` | 页面间通信 | 会用 events/emit/on |
| `getCurrentPages()` | 读取页面栈 | 能取页面实例回传数据 |
| 开发者工具 | 观察时序 | 用日志验证生命周期顺序 |

实验约定：

- 每个生命周期回调先写一行日志，通过实际操作观察触发顺序，不凭记忆背诵。
- 路由路径以 U03 注册的页面为准；真机与模拟器各至少验证一次返回刷新。
- 启动场景值、生命周期字段以官方文档为准，本单元聚焦机制与常用字段。

## 详细的理论知识讲解和示例伪代码

### 1. 两类生命周期

小程序存在两个层级的生命周期：

- **应用生命周期**：写在 `app.ts` 的 `App({})` 中，描述整个小程序从启动、前后台切换到出错的过程，全局只有一份。
- **页面生命周期**：写在每个页面的 `Page({})` 中，描述单个页面从加载、显示、隐藏到卸载的过程，每个页面各自独立。

关系示意：

```text
应用 onLaunch（仅一次）
  应用 onShow
    页面 onLoad → 页面 onShow → 页面 onReady
    （切后台）页面 onHide，应用 onHide
    （回前台）应用 onShow，页面 onShow
    （离开页）页面 onUnload
```

### 2. 应用生命周期

```typescript
// app.ts
App({
  onLaunch(options) {
    // 小程序初始化完成，全局只触发一次
    console.log('[App] onLaunch', options.scene)
  },
  onShow(options) {
    // 启动，或从后台进入前台
    console.log('[App] onShow', options.path)
  },
  onHide() {
    // 从前台进入后台
    console.log('[App] onHide')
  },
  onError(error) {
    // 发生脚本错误或 API 调用错误
    console.error('[App] onError', error)
  },
  onPageNotFound(res) {
    // 要打开的页面不存在
    console.warn('[App] onPageNotFound', res.path)
  },
  onUnhandledRejection(res) {
    // 未被 catch 的 Promise 拒绝
    console.warn('[App] onUnhandledRejection', res)
  },
  globalData: {
    appName: '逛吃指南'
  }
})
```

各回调说明：

| 回调 | 触发时机 | 典型用途 |
|---|---|---|
| `onLaunch` | 初始化完成，**仅一次** | 获取/恢复全局配置、检查登录态 |
| `onShow` | 启动或从后台回前台 | 刷新数据、读取启动参数 |
| `onHide` | 切入后台 | 暂停定时器/音视频、保存状态 |
| `onError` | JS 错误或 API 错误 | 统一收集、上报错误 |
| `onPageNotFound` | 页面路径不存在 | 重定向到兜底页 |
| `onUnhandledRejection` | Promise 未捕获拒绝 | 兜底处理异步错误 |
| `onThemeChange` | 系统明暗主题切换 | 跟随系统主题 |

#### 2.1 onLaunch / onShow 的启动参数

两者的 `options` 常用字段：

- `path`：启动时进入的页面路径；
- `query`：启动参数；
- `scene`：**启动场景值**，表示用户从哪个入口进来（扫码、分享、搜索等）；
- `shareTicket`：转发相关；
- `referrerInfo`：来源小程序/公众号信息。

```typescript
onShow(options) {
  console.log('进入页面:', options.path)
  console.log('场景值:', options.scene)
}
```

#### 2.2 冷启动与热启动

- **冷启动**：小程序此前不在运行，微信新建实例，先 `onLaunch` 再 `onShow`。
- **热启动**：小程序在后台“挂着”，用户再次进入，此时**不再触发 onLaunch**，只触发应用 `onShow` 与当前页 `onShow`。

因此“只需执行一次”的初始化放 `onLaunch`，“每次回到前台都要做”的刷新放 `onShow`，不要混用。

### 3. 页面生命周期

以详情页为例：

```typescript
// pages/detail/detail.ts
Page({
  data: { id: '', note: null },

  onLoad(query) {
    // 页面加载，仅一次，可拿到路由参数
    console.log('[Detail] onLoad', query)
    this.setData({ id: query.id })
  },
  onShow() {
    // 页面显示（每次进入都触发）
    console.log('[Detail] onShow')
  },
  onReady() {
    // 首次渲染完成，仅一次，节点可交互
    console.log('[Detail] onReady')
  },
  onHide() {
    // 页面被隐藏（navigateTo 到新页 / 切 Tab）
    console.log('[Detail] onHide')
  },
  onUnload() {
    // 页面被卸载（redirectTo/navigateBack/reLaunch）
    console.log('[Detail] onUnload')
  }
})
```

五个核心回调：

| 回调 | 次数 | 时机 | 典型用途 |
|---|---|---|---|
| `onLoad` | 一次 | 页面创建 | 取 query、初始化、首屏请求 |
| `onShow` | 多次 | 每次显示 | 返回时刷新数据、统计曝光 |
| `onReady` | 一次 | 首次渲染完成 | 依赖节点的操作 |
| `onHide` | 多次 | 被隐藏 | 暂停播放/计时 |
| `onUnload` | 一次 | 被销毁 | 清理定时器、解绑监听 |

#### 3.1 onLoad 与 onReady 的区别

- `onLoad` 只表示逻辑层页面创建，可以拿参数、发请求，但此时界面节点未必完成首次渲染。
- `onReady` 表示首次渲染完成，需要与渲染层节点打交道的操作（某些节点查询/上下文获取）在此之后才稳妥。
- 二者都只触发一次；`onShow` 在它们之间以及每次返回时都会触发。

#### 3.2 页面级事件回调

除五个核心生命周期外，页面还可提供一系列交互回调（本单元先认识，分享在 U25）：

- `onPullDownRefresh`：下拉刷新（需在配置开启）；
- `onReachBottom`：滚动触底（配合 onReachBottomDistance）；
- `onPageScroll`：页面滚动（高频，注意节流）；
- `onResize`：窗口尺寸变化（如旋转）；
- `onAddToFavorites`：收藏；
- `onShareAppMessage` / `onShareTimeline`：转发朋友/朋友圈（U25 深入）。

### 4. 生命周期顺序（重点）

#### 4.1 首次打开 A 页

```text
A.onLoad → A.onShow → A.onReady
```

#### 4.2 A 中 navigateTo 到 B，再返回

```text
打开 B:  A.onHide → B.onLoad → B.onShow → B.onReady
返回 A:  B.onUnload → A.onShow
```

要点：navigateTo **保留 A 页（只隐藏不卸载）**，因此返回时 A 只触发 `onShow`，不会重新 `onLoad`——这是“返回后刷新数据”要写在 `onShow` 的原因。

#### 4.3 A 中 redirectTo 到 B

```text
B 打开:  A.onUnload → B.onLoad → B.onShow → B.onReady
```

redirectTo 关闭并卸载当前页，A 无法返回。

#### 4.4 Tab 页之间 switchTab

```text
从 Tab A 切到 Tab B:  A.onHide → B.onShow（B 首次进入时还会 onLoad/onReady）
```

Tab 页切换只隐藏不卸载，且会关闭所有非 Tab 页面。

#### 4.5 reLaunch 到任意页

```text
所有页面 onUnload → 目标页 onLoad → onShow → onReady
```

reLaunch 清空整个页面栈，常用于登录失效后回到登录/首页。

### 5. 页面栈

#### 5.1 什么是页面栈

页面栈记录当前页面的层级关系：

- `wx.navigateTo`：栈中压入新页，**栈深度 +1**。
- `wx.navigateBack`：弹出页面，**栈深度 -1**。
- `wx.redirectTo`：替换栈顶，深度不变。
- `wx.reLaunch`：清空栈后只放目标页。
- `wx.switchTab`：关闭所有非 Tab 页并切到 Tab。

#### 5.2 最多 10 层

小程序页面栈**最多 10 层**。连续 navigateTo 超过 10 层后跳转失败。业务设计上应：

- 深层流程改用 redirectTo（如提交成功后不可返回表单页）；
- 或用 reLaunch 回到主流程；
- 避免把用户越带越深的导航设计。

查看当前栈：

```typescript
const pages = getCurrentPages()
console.log('当前页面栈深度:', pages.length)
console.log('栈顶页面:', pages[pages.length - 1].route)
```

### 6. 五种路由 API

#### 6.1 wx.navigateTo

保留当前页，打开非 Tab 页面，可返回：

```typescript
wx.navigateTo({
  url: '/pages/detail/detail?id=123&from=home',
  success() {
    console.log('跳转成功')
  },
  fail(err) {
    console.error('跳转失败', err)
  }
})
```

- 不能跳 tabBar 页面；会受 10 层限制。
- 路径前的 `/` 表示从根目录开始。

#### 6.2 wx.redirectTo

关闭当前页打开新页：

```typescript
wx.redirectTo({ url: '/pages/result/result?type=ok' })
```

适合“提交后”的结果页，避免返回又回到表单重复提交。

#### 6.3 wx.switchTab

跳转到 tabBar 页：

```typescript
wx.switchTab({ url: '/pages/index/index' })
```

- url 不能带参数；
- 会关闭所有非 Tab 页面。

#### 6.4 wx.reLaunch

关闭全部页面打开某页：

```typescript
wx.reLaunch({ url: '/pages/index/index' })
```

常用于登录失效、切换身份、异常兜底后重进主流程。

#### 6.5 wx.navigateBack

返回上一页或多级：

```typescript
// 返回上一级
wx.navigateBack()

// 返回两级
wx.navigateBack({ delta: 2 })
```

#### 6.6 路由 API 对比

| API | 当前页 | 目标页限制 | 页面栈 | 可返回 |
|---|---|---|---|---|
| navigateTo | 隐藏 | 非 Tab | +1 | 是 |
| redirectTo | 卸载 | 非 Tab | 不变 | 否 |
| switchTab | 非 Tab 全关闭 | 仅 Tab | 切 Tab | Tab 间 |
| reLaunch | 全部卸载 | 任意 | 清空 | 否 |
| navigateBack | 栈顶弹出 | 栈中页 | -1 | — |

### 7. 页面传参

#### 7.1 URL query

跳转时把参数拼在 URL 上：

```typescript
const id = 123
wx.navigateTo({ url: `/pages/detail/detail?id=${id}&title=${encodeURIComponent('探店')}`})
```

目标页接收：

```typescript
onLoad(query) {
  console.log(query.id)      // "123"，注意是字符串
  console.log(query.title)   // 解码后的"探店"
}
```

注意：

- query 中值默认是**字符串**，数字需要自行转换。
- 特殊字符（中文、空格、&）用 `encodeURIComponent` 编码。
- 参数不宜过大；复杂/大量数据用 EventChannel 或全局/缓存，而不是塞进 URL。

#### 7.2 EventChannel：父子页通信

navigateTo 可携带 `events` 监听被打开页面回传的事件，并通过被打开页的 `getOpenerEventChannel` 发消息：

父页面（列表/选择入口）：

```typescript
wx.navigateTo({
  url: '/pages/select-city/select-city',
  events: {
    // 监听子页面 emit 的事件
    citySelected(data) {
      console.log('收到选择的城市:', data.city)
    }
  },
  success(res) {
    // 也可主动向子页发消息
    res.eventChannel.emit('init', { defaultCity: '北京' })
  }
})
```

子页面（城市选择）：

```typescript
Page({
  onLoad() {
    const eventChannel = this.getOpenerEventChannel()
    eventChannel.on('init', (data) => {
      console.log('父页面给的默认值:', data.defaultCity)
    })
    this.eventChannel = eventChannel
  },
  onChoose(e) {
    const city = e.currentTarget.dataset.city
    // 回传给父页面，然后返回
    this.eventChannel.emit('citySelected', { city })
    wx.navigateBack()
  }
})
```

适用场景：选择城市/门店/分类后回填，且不想把数据放进全局或缓存。

### 8. navigateBack 回传数据

方式一：EventChannel（见上，推荐用于选择回填）。

方式二：通过 `getCurrentPages()` 拿到上一页实例，直接调用其方法：

```typescript
// 子页面
onConfirm() {
  const pages = getCurrentPages()
  const prevPage = pages[pages.length - 2] // 上一页
  prevPage?.onReceiveData?.({ value: 'from child' })
  wx.navigateBack()
}
```

父页面提供方法：

```typescript
Page({
  onReceiveData(data) {
    console.log('子页面返回:', data.value)
  }
})
```

两种方式选择：

- 结构清晰、解耦优先 → EventChannel；
- 简单回调、明确父子关系 → 页面实例方法。
- 不建议用 globalData 做一次性回传，容易残留脏数据。

### 9. 「逛吃指南」真实导航流程

#### 9.1 列表 → 详情 → 返回刷新

列表页：

```typescript
wx.navigateTo({ url: `/pages/detail/detail?id=${id}` })
```

详情页：`onLoad` 取 id 拉数据。

列表页在 `onShow` 中按需刷新（例如点赞状态可能变化）：

```typescript
Page({
  onShow() {
    // 返回本页时刷新需要同步的状态
    this.refreshIfNeeded()
  },
  refreshIfNeeded() {
    /* 拉取列表或合并本地变更 */
  }
})
```

#### 9.2 发布成功后的导航

发布成功后不应让用户返回还停留在发布表单，使用 redirectTo 或 switchTab：

```typescript
// 发布成功 → 回到首页/我的
wx.switchTab({ url: '/pages/profile/profile' })
```

#### 9.3 选择门店回填

发布页需要选择门店时，用 EventChannel 打开选择页，选择后回填到发布表单。

#### 9.4 Tab 间切换与角标

首页/探索/发布/我的通过 switchTab 或点击 tabBar 切换；如需更新某个 Tab 的数据，在其 `onShow` 处理。

### 10. 导航反模式与规避

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 对 Tab 页用 navigateTo | 跳转失败 | 用 switchTab |
| 深层流程不断 navigateTo | 超过 10 层失败 | redirectTo/reLaunch |
| 把刷新写在 onLoad 指望返回触发 | 返回后数据不更新 | 需要刷新时放 onShow |
| URL 塞大对象/不编码 | 超长、乱码、解析错 | EventChannel/缓存 + encode |
| 返回用全局变量传一次性数据 | 残留、易错乱 | EventChannel/实例方法 |
| 卸载后仍操作 setData | 警告/异常 | onUnload 清理异步与定时器 |
| onPageScroll 中频繁 setData | 卡顿 | 节流、减少通信（U27） |

### 11. 生命周期中的资源清理

在 `onUnload` / `onHide` 中清理：

- 定时器（setInterval/setTimeout）；
- 事件监听、订阅；
- 音视频播放、动画；
- 未完成请求的结果不再 setData。

```typescript
Page({
  timer: null as null | ReturnType<typeof setInterval>,
  onLoad() {
    this.timer = setInterval(() => this.tick(), 1000)
  },
  onUnload() {
    if (this.timer) clearInterval(this.timer)
  }
})
```

这与 U02“逻辑层对象残留可能泄漏”一脉相承，是性能与稳定性的基本功。

## 阶段验收作业

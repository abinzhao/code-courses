# 01-小程序生态定位与开发环境

## 目标

完成本知识单元后，学员应能建立对微信小程序的整体认知，并独立搭建好开发环境，而不是只会在开发者工具里点击“编译”。

学员应能够：

1. 用自己的语言说明小程序是什么、运行在哪里，以及它与 H5 网页、原生 App、公众号、小游戏的区别。
2. 说出小程序的技术构成：WXML、WXSS、JavaScript/TypeScript、配置文件与基础库各自承担的职责。
3. 区分小程序的能力边界：哪些能力可以直接使用，哪些需要授权、主体资质或服务端配合，哪些根本无法实现。
4. 完成小程序账号注册，理解主体类型（个人、企业、政府、媒体等）对能力与类目的影响，正确获取并保管 AppID。
5. 下载安装微信开发者工具，使用真实微信扫码登录，熟悉模拟器、编辑器、调试器三大区域。
6. 使用官方模板创建第一个项目，说清项目目录中每个核心文件与文件夹的作用。
7. 独立完成一次代码修改、编译、预览，在模拟器与真机上分别看到修改效果。
8. 理解基础库版本与微信客户端版本的关系，会切换调试基础库并判断版本兼容问题。
9. 列出小程序的关键开发限制（包体积、页面栈、域名校验、授权机制），并知道这些限制在课程后续的对应单元。
10. 建立“逻辑层与渲染层分离”的初步印象，为下一单元的双线程模型学习做好准备。

本单元只建立全局认知与环境基线。双线程模型细节、生命周期、路由与模板语法将在后续单元分别展开。

## 技术栈

本单元不使用后端框架、数据库或第三方 npm 包，重点是账号、工具与第一个原生项目。

| 工具或环境 | 用途 | 学习要求 |
|---|---|---|
| 微信账号 | 登录开发者工具、绑定小程序 | 能扫码登录，理解账号与小程序的绑定关系 |
| 小程序 AppID | 标识一个小程序 | 能在管理后台找到并正确填入项目 |
| 微信开发者工具当前稳定版 | 编码、编译、预览、调试、上传 | 能安装、登录、创建项目、切换基础库 |
| 微信客户端（手机） | 真机预览与真机调试 | 能扫码预览，理解开发者与体验成员权限 |
| WXML | 描述页面结构 | 知道它与 HTML 的对应关系与差异 |
| WXSS | 描述页面样式 | 知道它与 CSS 的对应关系与 rpx 概念 |
| JavaScript（逻辑层） | 页面逻辑与数据 | 知道它运行在逻辑层而非浏览器 |
| JSON 配置 | 全局与页面配置 | 能改窗口样式、注册页面（后续单元深入） |

课程约定：

- 所有工具、基础库统一使用“当前稳定版”表述，不写死小版本；开课时按官方渠道确认具体版本号。
- 没有小程序账号时，可先使用“测试号”或开发者工具的“测试号”模式学习，但涉及登录、支付、云开发等能力时需要真实 AppID。
- 本单元示例以微信开发者工具内置模板为准，操作系统以 macOS、Windows 主流版本均可，界面布局可能因版本不同略有差异。

开始前检查环境：

- 一台可联网的 macOS 或 Windows 电脑；
- 一个可正常登录的微信账号；
- 一部安装了微信的手机，用于真机预览；
- 建议预留 2GB 以上磁盘空间用于开发者工具与项目缓存。

## 详细的理论知识讲解和示例伪代码

### 1. 小程序是什么

#### 1.1 一句话定义

微信小程序是一种**运行在微信客户端内、无需下载安装、用完即走的轻量级应用**。它由微信提供运行环境与系统能力，开发者使用接近 Web 的技术（WXML、WXSS、JavaScript）编写业务，通过微信的分发入口触达用户。

理解这个定义要抓住三个关键词：

- **运行在微信客户端内**：小程序不是独立的操作系统进程级 App，它寄生于微信。微信为它提供运行容器、渲染环境和能力桥接。
- **无需下载安装**：用户不必去应用商店下载安装包，通过扫码、搜索、分享、下拉任务栏等入口即可打开；小程序的代码包由微信在打开时按需下载与缓存。
- **接近 Web 的技术**：结构、样式、脚本三件套与前端开发高度相似，但运行环境、API 和能力边界与浏览器明显不同。

常见误解：

> 小程序就是把网页放进微信里。

小程序在开发语言上接近 Web，但它运行在**逻辑层与渲染层分离的双线程环境**中，没有浏览器的 DOM/BOM，网络请求受合法域名约束，还能调用支付、蓝牙、定位等系统能力。它是介于 Web 与原生 App 之间的“宿主混合应用”。

#### 1.2 小程序的入口与分发

用户可以通过多种方式打开小程序，这决定了它的增长方式与普通网站、App 都不同：

- 微信内搜索小程序名称；
- 扫描小程序码、普通二维码（可配置打开指定页面）；
- 聊天、群聊中分享小程序卡片；
- 朋友圈分享（通过分享到朋友圈能力以单页模式打开）；
- “发现 - 小程序”历史列表、我的小程序收藏；
- 微信下拉聊天页调出最近使用的小程序；
- 公众号文章、视频号、直播、图文内容挂载跳转；
- 小程序之间互相跳转、从 App / 短信 / H5 中拉起（scheme、URL Link）。

对开发者的含义：小程序的流量高度依赖微信生态，分享卡片、小程序码和内容挂载是核心分发手段，这些将在阶段四“分享裂变与社交增长”单元专门训练。

### 2. 小程序与其他形态的区别

#### 2.1 与 H5 网页对比

| 对比项 | H5 网页 | 微信小程序 |
|---|---|---|
| 运行环境 | 浏览器 | 微信客户端的逻辑层 + 渲染层 |
| 页面技术 | HTML | WXML（标签与能力受限、有专用组件） |
| 样式技术 | CSS | WXSS（引入 rpx、部分选择器受限） |
| 脚本环境 | 有 window/document、DOM/BOM | 无 DOM/BOM，只能用小程序 API |
| 系统能力 | 受浏览器权限限制 | 通过 wx API 调用支付、蓝牙、定位、相机等 |
| 网络请求 | 跨域受 CORS 约束 | 受“合法域名”白名单约束，无跨域概念 |
| 分发方式 | URL，浏览器/搜索/链接 | 微信生态入口、小程序码、分享 |
| 离线与缓存 | 依赖浏览器缓存 | 代码包本地缓存，支持本地存储 |
| 启动体验 | 打开即加载网页 | 微信预加载容器，秒开体验更好 |
| 发布更新 | 部署到服务器即时生效 | 需上传、提交审核、发布，受平台审核约束 |

#### 2.2 与原生 App 对比

- **开发成本**：原生 App 需要分别为 iOS、Android 编写（Swift/Objective-C、Kotlin/Java），小程序一套代码跑在两端微信内。
- **分发与安装**：App 需应用商店下载安装，包体通常几十到几百 MB；小程序代码包主包限制很小，免安装。
- **能力深度**：原生 App 能更深度地调用系统与硬件、进行后台常驻；小程序能力由微信开放，受宿主管控，部分能力有使用门槛。
- **性能上限**：原生 App 直接调用系统渲染与计算，性能上限最高；小程序经过微信容器桥接，常规业务性能足够，但在极端复杂场景需要专门优化（Skyline 就是为此而生）。
- **触达路径**：App 依赖应用商店与推送；小程序依托微信社交关系链与生态入口。

#### 2.3 与公众号、小游戏对比

- **公众号**：以内容与服务号消息为核心，主要形态是图文、菜单和网页授权；公众号内的网页仍是 H5。小程序则是完整的应用形态，交互与能力更强，可与公众号互相跳转、绑定。
- **小游戏**：同样运行在微信内、同样无需安装，但小游戏以 Canvas/WebGL 游戏渲染为主，没有常规的 WXML 页面（或仅在少量场景使用），适合游戏而非业务应用。本课程不涉及小游戏开发。

### 3. 小程序的技术构成

一个小程序由以下几类文件共同组成：

| 技术 | 类比 Web | 承担职责 |
|---|---|---|
| WXML | HTML | 描述页面有哪些结构与组件，支持数据绑定、列表/条件渲染 |
| WXSS | CSS | 描述结构如何呈现，新增 rpx 适配单位 |
| JavaScript | 浏览器 JS | 处理业务逻辑、数据、生命周期、调用 wx API |
| TypeScript（可选） | TS | JavaScript 的类型化超集，编译后运行，本课程主线采用 |
| JSON | 配置文件 | 配置页面路径、窗口、tabBar、权限、组件等 |
| WXS（渲染层脚本） | 无直接对应 | 运行在渲染层的小脚本，常用于格式化与高频交互 |
| 基础库 | 类似运行时 SDK | 内置在微信中，提供组件、API 和运行时，版本决定可用能力 |

小程序代码分为两个层级：

- **全局层**：`app.js`、`app.json`、`app.wxss`，描述整个小程序的逻辑入口、全局配置与全局样式。
- **页面层**：每个页面通常由四个文件组成——`.wxml` 结构、`.wxss` 样式、`.js` 逻辑、`.json` 配置。

代码运行时被分到两个线程（下一单元深入）：

```text
逻辑层：运行 JavaScript，处理数据与业务（无 DOM）
   ↕ 通过微信 Native 层通信
渲染层：运行 WXML / WXSS，负责界面呈现
```

本单元只需要建立“JS 和界面不在同一个环境，数据要通过特定方式同步”的初步印象。

### 4. 小程序的能力边界

#### 4.1 能做什么

通过小程序开放的 `wx.*` API 与组件，可以实现：

- 网络请求、WebSocket、本地存储；
- 微信登录、用户头像昵称（合规方式）、手机号验证；
- 微信支付、发票、卡券；
- 定位、地图、导航；
- 拍照、选图、录音、视频、文件处理；
- 扫码（二维码/条形码）；
- 蓝牙、NFC、剪贴板、震动、屏幕亮度、网络状态；
- 订阅消息、客服消息；
- 分享、收藏、添加到我的小程序；
- 云开发（云数据库、云函数、云存储）等。

#### 4.2 能力的三类门槛

小程序能力并非全部“开箱即用”，大致分三类：

1. **可直接使用**：如基础 UI、本地存储、部分界面交互。
2. **需要用户授权或在配置中声明**：如定位、相机、相册、麦克风；需要在 `app.json` 配置 `permission` 用途说明，并在运行时请求授权。
3. **需要主体资质、类目审核或服务端配合**：如微信支付需要商户号，部分金融、医疗、政务类目有资质要求；涉及密钥的操作必须放在服务端或云函数。

#### 4.3 不能做什么

受微信容器与平台规则限制，下列事情无法或不应在小程序内实现：

- 直接操作 DOM、使用 `window`、`document` 等浏览器对象；
- 在前端代码中保存任何密钥（AppSecret、商户证书、服务器密码）；
- 绕过“合法域名”直接请求未备案/未配置的接口（开发期可临时关闭校验，上线不行）；
- 动态执行代码（如 `eval` 执行远程脚本、new Function 加载外部逻辑）；
- 无限制的后台常驻、随意拉起其他 App；
- 发布违反平台内容与类目规范的服务。

理解边界比记住 API 更重要：开发新功能前，先确认“宿主是否允许、是否需要授权或资质、密钥放哪”。

### 5. 小程序账号体系

#### 5.1 注册入口与流程

小程序账号在微信公众平台注册与管理，核心流程（以官方页面实际为准）：

```text
进入微信公众平台注册页
  → 选择账号类型“小程序”
  → 使用一个未绑定公众平台账号的邮箱
  → 邮箱激活
  → 选择主体类型并登记主体信息
  → 完成管理员实名认证（微信扫码）
  → 进入小程序管理后台
```

概念流程伪代码：

```text
输入: 可用邮箱、主体信息、管理员微信
1. 提交邮箱并收取激活邮件
2. 设置登录密码
3. 选择主体类型（个人/企业/政府/媒体/其他组织）
4. 填写并提交主体资料，个人主体使用身份证实名
5. 管理员微信扫码验证
6. 获得 AppID，进入管理后台
输出: 一个可登录、可开发的小程序账号
```

#### 5.2 主体类型与能力差异

| 主体类型 | 实名方式 | 典型能力差异 |
|---|---|---|
| 个人 | 身份证 + 管理员微信 | 可开发多数工具/内容类小程序，无法使用微信支付（不能开通商户号），部分商业类目受限 |
| 企业 | 营业执照等 | 可开通微信支付，类目最全，适合商业应用 |
| 政府/媒体/其他组织 | 对应资质 | 面向公共服务、媒体类，部分专属类目 |

对学习的影响：本课程主线项目「逛吃指南」涉及支付，个人主体无法真实开通支付，学习阶段可用：

- 企业/个体户主体开通测试商户号；
- 微信支付提供的沙箱/测试环境；
- 开发者工具与云开发支付的联调方式；
- 或先完整实现支付前后端逻辑，真机支付环节以课程指定方式演示。

#### 5.3 AppID 与 AppSecret

- **AppID**：小程序的唯一标识，创建项目、配置服务器域名、调用开放能力都要用。AppID 本身不是机密，但不应与无关项目混用。
- **AppSecret**：小程序密钥，用于服务端获取接口调用凭据。**它是机密，只能保存在服务端或云函数中，绝不能出现在小程序前端代码或仓库里。** 如怀疑泄露应在管理后台重置。

在管理后台还可以：

- 查看与管理项目成员（开发者、体验者）；
- 配置服务器合法域名（request、socket、uploadFile、downloadFile）；
- 查看版本管理（开发版、体验版、正式版）、提交审核与发布；
- 开通云开发、微信支付、订阅消息等能力。

#### 5.4 测试号

学习初期若暂不注册，可使用微信公众平台提供的“小程序测试号”或开发者工具的无 AppID 模式，但有明显限制：

- 无 AppID 模式下部分开放能力不可用、无法真机调用登录；
- 测试号方便快速体验，但不能正式发布、能力不完整。

建议尽早注册真实账号，后续云开发、登录、支付单元都依赖真实 AppID。

### 6. 微信开发者工具

#### 6.1 下载与安装

微信开发者工具是官方唯一集成开发环境，从微信官方文档/公众平台下载页获取，选择对应操作系统（macOS 注意芯片架构、Windows）的当前稳定版安装。

- macOS：下载后将应用拖入“应用程序”，首次运行如遇安全提示按系统流程允许。
- Windows：运行安装包，按向导安装。
- 不建议从第三方站点下载，避免被篡改的版本。

#### 6.2 登录

首次启动开发者工具需要用微信扫码登录。登录身份决定：

- 你能看到哪些你作为开发者的小程序；
- 预览、真机调试、上传时使用的开发者身份。

登录后可在设置中查看代理、编辑器主题、快捷键、模拟器与真机相关选项。

#### 6.3 界面布局

开发者工具主界面通常由以下区域组成（版本不同名称可能略有差异）：

```text
┌──────────────────────────────────────────────┐
│ 菜单栏 / 工具栏：编译、预览、真机调试、上传等      │
├──────────┬─────────────────────┬─────────────┤
│ 模拟器     │      编辑器           │   调试器     │
│ (页面渲染  │  (代码目录与文件编辑)  │ (Console、   │
│  与交互)   │                     │ Network等)   │
└──────────┴─────────────────────┴─────────────┘
```

- **模拟器**：在电脑上模拟微信渲染与机型，可切换机型、网络、缩放比例、显示基础库版本，支持点击、输入等基本交互。模拟器便于快速开发，但最终效果以真机为准。
- **编辑器**：文件树、代码编辑、搜索、Git、npm 构建等，支持代码提示与格式化。
- **调试器**：类似浏览器 DevTools，常用面板：
  - Console：查看逻辑层日志与报错；
  - Sources：源码与断点；
  - Network：网络请求；
  - Storage：本地存储；
  - AppData：当前页面 data，可实时查看与编辑；
  - Wxml：查看渲染层结构与样式；
  - Sensor：模拟定位、重力感应等。

#### 6.4 常用工具栏按钮

| 按钮 | 作用 |
|---|---|
| 编译 | 重新构建并在模拟器运行，可切换“普通编译/指定页面/条件编译” |
| 预览 | 生成二维码，用微信扫码在真机运行开发版 |
| 真机调试 | 真机运行并把调试信息连到电脑调试器 |
| 自动预览 | 代码保存后自动推送到真机 |
| 上传 | 把代码作为开发版/版本上传到管理后台（不是发布上线） |
| 切后台/清缓存 | 模拟小程序进入后台、清理数据/缓存/授权 |
| 详情 | 查看 AppID、基础库版本、本地设置（域名校验等） |

### 7. 创建第一个项目

#### 7.1 新建项目选项

在开发者工具选择“新建小程序”，通常需要填写：

- 项目名称与本地存放目录；
- AppID：填入真实 AppID，或选择测试号/无 AppID 模式；
- 开发模式：小程序；
- 后端服务：不使用云服务（云开发从 W7 单元开始系统接入）；
- 模板：初学者建议选择官方“JS 基础模板/TypeScript 模板”，本课程主线选 **TypeScript**。

#### 7.2 基础模板项目结构

官方模板生成后，目录大致如下：

```text
my-miniprogram/
```

各文件职责（后续单元逐一深入，这里先建立索引）：

- `app.wxss`：所有页面共享的样式；
- `pages/*`：业务页面四件套；
- `project.config.json`：AppID、源码目录、编译设置等项目级配置；
- `sitemap.json`：配置页面是否允许被微信搜索索引。

### 8. 完成第一次修改

#### 8.1 修改页面文字与数据

打开首页逻辑文件，可以看到页面有一个 `data` 对象，页面结构通过双花括号引用它。

最小示例（JavaScript）：

```javascript
// pages/index/index.js
Page({
  data: {
    message: '你好，逛吃指南'
  }
})
```

对应结构（WXML）：

```xml
<!-- pages/index/index.wxml -->
<view class="container">
  <text>{{ message }}</text>
</view>
```

修改 `data.message` 的值并保存，点击“编译”，模拟器中的文字会更新。这就是最基础的**数据绑定**：界面内容由数据决定。

使用 TypeScript 时，逻辑文件通常为 `.ts`，由开发者工具在构建时编译：

```typescript
// pages/index/index.ts
Page({
  data: {
    message: '你好，逛吃指南'
  }
})
```

#### 8.2 增加一个交互

给页面加一个按钮和处理函数，体验“事件 → 修改数据 → 界面更新”：

```xml
<view class="container">
  <text>{{ message }}</text>
  <button bindtap="onTap">点我更新</button>
</view>
```

```javascript
Page({
  data: {
    message: '你好，逛吃指南'
  },
  onTap() {
    this.setData({ message: '欢迎来到逛吃指南！' })
  }
})
```

点击按钮后文字变化。这里的 `setData` 不是普通赋值，它会把数据从逻辑层同步到渲染层——下一单元会深入其跨线程本质。

### 9. 模拟器、真机与基础库

#### 9.1 模拟器与真机差异

模拟器适合快速验证布局与逻辑，但与真机存在差异：

- 渲染细节、字体、安全区、滚动与动画可能不同；
- 部分硬件能力（蓝牙、NFC、真实定位、支付）模拟器无法完全还原；
- 性能表现必须以真机为准。

因此每个功能都应“模拟器开发 + 真机验证”。点击“预览”生成二维码，用本机微信扫码即可在真机打开开发版；“真机调试”可把真机日志与断点连到电脑。

#### 9.2 开发者与体验成员

- 被添加为“开发者”的成员可预览开发版、真机调试、上传；
- “体验者”可扫码体验“体验版”；
- 普通用户只能访问审核通过的正式版。

#### 9.3 基础库版本

- **基础库**内置在微信客户端中，提供小程序的组件、API 与运行时。微信版本越高，通常内置基础库越新。
- 新 API/组件只在达到某个基础库版本时可用；可在代码中通过版本比较或 `wx.canIUse` 做兼容。
- 开发者工具“详情 - 本地设置”可切换调试基础库，用于模拟低版本环境。

兼容判断示例：

```javascript
if (wx.canIUse('getLocation')) {
  // 该 API 在当前基础库可用
} else {
  // 给出降级提示
}
```

小程序管理后台可设置“最低基础库版本”，低于该版本的用户将收到升级提示。设置时要在“覆盖用户比例”和“新能力”之间权衡。

### 10. 关键开发限制速查

| 限制 | 规则概要 | 深入单元 |
|---|---|---|
| 包体积 | 单个包/主包有体积上限，总包体也有上限，超出需分包 | U26 分包加载 |
| 页面栈 | 路由栈最多 10 层 | U04 生命周期与路由 |
| 网络域名 | 正式环境只能请求已配置的合法域名，且需 HTTPS/备案 | U17 网络请求、U29 自建后端 |
| 授权 | 敏感能力需声明用途并在运行时授权，拒绝后要有兜底 | U16、U21 等 |
| 并发请求 | 同时存在的网络请求数量有上限 | U17 |
| setData | 数据经序列化跨线程传递，数据量/频率影响性能 | U02、U27 |
| 代码执行 | 禁止动态执行远程代码 | U02、U30 |

开发期可在“详情 - 本地设置”临时勾选“不校验合法域名”等选项以便本地联调，但**这些只对本机开发生效，上线版本一律按平台规则执行**，不能依赖它交付。

# 15-云存储与文件上传

## 目标

完成本知识单元后，学员应能把「图片/视频这类二进制大文件存到哪、怎么拿到、怎么删」讲清楚，并为「逛吃指南」打通完整的图文发布链路：用户在手机里选图、压缩、上传到云存储拿到 fileID，再把 fileID 随笔记内容写入云数据库，而不是把图片 base64 塞进数据库或只把临时路径留在前端。

学员应能够：

1. 说清云存储在云开发三件套（云数据库、云函数、云存储）中的定位：高可用、高持久、可扩展的对象存储，适合存放图片、视频、音频等二进制文件，而不是结构化数据。
2. 掌握 fileID 的概念：云存储文件的全局唯一标识，`cloud://` 开头，可在小程序端直接被 `image` 等组件识别，并说清它与 HTTPS URL、本地临时路径三者的区别与转换方式。
3. 使用 `wx.cloud.uploadFile` 完成单文件上传，正确设计 `cloudPath`（用户目录、日期、随机名、扩展名），理解同名覆盖规则与幂等问题。
4. 使用 `UploadTask` 的 `onProgressUpdate` 监听上传进度（已发字节/总字节），并用 `abort` 取消上传，能把进度准确展示到发布按钮上。
5. 使用 `wx.chooseMedia` 选择图片与视频，理解 `count`、`mediaType`、`sourceType`、`sizeType`、`maxDuration` 等参数，以及返回的 `tempFiles` 结构与本地临时文件的生命周期。
6. 使用 `wx.compressImage` 在上传前压缩图片，理解 `quality`、尺寸与文件体积的关系；知道视频可用 `wx.compressVideo`，并能根据大小决定是否压缩。
7. 使用 `wx.cloud.downloadFile` 把云文件下载为本地临时路径，使用 `wx.cloud.getTempFileURL` 批量把 fileID 换成带有效期的临时 HTTPS 链接，知道各自的适用场景。
8. 使用 `wx.cloud.deleteFile` 批量删除文件，并理解「孤儿文件」产生的原因与治理方式（删除笔记时级联清理、定时扫描）。
9. 实现多图批量上传：并发数控制、整体进度聚合、单图失败重试与部分失败处理，保证多张图与笔记记录的最终一致。
10. 说清云存储权限安全规则（所有用户可读、仅创建者可读写、按 openid 鉴权），并在「逛吃指南」中落地「选图 → 压缩 → 上传得 fileID → 写入笔记 → 删除笔记清理文件」的完整闭环。

本单元承接 U13 云数据库与 U14 云函数，是阶段二里程碑中「图文发布真实持久化」的关键一环；U16 将在此基础上完成登录鉴权与用户体系，让文件归属到真实用户。

## 技术栈

本单元基于微信原生小程序 + TypeScript，使用云开发 SDK（`wx.cloud`）与媒体 API，不引入第三方对象存储。

| 工具或 API | 用途 | 学习要求 |
|---|---|---|
| `wx.cloud.uploadFile` | 本地文件上传到云存储 | 掌握 cloudPath/filePath 与返回 fileID |
| `UploadTask` | 上传任务对象 | 会 onProgressUpdate/abort/then |
| `wx.cloud.downloadFile` | 云文件下载到本地 | 会取 tempFilePath |
| `wx.cloud.getTempFileURL` | fileID 换临时 HTTPS 链接 | 会批量换取并处理有效期 |
| `wx.cloud.deleteFile` | 删除云存储文件 | 会批量删除并读状态 |
| `wx.chooseMedia` | 选择图片/视频 | 掌握各参数与 tempFiles 结构 |
| `wx.compressImage` | 图片压缩 | 会设 quality 并处理结果 |
| `wx.compressVideo` | 视频压缩 | 了解 quality 与返回字段 |
| 云开发控制台「存储」 | 可视化管理文件与权限 | 会查看、上传、删除、配权限 |
| 云存储安全规则 | 文件读写鉴权 | 会按 openid 配置创建者权限 |
| TypeScript | 类型化上传服务 | 类型完整，不用 any 掩盖结构 |

实验约定：

- 云环境已在 U13 完成 `wx.cloud.init({ env })` 初始化，本单元所有 `wx.cloud.*` 调用均在初始化之后进行。
- 云存储目录按业务前缀划分（`notes/`、`avatars/`、`temp/`），文件名由代码生成，不直接使用用户相册中的原始文件名。
- 配额、单文件大小上限、临时链接有效期等数字以微信官方文档为准；编码时必须对「选择失败、压缩失败、上传失败、删除部分失败」逐一处理。

## 详细的理论知识讲解和示例伪代码

### 1. 云存储是什么：在云开发体系中的位置

#### 1.1 是什么

云存储是微信云开发提供的**对象存储**服务（Object Storage）。你可以把它理解成一个容量近乎无限、由腾讯云端运维的「文件仓库」：应用通过 API 把文件传上去，云端返回一个 fileID；之后可以凭 fileID 下载、展示或删除文件。它负责保存文件本身以及文件的少量元信息（大小、类型、更新时间），不负责查询业务关系。

#### 1.2 与云数据库、云函数、本地存储的关系

「逛吃指南」发布一篇图文笔记时，会同时碰到四种数据载体：

| 载体 | 存什么 | 谁来访问 | 典型内容 |
|---|---|---|---|
| 云存储 | 二进制大文件本体 | 小程序 / 云函数凭 fileID | 菜品图、探店视频 |
| 云数据库 | 结构化业务数据 | 小程序 / 云函数按集合查询 | 笔记标题、正文、图片 fileID 列表 |
| 云函数 | 后端逻辑与特权操作 | 小程序调用 | 级联删文件、签发登录态 |
| 本地 Storage / 临时文件 | 缓存与待上传文件 | 仅本机 | 草稿、刚选中的 tempFilePath |

关键关系是：**文件本体放云存储，文件的 fileID 作为「引用字段」存进云数据库**。数据库里不存图片二进制，只存一串 `cloud://` 文本，这样笔记记录可以被灵活查询、分页、排序，而图片由云存储承担分发。

#### 1.3 一个最小心智模型

```text
本地相册 --(wx.chooseMedia)--> 临时文件 tempFilePath
tempFilePath --(wx.cloud.uploadFile)--> 云端文件，得到 fileID
fileID --(随笔记写入)--> 云数据库 notes 集合的 images 字段
展示时：<image src="{{fileID}}"> 直接渲染，或 getTempFileURL 换链接
删除时：先/后用 deleteFile 清掉云端文件，再删数据库记录
```

误区提醒：

- 「把图片转 base64 存进数据库」——错误做法。base64 体积膨胀约 1/3，会把数据库记录撑得很大，查询和渲染都变慢；数据库不是文件系统。
- 「`wx.chooseMedia` 返回的路径可以直接存数据库以后展示」——错误。那是本地临时路径，换台手机或重启后就失效，必须上传云存储换成 fileID。

### 2. fileID：云存储文件的唯一标识

#### 2.1 是什么

fileID 是云存储中一个文件的全局唯一 ID，形如：

```text
cloud://cloud1-demo12345.636c-cloud1-demo12345-1258000000/notes/20261009/a1b2c3d4.jpg
```

它由三部分组成：`cloud://` 协议头、环境标识（哪个云环境）、以及环境内的完整路径。它和文件是一一对应的，删除后再传同名文件会得到新的 fileID（或覆盖，取决于路径与权限规则）。

#### 2.2 fileID、HTTPS URL、本地临时路径的区别

| 形式 | 示例 | 谁能访问 | 生命周期 | 用途 |
|---|---|---|---|---|
| fileID | `cloud://env.xxx/notes/a.jpg` | 同一云环境的小程序/云函数 | 随文件存在 | 数据库存储、组件渲染 |
| HTTPS 临时链接 | `https://...cos.ap-shanghai.myqcloud.com/...?sign=...` | 任何能访问该 URL 的程序 | 有有效期，过期失效 | 外发给服务端、`web-view`、下载工具 |
| 本地临时路径 | `http://tmp/xxx.jpg` 或 `wxfile://...` | 仅本机本小程序 | 随时可能被清理 | 选中后、压缩后、上传前 |

在云开发小程序中，`image`、`video` 等组件可以**直接把 fileID 作为 src 渲染**，SDK 会在底层完成鉴权与取流，无需先换链接。

#### 2.3 可运行示例

```typescript
// 页面 data
Page({
  data: {
    // fileID 可直接用于 image 的 src
    cover: 'cloud://cloud1-demo12345.636c-cloud1-demo12345-1258000000/notes/demo/cover.jpg',
  },
})
```

```xml
<!-- 页面 wxml：直接渲染云存储文件 -->
<image class="cover" src="{{cover}}" mode="aspectFill" />
```

误区提醒：

- 「fileID 可以发给浏览器或外部服务器直接下载」——不行。fileID 只在微信云开发体系内被识别；外部环境要用 `getTempFileURL` 换成 HTTPS 链接。
- 「fileID 里的路径可以本地拼接目录来遍历文件夹」——不行。云存储是对象存储，没有真正的「文件夹」，前缀只是对象名的一部分，不能像磁盘那样列目录（云函数/控制台可按前缀列举）。

### 3. 开通云存储、控制台管理与 cloudPath 命名规则

#### 3.1 开通与控制台

在微信开发者工具或云开发控制台中选择云环境，进入「存储」即可开通。开通后可以：

1. 可视化上传、下载、删除文件；
2. 按「前缀 + 文件名」浏览，看到文件大小、类型、更新时间；
3. 配置**权限设置**（安全规则），决定小程序端用户能读、写哪些文件；
4. 查看容量与使用量，理解云存储按「存储空间 + 下载流量 + 请求次数」计费。

#### 3.2 cloudPath 命名规则

上传时必须指定 `cloudPath`，即文件在云端的「对象名」。它有严格的字符与长度约束：

- 只能使用字母、数字以及部分允许的符号；大小写不敏感；
- 不能以 `/` 开头；总长度有限制；
- 同一路径重复上传会**覆盖**旧文件，因此业务文件不能用可预测的固定名。

推荐的命名方式：「业务前缀 / 用户或日期目录 / 随机唯一名 . 扩展名」。

#### 3.3 可运行示例：生成安全的 cloudPath

```typescript
/**
 * 生成云端存储路径
 * @param prefix 业务前缀，如 notes / avatars
 * @param ext 扩展名（不含点），如 jpg / mp4
 */
export function buildCloudPath(prefix: string, ext: string): string {
  const now = new Date()
  const ymd = `${now.getFullYear()}${pad(now.getMonth() + 1)}${pad(now.getDate())}`
  const rand = `${Date.now().toString(36)}-${Math.random().toString(36).slice(2, 10)}`
  return `${prefix}/${ymd}/${rand}.${ext}`.toLowerCase()
}

function pad(n: number): string {
  return n < 10 ? `0${n}` : `${n}`
}

// 用法
buildCloudPath('notes', 'jpg')
// => notes/20261009/lx1k2a9p-ab12cd34.jpg
```

误区提醒：

- 直接用用户相册原始文件名做 cloudPath——原始名可能含非法字符、中文、空格，且多人极易重名导致互相覆盖。
- 所有文件都丢到根目录——随着文件增多无法按前缀批量管理与清理，级联删除与孤儿扫描都很难做。

### 4. wx.cloud.uploadFile：上传第一个文件

#### 4.1 是什么

`wx.cloud.uploadFile` 把一个本地文件上传到云存储的指定路径，成功后返回该文件的 fileID。它是整个发布链路的核心：把「随时会消失的本地临时文件」变成「持久的云端文件」。

#### 4.2 参数与返回

主要参数：

- `cloudPath: string`：云端对象名（必填）；
- `filePath: string`：本地文件路径，通常来自 `chooseMedia` 或 `compressImage` 的结果（必填）；
- `header?: object`：附带的请求头；
- `success / fail / complete`：回调。若不传回调，接口返回一个 `UploadTask`（同时也是 Promise）。

成功结果：`{ fileID: string, statusCode: number, data: ..., errMsg: string }`。

#### 4.3 可运行示例

```typescript
import { buildCloudPath } from '../../utils/cloudPath'

/** 上传单个图片文件，成功返回 fileID */
export function uploadImage(filePath: string): Promise<string> {
  return new Promise((resolve, reject) => {
    wx.cloud.uploadFile({
      cloudPath: buildCloudPath('notes', 'jpg'),
      filePath,
      success(res) {
        resolve(res.fileID)
      },
      fail(err) {
        reject(new Error(err.errMsg || '上传失败'))
      },
    })
  })
}

// 在页面中调用
async function onPickAndUpload(this: WechatMiniprogram.Page.Instance<Record<string, never>, Record<string, never>>) {
  const choose = await wx.chooseMedia({ count: 1, mediaType: ['image'], sizeType: ['compressed'] })
  const localPath = choose.tempFiles[0].tempFilePath
  const fileID = await uploadImage(localPath)
  console.log('上传成功，fileID =', fileID)
}
```

误区提醒：

- 「上传成功就万事大吉，不用记录 fileID」——如果不把 fileID 落库，文件就成了无法被业务引用、也无法被正常清理的孤儿文件。
- 「失败不用管，用户自己会再点」——上传失败必须给明确反馈，并保留本地路径允许重试，否则用户以为发布成功其实图片丢失。

### 5. UploadTask：上传进度、取消与任务控制

#### 5.1 是什么

当 `uploadFile` 不传入 success/fail 回调时，返回值是一个 `UploadTask`。它既是 Promise（可以 `await` 拿结果），又提供 `onProgressUpdate` 监听进度、`abort` 取消上传。发布大图/视频时，进度条能显著缓解用户「是不是卡死了」的焦虑。

#### 5.2 进度回调字段

`onProgressUpdate(res)` 中：

- `res.progress`：0–100 的百分比；
- `res.totalBytesSent`：已上传字节数；
- `res.totalBytesExpectedToSend`：文件总字节数。

#### 5.3 可运行示例

```typescript
import { buildCloudPath } from '../../utils/cloudPath'

interface UploadHandle {
  task: WechatMiniprogram.UploadTask
  promise: Promise<string>
}

/** 带进度与取消能力的上传 */
export function uploadWithProgress(
  filePath: string,
  onProgress: (percent: number) => void,
): UploadHandle {
  const task = wx.cloud.uploadFile({
    cloudPath: buildCloudPath('notes', 'jpg'),
    filePath,
  })

  task.onProgressUpdate((p) => {
    onProgress(p.progress)
  })

  const promise = task.then((res) => res.fileID)

  return { task, promise }
}
```

页面中使用：

```typescript
const handle = uploadWithProgress(localPath, (percent) => {
  this.setData({ uploadPercent: percent })
})
try {
  const fileID = await handle.promise
} catch (err) {
  wx.showToast({ title: '上传失败', icon: 'none' })
}

// 用户点「取消」
// handle.task.abort()
```

误区提醒：

- 「`abort` 之后云端一定没有残留文件」——取消可能发生在文件已传完但响应未回来的瞬间，云端可能已有对象；严谨做法是把这类文件放到 `temp/` 前缀，配合孤儿清理。
- 「多张图各自显示独立百分比就够了」——多图发布时用户更关心**整体进度**，需要做进度聚合（见第 11 节）。

### 6. wx.chooseMedia：选择图片与视频

#### 6.1 是什么

`wx.chooseMedia` 是当前推荐的媒体选择 API（替代了较早的 `wx.chooseImage` / `wx.chooseVideo`），一次调用可以选图片或视频，返回本地临时文件信息。它不会上传任何内容，只负责「从相册/相机拿到本地文件」。

#### 6.2 关键参数

- `count`：最多选择数量（图片最多 9 个数量级，以文档为准）；
- `mediaType`：`['image']`、`['video']` 或 `['image', 'video']`；
- `sourceType`：`['album', 'camera']`，相册还是拍摄；
- `sizeType`：`['original', 'compressed']`，是否使用系统压缩版；
- `maxDuration` / `camera`：拍摄视频时长上限、前后置摄像头。

返回 `res.tempFiles`，每项包含 `tempFilePath`、`size`，视频还包含 `duration`、`height`、`width`、`fileType` 等；`res.type` 表示来源是相册还是相机。

#### 6.3 可运行示例

```typescript
interface PickedFile {
  path: string
  size: number
  mediaType: 'image' | 'video'
}

/** 选择最多 9 个图片/视频 */
export function pickNoteMedias(count = 9): Promise<PickedFile[]> {
  return new Promise((resolve, reject) => {
    wx.chooseMedia({
      count,
      mediaType: ['image', 'video'],
      sourceType: ['album', 'camera'],
      sizeType: ['compressed'],
      maxDuration: 60,
      success(res) {
        const files: PickedFile[] = res.tempFiles.map((f) => ({
          path: f.tempFilePath,
          size: f.size,
          // fileType 在视频时为 video，图片为 image；做一次归一
          mediaType: (f.fileType === 'video' ? 'video' : 'image') as 'image' | 'video',
        }))
        resolve(files)
      },
      fail(err) {
        // 用户主动取消也会走 fail，按业务区分提示
        reject(new Error(err.errMsg))
      },
    })
  })
}
```

误区提醒：

- 「选了 9 张就可以假设用户网络能一次传完」——弱网下大图可能传很久或失败，必须有压缩、进度与重试。
- 把「用户取消选择」当成错误弹红色提示——取消是正常行为，应静默处理。
- 继续用已停止维护的 `wx.chooseImage`——新项目统一用 `wx.chooseMedia`，能力更完整（支持视频、信息更丰富）。

### 7. wx.compressImage / compressVideo：上传前压缩

#### 7.1 为什么要压缩

手机原图常达 3–12 MB，直接上传在弱网下慢且容易失败，云端存储与流量成本也更高；而笔记列表里展示的图片往往只需要几百像素。上传前压缩是「客户端用一点 CPU，换网络与成本的大幅节省」的标准做法。

#### 7.2 wx.compressImage

参数：`src`（原图临时路径）、`quality`（0–100，质量越高越清晰、体积越大）、可选 `compressedWidth`（压缩后的宽，高按比例缩放）。成功返回新的 `tempFilePath`。

#### 7.3 可运行示例

```typescript
/** 压缩图片；超过阈值才压缩，失败时回退原图 */
export async function compressIfNeeded(
  filePath: string,
  size: number,
  maxSize = 1.5 * 1024 * 1024,
): Promise<string> {
  if (size <= maxSize) return filePath
  try {
    const res = await wx.compressImage({
      src: filePath,
      quality: 72,
      compressedWidth: 1280,
    })
    return res.tempFilePath
  } catch (err) {
    // 压缩失败不应阻断发布，回退使用原图
    console.warn('压缩失败，使用原图上传', err)
    return filePath
  }
}
```

视频可用 `wx.compressVideo({ src, quality: 'medium' })`，返回压缩后的 `tempFilePath` 与 `size`；压缩耗时较长，应提示等待并允许取消。

#### 7.4 参数怎么选

| 场景 | quality | 宽度建议 | 说明 |
|---|---:|---:|---|
| 缩略图/列表图 | 50–60 | 400–600 | 体积优先 |
| 笔记正文图 | 70–80 | 1080–1280 | 清晰度与体积平衡 |
| 原图回看/打印 | 90–100 | 不缩放 | 仅在确有必要时 |

误区提醒：

- quality 越低越好——过低会出现明显色块、文字发虚，影响「逛吃」内容观感。
- 压缩是同步瞬间完成——大图压缩要几百毫秒到数秒，应在真机实测；不能在压缩过程中让界面无响应无提示。
- 反复压缩同一张图——每次有损压缩都会累积失真，只对原图压缩一次。

### 8. wx.cloud.downloadFile：下载到临时路径

#### 8.1 是什么

`wx.cloud.downloadFile` 凭 fileID 把云端文件下载为本地临时文件，返回 `tempFilePath`。它适合「把云文件保存到本地、交给需要本地路径的 API 处理（如再压缩、保存到相册）」的场景。

#### 8.2 可运行示例

```typescript
/** 下载云文件并保存到用户相册（图片） */
export async function saveImageToAlbum(fileID: string): Promise<void> {
  const dl = await wx.cloud.downloadFile({ fileID })
  await wx.saveImageToPhotosAlbum({ filePath: dl.tempFilePath })
}

// 调用（注意 saveImageToPhotosAlbum 需要相册授权，失败要引导设置）
saveImageToAlbum(fileID)
  .then(() => wx.showToast({ title: '已保存', icon: 'success' }))
  .catch(() => wx.showToast({ title: '保存失败', icon: 'none' }))
```

`downloadFile` 同样返回 `DownloadTask`，支持 `onProgressUpdate` 与 `abort`，用法与上传任务一致。

误区提醒：

- 「只是想在页面上显示图片也要先 downloadFile」——不必。`image` 组件直接用 fileID 作 src 即可，多一次下载反而浪费流量。
- 「下载得到的 tempFilePath 可以长期使用」——临时文件随时可能被系统清理，需要长期保存就写入相册或重新下载。

### 9. getTempFileURL：把 fileID 换成可访问的 HTTPS 链接

#### 9.1 是什么

`wx.cloud.getTempFileURL` 把一个或多个 fileID 换成带签名、**有有效期**的 HTTPS 链接。当文件要「走出微信云开发体系」时（例如传给自有后端、在 `web-view` 中打开、用非云开发的下载工具拉取、生成可外发的海报图），就需要这个转换。

#### 9.2 参数与返回

- `fileList`：字符串数组（也支持 `{ fileID, maxAge }` 对象形式指定有效期）；
- 返回 `res.fileList`，每项包含 `fileID`、`tempFileURL`、`status`（0 为成功）、`maxAge`、`errMsg`。

#### 9.3 可运行示例

```typescript
/** 批量换取临时链接，返回 fileID -> URL 映射 */
export async function resolveTempURLs(fileIDs: string[]): Promise<Record<string, string>> {
  if (fileIDs.length === 0) return {}
  const res = await wx.cloud.getTempFileURL({ fileList: fileIDs })
  const map: Record<string, string> = {}
  for (const item of res.fileList) {
    if (item.status === 0) {
      map[item.fileID] = item.tempFileURL
    } else {
      console.error('换取临时链接失败', item.fileID, item.errMsg)
    }
  }
  return map
}
```

使用建议：

1. **临时链接即换即用**，不要把它长期存进数据库——存库的应是长期有效的 fileID；
2. 链接过期后重新换取即可，换取操作开销很小；
3. 有效期具体时长与可配置范围以官方文档为准，不要在业务里硬编码「永远有效」。

误区提醒：

- 「把临时链接存库，以后直接用」——链接过期即失效，历史数据会大面积裂图。
- 「一次只换一个，循环 await」——应批量传入 fileList，一次请求换多个，减少往返。

### 10. deleteFile：删除文件与批量删除

#### 10.1 是什么

`wx.cloud.deleteFile` 按 fileID 列表删除云端文件，返回每个文件的删除状态。它用于两类场景：删除笔记时清理其图片/视频；清理临时文件与孤儿文件。删除操作受权限约束：小程序端只能删「安全规则允许自己删」的文件，越权删除应由云函数完成。

#### 10.2 可运行示例

```typescript
/** 批量删除云文件；返回是否全部成功 */
export async function deleteCloudFiles(fileIDs: string[]): Promise<boolean> {
  const valid = fileIDs.filter((id) => id && id.startsWith('cloud://'))
  if (valid.length === 0) return true
  const res = await wx.cloud.deleteFile({ fileList: valid })
  const failed = res.fileList.filter((item) => item.status !== 0)
  if (failed.length > 0) {
    console.error('部分文件删除失败', failed)
    return false
  }
  return true
}
```

返回的 `fileList` 每项含 `fileID`、`status`、`errMsg`，因此即便「部分失败」也能精确定位是哪些文件，便于重试。

误区提醒：

- 「fileID 已经从数据库删掉，文件占不占空间无所谓」——文件本体仍在云存储中持续占用空间与产生成本，形成孤儿文件。
- 「随便什么 fileID 都能删」——小程序端受安全规则限制；删除他人的文件必须在云函数中用管理端权限执行并先做归属校验。

### 11. 批量上传：并发控制、进度聚合与失败重试

#### 11.1 为什么不能简单 Promise.all

一篇笔记最多 9 个媒体文件，若直接 `Promise.all` 同时传，弱网下会争抢带宽、任一失败即整体 reject、且没有单图重试；而一次只传一个又太慢。工程上常用「**有限并发 + 整体进度 + 单项重试**」。

#### 11.2 可运行示例

```typescript
interface BatchItem {
  path: string
  size: number
}

interface BatchResult {
  fileIDs: string[]
  failed: string[]
}

/** 有限并发执行器 */
async function runWithConcurrency<T, R>(
  items: T[],
  limit: number,
  worker: (item: T, index: number) => Promise<R>,
): Promise<R[]> {
  const results: R[] = new Array(items.length)
  let cursor = 0
  async function next(): Promise<void> {
    while (cursor < items.length) {
      const index = cursor
      cursor += 1
      results[index] = await worker(items[index], index)
    }
  }
  const runners = Array.from({ length: Math.min(limit, items.length) }, () => next())
  await Promise.all(runners)
  return results
}

/** 带重试的单次上传 */
async function uploadOnceWithRetry(filePath: string, retries = 2): Promise<string> {
  let lastErr: unknown
  for (let attempt = 0; attempt <= retries; attempt += 1) {
    try {
      const res = await wx.cloud.uploadFile({
        cloudPath: buildCloudPath('notes', 'jpg'),
        filePath,
      })
      return res.fileID
    } catch (err) {
      lastErr = err
      await delay(500 * (attempt + 1))
    }
  }
  throw lastErr instanceof Error ? lastErr : new Error('上传失败')
}

function delay(ms: number): Promise<void> {
  return new Promise((r) => setTimeout(r, ms))
}
```

进度聚合：以「总字节」为权重，比按「文件个数」更准确。

```typescript
export async function uploadBatch(
  items: BatchItem[],
  onProgress: (percent: number) => void,
): Promise<BatchResult> {
  const sent = new Array(items.length).fill(0)
  const totalBytes = items.reduce((sum, it) => sum + it.size, 0)
  const fileIDs: string[] = []
  const failed: string[] = []

  await runWithConcurrency(items, 3, async (item, index) => {
    try {
      const task = wx.cloud.uploadFile({
        cloudPath: buildCloudPath('notes', 'jpg'),
        filePath: item.path,
      })
      task.onProgressUpdate((p) => {
        sent[index] = Math.floor((item.size * p.progress) / 100)
        const done = sent.reduce((a, b) => a + b, 0)
        onProgress(Math.min(100, Math.floor((done / totalBytes) * 100)))
      })
      const res = await task
      fileIDs[index] = res.fileID
    } catch (err) {
      console.error('第', index, '张上传失败', err)
      failed.push(item.path)
    }
  })

  return { fileIDs: fileIDs.filter(Boolean), failed }
}
```

误区提醒：

- 并发开得越大越快——超过网络承载能力反而加剧超时，3 个左右是较稳妥的经验值，需真机实测调整。
- 「部分失败也照常发布，失败的位置悄悄空着」——会让笔记出现「缺图」；应在发布前明确告知用户哪些图失败，允许重试或剔除。
- 重试不做间隔——立即重试在弱网下容易连续失败，应递增等待。

### 12. 云存储权限与安全规则

#### 12.1 为什么需要权限

云存储里既有「所有人可见的笔记图片」，也有「未发布的临时文件、用户头像」。如果权限配置成「所有用户可读写」，任何用户都能删除或覆盖他人的文件；配置成「所有人不可读写」又会让正常浏览失败。权限必须按业务最小化。

#### 12.2 常见权限模型

云开发控制台「存储 → 权限设置」中用安全规则描述，常见四类：

1. 所有用户可读，仅创建者可读写；
2. 仅创建者可读写；
3. 所有用户可读，仅管理端（云函数）可写；
4. 自定义安全规则。

「创建者」身份来自平台鉴权后的用户 openid（云开发会在规则里注入 `auth.openid`），**不是前端传上来的某个字段**。

#### 12.3 自定义规则示例（概念示例，字段名以文档为准）

```json
// notes 目录：登录用户可读；只有文件创建者本人可写/删
{
  "read": true,
  "write": "auth.openid == request.openid"
}
```

配合第 4 节的上传：文件的「创建者」由平台记录，前端无法伪造。对于「删除他人违规内容」这类操作，规则不应放开，而是在**云函数中校验管理员身份后用管理端 SDK 删除**。

#### 12.4 最小权限实践

| 目录 | 建议权限 | 理由 |
|---|---|---|
| `notes/**` | 所有用户可读，创建者/云函数可写删 | 笔记要公开浏览 |
| `avatars/**` | 所有用户可读，本人可写 | 头像公开展示 |
| `temp/**` | 仅本人可读写，定期清理 | 未发布内容，不应公开 |

误区提醒：

- 「前端先比对 openid 相同才允许点删除按钮就安全了」——按钮隐藏只是体验，真正的防线是云端安全规则；攻击者可以绕过界面直接发请求。
- 「为了方便联调，先全开权限，以后再收」——权限放开期间的文件可被任意篡改/删除，且很容易忘记收回。

### 13. 发布链路实战：选图 → 压缩 → 上传 → fileID 写入笔记

#### 13.1 整体时序

把前面各节串成「逛吃指南」的完整发布链路：

```text
1) wx.chooseMedia 选 1~9 个媒体，得到本地临时文件与大小
2) 逐个 compressIfNeeded 压缩（图片），得到待上传路径
3) uploadBatch 有限并发上传，聚合整体进度，收集 fileIDs
4) 全部成功后，把 fileIDs 随标题/正文/位置写入 notes 集合
5) 若写库失败：删除已上传文件（补偿），提示用户重试，避免孤儿
```

#### 13.2 可运行示例：发布服务

```typescript
import { pickNoteMedias } from './media'
import { compressIfNeeded } from './compress'
import { uploadBatch } from './batchUpload'
import { deleteCloudFiles } from './delete'

interface PublishDraft {
  title: string
  content: string
  location?: string
}

/** 发布一篇图文笔记，返回新建记录 id */
export async function publishNote(
  draft: PublishDraft,
  onProgress: (percent: number) => void,
): Promise<string> {
  // 1. 选图
  const picked = await pickNoteMedias(9)

  // 2. 压缩
  const prepared = await Promise.all(
    picked.map(async (f) => ({
      path: f.mediaType === 'image' ? await compressIfNeeded(f.path, f.size) : f.path,
      size: f.size,
    })),
  )

  // 3. 上传
  const { fileIDs, failed } = await uploadBatch(prepared, onProgress)
  if (failed.length > 0 || fileIDs.length === 0) {
    // 已成功上传的也要清掉，避免半成品
    await deleteCloudFiles(fileIDs)
    throw new Error('部分图片上传失败，请重试')
  }

  // 4. 写库（openid 由云函数/安全规则注入，不由前端传）
  try {
    const res = await wx.cloud.database().collection('notes').add({
      data: {
        title: draft.title,
        content: draft.content,
        location: draft.location ?? '',
        images: fileIDs,
        likes: 0,
        createdAt: new Date(),
      },
    })
    return res._id
  } catch (dbErr) {
    // 5. 写库失败的补偿：删掉已上传文件
    await deleteCloudFiles(fileIDs)
    throw dbErr
  }
}
```

页面里：

```typescript
async onPublish() {
  if (this.data.title.trim() === '') {
    wx.showToast({ title: '请填写标题', icon: 'none' })
    return
  }
  this.setData({ publishing: true })
  try {
    const id = await publishNote(
      { title: this.data.title, content: this.data.content, location: this.data.location },
      (percent) => this.setData({ progress: percent }),
    )
    wx.showToast({ title: '发布成功', icon: 'success' })
    wx.redirectTo({ url: `/pages/note-detail/note-detail?id=${id}` })
  } catch (err) {
    wx.showToast({ title: err instanceof Error ? err.message : '发布失败', icon: 'none' })
  } finally {
    this.setData({ publishing: false })
  }
}
```

误区提醒：

- 「先写库再传图」——记录里会先出现空 images，且传图失败后还要回滚数据库；本链路采用「先传图、成功后写库、写库失败补偿删图」，更易保证一致。
- 「把当前用户 openid 由前端读出来一起写库」——身份应由云函数/安全规则从平台上下文取，前端传的 openid 不可信（U16 会系统讲）。
- 「发布成功以前端调用返回为准，不校验」——应以数据库中确实存在该记录、且记录内 fileID 可渲染为准。

### 14. 删除笔记时的文件清理与一致性

#### 14.1 问题本质

删除一篇笔记涉及两处真值：数据库记录 + 云存储文件。两者不是一个原子操作，顺序不同，失败时的「补救方向」也不同：

- **先删文件、再删库**：删库失败 → 笔记还在但图没了（用户可见的损坏）；
- **先删库、再删文件**：删文件失败 → 记录已消失但留下孤儿文件（用户无感，可事后清理）。

因此通常选择「**先删数据库记录，再尽力删除文件；删文件失败进入待清理队列/定时任务**」，把问题降级为不影响用户的后台治理。

#### 14.2 可运行示例：云函数级联删除

```typescript
// cloudfunctions/deleteNote/index.ts （云函数，管理端权限）
import cloud from 'wx-server-sdk'

cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const db = cloud.database()

interface NoteRecord {
  images: string[]
  authorOpenid: string
}

exports.main = async (event: { noteId: string }) => {
  const { OPENID } = cloud.getWXContext()

  const doc = await db.collection('notes').doc(event.noteId).get()
  const note = doc.data as NoteRecord

  // 归属校验：只能删自己的笔记（管理员逻辑另判）
  if (note.authorOpenid !== OPENID) {
    return { ok: false, code: 'FORBIDDEN' }
  }

  // 1. 先删数据库记录
  await db.collection('notes').doc(event.noteId).remove()

  // 2. 再尽力删文件；失败不阻断，记录到待清理集合
  const images = note.images ?? []
  if (images.length > 0) {
    const res = await cloud.deleteFile({ fileList: images })
    const failed = res.fileList.filter((f) => f.status !== 0).map((f) => f.fileID)
    if (failed.length > 0) {
      await db.collection('file_cleanup_tasks').add({
        data: { fileIDs: failed, noteId: event.noteId, createdAt: new Date(), retries: 0 },
      })
    }
  }

  return { ok: true }
}
```

再配一个定时触发的云函数，读取 `file_cleanup_tasks` 重试删除并淘汰超过次数的任务、记录告警。

#### 14.3 孤儿文件的兜底治理

即便补偿与级联都做了，仍可能因崩溃、取消产生孤儿文件，常用两种兜底：

1. 删除链路的待清理队列 + 定时重试（覆盖「删文件失败」）；
2. 定期任务扫描 `temp/**` 等临时前缀中超过 N 天的对象直接清理（覆盖「流程中断」）。

误区提醒：

- 「删除接口返回成功就代表文件一定删了」——要检查返回列表中每个文件的 `status`，部分失败必须可追踪。
- 「定时任务全库扫描所有文件找孤儿」——成本高且容易误删；按临时前缀 + 待清理表做定向治理更安全。

### 15. 常见误区、成本与安全清单

#### 15.1 功能正确性误区汇总

1. 用 base64/数据库存文件本体；
2. 把本地临时路径当永久地址落库；
3. 用原始文件名上传导致非法字符或互相覆盖；
4. 上传/删除只看整体回调、不逐项处理状态；
5. 批量上传无并发限制、无重试、无整体进度；
6. 删除笔记不清文件，长期积累孤儿。

#### 15.2 安全红线

- 文件的「创建者/归属」由平台 openid 决定，前端无法伪造；越权删除必须经云函数校验；
- 云存储权限按目录最小化：公开内容可读、临时与私有内容仅本人可读写；
- 任何密钥（云环境之外的自有存储密钥等）只能存在服务端/云函数，**绝不能写进小程序包或前端代码**；
- 用户上传的图片/视频应配合内容安全检测，违规内容不能直接公开（与 U16 合规收集一脉相承）。

#### 15.3 成本意识

云存储成本来自三块：存储空间、下载/回源流量、请求次数。减少成本的手段包括：上传前压缩、用 fileID 直接渲染（避免不必要的下载）、及时清理孤儿与临时文件、列表用缩略图而不是原图。

#### 15.4 发布前自检清单

```text
[ ] chooseMedia 取消操作不报错、不弹窗
[ ] 大图在真机压缩后体积明显下降且画质可接受
[ ] 上传进度整体准确，断网/切后台后行为可预期
[ ] 单图失败可重试，部分失败不会产生缺图笔记
[ ] 写库失败会补偿删除已上传文件
[ ] 删除笔记后云端文件被清理，失败进入待清理队列
[ ] notes/avatars/temp 目录权限按最小化配置
[ ] 前端代码与包中无任何密钥
```

参考代码：

```typescript
export function uploadWithProgress(
  filePath: string,
  onProgress: (percent: number) => void,
): { task: WechatMiniprogram.UploadTask; promise: Promise<string> } {
  const task = wx.cloud.uploadFile({
    cloudPath: buildCloudPath('temp', 'jpg'),
    filePath,
  })

  return { task, promise: task.then((res) => res.fileID) }
}
```

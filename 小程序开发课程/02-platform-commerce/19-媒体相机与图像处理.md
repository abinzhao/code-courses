# 19-媒体相机与图像处理

## 目标

完成本知识单元后，学员应能把「用户选了一张照片/一段视频之后，数据在小程序里经历了什么」完整讲清，并为「逛吃指南」的发布页交付多图、视频、现场拍摄与分享海报能力，而不是只会调一个 `wx.chooseImage` 拿到路径后直接拼接。

学员应能够：

1. 说清小程序的四类文件：代码包文件、本地临时文件、本地缓存文件（用户文件目录）、云端文件，以及各自的生命周期与可写性。
2. 使用 `wx.chooseMedia` 完成图片/视频选择，理解 `count`、`mediaType`、`sourceType`、`sizeType`、`camera`、`maxDuration` 等参数与返回结构 `tempFiles`。
3. 使用 `wx.previewMedia` / `wx.previewImage` 做全屏预览，并能处理视频封面、起始下标等细节。
4. 使用 `wx.compressImage` / `wx.compressVideo` 在上传前控制体积，理解质量参数、尺寸参数与反复压缩的代际损失。
5. 使用 `wx.saveImageToPhotosAlbum` 保存海报，并在 `scope.writePhotosAlbum` 被拒绝时给出可恢复的引导（设置页兜底），而不是静默失败。
6. 使用 `camera` 组件与 `CameraContext` 完成拍照、录像，理解它与 `chooseMedia` 调起系统相机的差异。
7. 使用 `onCameraFrame` 获取实时帧数据，知道帧回调的性能边界（禁止逐帧 `setData`、按帧采样、页面隐藏时停止监听）。
8. 使用 `video` 组件与 `VideoContext` 完成视频播放控制，并理解封面、自动播放策略与基础音频能力约束。
9. 掌握新版 Canvas 2D（`type="2d"`）：获取节点与上下文、按 DPR 缩放、离屏画布、绘制图片与文字、圆角裁剪、`canvasToTempFilePath` 导出临时图片生成分享海报。
10. 使用 `editor` 富文本组件完成图文混排编辑，并在「逛吃指南」中升级发布页：多图/视频/拍摄/海报上传走云存储或服务端，提交时拿到的是远程地址而非临时路径。

本单元承接 U17/U18 的网络与列表工程，是阶段三“平台能力”的第一块硬件相关能力，也为 U24 的分享传播提供海报素材。

## 技术栈

本单元使用微信原生能力 + TypeScript，媒体文件最终通过云存储或自建服务端持久化。

| 工具或环境 | 用途 | 学习要求 |
|---|---|---|
| wx.chooseMedia | 选择图片/视频（相册或拍摄） | 掌握参数组合与 tempFiles 结构 |
| wx.previewMedia / wx.previewImage | 全屏预览图片与视频 | 会传 sources、current、poster |
| wx.compressImage / wx.compressVideo | 上传前压缩 | 理解 quality、分辨率与体积关系 |
| wx.saveImageToPhotosAlbum | 保存图片到系统相册 | 会处理授权拒绝与 openSetting 兜底 |
| camera 组件 | 页内自定义相机预览 | 掌握属性、binderror、设备切换 |
| wx.createCameraContext | CameraContext 拍照录像 | takePhoto/startRecord/stopRecord |
| CameraContext.onCameraFrame | 实时帧监听 | 理解 ArrayBuffer 帧数据与性能边界 |
| video 组件 + VideoContext | 视频播放与控制 | play/pause/seek、poster、controls |
| canvas type="2d" | 新版 2D 画布 | 节点查询、DPR、绘制与导出 |
| canvas.createOffscreenCanvas | 离屏绘制 | 预渲染素材、合成海报 |
| wx.canvasToTempFilePath | 画布导出临时图片 | 新版需传 canvas 节点 |
| editor 组件 + EditorContext | 富文本图文编辑 | format、insertImage、getContents |
| wx.getSetting / authorize / openSetting | 授权查询与拒绝兜底 | 理解三种授权状态 |
| wx.uploadFile | 上传文件到自建服务端 | filePath/name/formData，域名白名单 |
| wx.cloud.uploadFile | 上传到云存储 | cloudPath 规范，得到 fileID |
| FileSystemManager | 临时文件落为本地用户文件 | saveFile、USER_DATA_PATH |
| TypeScript | 类型化媒体模块 | 不用 any 掩盖 tempFiles 结构 |

权限与文件约定：

- 使用相机、麦克风、相册写入分别需要 `scope.camera`、`scope.record`、`scope.writePhotosAlbum`；这些能力还要求在小程序后台配置隐私接口与隐私协议，用户同意隐私政策后授权链路才完整。
- `chooseMedia` 得到的是**临时文件**，微信会在存储空间紧张时清理；要长期保留只能“上传到云端/服务端”或“保存到系统相册”，不能把临时路径写进数据库当作可长期访问的地址。
- 本单元 API 参数与返回以官方文档为准，所有异步媒体操作必须处理 fail，真机与开发者工具表现不一致时以真机为准。

## 详细的理论知识讲解和示例伪代码

### 1. 媒体能力全景：四类文件与一条完整链路

在小程序里谈“图片/视频”，先谈**文件**。逻辑层 JS 拿不到用户手机的磁盘，所有媒体素材都以“受微信托管的文件路径”出现，常见有四类：

| 类型 | 来源示例 | 路径特征 | 生命周期 | 可写性 |
|---|---|---|---|---|
| 代码包文件 | 打包自带的占位图 | `/assets/logo.png` | 随版本存在 | 只读 |
| 本地临时文件 | `chooseMedia`、拍照、`canvasToTempFilePath` | `http://tmp/...` 或 `wxfile://tmp...` | 本次运行期，可能随时被清理 | 可读 |
| 本地缓存文件 | FileSystemManager 写入用户目录 | `wx.env.USER_DATA_PATH` 下 | 持久化，直到用户清理或超配额 | 可读写 |
| 云端文件 | 云存储 fileID 或服务端 HTTPS 地址 | `cloud://...` / `https://...` | 由云端保存 | 经接口管理 |

一条典型的发布链路是：

```text
chooseMedia / camera 拍照
  -> 得到本地临时文件路径
  -> （可选）compressImage/compressVideo 压缩
  -> 预览确认 / Canvas 合成海报
  -> uploadFile 或 wx.cloud.uploadFile 上传
  -> 得到远程 URL / fileID
  -> 把远程地址随业务数据提交入库
  -> 列表、详情、分享都消费远程地址
```

核心结论：

> 临时路径只在“这一步”有效，入库的必须是远程地址。把 `http://tmp/xxx` 存进数据库，等于存了一个几天后必然失效的死链。

如果需要在不上传的前提下把临时文件留在本地（例如离线拍摄后稍后再发），可用 FileSystemManager 写入用户目录：

```typescript
const fs = wx.getFileSystemManager()

function persistTempFile(tempFilePath: string): string {
  // wx.env.USER_DATA_PATH 是本小程序可持久读写的用户目录
  const target = `${wx.env.USER_DATA_PATH}/pending_${Date.now()}.jpg`
  fs.saveFileSync(tempFilePath, target)
  return target
}
```

误区提醒：

- “`tempFilePath` 是永久的”——错误，它是临时文件，会被微信回收。
- “拿到路径就能在 WXML 直接 `src` 永久使用”——当前页面可用，但跨天、跨启动后不保证可用，必须上传或落盘。

### 2. wx.chooseMedia：图片与视频的统一选择入口

`wx.chooseMedia` 是 2020 年后推出的统一选择接口，替代过去分散的 `wx.chooseImage` / `wx.chooseVideo`，支持图片、视频与混合选择。

```typescript
interface PickedMedia {
  tempFilePath: string
  size: number
  fileType: 'image' | 'video'
  width: number
  height: number
  duration?: number
  thumbTempFilePath?: string
}

async function pickFoodMedia(maxCount = 9): Promise<PickedMedia[]> {
  const res = await wx.chooseMedia({
    count: maxCount, // 图片最多 9 张
    mediaType: ['image', 'video'], // image / video / mix
    sourceType: ['album', 'camera'], // 相册 + 拍摄
    sizeType: ['compressed'], // original / compressed
    camera: 'back', // back / front
    maxDuration: 30, // 视频最长拍摄秒数
  })

  return res.tempFiles.map((f) => ({
    tempFilePath: f.tempFilePath,
    size: f.size,
    fileType: f.fileType,
    width: f.width,
    height: f.height,
    duration: f.duration,
    thumbTempFilePath: f.thumbTempFilePath,
  }))
}
```

关键参数与约束：

1. `count`：最多选择数量。图片最多 9 张；视频一次通常只能选/拍 1 条，混合模式下总数受相册能力限制，以真机表现为准。
2. `mediaType`：`image`、`video`、`mix`。只允许图片时务必显式传 `['image']`，不要默认放开视频再在前端拦截。
3. `sourceType`：`album` 与 `camera`。做“纯拍摄”场景可只传 `['camera']`，但更推荐自定义 `camera` 组件以获得统一 UI。
4. `sizeType`：`compressed` 让微信先做一次系统级压缩，`original` 保留原图。UGC 发布默认用 `compressed`。
5. `maxDuration` / `camera`：仅在拍摄入口生效，从相册选历史视频不受拍摄时长约束。

返回中视频文件还带 `duration`、`thumbTempFilePath`（视频封面缩略图），列表展示视频时应优先用封面而不是黑屏 `video` 组件。

误区提醒：

- 用户取消选择会走 fail（`errMsg` 含 `cancel`），这是正常行为，不要弹“系统错误”。

```typescript
try {
  const files = await pickFoodMedia()
  // ...
} catch (err) {
  const msg = (err as { errMsg?: string }).errMsg ?? ''
  if (!msg.includes('cancel')) {
    wx.showToast({ title: '选择失败，请重试', icon: 'none' })
  }
}
```

### 3. wx.previewMedia / wx.previewImage：全屏预览

用户点缩略图要能看大图、播放视频。图片场景 `wx.previewImage` 最简单，混合场景用 `wx.previewMedia`。

```typescript
function previewAll(medias: PickedMedia[], index: number): void {
  wx.previewMedia({
    current: index,
    sources: medias.map((m) => ({
      url: m.tempFilePath, // 已发布内容应使用远程 URL
      type: m.fileType, // 'image' | 'video'
      poster: m.fileType === 'video' ? m.thumbTempFilePath : undefined,
    })),
  })
}
```

纯图片也可以：

```typescript
wx.previewImage({
  current: urls[index], // 当前显示图片的链接，需与 urls 中某一项一致
  urls,
})
```

工程细节：

- `sources` / `urls` 必须是真实可访问的路径数组；空数组调用会失败。
- 预览未发布的本地素材用临时路径；预览已发布内容必须用服务端地址，不要把临时路径回传给别的用户预览。
- 视频 `poster` 用封面图，避免进入预览瞬间黑屏。

误区提醒：

- 预览能力是“只读查看”，不能在预览页做删除、裁剪编辑；需要编辑请自行实现或选 `chooseMedia` 时依赖系统裁剪能力。

### 4. 图片与视频压缩：wx.compressImage / wx.compressVideo

相册原图可能 5-12 MB，直接上传慢且贵。`wx.compressImage` 用系统编码器压缩：

```typescript
async function compressImageIfNeeded(
  src: string,
  size: number,
  maxSizeKB = 500,
): Promise<{ path: string; compressed: boolean }> {
  if (size <= maxSizeKB * 1024) {
    return { path: src, compressed: false }
  }

  const res = await wx.compressImage({
    src,
    quality: 72, // 0-100，仅对 jpg 生效明显
    compressedWidth: 1280, // 可选，按宽等比缩放
  })

  return { path: res.tempFilePath, compressed: true }
}
```

多级压缩策略（体积仍超标时逐步降质，最多两轮，避免死循环）：

```typescript
async function compressToLimit(file: PickedMedia, limitKB: number): Promise<string> {
  let src = file.tempFilePath
  let size = file.size
  const qualities = [75, 55]

  for (const quality of qualities) {
    if (size <= limitKB * 1024) break
    const res = await wx.compressImage({ src, quality })
    src = res.tempFilePath
    const info = await wx.getFileInfo({ filePath: src })
    size = info.size
  }

  if (size > limitKB * 1024) {
    throw new Error('图片压缩后仍超过上限')
  }
  return src
}
```

要点：

1. `quality` 对 JPEG 最有效；PNG 透明图转 JPEG 会丢透明通道，导出格式要按业务选择。
2. 每压一次都会重新编码，**反复压缩有代际损失**，所以应从原图出发压缩，而不是拿已压缩结果反复压。
3. 压缩后必须重新读取 `size` 判断是否达标，不能假设 quality=60 体积就一定减半。

误区提醒：

- 不要在用户选择 9 张图后串行压缩又不提示，应配合 loading，并考虑用 `Promise.all` 并发（注意内存峰值）。

**视频压缩 wx.compressVideo：** 视频体积远大于图片，上传前压缩收益更高：

```typescript
async function compressVideo(src: string): Promise<{ path: string; size: number }> {
  const res = await wx.compressVideo({
    src,
    quality: 'medium', // low / medium / high
    // 也可精确指定 bitrate、fps、resolution
  })

  return { path: res.tempFilePath, size: res.size }
}
```

`quality` 与精确参数（`bitrate`、`fps`、`resolution`）二选一即可，UGC 场景用 `medium` 最省心。要在 UI 上提示“视频处理中”，视频编码耗时明显高于图片，且只在真机上表现真实。

### 5. camera 组件与 CameraContext：自定义拍摄

当产品要求“在发布页内嵌一个拍摄框、统一切换前后摄像头与闪光灯”时，用 `camera` 组件而不是 `chooseMedia` 跳系统相机。

```xml
<!-- pages/publish/publish.wxml -->
<view class="shooter" wx:if="{{shooting}}">
  <camera
    device-position="{{device}}"
    flash="{{flash}}"
    frame-size="medium"
    binderror="onCameraError"
    bindstop="onCameraStop"
    class="camera"
  ></camera>

  <view class="bar">
    <button size="mini" bindtap="toggleDevice">翻转</button>
    <button type="primary" bindtouchstart="startRecord" bindtouchend="stopRecord">
      按住录像 / 点击拍照
    </button>
  </view>
</view>
```

```typescript
Page({
  data: {
    shooting: false,
    device: 'back' as 'back' | 'front',
    flash: 'auto' as 'auto' | 'on' | 'off',
  },

  onCameraError(e: WechatMiniprogram.CustomEvent<{ errMsg: string }>) {
    // 未授权/被占用都会触发
    wx.showToast({ title: '相机不可用，请检查权限', icon: 'none' })
    this.setData({ shooting: false })
  },

  onCameraStop() {
    this.setData({ shooting: false })
  },

  toggleDevice() {
    this.setData({ device: this.data.device === 'back' ? 'front' : 'back' })
  },

  takePhoto() {
    const camera = wx.createCameraContext()
    camera.takePhoto({
      quality: 'high', // high / normal / low
      success: (res) => {
        this.appendImage(res.tempImagePath)
      },
    })
  },

  startRecord() {
    const camera = wx.createCameraContext()
    camera.startRecord({
      timeoutCallback: (res) => {
        // 达到最大时长被系统自动结束
        this.appendVideo(res.tempVideoPath, res.tempThumbPath)
      },
    })
  },

  stopRecord() {
    const camera = wx.createCameraContext()
    camera.stopRecord({
      success: (res) => {
        this.appendVideo(res.tempVideoPath, res.tempThumbPath)
      },
    })
  },
})
```

`camera` 与 `chooseMedia({sourceType:['camera']})` 的差异：

| 对比项 | camera 组件 | chooseMedia 系统相机 |
|---|---|---|
| UI 控制权 | 完全自定义 | 微信系统界面 |
| 权限 | 页面渲染即需要 scope.camera | 跳系统界面时申请 |
| 实时帧 | 支持 onCameraFrame | 不支持 |
| 开发者工具 | 支持有限，以真机为准 | 以真机为准 |

误区提醒：

- 录像同时需要 `scope.camera` 与 `scope.record`，只申请相机权限会在录像时报错。
- 离开页面或 `onHide` 时应让相机停止，避免后台占用摄像头（iOS 上会有绿条/隐私提示）。

### 6. onCameraFrame：实时帧数据与性能边界

`CameraContext.onCameraFrame` 让逻辑层拿到预览的每一帧，可用于简单视觉处理（亮度判断、扫光动画、自定义扫码的前置检测等）。

```typescript
let frameListener: WechatMiniprogram.CameraFrameListener | null = null
let frameCount = 0

Page({
  startFrameListener() {
    const camera = wx.createCameraContext()

    frameListener = camera.onCameraFrame((frame) => {
      frameCount += 1
      // 每 10 帧采样一次，绝不逐帧 setData
      if (frameCount % 10 !== 0) return

      const brightness = averageBrightness(frame.data, frame.width, frame.height)
      this.setData({ brightnessHint: brightnessLabel(brightness) })
    })

    frameListener.start()
  },

  onHide() {
    frameListener?.stop()
  },

  onUnload() {
    frameListener?.stop()
    frameListener = null
  },
})

/** 取若干采样点估算平均亮度（仅示意，数据格式以平台为准） */
function averageBrightness(data: ArrayBuffer, width: number, height: number): number {
  const bytes = new Uint8Array(data)
  let sum = 0
  let count = 0
  const step = Math.max(1, Math.floor(bytes.length / 2000))
  for (let i = 0; i < bytes.length; i += step) {
    sum += bytes[i]
    count += 1
  }
  return count > 0 ? sum / count : 0
}
```

性能红线：

1. 帧回调频率可达每秒 20-30 次，`frame.data` 是 ArrayBuffer，体量很大；**逐帧 setData 会让跨线程通信直接打爆**，界面必然掉帧。
2. 计算要轻：按帧采样、只取需要的字节；重计算（人脸识别、滤镜卷积）应放到 Worker 或原生插件，不要在回调里跑大循环。
3. `onHide`、`onUnload` 必须 `stop()`，否则摄像头与监听都在后台持续耗电。

误区提醒：

- 不同平台帧数据像素格式可能不同，不能假定一定是 RGBA；跨平台算法只做与格式无关的粗略统计，或通过官方文档确认格式。

### 7. video 组件与 VideoContext：视频播放

发布后详情页要播放视频，使用 `video` 组件：

```xml
<video
  id="foodVideo"
  src="{{videoUrl}}"
  poster="{{poster}}"
  controls
  show-center-play-btn
  enable-progress-gesture
  object-fit="cover"
  class="video"
></video>
```

```typescript
Page({
  data: { videoUrl: '', poster: '' },

  replay() {
    // 自定义组件内需传第二参数 this
    const video = wx.createVideoContext('foodView', this)
    video.seek(0)
    video.play()
  },

  pause() {
    wx.createVideoContext('foodView', this).pause()
  },
})
```

要点：

1. `poster` 封面图几乎是必需的，弱网下没封面就是黑屏。
2. 受自动播放策略限制，`autoplay` 在不同场景下行为不同，带声音的自动播放通常不被允许；信息流静音自动播放要按平台规则验证。
3. 一个页面不要同时放多个可播放 `video`，列表里用封面图 + 播放图标，点进详情再挂载 `video`，省内存也省流量。

误区提醒：

- 不要把本地临时路径用于线上视频播放；入库与播放都应走云端地址。
- 视频时长、封面在选择阶段就应记录（`duration`、`thumbTempFilePath`），不要等播放时再取。

### 8. Canvas 2D 新版：节点、上下文与 DPR

老版 `<canvas canvas-id="">` 的 API 是全局 `wx.createCanvasContext`，已不推荐。新版使用 `<canvas type="2d">`，接口与 Web Canvas 几乎一致：

```xml
<canvas
  type="2d"
  id="posterCanvas"
  class="poster-canvas"
  style="width: 300px; height: 420px;"
></canvas>
```

```typescript
interface CanvasQueryResult {
  node: WechatMiniprogram.Canvas
  width: number
  height: number
}

function queryPosterCanvas(): Promise<CanvasQueryResult> {
  return new Promise((resolve, reject) => {
    wx.createSelectorQuery()
      .select('#posterCanvas')
      .fields({ node: true, size: true })
      .exec((res) => {
        if (res[0]) resolve(res[0] as unknown as CanvasQueryResult)
        else reject(new Error('未找到画布节点'))
      })
  })
}
```

初始化时必须按设备像素比（DPR）缩放，否则导出的海报在高清屏上发虚：

```typescript
async function setupCanvas(): Promise<{
  canvas: WechatMiniprogram.Canvas
  ctx: WechatMiniprogram.CanvasRenderingContext.CanvasRenderingContext2D
  cssWidth: number
  cssHeight: number
}> {
  const { node, width, height } = await queryPosterCanvas()
  const ctx = node.getContext('2d')
  const dpr = wx.getWindowInfo().pixelRatio

  // 画布内部分辨率 = CSS 尺寸 × DPR
  node.width = width * dpr
  node.height = height * dpr
  ctx.scale(dpr, dpr)

  return { canvas: node, ctx, cssWidth: width, cssHeight: height }
}
```

要点：

- `canvas.width` 是物理像素，WXSS 宽是 CSS 像素，两者关系靠 `ctx.scale(dpr, dpr)` 统一，之后所有绘制都按 CSS 坐标写。
- 在自定义组件中查询要加 `.in(this)`：`wx.createSelectorQuery().in(this)`。
- 新版画布绘制是同步 API + 部分异步资源（图片），不再有老版 `ctx.draw()`。

误区提醒：

- 新旧两版不能混用参数：新版 `canvasToTempFilePath` 直接传 `canvas` 节点，不传 `canvasId`。

### 9. 离屏画布：createOffscreenCanvas

海报里有些素材（水印印章、固定装饰、二维码）每次都一样，可以先画在**离屏画布**上，再整体贴到主画布，减少重复绘制代码。

```typescript
function makeWatermarkStamp(
  mainCanvas: WechatMiniprogram.Canvas,
): WechatMiniprogram.OffscreenCanvas {
  const off = mainCanvas.createOffscreenCanvas({ type: '2d', width: 160, height: 48 })
  const ctx = off.getContext('2d')

  ctx.fillStyle = 'rgba(0,0,0,0.45)'
  ctx.fillRect(0, 0, 160, 48)
  ctx.fillStyle = '#ffffff'
  ctx.font = '14px sans-serif'
  ctx.fillText('逛吃指南', 12, 30)

  return off
}
```

主画布合成时直接 `drawImage` 离屏节点：

```typescript
const stamp = makeWatermarkStamp(canvas)
ctx.drawImage(stamp, cssWidth - 170, cssHeight - 58, 160, 48)
```

离屏画布还适用于：先把网络图缩放到目标尺寸再贴主画布、对帧数据做中转绘制等。它不占 WXML 节点，尺寸由参数指定。

### 10. 绘制图片与文字：生成分享海报

海报 = 背景 + 圆角封面图 + 标题 + 地址 + 水印。加载图片要用画布节点的 `createImage`，不能用逻辑层 `new Image()`。

```typescript
interface PosterData {
  cover: string
  title: string
  address: string
}

function loadImage(
  canvas: WechatMiniprogram.Canvas,
  src: string,
): Promise<WechatMiniprogram.Image> {
  return new Promise((resolve, reject) => {
    const img = canvas.createImage()
    img.onload = () => resolve(img)
    img.onerror = () => reject(new Error('图片加载失败'))
    img.src = src
  })
}

/** 圆角矩形路径，兼容不支持 ctx.roundRect 的基础库 */
function traceRoundRect(
  ctx: WechatMiniprogram.CanvasRenderingContext.CanvasRenderingContext2D,
  x: number,
  y: number,
  w: number,
  h: number,
  r: number,
): void {
  const radius = Math.min(r, w / 2, h / 2)
  ctx.beginPath()
  ctx.moveTo(x + radius, y)
  ctx.arcTo(x + w, y, x + w, y + h, radius)
  ctx.arcTo(x + w, y + h, x, y + h, radius)
  ctx.arcTo(x, y + h, x, y, radius)
  ctx.arcTo(x, y, x + w, y, radius)
  ctx.closePath()
}

/** cover 模式裁剪绘制，保证图片不变形 */
function drawCover(
  ctx: WechatMiniprogram.CanvasRenderingContext.CanvasRenderingContext2D,
  img: WechatMiniprogram.Image,
  x: number,
  y: number,
  w: number,
  h: number,
): void {
  const scale = Math.max(w / img.width, h / img.height)
  const drawW = img.width * scale
  const drawH = img.height * scale
  const dx = x + (w - drawW) / 2
  const dy = y + (h - drawH) / 2

  ctx.save()
  traceRoundRect(ctx, x, y, w, h, 12)
  ctx.clip()
  ctx.drawImage(img, dx, dy, drawW, drawH)
  ctx.restore()
}

async function drawPoster(data: PosterData): Promise<string> {
  const { canvas, ctx, cssWidth, cssHeight } = await setupCanvas()

  // 背景
  ctx.fillStyle = '#ffffff'
  ctx.fillRect(0, 0, cssWidth, cssHeight)

  // 封面
  const cover = await loadImage(canvas, data.cover)
  drawCover(ctx, cover, 16, 16, cssWidth - 32, 240)

  // 标题：超长手动截断（fillText 不会自动折行）
  ctx.fillStyle = '#222222'
  ctx.font = 'bold 20px sans-serif'
  ctx.fillText(ellipsis(data.title, 14), 16, 292)

  // 地址
  ctx.fillStyle = '#888888'
  ctx.font = '13px sans-serif'
  ctx.fillText(ellipsis(data.address, 20), 16, 320)

  // 水印
  const stamp = makeWatermarkStamp(canvas)
  ctx.drawImage(stamp, cssWidth - 170, cssHeight - 60, 160, 48)

  // 导出临时图片
  const res = await wx.canvasToTempFilePath({
    canvas,
    fileType: 'jpg', // jpg / png
    quality: 1,
  })
  return res.tempFilePath
}

function ellipsis(text: string, max: number): string {
  return text.length > max ? `${text.slice(0, max - 1)}…` : text
}
```

文字排版细节：

1. `fillText` 不自动换行，多行文字要按宽度手动测量（`ctx.measureText`）后逐行绘制。
2. 中文字体在不同手机回退字体不同，海报避免使用冷门字体；需要特殊字体应随包加载字体文件（`wx.loadFontFace`）。
3. 封面用 cover 裁剪 + 圆角 clip，直接 `drawImage(img, x, y, w, h)` 会把图片拉变形。

误区提醒：

- `canvasToTempFilePath` 必须在绘制完成之后调用；图片是异步加载的，要在 `img.onload` 之后再导出，否则导出的是空白图。

### 11. editor 富文本组件：图文混排

笔记类内容要加粗、分段、插图，用 `editor` 组件承载富文本，而不是在 `textarea` 里塞 HTML。

```xml
<editor
  id="noteEditor"
  placeholder="记录这家店的味道、环境和推荐菜…"
  show-img-size
  show-img-toolbar

  bindinput="onEditorInput"
  class="editor"
></editor>

<view class="toolbar">
  <button size="mini" data-name="bold" bindtap="onFormat">加粗</button>
  <button size="mini" data-name="italic" bindtap="onFormat">斜体</button>
  <button size="mini" bindtap="insertImage">插图</button>

```

```typescript
Page({
  editorCtx: null as WechatMiniprogram.EditorContext | null,
  html: '',

  onEditorReady() {
    wx.createSelectorQuery()
      .select('#noteEditor')
      .context((res) => {
        this.editorCtx = res.context as WechatMiniprogram.EditorContext
      })
      .exec()
  },

  onEditorInput(e: WechatMiniprogram.CustomEvent<{ html: string; delta: unknown }>) {
    this.html = e.detail.html
  },

  onFormat(e: WechatMiniprogram.TouchEvent) {
    const name = e.currentTarget.dataset.name as 'bold' | 'italic'
    this.editorCtx?.format(name)
  },

  async insertImage() {
    const res = await wx.chooseMedia({
      count: 1,
      mediaType: ['image'],
      sizeType: ['compressed'],
    })
    const tempPath = res.tempFiles[0].tempFilePath

    // 先上传拿远程地址，再插入编辑器，保证富文本里不是临时路径
    const url = await uploadOne(tempPath)
    this.editorCtx?.insertImage({ src: url, width: '100%' })
  },

  async getHTML(): Promise<string> {
    const res = await this.editorCtx!.getContents()
    return res.html
  },
})
```

要点：

1. `editor` 内容可取 `html` 或 `delta`（结构化 JSON）；渲染到他人页面时要注意内容清洗，富文本是 XSS 高风险区，清洗必须在服务端做。
2. 插入的图片应先上传得到远程地址；直接插临时路径，提交后别人打开富文本图片全部失效。
3. 回显编辑用 `setContents({ html })`；编辑器必须 `bindready` 之后再操作，过早调用会失败。

误区提醒：

- `editor` 不是 `textarea` 的美化版，它产出的是结构化内容；只需要纯文本的场景不要用富文本，徒增清洗成本。

### 12. 媒体权限与拒绝兜底

媒体能力是三层门：

```text
隐私协议（后台配置，用户同意） -> scope 授权（系统弹窗） -> API 调用
```

每个 scope 有三种状态：`true`（已授权）、`false`（已拒绝，微信不再弹系统框）、`undefined`（从未询问，可弹系统授权框）。对 `false` 状态，唯一的恢复路径是引导用户去 `openSetting` 手动开启。

```typescript
async function ensureScope(scope: string, tip: string): Promise<boolean> {
  const setting = await wx.getSetting()
  const granted = setting.authSetting[scope]

  if (granted === true) return true

  if (granted === false) {
    // 已拒绝：系统弹窗不会再出现，必须引导去设置页
    const modal = await wx.showModal({
      title: '需要权限',
      content: tip,
      confirmText: '去设置',
      cancelText: '暂不',
    })
    if (!modal.confirm) return false

    const openRes = await wx.openSetting()
    return openRes.authSetting[scope] === true
  }

  // 从未询问：尝试系统授权弹窗
  try {
    await wx.authorize({ scope })
    return true
  } catch {
    return false
  }
}
```

保存海报的完整兜底示例：

```typescript
async function savePoster(filePath: string): Promise<void> {
  const ok = await ensureScope(
    'scope.writePhotosAlbum',
    '保存海报需要访问你的系统相册，用于把图片写入相册',
  )
  if (!ok) {
    wx.showToast({ title: '已取消保存', icon: 'none' })
    return
  }

  try {
    await wx.saveImageToPhotosAlbum({ filePath })
    wx.showToast({ title: '海报已保存', icon: 'success' })
  } catch {
    wx.showToast({ title: '保存失败，请重试', icon: 'none' })
  }
}
```

关键原则：

- **授权拒绝必须兜底**：不能让按钮点了没反应；至少解释“为什么需要”，并提供“去设置”入口。
- 不要一进页面就连续申请多个权限，应在用户触发对应功能时再申请，拒绝率更低，也符合审核预期。
- 隐私协议未同意时调用隐私接口会失败，需配合平台隐私弹窗组件处理。

误区提醒：

- 反复调用 `wx.authorize` 请求已被拒绝的权限是无效的——`false` 状态下系统不会再弹窗，只能走 `openSetting`。

### 13. 文件上传：走云存储或服务端

媒体素材**不能入库临时路径**，持久化只有两条主路径。

自建服务端用 `wx.uploadFile`（必须在小程序后台配置 uploadFile 合法域名，且为 HTTPS）：

```typescript
async function uploadToServer(filePath: string): Promise<string> {
  const res = await wx.uploadFile({
    url: 'https://api.guangchi.example.com/v1/files',
    filePath,
    name: 'file',
    formData: { scene: 'food_post' },
    header: { Authorization: `Bearer ${getToken()}` },
  })

  const body = JSON.parse(res.data) as { code: number; data: { url: string } }
  if (res.statusCode !== 200 || body.code !== 0) {
    throw new Error('上传失败')
  }
  return body.data.url
}
```

云开发用云存储，得到 fileID，业务库里存 fileID，展示时可换取临时链接：

```typescript
async function uploadToCloud(filePath: string): Promise<string> {
  const ext = filePath.match(/\.(\w+)$/)?.[1] ?? 'jpg'
  const cloudPath = `posts/${Date.now()}-${Math.random().toString(36).slice(2, 8)}.${ext}`

  const res = await wx.cloud.uploadFile({ cloudPath, filePath })
  return res.fileID
}
```

多文件上传与失败重试：

```typescript
async function uploadAll(files: PickedMedia[]): Promise<string[]> {
  const results = await Promise.allSettled(files.map((f) => uploadOne(f)))

  const failed = results.filter((r) => r.status === 'rejected').length
  if (failed > 0) {
    throw new Error(`${failed} 个文件上传失败`)
  }

  return results
    .filter((r): r is PromiseFulfilledResult<string> => r.status === 'fulfilled')
    .map((r) => r.value)
}
```

要点：

1. 上传是独立于业务提交的一步：先传文件拿地址，再把地址随 JSON 提交业务接口，不要让服务端从临时路径反查文件。
2. 封面、视频、海报都要上传；富文本里的图片应在插入前就已上传。
3. 并发上传要控制数量与内存，9 张图一般可接受，视频建议串行并显示进度。

误区提醒：

- 不要在前端把图片转成 base64 塞进 JSON 提交，体积膨胀约 1/3 且占用跨线程带宽，文件就该走文件通道。

### 14. 综合实战：升级「逛吃指南」发布页

把前面所有能力收敛到发布页：多图/视频、拍摄、海报生成、统一上传提交。

数据模型：

```typescript
interface PublishMedia {
  id: string
  type: 'image' | 'video'
  localPath: string
  thumb?: string
  remoteUrl?: string
}

interface PublishForm {
  title: string
  content: string
  medias: PublishMedia[]
  posterPath?: string
}
```

WXML 结构（缩略图网格 + 添加入口 + 海报按钮）：

```xml
<view class="media-grid">
  <view wx:for="{{form.medias}}" wx:key="id" class="cell" bindtap="preview" data-index="{{index}}">
    <image src="{{item.thumb || item.localPath}}" mode="aspectFill" class="thumb" />
    <view wx:if="{{item.type === 'video'}}" class="badge">视频</view>
    <icon type="clear" size="16" catchtap="removeMedia" data-id="{{item.id}}" class="del" />
  </view>

  <view wx:if="{{form.medias.length < 9}}" class="cell add" bindtap="chooseMore">
    <text>＋</text>
  </view>
</view>

<button bindtap="makePoster" disabled="{{!firstImage}}">生成分享海报</button>
<image wx:if="{{form.posterPath}}" src="{{form.posterPath}}" mode="widthFix" class="poster" />
<button bindtap="savePoster" wx:if="{{form.posterPath}}">保存海报到相册</button>
<button type="primary" bindtap="submit" loading="{{publishing}}">发布</button>
```

核心逻辑：

```typescript
Page({
  data: {
    form: { title: '', content: '', medias: [] } as PublishForm,
    publishing: false,
  },

  async chooseMore() {
    try {
      const picked = await pickFoodMedia(9 - this.data.form.medias.length)
      const next: PublishMedia[] = picked.map((f) => ({
        id: `${Date.now()}_${Math.random().toString(36).slice(2, 7)}`,
        type: f.fileType,
        localPath: f.tempFilePath,
        thumb: f.thumbTempFilePath,
      }))
      this.setData({ 'form.medias': [...this.data.form.medias, ...next].slice(0, 9) })
    } catch (err) {
      if (!String((err as { errMsg?: string }).errMsg).includes('cancel')) {
        wx.showToast({ title: '选择失败', icon: 'none' })
      }
    }
  },

  removeMedia(e: WechatMiniprogram.TouchEvent) {
    const id = e.currentTarget.dataset.id as string
    this.setData({
      'form.medias': this.data.form.medias.filter((m) => m.id !== id),
    })
  },

  preview(e: WechatMiniprogram.TouchEvent) {
    const index = e.currentTarget.dataset.index as number
    previewAll(
      this.data.form.medias.map((m) => ({
        tempFilePath: m.localPath,
        fileType: m.type,
        size: 0,
        width: 0,
        height: 0,
        thumbTempFilePath: m.thumb,
      })),
      index,
    )
  },

  async makePoster() {
    const first = this.data.form.medias.find((m) => m.type === 'image')
    if (!first) {
      wx.showToast({ title: '请先选择一张图片', icon: 'none' })
      return
    }

    wx.showLoading({ title: '生成中', mask: true })
    try {
      const posterPath = await drawPoster({
        cover: first.localPath,
        title: this.data.form.title || '逛吃指南',
        address: '广州 · 西关',
      })
      this.setData({ 'form.posterPath': posterPath })
    } finally {
      wx.hideLoading()
    }
  },

  async submit() {
    if (this.data.publishing) return
    if (this.data.form.medias.length === 0) {
      wx.showToast({ title: '至少选择一个图片或视频', icon: 'none' })
      return
    }

    this.setData({ publishing: true })
    wx.showLoading({ title: '发布中', mask: true })
    try {
      // 1. 先上传全部媒体，把远程地址回填到模型
      const urls = await uploadAll(
        this.data.form.medias.map((m) => ({
          tempFilePath: m.localPath,
          fileType: m.type,
          size: 0,
          width: 0,
          height: 0,
          thumbTempFilePath: m.thumb,
        })),
      )

      const medias = this.data.form.medias.map((m, i) => ({ ...m, remoteUrl: urls[i] }))

      // 2. 海报也要上传（可选：分享时再生成）
      let posterUrl: string | undefined
      if (this.data.form.posterPath) {
        posterUrl = await uploadOne({
          tempFilePath: this.data.form.posterPath,
          fileType: 'image',
          size: 0,
          width: 0,
          height: 0,
        })
      }

      // 3. 业务提交：入库的全部是远程地址
      await createPost({
        title: this.data.form.title,
        content: this.data.form.content,
        medias: medias.map((m) => ({ type: m.type, url: m.remoteUrl, thumb: m.thumb })),
        posterUrl,
      })

      wx.showToast({ title: '发布成功', icon: 'success' })
      setTimeout(() => wx.navigateBack(), 800)
    } catch {
      wx.showToast({ title: '发布失败，请重试', icon: 'none' })
    } finally {
      wx.hideLoading()
      this.setData({ publishing: false })
    }
  },

  savePoster() {
    if (this.data.form.posterPath) {
      savePoster(this.data.form.posterPath)
    }
  },
})
```

这个发布页的工程特征：临时路径只在本地编辑阶段使用，入库全是远程地址；任何一步失败都停在当前状态可重试，不会产生半条远程记录；授权、取消、压缩、帧处理都有明确边界。

### 15. 常见误区、性能与上线自查清单

**功能误区：**

1. 把 `tempFilePath` 当永久地址入库或在他人页面使用；
2. 用户取消选择也弹“系统错误”；
3. 只申请相机权限就录像，漏掉麦克风权限；
4. 逐帧 `setData`，相机页严重掉帧；
5. 拿已经压缩过的图反复压缩，画质崩坏；
6. Canvas 不做 DPR 缩放，海报在高清屏发虚；图片未加载完就导出；
7. editor 里插入本地临时图，提交后他人看不到图；
8. 授权被拒绝后没有任何解释与设置页入口；
9. 列表页直接铺多个 `video` 组件；
10. 用 base64 塞 JSON 上传文件。

**性能要点：**

- 上传前压缩、控制分辨率（图最长边 1280-1920、视频 medium 质量）；
- 帧监听按需采样、离开即停；
- 列表用封面图，详情才挂载播放器；
- 大图绘制与海报生成期间用 loading 遮罩，避免用户重复点击。

**上线前自查清单：**

1. 相机/麦克风/相册写入是否都配置了隐私接口与授权兜底；
2. uploadFile 合法域名是否已配置且为 HTTPS（或云存储安全规则是否正确）；
3. 入库字段是否全部为远程地址，测试中搜索不到 `http://tmp`；
4. 拒绝授权、取消选择、上传失败、压缩超限四条异常路径是否都走通过；
5. 真机（iOS + Android）上拍摄、录像、海报保存是否都验证过。

async function chooseMore(currentCount: number) {
  const picked = await pickFoodMedia(9 - currentCount)
  const normalized = await Promise.all(
    picked.map(async (f) =>

# 00-课程总纲与培养标准

本文件是课程的顶层培养契约，规定培养目标、结业能力标准、技术路线、阶段路径、节奏与评分方式。它是框架文档，不是知识单元；具体教学内容以五个阶段目录中的 32 个单元为准。

## 课程定位

本课程培养的是**能独立交付真实微信小程序（含交易闭环）的小程序工程师**。结业学员面对一个中等复杂业务需求时，应能在微信宿主环境的能力边界内，独立完成从需求拆解、页面与组件开发、云端数据与后端对接、登录鉴权、媒体/地图/硬件能力接入、支付交易、消息触达、性能治理、工程化发布到上线运营和文档交付的完整闭环，而不是只能在他人搭好的架子里填充页面。

- 周期：16 周，每周 2 个知识单元，共 32 个单元。
- 建议投入：学员每周约 25-30 小时，导师每周约 12-15 小时。
- 前置基础：JavaScript（ES2022+）、TypeScript 基础、HTTP、Git；不具备者先修全栈课程公共基础单元。
- 产出要求：每周有编码提交，按 W4/W8/W12/W14/W16 五个里程碑验收，结业时小程序为正式已发布版本并完成答辩。
- 主线项目：「逛吃指南」本地生活小程序，五个阶段持续演进同一业务。

## 结业能力标准

结业学员应在以下九个维度达到行为化标准，即“能当场做出”，而不是“听说过”。

| 维度 | 结业行为标准 |
|---|---|
| 需求拆解 | 能把产品需求拆成页面、组件、数据字段、云端集合/接口、权限点、授权项与测试点，并识别宿主能力边界、审核合规与异常流程 |
| 原生开发 | 能基于双线程模型正确使用 App/Page/Component 构造器、生命周期、路由、WXML/WXSS/WXS 与事件系统，规范使用 setData 完成多页面应用 |
| 组件化 | 能设计高内聚低耦合的组件树，用自定义组件、behaviors、插槽、observers、relations 与样式隔离组织复用，并能使用 glass-easel 新范式 |
| 云端与后端 | 能用云数据库、云函数、云存储完成全栈开发并正确配置安全规则与权限；能对接自建 Node 后端（JWT 鉴权），讲清云开发与自建后端的选型与混合架构 |
| 登录鉴权 | 能实现 wx.login 静默登录与 openid/unionid 账号体系，维护自定义登录态，合规接入手机号验证与头像昵称填写，杜绝前端伪造身份 |
| 平台能力与商业化 | 能接入媒体与相机、定位地图、扫码与设备能力；能实现微信支付下单、回调验签、订单状态机、退款与对账闭环，以及订阅消息触达 |
| 性能 | 能通过分包、按需注入、setData 优化、纯数据字段、WXS 响应事件等手段控制包体积、启动与帧率；能用 Skyline 与 Worklet 完成高级渲染并量化前后收益 |
| 工程化与测试 | 能使用构建 npm、TypeScript、ESLint/Prettier、miniprogram-ci 与 CI 流水线；能编写组件单测、云函数测试与 automator 自动化测试并以门禁质量 |
| 上线运营与表达 | 能完成体验版、审核、发布与回退全流程，应对审核规范与类目资质，使用数据运营分析；能编写 README、接口说明、发布记录与复盘，并在答辩中清晰解释架构、合规与权衡 |

结业通过条件：小程序正式发布且交易闭环可演示、测试与质量门禁通过、九个维度均有对应证据，且结业答辩评分达到合格线；任一维度缺失证据不予通过。

## 学习原则

1. 先理解机制，再记 API：能讲清双线程模型、setData 跨线程成本与宿主能力边界后才使用框架封装。
2. 所有知识点必须落到可运行代码，不接受只写笔记的学习方式。
3. 所有代码必须进入 Git 仓库；Git 分支协作、提交规范与 Code Review 贯穿全程，不单独占用单元。
4. 每个单元按“目标 → 理论 → 示例 → 练习 → 验收”五步闭环完成。
5. 评审不只看能否运行，还要看命名、边界、异常处理、数据结构、授权安全与合规性。
6. 不追逐实验性 API：Skyline、glass-easel Chaining 等新能力以官方状态与基础库覆盖为准，主线保持可回退。
7. 安全默认内置：密钥只走云函数/环境变量，数据库安全规则、最小权限、输入校验、支付验签从第一个真实项目开始执行。
8. 合规前置：用户授权、隐私接口声明、内容与类目资质在开发阶段即处理，不把审核问题留到上线前。
9. 先自评再送审：对照评分表能解释每一分的得失，返工是正常学习环节。
10. 云开发与自建后端都要动手：先借云开发建立全栈闭环，再用自建后端理解企业架构，不接受“只配过一次环境”。

## 推荐技术路线表

所有版本统一表述为当前稳定版，开课时按官方渠道确认具体版本号。

| 方向 | 主线技术（当前稳定版） | 说明 |
|---|---|---|
| 语言 | JavaScript、TypeScript 当前稳定版 | 逻辑层业务全程严格类型；WXML/WXS 能力边界单独讲清 |
| 原生框架 | 微信小程序原生框架 + 当前基础库 | App/Page/Component、双线程模型、生命周期 |
| 组件内核 | glass-easel | Chaining、动态 slot、新 WXML 编译器 |
| 渲染引擎 | WebView（主线）、Skyline（专题） | 按特性状态与覆盖率选择，可回退 |
| 开发工具 | 微信开发者工具 | 调试、npm 构建、预览、上传、自动化 |
| Serverless 后端 | 微信云开发 CloudBase | 云数据库/云函数/云存储/云调用/云支付 |
| 自建后端 | Node.js LTS、Express 或 NestJS | 对接全栈课程成果，JWT、HTTPS、合法域名 |
| 数据库 | 云数据库、PostgreSQL（自建线） | 文档型权限规则与关系型建模对照 |
| 登录 | wx.login、openid/unionid、自定义登录态、JWT | 静默登录、手机号、头像昵称合规能力 |
| 位置 | wx 定位、map、腾讯位置服务 | POI、逆地址、路线规划 |
| 支付 | 微信支付 JSAPI、云开发支付 | 下单/回调/退款/对账 |
| 消息 | 订阅消息、客服消息 | 一次性/长期订阅 |
| 工程化 | npm、ESLint、Prettier、miniprogram-ci、GitHub Actions | 构建、规范、CI、自动化发布 |
| 组件库 | Vant Weapp 或 TDesign Miniprogram | UI 复用 |
| 测试 | Jest、miniprogram-simulate、miniprogram-automator | 单元、组件、端到端 |
| 跨端（选修） | Taro、uni-app | React 系 / Vue 系跨端与多平台差异 |

## 五阶段培养路径与阶段产出

| 阶段 | 周次 | 单元 | 培养目标 | 阶段产出 |
|---|---|---|---|---|
| 一、入门与核心基础 | W1-W4 | U01-U08 | 建立小程序生态、双线程模型、配置、路由、模板与事件心智模型 | 静态四 Tab 项目骨架、多机型适配 |
| 二、组件化与云开发 | W5-W8 | U09-U16 | 掌握组件化复用，用云数据库/云函数/云存储完成全栈与登录 | 云开发版应用、登录鉴权与用户体系 |
| 三、平台能力与商业化 | W9-W12 | U17-U24 | 掌握网络/列表工程、媒体、地图、扫码、支付与订阅消息 | 完整商业化交易闭环小程序 |
| 四、性能与增长 | W13-W14 | U25-U28 | 掌握分享增长、分包与包体积、运行时性能、Skyline 渲染 | 性能达标、增长可追踪的应用 |
| 五、工程化、多端与结业 | W15-W16 | U29-U32 | 对接自建后端，落地工程化发布、自动化测试，完成上线与答辩 | 已上线小程序、CI/测试证据、跨端 demo、结业答辩 |

各阶段里程碑：

- **W4 里程碑**：理解双线程模型与生命周期，独立完成结构规范、多机型适配、交互反馈完整的静态多页面应用。
- **W8 里程碑**：具备组件化与云开发全栈能力，登录鉴权、数据持久化、文件上传与权限安全全部闭环。
- **W12 里程碑**：独立交付带媒体、地图、扫码、支付与订阅消息的商业化小程序，交易流程幂等可重复。
- **W14 里程碑**：主包体积、启动与帧率指标量化达标，分享裂变链路可追踪，核心页面完成 Skyline 改造且可回退。
- **W16 里程碑**：小程序通过审核正式发布，自建后端对接、工程化 CI 与自动化测试齐备，通过结业答辩并交付跨端 demo。

## 作业提交规范

每次作业必须包含以下内容：

- 需求说明与本次改动说明；
- 本地/模拟器与真机运行方式、测试方式；
- 提交物清单（代码、测试、文档、截图或录屏、体验版二维码）；
- 自评结果：评分表逐项得分与依据；
- 涉及授权、支付、隐私接口的合规处理说明；
- 已知问题与下一步计划；
- Git 提交记录，提交信息使用约定格式。

提交信息格式示例：

```text
feat: add note publish with location
fix: correct order callback signature verify
test: cover coupon scan redeem flow
docs: add cloud function deploy steps
```

提交要求：

1. 以分支加 Pull Request 或 Merge Request 提交，不直接向主分支推送作业。
2. 一个提交只做一件事，提交信息能让评审者不看代码也知道改动意图。
3. 密钥、商户证书、access_token、云环境密钥一律不得写入小程序前端包或仓库；敏感操作收敛到云函数/服务端。
4. 数据库集合必须配置最小权限的安全规则，前端默认不可直接读写他人数据。
5. PR 描述须包含自评得分与测试证据；命中强制不通过条件的作业先自行返工。
6. 支付类作业须给出回调验签、幂等与订单状态流转证据，不接受“能拉起支付即完成”。
7. 工程化类作业须附“从零复现”步骤，评审者按步骤能在干净环境重建构建、CI 与上传流程。

## 评分标准权重

单元与阶段作业统一采用 100 分制，权重如下：

| 维度 | 权重 | 判断标准 |
|---|---:|---|
| 功能完成度 | 25% | 需求与边界场景完整，主流程与异常流程均可工作 |
| 代码与设计质量 | 20% | 命名、分层、组件边界、数据结构、setData 使用 |
| 测试质量 | 15% | 分层测试合理，关键路径与越权场景覆盖，断言有效 |
| 安全与合规 | 20% | 登录鉴权、数据库安全规则、密钥管理、支付验签、授权与隐私合规 |
| 工程规范 | 10% | Git 提交、目录组织、Lint/格式化、CI 门禁 |
| 文档与表达 | 10% | README、接口说明、发布记录、复盘与答辩表达 |

结业成绩由阶段里程碑（40%）、结业项目实现（35%）、发布上线与答辩（25%）综合构成；评分表中列明的强制不通过条件具有一票否决效力。五个里程碑（W4/W8/W12/W14/W16）共同构成里程碑成绩，其中 W12 商业化交易闭环与 W16 正式发布是独立证据点，不得以其他阶段成果替代。

## 强制不通过条件（一票否决）

- 小程序无法运行或主流程（登录 → 浏览 → 发布/下单 → 支付）断裂；
- 密钥、商户证书或云密钥出现在前端代码包、仓库或截图中；
- 数据库集合使用“所有用户可读写”且无合理依据，或可越权读写他人数据；
- 支付无回调验签、无幂等控制，可被伪造回调或重复扣款；
- 以吞异常、删测试、关检查方式制造“通过”；
- 未处理隐私接口声明与用户授权，或使用已废弃的授权方式且无降级方案；
- 提交物无任何可运行证据或答辩无法解释核心机制。

## 导师关注点

- 不替学员写完整答案，用追问让学员解释自己的代码与权衡。
- 每周至少组织一次“从报错到根因”的调试训练，要求学员用证据而非猜测定位问题。
- 每个阶段安排一次重构训练，让学员为可维护性修改自己过去的代码。
- 持续检查双线程边界、setData 数据量与频率、数据库安全规则和密钥收敛，不让安全与性能问题累积。
- 云开发阶段重点检查安全规则与云函数权限边界；支付阶段重点检查验签、幂等与订单状态机。
- 性能阶段要求量化证据（包体积、启动、帧率前后对比），不接受“感觉变快”。
- 上线阶段重点检查隐私合规、类目资质与审核材料，跟踪真实审核结果与拒因整改。
- 版本差异出现时以官方文档、基础库状态和项目实际依赖为准，不用过时教程照本宣科。

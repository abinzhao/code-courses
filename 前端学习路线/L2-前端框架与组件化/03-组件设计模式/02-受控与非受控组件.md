## 内容讲解

### 一、什么是受控与非受控

这两个概念的核心区别在于**状态的归属**：

```
受控组件：状态由外部（父组件）持有和管理
非受控组件：状态由组件内部自行持有和管理
```

**类比**：想象一个酒店的空调。
- **受控模式**：前台统一控制每个房间的温度，你房间里没有调节开关（状态在前台）
- **非受控模式**：每个房间有自己的遥控器，你随便调，前台不管（状态在房间内部）

在组件设计中，这决定了「单一数据源」在哪里。

---

### 二、状态的上移与下放

```jsx
// 受控：状态在父组件
function Parent() {
  const [value, setValue] = useState('');
  return <Input value={value} onChange={setValue} />;
}

// 非受控：状态在 Input 内部
function Parent() {
  return <Input defaultValue="hello" />;
}
```

关键差异：
- 受控模式：父组件**拥有**状态，随时可以读取和干预
- 非受控模式：父组件**不拥有**状态，只在初始化和提交等关键时刻才访问

### 三、React 实现

#### 3.1 受控表单

```jsx
function ControlledForm() {
  const [name, setName]       = useState('');
  const [email, setEmail]     = useState('');
  const [agree, setAgree]     = useState(false);
  const [city, setCity]       = useState('beijing');

  function handleSubmit(e) {
    e.preventDefault();
    // 状态全部在此，随时可以校验、转换、提交
    console.log({ name, email, agree, city });
  }

  return (
    <form onSubmit={handleSubmit}>
      {/* 文本输入：value + onChange 是关键 */}
      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="姓名"
      />

      {/* textarea 在 React 中也是用 value，不是 innerHTML */}
      <textarea
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />

      {/* checkbox：checked + onChange */}
      <label>
        <input
          type="checkbox"
          checked={agree}
          onChange={(e) => setAgree(e.target.checked)}
        />
        同意协议
      </label>

      {/* select：value 在 <select> 上，而非 <option> */}
      <select value={city} onChange={(e) => setCity(e.target.value)}>
        <option value="beijing">北京</option>
        <option value="shanghai">上海</option>
      </select>

      <button type="submit">提交</button>
    </form>
  );
}
```

**受控表单的核心规则**：
- `value`（或 `checked`）始终由 React state 驱动
- 每次输入都触发 `onChange`，更新 state，触发重新渲染
- **没有 `onChange` 的 `value` 绑定会导致输入框只读**（React 强制数据的单向流动）

#### 3.2 非受控表单

```jsx
import { useRef } from 'react';

function UncontrolledForm() {
  const nameRef    = useRef(null);
  const emailRef   = useRef(null);
  const agreeRef   = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    // 只在提交时读取 DOM 的真实值
    console.log({
      name:  nameRef.current.value,
      email: emailRef.current.value,
      agree: agreeRef.current.checked,
    });
  }

  return (
    <form onSubmit={handleSubmit}>
      {/* defaultValue 设置初始值，后续输入由 DOM 自行管理 */}
      <input ref={nameRef}  defaultValue=""     placeholder="姓名" />
      <input ref={emailRef} defaultValue=""     placeholder="邮箱" />
      <label>
        <input ref={agreeRef} type="checkbox" defaultChecked={false} />
        同意协议
      </label>
      <button type="submit">提交</button>
    </form>
  );
}
```

**非受控表单的特点**：
- 使用 `defaultValue` / `defaultChecked` 而非 `value` / `checked`
- 通过 `ref` 在需要时读取 DOM 的真实值
- React 不追踪中间输入过程，性能更好（适合超大表单）

#### 3.3 选择决策表

| 场景 | 推荐模式 | 原因 |
|---|---|---|
| 每次输入需要即时反馈（搜索、校验） | 受控 | 需要实时读取状态 |
| 表单字段之间存在联动 | 受控 | 联动逻辑需要集中状态 |
| 需要动态禁用/启用提交按钮 | 受控 | 根据状态计算按钮状态 |
| 超大表单（50+ 字段），无实时校验 | 非受控 | 避免频繁渲染 |
| 文件上传 `<input type="file">` | 非受控 | 安全限制，无法设置 value |
| 与第三方非 React 库集成 | 非受控 | DOM 是第三方库的真实源 |
| 简单的一次性提交表单 | 非受控 | 减少样板代码 |

### 四、Vue 实现

#### 4.1 v-model 的受控本质

Vue 的 `v-model` 是受控模式的语法糖：

```vue
<!-- 这两行等价 -->
<input v-model="name" />
<input :value="name" @input="name = $event.target.value" />
```

Vue 的「双向绑定」本质是**单向数据流 + 自动事件处理**，状态依然由组件 data/ref 持有，所以 `v-model` 是受控模式。

```vue
<template>
  <form @submit.prevent="handleSubmit">
    <!-- 文本 -->
    <input v-model="form.name" placeholder="姓名" />

    <!-- textarea -->
    <textarea v-model="form.email" placeholder="邮箱" />

    <!-- checkbox：注意类型转换 -->
    <label>
      <input type="checkbox" v-model="form.agree" />
      同意协议
    </label>

    <!-- select -->
    <select v-model="form.city">
      <option value="beijing">北京</option>
      <option value="shanghai">上海</option>
    </select>

    <button type="submit">提交</button>
  </form>
</template>

<script setup>
import { reactive } from 'vue'

const form = reactive({
  name: '',
  email: '',
  agree: false,
  city: 'beijing'
})

function handleSubmit() {
  console.log(form) // 状态始终同步
}
</script>
```

#### 4.2 defineModel —— Vue 3.4+ 的受控组件利器

当你把 `v-model` 用在**自定义组件**上时，`defineModel` 让双向绑定的实现极其简洁：

```vue
<!-- MyInput.vue -->
<template>
  <div class="my-input">
    <label v-if="label">{{ label }}</label>
    <input
      v-model="model"
      :placeholder="placeholder"
      @blur="$emit('blur')"
    />
  </div>
</template>

<script setup>
defineProps({
  label: String,
  placeholder: String,
})

defineEmits(['blur'])

// 相当于自动实现：
// const props = defineProps({ modelValue: String })
// const emit  = defineEmits(['update:modelValue'])
// const model = computed({
//   get: () => props.modelValue,
//   set: (val) => emit('update:modelValue', val)
// })
const model = defineModel()
</script>
```

父组件使用：

```vue
<MyInput v-model="username" label="用户名" />
```

`defineModel` 背后是标准的 Vue 组件通信模式（prop 下传 + event 上传），仅仅是语法简化，不改变单向数据流的本质。

#### 4.3 Vue 中的非受控实现

Vue 通常用 `v-model`（受控模式），非受控模式主要用于和第三方 DOM 库集成：

```vue
<template>
  <input ref="inputRef" :value="initialValue" />
</template>

<script setup>
import { ref } from 'vue'

const props = defineProps({
  initialValue: { type: String, default: '' }
})

const inputRef = ref(null)

/** 暴露给父组件读取当前值的方法 */
function getValue() {
  return inputRef.value?.value
}

defineExpose({ getValue, inputRef })
</script>
```

### 五、半受控组件（混合模式）

**核心思想**：组件同时支持受控和非受控两种用法，由是否传入 `value` prop 来决定行为。

这是 Ant Design、Element Plus 等主流组件库的标准做法。以 Input 为例：

| 父组件传入 | Input 行为 | 模式 |
|---|---|---|
| `value` + `onChange` | 值由 `value` 控制，变化通过 `onChange` 通知 | 受控 |
| `defaultValue` | 值由内部 state 管理 | 非受控 |

---

### 六、实战：支持受控/非受控的 Input 组件

#### React 实现

```jsx
import { useState, useRef } from 'react';

/**
 * Input —— 同时支持受控和非受控两种用法
 *
 * 受控用法：   <Input value={val} onChange={setVal} />
 * 非受控用法： <Input defaultValue="hello" />
 */
function Input({
  value: controlledValue,
  defaultValue,
  onChange,
  ...rest
}) {
  // 判断是否为受控模式：父组件传入了 value prop
  const isControlled = controlledValue !== undefined;

  // 非受控模式使用内部 state
  const [internalValue, setInternalValue] = useState(defaultValue ?? '');

  // 受控模式用外部 value，非受控模式用内部 state
  const displayValue = isControlled ? controlledValue : internalValue;

  // 用 ref 保存 onChange 引用，避免 effect 依赖变化导致频繁重新绑定
  const onChangeRef = useRef(onChange);
  onChangeRef.current = onChange;

  function handleChange(e) {
    const newValue = e.target.value;
    // 非受控模式：更新内部 state
    if (!isControlled) {
      setInternalValue(newValue);
    }
    // 两种模式都通知外部
    onChangeRef.current?.(newValue);
  }

  return (
    <input {...rest} value={displayValue} onChange={handleChange} />
  );
}

// ============= 使用示例 =============

function Demo() {
  const [name, setName] = useState('');

  return (
    <div>
      {/* 受控用法 */}
      <Input
        value={name}
        onChange={(v) => setName(v)}
        placeholder="受控输入"
      />
      <p>当前值：{name}</p>

      {/* 非受控用法 */}
      <Input
        defaultValue="默认文本"
        onChange={(v) => console.log('变化:', v)}
        placeholder="非受控输入"
      />
    </div>
  );
}
```

**设计要点**：
- `controlledValue !== undefined` 判断模式，比检查 `null` 更安全
- 非受控模式才更新内部 state，受控模式依赖父组件更新
- `onChangeRef` 避免 effect 依赖 `onChange` 导致的不必要重新绑定

#### Vue 实现

```vue
<!-- SmartInput.vue -->
<template>
  <input
    v-bind="$attrs"
    :value="displayValue"
    @input="handleInput"
  />
</template>

<script setup>
import { ref, computed } from 'vue'

const props = defineProps({
  modelValue: { type: String, default: undefined },
  defaultValue: { type: String, default: '' },
})

const emit = defineEmits(['update:modelValue', 'change'])

// 判断是否受控：父组件是否使用了 v-model（即传入了 modelValue）
const isControlled = computed(() => props.modelValue !== undefined)

// 非受控模式的内部状态
const internalValue = ref(props.defaultValue)

// 显示值：受控用外部，非受控用内部
const displayValue = computed(() =>
  isControlled.value ? props.modelValue : internalValue.value
)

function handleInput(e) {
  const newValue = e.target.value
  // 非受控：更新内部状态
  if (!isControlled.value) {
    internalValue.value = newValue
  }
  // 两种模式都通知外部
  emit('update:modelValue', newValue)
  emit('change', newValue)
}
</script>
```

使用：

```vue
<template>
  <div>
    <!-- 受控用法（v-model） -->
    <SmartInput v-model="name" placeholder="受控输入" />
    <p>当前值：{{ name }}</p>

    <!-- 非受控用法 -->
    <SmartInput
      default-value="默认文本"
      @change="(v) => console.log('变化:', v)"
      placeholder="非受控输入"
    />
  </div>
</template>

<script setup>
import { ref } from 'vue'
const name = ref('')
</script>
```

## 常见问题

**Q1：为什么 React 受控组件中 `value={null}` 会导致输入框可编辑？**

React 将 `value={null}` 和 `value={undefined}` 视为「不受控」，会回退到 DOM 原生行为。但这是未定义行为，不要依赖它。始终显式选择受控或非受控模式。

**Q2：React 中 `value={state}` 但没有 `onChange` 会怎样？**

输入框会变成**只读**，无法输入任何字符。React 在控制台会警告：`You provided a value prop without an onChange handler`。

**Q3：Vue 的 v-model 是双向绑定，是不是说明 Vue 不遵循单向数据流？**

不是。`v-model` 本质是 `:value` + `@input` 的语法糖，数据仍然从父组件单向流向子组件，子组件通过事件通知父组件修改。它简化了写法，但不改变数据流的方向。

**Q4：什么场景必须用非受控？**

- `<input type="file">`：浏览器安全策略禁止 JS 设置文件输入的值
- 富文本编辑器：DOM 由编辑器库自行管理，React/Vue 不应干预
- 与第三方 DOM 库集成（如地图、图表）：DOM 是唯一真实源
- Canvas/WebGL 元素：渲染由底层 API 控制

**Q5：受控表单每次输入都重新渲染，性能是否有问题？**

对于常规表单（几十个字段以内），每次输入的重新渲染开销极小，用户完全无感知。如果表单超过 100 个输入字段，可以考虑：非受控 + 提交时读取，或者为每个字段做 `React.memo` 隔离渲染。

**Q6：`defineModel` 和 `.sync` 修饰符有什么关系？**

Vue 2 的 `.sync` 修饰符（Vue 3 中已移除）和 `v-model` 是同一种机制的不同 API。Vue 3.4 的 `defineModel` 是封装了 `props.modelValue` + `emit('update:modelValue')` 的语法糖，是 Vue 2 `.sync` 思想的现代化实现。

**Q7：半受控组件如何避免同时传入 `value` 和 `defaultValue` 时的歧义？**

组件库的惯例：如果检测到 `value` 传入，忽略 `defaultValue`，以受控模式运行。同时传两个时，在控制台警告。不要在同一个组件实例上同时使用两种模式。

## 实操作业

### 基础练习：实现受控表单校验

用 React 或 Vue 实现一个注册表单（用户名、密码、确认密码、邮箱），要求：
- 全部使用受控模式
- 实时校验：用户名长度 ≥ 3、密码长度 ≥ 6、两次密码一致、邮箱格式
- 校验失败时输入框显示红色边框和错误提示
- 所有字段通过后才允许点击提交按钮

### 进阶练习：实现半受控 Select 组件

参考本节 Input 的实现，写一个支持受控/非受控的 `<Select>` 组件：
- 受控：`<Select value={val} onChange={setVal} options={...} />`
- 非受控：`<Select defaultValue="bj" options={...} />`
- 同时实现 React 和 Vue 版本
- 对比两种实现中，受控/非受控判断逻辑的异同

### 挑战练习：跨框架受控表单库

设计一套统一的表单状态管理方案：
- 在不同的 JS 文件中，用纯函数（不依赖 React 或 Vue）管理表单状态
- 分别用 React Hooks 和 Vue Composable 封装这套逻辑
- 支持字段级别的校验、表单级别的提交前校验、字段联动
- 核心逻辑只写一次，适配两个框架时只写适配层

### 作业参考与验收

- **基础**：字段 state 单一来源，实时校验与提交校验共用纯函数。长度练习规则不是生产密码政策；复制请求绕过 disabled 时服务端也拒绝非法数据。
- **进阶**：用 value!==undefined 判断受控，不能用 truthy；内部值只在非受控时更新。测试空字符串、父值更新、defaultValue 初值以及受控模式切换的警告/策略。
- **挑战**：纯函数管理 values/errors/touched，适配层订阅与更新；字段规则在核心执行。React/Vue 运行同一组输入断言，异步校验旧结果不得覆盖新输入。

## 本节小结

- **受控组件**：状态在外部，组件只负责渲染，通过 `value + onChange`（React）或 `v-model`（Vue）实现
- **非受控组件**：状态在内部，通过 `defaultValue + ref`（React）或内部 `ref`（Vue）实现
- **半受控组件**：同时支持两种模式，根据是否传入 `value` 自动切换，是组件库的标准做法
- `v-model` 是受控模式的语法糖，不违背单向数据流
- 选型核心：需要实时干预状态 → 受控；只需初始值和最终值 → 非受控

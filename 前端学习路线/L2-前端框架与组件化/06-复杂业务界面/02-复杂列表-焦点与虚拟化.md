## 学习目标

- 能把排序、筛选、分页与选中项设计为稳定状态。
- 能选择原生 table 或交互 grid，处理键盘与焦点恢复。
- 能证明虚拟化收益并说明搜索、打印和无障碍代价。

## 内容讲解

### 1. 列表状态

过滤、排序与页码可进入 URL，支持刷新与分享；临时展开状态就近保存；跨页选中项按稳定资源 ID 保存，不能按数组下标。

```js
const selected = new Set(['article-1']);
function toggle(id) {
  const next = new Set(selected);
  if (next.has(id)) next.delete(id);
  else next.add(id);
  return next;
}
```

框架 state 更新须使用当前状态或函数式更新，避免闭包陈旧。数据刷新后检查已选资源是否仍存在且有操作权限。

“选中当前页”和“选中所有匹配”是不同产品行为，后者不能只上传当前页 IDs 假装全量操作。服务端再次授权每个资源。

### 2. table 与 grid

普通数据展示优先原生 table，表头使用 th/scope，操作使用可聚焦按钮。只有需要二维键盘移动与单元格交互时再采用 ARIA grid，并实现 roving tabindex、方向键和编辑退出。

给普通 table 添加 role=grid 不会自动生成键盘行为。自动无障碍扫描通过也不能证明方向键、焦点和屏幕阅读器体验正确。

删除当前行后焦点移至相邻可操作行或列表标题；弹窗关闭后回到触发按钮，触发节点已经删除时选稳定替代目标。

### 3. 虚拟化的计算

固定行高时：

```text
start = max(0, floor(scrollTop / rowHeight) - overscan)
end = min(total, ceil((scrollTop + viewportHeight) / rowHeight) + overscan)
topSpacer = start × rowHeight
bottomSpacer = (total - end) × rowHeight
```

只渲染 [start,end) 可以减少 DOM 数量。动态行高需测量与缓存；图片加载、字体和展开会改变高度，必须维护锚点避免滚动跳跃。

使用成熟库前先测量现有 DOM 与长任务，再评估收益。小列表不需要虚拟化；内容搜索、打印、页面内查找、爬虫和屏幕阅读器可能看不到未渲染行，需要服务端搜索、导出或非虚拟阅读模式。

### 4. SSR 与 hydration

服务端和客户端首次渲染必须一致。不能在渲染时读 localStorage、随机数或设备时区后让结构发生变化；在客户端阶段读取并有明确初始状态。

权限、数据和 HTML 来源安全仍由服务端控制，hydration warning 不能用宽泛 suppress 来隐藏真实错配。

## 常见问题

**useMemo 能解决所有列表性能吗？** 不能，先看 DOM 数量、重渲染、计算热点和布局成本。

**全量选择可以在前端直接批量提交吗？** 需明确范围与二次确认，服务端还要限制数量、权限和幂等。

## 实操作业

基础实现 URL 筛选与稳定选择；进阶实现删除后的焦点恢复；挑战对比 100/10000 条列表并给出虚拟化及阅读替代方案。

### 参考答案与验收

排序后选中 ID 不变；刷新保留 URL 筛选；删除不丢失键盘位置。性能报告应有相同设备和数据，不能只给最终帧率截图。

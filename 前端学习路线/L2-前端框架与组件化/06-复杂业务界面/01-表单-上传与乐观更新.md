## 学习目标

- 能建立包含校验、提交、冲突和重试的表单状态机。
- 能设计上传协议与乐观更新回滚，避免重复写入。

## 内容讲解

### 1. 表单状态机

```text
idle → validating → submitting → success
                       ↓
                    error → 重试
                       ↓
                  conflict → 合并/另存
```

字段值、触碰状态、字段错误与服务端错误分开保存。前端校验改善体验，服务端执行权威校验；角色、所有者与金额等不能由表单可信传入。

错误信息通过 `aria-describedby` 与字段关联，提交失败将焦点移至错误摘要或首个错误字段。不得仅以红色边框表示错误。

### 2. 提交契约

文章编辑请求带文章 ID、内容、baseRevision 和 mutationId。提交后禁用重复点击只减少误触，后端幂等才能防止网络重试重复写入。

| 响应 | 前端处理 |
|---|---|
| 422 字段错误 | 对应字段显示，保留用户输入 |
| 401 | 保留草稿，提示重新登录 |
| 403 | 停止重试，说明权限问题 |
| 409 版本冲突 | 展示当前版本，允许合并/另存 |
| 超时 | 状态未知，按相同 mutationId 查询或重试 |
| 5xx | 可控重试，避免清空内容 |

React effect 不应因表单 state 改变自动提交。提交放在显式事件或框架 action 流程中，避免重复 effect 导致写入。

### 3. 上传边界

前端 `accept` 和 File.type 只是提示；服务端检查大小、实际格式、权限和存储目标。上传文件名不能成为路径，内容不应在主站 origin 下被任意执行。

```js
const file = input.files?.[0];
if (!file) return;
if (file.size > 5 * 1024 * 1024) throw new Error('图片超过 5 MiB');
const preview = URL.createObjectURL(file);
image.src = preview;
// 替换图片或组件卸载时 revoke，避免 Blob 被持续保留。
image.onload = () => URL.revokeObjectURL(preview);
```

上传用 FormData 时不要手工设置 multipart Content-Type，浏览器需要生成 boundary。需要进度时可使用 XHR 的 upload progress；Fetch 的上传进度并非跨浏览器通用开箱能力。

大文件流程可以分片、校验和、可续传上传会话，但每片权限、合并大小和最终内容仍要校验。

### 4. 乐观更新

收藏适合乐观更新：先保存本资源快照，显示新状态；失败回滚该次修改；成功用服务器结果与 revision 校准。并发 mutation 时不能用旧快照覆盖另一已成功更新。

支付、角色授权和审核发布等高影响操作更适合等待服务端确认。乐观 UI 不能把“界面已显示”当作持久化完成。

### 5. 页面状态

每个数据区至少有 loading、empty、error、success；列表刷新可保留旧结果并明确正在刷新；分页失败允许重试当前页。禁止错误时无限 spinner 或用空列表掩盖请求失败。

## 常见问题

**按钮禁用就能保证幂等吗？** 不能，跨标签页、超时和服务端重试仍存在。

**上传图片可以直接拼入 HTML 吗？** 不可信文件仍需处理，SVG 等格式可能含主动内容，服务端策略需明确。

## 实操作业

基础实现字段错误与焦点；进阶完成上传取消、替换预览和失败恢复；挑战模拟两个编辑者 revision 冲突与收藏并发更新。

### 参考答案与验收

失败保留输入；状态未知不产生新 mutationId；预览替换释放 Blob；409 不静默覆盖。组件测试覆盖键盘和错误显示，真实浏览器覆盖文件选择与上传中断。

## 内容讲解

### 一、Props 传递和单向数据流

Props 是父组件向子组件传递数据的唯一官方通道，遵循**单向数据流**原则——数据只能从父级流向子级，子组件不应直接修改 props。

```vue
<!-- 子组件 UserCard.vue -->
<script setup lang="ts">
// ============ 类型安全的 Props 声明 ============
interface Props {
  // 必填
  name: string
  // 可选 + 默认值
  age?: number
  // 联合类型
  role?: 'admin' | 'editor' | 'viewer'
  // 复杂类型：对象
  address?: {
    city: string
    street: string
  }
  // 回调函数类型（虽然推荐用 emit，但这也是一种模式）
  onDelete?: (id: number) => void
}

const props = withDefaults(defineProps<Props>(), {
  age: 0,
  role: 'viewer',
  address: () => ({ city: '未知', street: '' })
})

// ============ Props 校验（运行时声明方式） ============
// 如果需要运行时校验（类型声明方式不提供），可以用 validator：
// defineProps({
//   age: {
//     type: Number,
//     validator: (value: number) => value >= 0 && value <= 150
//   }
// })

// ============ 单向数据流演示 ============
// ❌ 不要这样做：直接修改 prop
// props.age++

// ✅ 正确做法：创建本地副本
import { ref, computed } from 'vue'
const localAge = ref(props.age)

// ✅ 或者通过 computed 做转换
const formattedRole = computed(() => {
  const map = { admin: '管理员', editor: '编辑者', viewer: '观察者' }
  return map[props.role]
})
</script>

<template>
  <div class="user-card">
    <h3>{{ name }}</h3>
    <p>年龄：{{ age }}</p>
    <p>角色：{{ formattedRole }}</p>
    <p>地址：{{ address.city }} {{ address.street }}</p>
  </div>
</template>
```

```vue
<!-- 父组件 -->
<template>
  <!-- 静态 prop -->
  <UserCard name="张三" />

  <!-- 动态 prop：用 v-bind（:） -->
  <UserCard
    :name="user.name"
    :age="user.age"
    :role="user.role"
    :address="user.address"
  />

  <!-- 传递对象的所有属性（等价于上面） -->
  <UserCard v-bind="user" />

  <!-- 非 prop 属性（class, style, id 等）会自动继承到子组件根元素 -->
  <UserCard name="李四" class="highlight" id="card-1" />
</template>
```

**单向数据流的实际含义**：
- 当父组件的数据变化时，子组件自动更新
- 子组件内部不应该直接修改 props
- 如果子组件需要"修改"，应该通过 emit 通知父组件，由父组件来改
- 这个原则保证了数据流可追踪，不会出现"数据被谁改了"的困惑

### 二、Emits 触发父组件事件

子组件通过 emit 通知父组件发生了什么事（而不是直接修改父组件的数据）：

```vue
<!-- 子组件 TodoItem.vue -->
<script setup lang="ts">
// ============ 类型安全的 Emits 声明 ============
interface Emits {
  (e: 'delete', id: number): void
  (e: 'toggle', id: number, completed: boolean): void
  (e: 'edit', id: number, newText: string): void
}

const emit = defineEmits<Emits>()

// 在方法中触发事件
function handleDelete(id: number) {
  emit('delete', id)
}

function handleToggle(id: number, completed: boolean) {
  emit('toggle', id, !completed)
}
</script>

<template>
  <div class="todo-item">
    <span>待办内容</span>
    <button @click="handleDelete(1)">删除</button>
    <button @click="handleToggle(1, false)">切换</button>
  </div>
</template>
```

```vue
<!-- 父组件 -->
<script setup lang="ts">
import { ref } from 'vue'

const todos = ref([...])

// 处理子组件事件
function onDelete(id: number) {
  todos.value = todos.value.filter(t => t.id !== id)
}

function onToggle(id: number, completed: boolean) {
  const todo = todos.value.find(t => t.id === id)
  if (todo) todo.completed = completed
}
</script>

<template>
  <TodoItem
    v-for="todo in todos"
    :key="todo.id"
    @delete="onDelete"
    @toggle="onToggle"
  />
</template>
```

**对比 React**：Vue 的 emit 类似 React 中通过 props 传递 `onXxx` 回调（如 `onDelete={handleDelete}`），但 Vue 的方式更接近原生 DOM 事件——事件名是字符串，使用 `@` 监听，类型检查由 TypeScript 泛型提供。

### 三、插槽（Slots）

插槽是 Vue 组件内容分发的核心机制，让你能把模板片段传入子组件。

#### 3.1 默认插槽

最简单的形式：子组件留一个"坑"，父组件填内容：

```vue
<!-- 子组件 BaseCard.vue -->
<template>
  <div class="card">
    <div class="card-header">
      <slot name="header">默认标题</slot>
    </div>
    <div class="card-body">
      <!-- 默认插槽：没有 name 属性 -->
      <slot>默认内容，父组件不传时显示</slot>
    </div>
    <div class="card-footer">
      <slot name="footer">
        <button>默认按钮</button>
      </slot>
    </div>
  </div>
</template>
```

#### 3.2 具名插槽

给插槽起名字，父组件通过 `v-slot:name`（或缩写 `#name`）指定内容放到哪个插槽：

```vue
<!-- 父组件使用 -->
<template>
  <BaseCard>
    <!-- 具名插槽：用 #name 缩写 -->
    <template #header>
      <h2>用户信息</h2>
    </template>

    <!-- 默认插槽：直接写内容，或显式 #default -->
    <p>这里是卡片的正文内容</p>

    <template #footer>
      <button @click="save">保存</button>
      <button @click="cancel">取消</button>
    </template>
  </BaseCard>
</template>
```

#### 3.3 作用域插槽

子组件向父组件暴露数据，父组件决定如何渲染。这是插槽最强大的用法：

```vue
<!-- 子组件 DataList.vue -->
<script setup lang="ts">
interface Props {
  items: Array<{ id: number; name: string; value: number }>
}

const props = defineProps<Props>()
</script>

<template>
  <ul>
    <li v-for="item in items" :key="item.id">
      <!-- 通过 slot 的 v-bind 把 item 暴露给父组件 -->
      <slot name="item" :item="item" :index="0">
        <!-- 默认渲染 -->
        {{ item.name }}: {{ item.value }}
      </slot>
    </li>
  </ul>
</template>
```

```vue
<!-- 父组件使用作用域插槽 -->
<template>
  <DataList :items="metrics">
    <!-- 解构接收子组件暴露的数据 -->
    <template #item="{ item, index }">
      <div class="metric-row">
        <span class="rank">#{{ index + 1 }}</span>
        <span class="name">{{ item.name }}</span>
        <!-- 父组件决定数据如何可视化 -->
        <div class="bar" :style="{ width: item.value + '%' }"></div>
        <span class="value">{{ item.value }}%</span>
      </div>
    </template>
  </DataList>
</template>
```

**作用域插槽的本质**：子组件拥有数据，但把"如何渲染"的决定权交给父组件。这相当于 React 中的 render props 模式，但 Vue 的模板语法更直观。

#### 3.4 动态插槽名

Vue 3 支持用动态值作为插槽名：

```vue
<template>
  <DynamicLayout>
    <template #[dynamicSlotName]>
      <!-- 插槽名由变量 dynamicSlotName 动态决定 -->
      <p>动态插槽内容</p>
    </template>
  </DynamicLayout>
</template>

<script setup lang="ts">
import { ref } from 'vue'
const dynamicSlotName = ref('header')  // 可以是 'header', 'footer', 'sidebar' 等
</script>
```

**场景**：基于配置渲染不同的布局区域（如 CMS 的拖拽布局）。

### 四、provide / inject 依赖注入

当组件层级较深（祖孙通信）时，逐层传递 props 会很繁琐。`provide` / `inject` 允许祖先组件向所有后代组件注入数据——**无论嵌套多深**。

```vue
<!-- 祖先组件 App.vue -->
<script setup lang="ts">
import { ref, provide, readonly } from 'vue'

// ============ 注入静态值 ============
provide('appName', '我的应用')

// ============ 注入响应式数据 ============
const theme = ref<'light' | 'dark'>('light')
const user = ref({ name: '张三', role: 'admin' })

provide('theme', theme)         // 后代可以通过 inject 读写
provide('user', readonly(user)) // 只读注入，防止后代修改

// ============ 注入方法 ============
function setTheme(t: 'light' | 'dark') {
  theme.value = t
}
provide('setTheme', setTheme)

// ============ 注入组合式函数 ============
// 更推荐的方式：把状态 + 方法封装在一起
function useAppContext() {
  const theme = ref<'light' | 'dark'>('light')
  const toggleTheme = () => {
    theme.value = theme.value === 'light' ? 'dark' : 'light'
  }
  return { theme, toggleTheme }
}
provide('appContext', useAppContext())
</script>
```

```vue
<!-- 深层次的后代组件 DeepChild.vue -->
<script setup lang="ts">
import { inject } from 'vue'

// ============ 注入基本值 ============
const appName = inject<string>('appName', '默认应用')

// ============ 注入响应式数据 ============
// 注意：inject 返回的是响应式引用，可以直接读写
const theme = inject('theme')         // 返回 Ref<'light' | 'dark'>
const user = inject('user')           // 返回 DeepReadonly<Ref<...>>
const setTheme = inject<(t: string) => void>('setTheme')

// ============ 注入组合式函数 ============
interface AppContext {
  theme: Ref<'light' | 'dark'>
  toggleTheme: () => void
}
const appContext = inject<AppContext>('appContext')

// 使用注入的数据
function switchTheme() {
  // 方式 1：调用注入的方法
  setTheme?.('dark')

  // 方式 2：使用注入的组合式函数
  appContext?.toggleTheme()
}
</script>

<template>
  <div>
    <p>应用名：{{ appName }}</p>
    <p>当前主题：{{ theme }}</p>
    <button @click="switchTheme">切换主题</button>
  </div>
</template>
```

**provide/inject 最佳实践**：

1. **用 Symbol 作为 key**（避免命名冲突）：

```typescript
// keys.ts
import type { InjectionKey, Ref } from 'vue'

export const THEME_KEY: InjectionKey<Ref<'light' | 'dark'>> = Symbol('theme')
export const USER_KEY: InjectionKey<Ref<User>> = Symbol('user')

// 使用
provide(THEME_KEY, theme)
const theme = inject(THEME_KEY)  // 类型自动推导
```

2. **尽量让 provide 的数据只读**，修改方法由 provider 统一提供
3. **不要在 inject 的地方修改数据**，走 provider 暴露的方法
4. **配合 `readonly()`** 防止后代组件意外修改共享状态

**对比 React**：`provide/inject` ≈ React 的 Context API + `useContext`，但 Vue 的实现更轻量——不需要 Provider 组件包裹，直接在 `setup` 中调用即可，而且是响应式的（React Context 值变化会导致整个子树重渲染，Vue 只会触发使用了该注入值的组件更新）。

### 五、组件 v-model 的双向绑定原理

组件上的 `v-model` 本质是 Props + Emits 的语法糖：

```vue
<!-- ============ 原理拆解 ============ -->

<!-- 父组件写 -->
<CustomInput v-model="text" />

<!-- 等价于 -->
<CustomInput
  :model-value="text"
  @update:model-value="text = $event"
/>

<!-- ============ 子组件实现 ============ -->
<script setup lang="ts">
// Vue 3.4+ 推荐：defineModel
const model = defineModel<string>({ required: true })

// Vue 3.4 之前：手动实现
const props = defineProps<{ modelValue: string }>()
const emit = defineEmits<{ 'update:modelValue': [value: string] }>()

const model = computed({
  get: () => props.modelValue,
  set: (value) => emit('update:modelValue', value)
})
</script>

<template>
  <!-- 直接绑定到原生元素或做自定义处理 -->
  <input v-model="model" />
</template>
```

#### 多个 v-model 绑定

```vue
<!-- 父组件 -->
<AddressForm
  v-model:province="province"
  v-model:city="city"
  v-model:district="district"
/>

<!-- 子组件 AddressForm.vue -->
<script setup lang="ts">
const province = defineModel<string>('province', { required: true })
const city = defineModel<string>('city', { required: true })
const district = defineModel<string>('district', { default: '' })
</script>
```

#### v-model 修饰符

```vue
<script setup lang="ts">
interface Props {
  modelValue: string
  modelModifiers?: {
    capitalize?: boolean
    trim?: boolean
  }
}

const props = withDefaults(defineProps<Props>(), {
  modelModifiers: () => ({})
})

const emit = defineEmits<{ 'update:modelValue': [value: string] }>()

function emitValue(value: string) {
  // 根据修饰符处理值
  if (props.modelModifiers?.capitalize) {
    value = value.charAt(0).toUpperCase() + value.slice(1)
  }
  if (props.modelModifiers?.trim) {
    value = value.trim()
  }
  emit('update:modelValue', value)
}
</script>
```

```vue
<!-- 父组件使用修饰符 -->
<CustomInput v-model.capitalize.trim="text" />
```

### 六、实战：通用 Modal 组件

这个实战涵盖了 Props、Emits、插槽（默认 + 具名 + 作用域插槽）、过渡动画：

```vue
<!-- ==================== Modal.vue ==================== -->
<script setup lang="ts">
import { watch } from 'vue'

// ============ Props ============
interface Props {
  visible: boolean
  title?: string
  width?: string          // 如 '500px'、'60%'
  closable?: boolean       // 是否显示关闭按钮
  maskClosable?: boolean   // 点击遮罩是否关闭
  confirmText?: string
  cancelText?: string
  showFooter?: boolean
  loading?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  title: '',
  width: '520px',
  closable: true,
  maskClosable: true,
  confirmText: '确定',
  cancelText: '取消',
  showFooter: true,
  loading: false
})

// ============ Emits ============
interface Emits {
  (e: 'update:visible', value: boolean): void
  (e: 'confirm'): void
  (e: 'cancel'): void
  (e: 'close'): void
  (e: 'after-enter'): void
  (e: 'after-leave'): void
}

const emit = defineEmits<Emits>()

// ============ 关闭逻辑 ============
function handleClose() {
  if (!props.closable) return
  emit('update:visible', false)
  emit('close')
}

function handleMaskClick() {
  if (props.maskClosable) {
    emit('update:visible', false)
    emit('cancel')
  }
}

function handleConfirm() {
  emit('confirm')
}

function handleCancel() {
  emit('update:visible', false)
  emit('cancel')
}

// ============ 锁定 body 滚动 ============
watch(
  () => props.visible,
  (val) => {
    if (val) {
      document.body.style.overflow = 'hidden'
    } else {
      document.body.style.overflow = ''
    }
  }
)
</script>

<template>
  <!-- 使用 Vue 内置 Transition 组件 -->
  <Teleport to="body">
    <Transition
      name="modal"
      @after-enter="$emit('after-enter')"
      @after-leave="$emit('after-leave')"
    >
      <div v-if="visible" class="modal-root" @click.self="handleMaskClick">
        <!-- 遮罩层 -->
        <div class="modal-mask"></div>

        <!-- 弹窗本体 -->
        <div class="modal-wrapper">
          <div class="modal-container" :style="{ width }">
            <!-- 头部插槽 -->
            <div v-if="$slots.header || title" class="modal-header">
              <slot name="header">
                <h3 class="modal-title">{{ title }}</h3>
              </slot>
              <button
                v-if="closable"
                class="modal-close"
                @click="handleClose"
              >
                ✕
              </button>
            </div>

            <!-- 内容插槽（默认插槽 + 作用域插槽） -->
            <div class="modal-body">
              <slot :close="handleClose" :confirm="handleConfirm">
                <!-- 父组件不传内容时的默认展示 -->
                <p class="modal-default-text">这里是弹窗内容区域</p>
              </slot>
            </div>

            <!-- 底部插槽 -->
            <div v-if="showFooter" class="modal-footer">
              <slot name="footer">
                <button class="btn-cancel" @click="handleCancel">
                  {{ cancelText }}
                </button>
                <button
                  class="btn-confirm"
                  :disabled="loading"
                  @click="handleConfirm"
                >
                  {{ loading ? '处理中...' : confirmText }}
                </button>
              </slot>
            </div>
          </div>
        </div>
      </div>
    </Transition>
  </Teleport>
</template>
```

```vue
<!-- ==================== 父组件使用示例 ==================== -->
<script setup lang="ts">
import { ref } from 'vue'
import Modal from './Modal.vue'

const showModal = ref(false)
const userName = ref('')

function handleConfirm() {
  console.log('确认操作，用户名：', userName.value)
  showModal.value = false
}
</script>

<template>
  <button @click="showModal = true">打开弹窗</button>

  <!-- 基础用法：只用 props + emits -->
  <Modal
    v-model:visible="showModal"
    title="编辑用户信息"
    @confirm="handleConfirm"
    @cancel="showModal = false"
  >
    <!-- 默认插槽：弹窗内容 -->
    <label>
      用户名：
      <input v-model="userName" placeholder="请输入用户名" />
    </label>
    <p>请填写完整的用户信息，包括姓名、邮箱和角色。</p>
  </Modal>

  <!-- 高级用法：自定义头部 + 自定义底部 + 作用域插槽 -->
  <Modal v-model:visible="showModal" width="640px">
    <!-- 自定义头部插槽 -->
    <template #header>
      <div style="display: flex; align-items: center; gap: 8px;">
        <span style="font-size: 20px;">⚠️</span>
        <h3 style="margin:0;">确认删除</h3>
      </div>
    </template>

    <!-- 作用域插槽：拿到子组件的 close 和 confirm 方法 -->
    <template #default="{ close, confirm }">
      <p>此操作不可撤销，确定要继续吗？</p>
      <p style="color: #999; font-size: 13px;">
        删除后数据将被永久移除，建议先导出备份。
      </p>
      <div style="margin-top: 16px;">
        <button @click="confirm" style="margin-right: 8px;">作用域-确认</button>
        <button @click="close">作用域-关闭</button>
      </div>
    </template>

    <!-- 自定义底部：只需要一个按钮 -->
    <template #footer>
      <button
        style="background:#e74c3c;color:white;border:none;
               padding:8px 24px;border-radius:8px;cursor:pointer;"
        @click="handleConfirm"
      >
        确认删除
      </button>
    </template>
  </Modal>
</template>
```

**要点回顾**：
- Props 控制 Modal 的显示/隐藏、标题、宽度、按钮文案
- Emits 通知父组件确认/取消/关闭事件
- 默认插槽放弹窗内容，具名插槽自定义头部和底部
- 作用域插槽向父组件暴露 `close` 和 `confirm` 方法
- Teleport 将弹窗渲染到 body，避免层叠问题
- Transition 实现淡入 + 缩放入场动画
- watch 在弹窗打开时锁定 body 滚动

## 常见问题

**Q1：Props 到底能不能在子组件中修改？**

A：技术上可以（JS 没有强制限制），但这是反模式。修改 prop 会破坏单向数据流，导致数据来源不可追踪。正确做法：(1) 创建本地副本 `const local = ref(props.xxx)`；(2) 通过 computed 做转换；(3) 通过 emit 通知父组件修改。

**Q2：什么时候用 props 传递数据，什么时候用 provide/inject？**

A：父子直接通信（1-2 层）用 props + emit。跨越多层（3 层以上）、或不确定会被嵌套多深的数据（如主题、语言、用户信息）用 provide/inject。provide/inject 的缺点是数据来源不明显，过度使用会降低代码可读性。

**Q3：emit 和 props 中传回调函数有什么区别？**

A：emit 是 Vue 推荐的方式，更符合事件驱动模型，事件名清晰表达意图。props 传回调函数也可以工作，但在 Vue DevTools 中无法像 emit 事件那样追踪。Vue 3 的 `defineEmits` 提供完整的类型支持，emit 是更规范的选择。

**Q4：插槽和作用域插槽的本质区别是什么？**

A：默认插槽和具名插槽是**父组件提供模板，子组件决定放在哪里**。作用域插槽是**子组件提供数据，父组件决定如何渲染**。作用域插槽实现了"控制反转"——子组件拥有数据和处理逻辑，但视觉呈现权交给父组件。

**Q5：v-model 和 .sync 修饰符有什么区别？**

A：Vue 2 中 `.sync` 是 v-model 之外的另一种双向绑定方式。Vue 3 统一了——移除了 `.sync`，v-model 可以绑定多个，本质上等价于 Vue 2 的 `.sync`。简单说：Vue 3 的多个 `v-model:xxx` = Vue 2 的多个 `.sync`。

**Q6：Teleport + Modal 中的 Transition 为什么不生效？**

A：常见原因是 Transition 的直接子元素缺少 `v-if` 或 `v-show` 条件渲染指令。Transition 通过观察子元素的进入/离开来触发动画，如果没有条件切换，动画不会执行。此外，Teleport 不影响 Transition 的工作——它们配合使用是完全支持的。

**Q7：provide 的数据是响应式的吗？修改后后代组件会自动更新吗？**

A：如果你 provide 的是 `ref` 或 `reactive` 创建的响应式数据，后代组件 inject 后会自动跟踪变化。如果你 provide 的是普通 JS 值（字符串、数字），则不是响应式的。最佳实践：始终 provide 响应式数据；如果需要不可变性，用 `readonly()` 包装。

**Q8：动态插槽名有什么实际用途？**

A：主要用于配置驱动的布局系统。例如 CMS 系统根据后台配置动态决定某个内容块渲染到 header / sidebar / main / footer 区域，而不是硬编码。典型场景：低代码平台的页面搭建器中，不同组件配置不同的 slot 出口。

## 实操作业

### 基础：可复用消息卡片组件

- Props：头像、昵称、时间、消息内容、消息类型（text/image/file）
- 插槽：默认插槽放消息内容，`#actions` 插槽放操作按钮
- Emits：`delete`、`reply`、`forward`
- 使用 TypeScript 严格类型声明

### 进阶：通用抽屉组件（Drawer）

仿照实战中的 Modal，实现一个侧边滑出的 Drawer 组件：
- 支持四个方向：left / right / top / bottom
- 不同方向对应不同的滑入滑出动画
- 支持具名插槽自定义 header / body / footer
- 作用域插槽暴露 `close` 方法
- 支持 `v-model:visible` 双向绑定

### 挑战：多层嵌套的权限控制表格

用 provide/inject + 插槽实现：
- 顶层组件用 `provide` 注入当前用户权限（如 `canEdit`、`canDelete`、`canView`）
- 表格的每一行是一个独立组件（嵌套 2-3 层），通过 `inject` 获取权限
- 用作用域插槽自定义操作列，根据权限动态显示/隐藏按钮
- 行内编辑模式：点击编辑按钮后该行变为可编辑状态（v-model 绑定行数据）
- 支持全局"只读模式"切换（修改 provide 的 `readonly` 状态，所有行联动）

### 作业参考与验收

- **基础**：用判别联合区分 text/image/file，事件带稳定消息 ID；actions 插槽可替换。缺头像回退，HTML 消息按文本渲染，未知类型在类型检查/运行校验被发现。

## 本节小结

- **Props**：父→子单向数据流，只读，TypeScript 接口声明类型安全
- **Emits**：子→父事件通知，不直接修改 props
- **四种插槽**：默认插槽（内容分发）、具名插槽（多区域分发）、作用域插槽（数据与渲染分离）、动态插槽名（配置驱动）
- **provide/inject**：跨层级依赖注入，配合 Symbol 做类型安全的 key
- **组件 v-model**：Props + Emits 的语法糖，Vue 3.4+ 用 defineModel 一行搞定
- **Modal 实战**：综合运用所有通信方式，配合 Teleport + Transition 实现完整弹窗

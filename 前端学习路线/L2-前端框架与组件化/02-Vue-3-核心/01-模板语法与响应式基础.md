## 内容讲解

### 一、Composition API vs Options API

Vue 3 同时支持两种 API 风格，你需要了解它们的差异和选择依据。

**Options API（选项式）**：对 Vue 新手友好，按 `data`、`methods`、`computed`、`watch` 等选项组织代码。缺点是：同一逻辑关注点的代码分散在不同选项中，组件大了之后维护困难。

```vue
<script>
export default {
  data() {
    return { count: 0, name: '' }
  },
  methods: {
    increment() { this.count++ }
  },
  computed: {
    double() { return this.count * 2 }
  }
}
</script>
```

**Composition API（组合式）**：按逻辑关注点组织代码。你把相关状态和逻辑放在一起，更接近原生 JS 的编写方式，也更容易抽取可复用的组合函数（类似 React Hooks）。

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const count = ref(0)
const double = computed(() => count.value * 2)

function increment() {
  count.value++
}
</script>
```

| 对比维度 | Options API | Composition API |
|---------|------------|-----------------|
| 学习曲线 | 新手友好，结构固定 | 需要理解响应式引用 |
| 代码组织 | 按选项类型分散 | 按逻辑关注点聚合 |
| TypeScript 支持 | 需要额外类型推导 | 原生支持，类型安全 |
| 逻辑复用 | Mixins（命名冲突、来源不明） | 组合函数（composables），清晰可追踪 |
| 打包体积 | 较大 | Tree-shaking 友好，更小 |

**建议**：新项目一律使用 Composition API + `<script setup>`。学习 Options API 是为了维护老项目，不是未来方向。

### 二、ref() 和 reactive() 详解

这是 Vue 3 响应式系统的两大核心 API，理解它们的区别至关重要。

#### ref()

`ref()` 对任意类型的值创建响应式引用，返回一个 `.value` 属性访问的响应式对象：

```typescript
import { ref } from 'vue'

const count = ref(0)           // Ref<number>
const name = ref('张三')        // Ref<string>
const list = ref([1, 2, 3])    // Ref<number[]>

console.log(count.value)  // 0 —— 在 JS 中必须用 .value 访问
count.value++             // 触发响应式更新

// 模板中自动解包，不需要 .value
// <template><p>{{ count }}</p></template>
```

核心规则：
- JS 代码中访问/修改需要 `.value`
- 模板中自动解包（顶层 ref 直接写变量名）
- 深层嵌套的对象也会被内部转为 reactive

**为什么需要 `.value`？** 因为 JS 的原始类型（number、string、boolean）是值传递，无法被追踪。`ref()` 用一个对象的 `.value` getter/setter 来拦截读写，实现了对原始类型的响应式。

#### reactive()

`reactive()` 对对象类型创建深层响应式代理：

```typescript
import { reactive } from 'vue'

const state = reactive({
  user: { name: '张三', age: 25 },
  items: ['a', 'b', 'c']
})

// 直接访问，不需要 .value
state.user.name = '李四'   // 触发响应式更新
state.items.push('d')       // 触发响应式更新
```

#### 选用场景与限制

| | ref() | reactive() |
|---|------|-----------|
| 适用类型 | 任意类型（原始值 + 对象） | 仅对象类型（Object、Array、Map、Set） |
| 访问方式 | `.value` | 直接访问 |
| 解构 | 不解构（用 toRefs） | **解构会丢失响应式** |
| 替换 | 可替换整个值 | **不能直接替换整个对象** |
| 模板解包 | 顶层自动解包 | 不需要解包 |

**reactive() 的两大限制**：

1. **不能整体替换**：
```typescript
let state = reactive({ count: 0 })
// ❌ 这样会断开响应式链接
state = reactive({ count: 1 })
// ✅ ref 可以
const state = ref({ count: 0 })
state.value = { count: 1 }  // 仍然响应式
```

2. **解构会丢失响应式**：
```typescript
const state = reactive({ count: 0, name: 'Vue' })
// ❌ count 现在是普通 number
const { count, name } = state
// ✅ 使用 toRefs 保持响应式
import { toRefs } from 'vue'
const { count, name } = toRefs(state)
```

**推荐策略**：
- 单个原始值 → `ref()`
- 单个对象，不需要整体替换 → `reactive()` 或 `ref()`
- 需要整体替换的对象 → `ref()`
- 组合函数（composable）返回值 → `ref()`，配合 `toRefs()` 更灵活

社区实践中，很多人选择**全部使用 ref()**，避免 `.value` 和解构混淆带来的心智负担。这是完全可行的选择。

### 三、响应式原理：Proxy（Vue 3）vs Object.defineProperty（Vue 2）

Vue 3 的响应式系统基于 ES6 Proxy，这是相比 Vue 2 最底层的变革。

#### Vue 2 的 Object.defineProperty

```javascript
// Vue 2 方式：逐个属性劫持
function defineReactive(obj, key) {
  let value = obj[key]
  Object.defineProperty(obj, key, {
    get() {
      console.log(`读取 ${key}`)
      return value
    },
    set(newVal) {
      console.log(`设置 ${key} = ${newVal}`)
      value = newVal
    }
  })
}
```

这导致 Vue 2 的三个著名限制：
1. **无法检测属性的添加/删除** —— 需要 `Vue.set()` / `Vue.delete()`
2. **无法检测数组索引赋值和 length 修改** —— 重写了 7 个数组方法
3. **初始化时要递归遍历所有属性** —— 大对象性能差

#### Vue 3 的 Proxy

```javascript
// Vue 3 方式：代理整个对象
function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      // 收集依赖（track）
      console.log(`读取 ${String(key)}`)
      const result = Reflect.get(target, key, receiver)
      // 懒代理：嵌套对象访问时才递归包装
      if (typeof result === 'object' && result !== null) {
        return reactive(result)
      }
      return result
    },
    set(target, key, value, receiver) {
      console.log(`设置 ${String(key)} = ${value}`)
      const oldValue = target[key]
      const result = Reflect.set(target, key, value, receiver)
      // 触发更新（trigger）
      if (oldValue !== value) {
        // 通知依赖更新
      }
      return result
    },
    deleteProperty(target, key) {
      console.log(`删除 ${String(key)}`)
      return Reflect.deleteProperty(target, key)
    }
  })
}

const state = reactive({ count: 0, items: [1, 2] })
state.count = 1        // ✅ 触发
state.newProp = 'hi'   // ✅ 触发（Vue 2 做不到）
state.items[0] = 99    // ✅ 触发（Vue 2 做不到）
delete state.count     // ✅ 触发（Vue 2 做不到）
```

**Proxy 带来的优势**：
- 代理整个对象，无需提前知道所有属性
- 能拦截 13 种操作（get、set、deleteProperty、has、ownKeys 等）
- 懒代理：嵌套对象在访问时才递归包装，初始化更快
- 原生支持数组索引和 `length` 修改

这个底层变化是你理解 Vue 3 "为什么更好" 的关键。在实际开发中，最直观的感受就是：**不用再担心 `Vue.set()` 了**。

### 四、模板语法

#### 插值

```vue
<template>
  <!-- 文本插值 -->
  <p>{{ message }}</p>

  <!-- JS 表达式（单条，不能写语句） -->
  <p>{{ price * quantity }}</p>
  <p>{{ isLogin ? '欢迎回来' : '请登录' }}</p>
  <p>{{ items.length > 0 ? `${items.length} 条记录` : '暂无数据' }}</p>

  <!-- ⚠️ 不能写语句：{{ if (ok) { return 'yes' } }}  ❌ -->
  <!-- ⚠️ 不能写赋值：{{ foo = 1 }}  ❌ -->
</template>
```

#### 核心指令

```vue
<template>
  <!-- v-bind：单向绑定属性 -->
  <!-- 简写 :href="url"，等价于 v-bind:href="url" -->
  <a :href="url" :title="tooltip">链接</a>
  <img :src="imageSrc" :alt="imageAlt" />
  <!-- 动态绑定多个属性 -->
  <div v-bind="attrsObject"></div>
  <!-- 动态属性名（Vue 3） -->
  <div :[attrName]="attrValue"></div>

  <!-- v-model：双向绑定（语法糖，展开是 :value + @input） -->
  <input v-model="username" />
  <!-- 等价于 -->
  <input :value="username" @input="username = ($event.target as HTMLInputElement).value" />

  <!-- 条件渲染 -->
  <!-- v-show：始终渲染，切换 display -->
  <div v-show="isVisible">通过 CSS display 控制显示</div>

  <!-- v-if / v-else-if / v-else：条件为假时不渲染 DOM -->
  <div v-if="score >= 90">优秀</div>
  <div v-else-if="score >= 60">及格</div>
  <div v-else>不及格</div>

  <!-- 列表渲染 -->
  <!-- key 必须是唯一且稳定的标识，不能用 index -->
  <li v-for="item in items" :key="item.id">
    {{ item.name }}
  </li>
  <!-- 同时获取索引 -->
  <li v-for="(item, index) in items" :key="item.id">
    {{ index + 1 }}. {{ item.name }}
  </li>
  <!-- 遍历对象 -->
  <li v-for="(value, key, index) in obj" :key="key">
    {{ key }}: {{ value }}
  </li>
</template>
```

#### v-if vs v-show 详解

| 对比维度 | v-if | v-show |
|---------|------|--------|
| 渲染机制 | 条件为假时元素根本不渲染到 DOM | 始终渲染，通过 `display: none` 切换 |
| 切换开销 | 高（创建/销毁 DOM + 组件生命周期） | 低（只改 CSS） |
| 初始开销 | 条件为假时为零 | 始终有初始渲染开销 |
| 生命周期 | 会触发 created/mounted/unmounted | 只挂载一次，后续只切换 CSS |
| 适用场景 | 运行时条件很少改变的场景 | 频繁切换的场景 |
| 配合 `<template>` | ✅ 可以包裹多个元素 | ❌ 不能用于 `<template>` |

**经验法则**：如果切换频率高（如 Tab 切换），用 `v-show`；如果条件在一次会话中基本不变（如权限判断），用 `v-if`。

#### v-for 的 key 绑定规则

`key` 是 Vue 虚拟 DOM diff 算法的核心标识，**必须绑定且必须唯一稳定**：

```vue
<!-- ✅ 正确：用唯一 ID -->
<li v-for="item in items" :key="item.id">{{ item.name }}</li>

<!-- ❌ 错误：用 index（列表顺序变化时会导致错误的复用） -->
<li v-for="(item, index) in items" :key="index">{{ item.name }}</li>

<!-- ❌ 错误：在同一元素上同时使用 v-if 和 v-for -->
<!-- Vue 3 中 v-if 优先级更高，会导致 v-for 的变量不可用 -->
<li v-for="item in items" v-if="item.active" :key="item.id">
<!-- ✅ 正确：用 computed 预过滤 -->
<li v-for="item in activeItems" :key="item.id">
```

**为什么 key 不能用 index？** 当列表项插入、删除或排序时，index 会变化，Vue 可能复用错误的 DOM 元素，导致动画异常、输入框状态错乱等问题。

### 五、事件处理

```vue
<template>
  <!-- 内联处理器 -->
  <button @click="count++">+1</button>

  <!-- 方法处理器 -->
  <button @click="handleClick">点击</button>

  <!-- 传入参数 -->
  <button @click="handleDelete(item.id)">删除</button>

  <!-- 访问原生事件对象 -->
  <button @click="handleEvent($event)">事件对象</button>
  <!-- 同时传参和事件对象 -->
  <button @click="handleBoth('hello', $event)">传参+事件</button>

  <!-- 事件修饰符 -->
  <form @submit.prevent="onSubmit">       <!-- 阻止默认行为 -->
  <div @click.stop="onClick">             <!-- 阻止冒泡 -->
  <button @click.once="doOnce">           <!-- 只触发一次 -->
  <input @keyup.enter="onEnter">          <!-- 按键修饰符 -->
  <div @click.self="onSelf">              <!-- 只在 event.target 是自己时触发 -->
  <a @click.prevent.stop>                 <!-- 修饰符可以链式调用 -->

  <!-- 系统按键修饰符 -->
  <div @click.ctrl="onCtrlClick">         <!-- Ctrl + 点击 -->
  <div @keyup.ctrl.enter="onCtrlEnter">   <!-- Ctrl + Enter -->

  <!-- exact 修饰符：精确匹配 -->
  <div @click.ctrl.exact="onCtrlOnly">    <!-- 仅 Ctrl，不包含 Shift 等组合 -->
</template>
```

### 六、计算属性 computed

`computed` 是基于依赖的缓存计算属性，与方法的区别是核心高频考点：

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const items = ref([
  { id: 1, name: '苹果', price: 10, count: 2 },
  { id: 2, name: '香蕉', price: 5, count: 5 }
])

// 计算属性：依赖不变时读取缓存值，不会重新计算
const totalPrice = computed(() => {
  console.log('computed 重新计算')  // 只在 items 变化时打印
  return items.value.reduce((sum, item) => sum + item.price * item.count, 0)
})

// 方法：每次访问都会重新执行
function getTotalPrice() {
  console.log('方法重新执行')  // 每次调用都打印
  return items.value.reduce((sum, item) => sum + item.price * item.count, 0)
}
</script>

<template>
  <!-- 多次读取 computed，只计算一次，使用缓存 -->
  <p>总价: {{ totalPrice }}</p>
  <p>总价: {{ totalPrice }}</p>

  <!-- 多次调用方法，每次都执行 -->
  <p>总价: {{ getTotalPrice() }}</p>
  <p>总价: {{ getTotalPrice() }}</p>
</template>
```

**对比 React 类比**：`computed` ≈ React 中的 `useMemo`，都是缓存计算结果，但 Vue 的 `computed` 自动收集依赖，无需手动声明依赖数组。

### 七、实战：Composition API 响应式计数器 + TodoList

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

// ==================== 计数器 ====================
const count = ref(0)

// 计算属性
const doubleCount = computed(() => count.value * 2)
const isEven = computed(() => count.value % 2 === 0)

function increment() { count.value++ }
function decrement() { count.value-- }
function reset() { count.value = 0 }

// ==================== TodoList ====================

// 类型定义
interface Todo {
  id: number
  text: string
  completed: boolean
}

const todos = ref<Todo[]>([])
const newTodoText = ref('')
let nextId = 1

// 计算属性
const activeTodos = computed(() => todos.value.filter(t => !t.completed))
const completedTodos = computed(() => todos.value.filter(t => t.completed))

const statsText = computed(() => {
  const total = todos.value.length
  const active = activeTodos.value.length
  return `共 ${total} 项，${active} 项待完成`
})

function addTodo() {
  const text = newTodoText.value.trim()
  if (!text) return

  todos.value.push({
    id: nextId++,
    text,
    completed: false
  })
  newTodoText.value = ''  // 清空输入框
}

function toggleTodo(id: number) {
  const todo = todos.value.find(t => t.id === id)
  if (todo) {
    todo.completed = !todo.completed
  }
}

function removeTodo(id: number) {
  todos.value = todos.value.filter(t => t.id !== id)
}

function clearCompleted() {
  todos.value = todos.value.filter(t => !t.completed)
}
</script>

<template>
  <div class="app">
    <!-- 计数器区 -->
    <section class="counter-section">
      <h2>计数器</h2>
      <p class="count-display">{{ count }}</p>
      <p>两倍值：{{ doubleCount }} | {{ isEven ? '偶数' : '奇数' }}</p>
      <div class="btn-group">
        <button @click="decrement" :disabled="count <= 0">-1</button>
        <button @click="increment">+1</button>
        <button @click="reset">重置</button>
      </div>
    </section>

    <!-- TodoList 区 -->
    <section class="todo-section">
      <h2>TodoList（{{ statsText }}）</h2>

      <!-- 添加 -->
      <form @submit.prevent="addTodo" class="add-form">
        <input
          v-model="newTodoText"
          placeholder="输入待办事项..."
          @keyup.enter="addTodo"
        />
        <button type="submit" :disabled="!newTodoText.trim()">添加</button>
      </form>

      <!-- 列表 -->
      <ul v-if="todos.length" class="todo-list">
        <li
          v-for="todo in todos"
          :key="todo.id"
          :class="{ completed: todo.completed }"
        >
          <input
            type="checkbox"
            :checked="todo.completed"
            @change="toggleTodo(todo.id)"
          />
          <span class="todo-text">{{ todo.text }}</span>
          <button class="btn-delete" @click="removeTodo(todo.id)">删除</button>
        </li>
      </ul>
      <p v-else class="empty-hint">暂无待办事项，添加一个吧！</p>

      <!-- 底部操作 -->
      <div v-if="completedTodos.length" class="footer">
        <button @click="clearCompleted">
          清除已完成（{{ completedTodos.length }}）
        </button>
      </div>
    </section>
  </div>
</template>
```

**要点回顾**：
- `ref()` 包装基本类型和数组，模板自动解包
- `computed` 缓存计算结果，依赖不变不重算
- `v-model` 双向绑定表单控件
- `v-for` 必须绑定稳定的 `key`
- `v-if` / `v-show` 按切换频率选择
- 事件用 `@` 简写，修饰符链式调用

## 常见问题

**Q1：ref 和 reactive 到底该用哪个？**

A：社区两派观点都存在。新手建议方案：表单类对象（用户信息、配置等）用 `reactive()`，其余场景（单个值、列表、需要整体替换的对象）用 `ref()`。如果不想纠结，**统一用 ref()** 也是最简单可行的选择，因为 Vue 3.3+ 的响应式语法糖更进一步减轻了 `.value` 的心智负担。

**Q2：为什么要在 JS 中写 .value？能不能去掉？**

A：不能，这是 Vue 3 响应式的核心设计。原始类型在 JS 中是值传递，无法被追踪，必须用对象包装。如果你觉得繁琐，可以关注 Vue 的 Reactivity Transform 实验性提案（但截至 3.4 已被撤回），建议适应 `.value` 写法。

**Q3：v-if 和 v-show 可以一起用吗？**

A：可以，但不推荐直接写在同一个元素上。Vue 3 中 `v-if` 优先级更高，`v-show` 只在 `v-if` 为 true 时生效。如果需要同时控制渲染和显示建议分拆或使用 computed。

**Q4：v-for 的 key 用 index 会有什么实际问题？**

A：经典场景：一个待办列表，每项有输入框。当你删除第一项时，由于 index 偏移，Vue 会复用 DOM 导致输入框内容错位到上一行。用唯一 ID 就能正确识别每个节点。

**Q5：computed 和 method 的性能差距有多大？**

A：单个场景差距肉眼不可见。但当模板中有多处引用同一个计算逻辑，且依赖大量数据时，`computed` 只算一次，`method` 每次重渲染都执行。核心是语义：`computed` 描述“派生状态”，`method` 描述“行为”。

**Q6：@click 和 @click.prevent 有什么区别？**

A：`@click` 直接绑定事件处理器，默认行为正常执行。`@click.prevent` 等价于 `e.preventDefault()`，阻止默认行为（如阻止链接跳转、表单提交）。类似的还有 `.stop`（阻止冒泡）、`.self`（只响应自身事件）、`.once`（只触发一次）。

**Q7：Vue 3 Proxy 和 Vue 2 defineProperty 最直观的区别是什么？**

A：最直观的区别是：Vue 3 中你可以随意添加/删除对象的属性、通过索引修改数组，响应式自动生效。Vue 2 中这些操作需要 `Vue.set()` / `Vue.delete()` / 重写的数组方法。开发体验提升显著。

**Q8：reactive 对象解构后为什么丢失响应式？**

A：`reactive` 返回的是一个 Proxy 对象，通过 Proxy 的 `get` 拦截来实现响应式。解构时拿到的是原始值（普通 number/string），不再经过 Proxy，自然丢失响应式。用 `toRefs()` 可以把每个属性转成 `ref`，解构后仍保持响应式连接。

## 本节小结

- **两种 API**：新项目用 Composition API + `<script setup>`，Options API 用于维护老项目
- **响应式 API**：`ref()` 用于所有类型，`.value` 访问；`reactive()` 仅对象，解构需 `toRefs()`
- **底层原理**：Vue 3 用 Proxy 代理整个对象，弥补了 Vue 2 defineProperty 的全部短板
- **模板指令**：`v-bind`（`:`）、`v-model`、`v-if`/`v-show`、`v-for`（必须 key）
- **v-if vs v-show**：频繁切换用 v-show，条件稳定用 v-if
- **computed**：基于依赖缓存，自动追踪，类似 React 的 useMemo
- **事件处理**：`@` 绑定 + 修饰符链式调用

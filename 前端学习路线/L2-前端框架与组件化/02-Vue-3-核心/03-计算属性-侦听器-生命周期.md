## 内容讲解

### 一、computed 的 getter/setter 双模式

通常情况下，`computed` 返回只读的派生值。但你可以通过提供 getter 和 setter 创建一个**可写的计算属性**：

```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const firstName = ref('张')
const lastName = ref('三')

// ============ 只读模式（默认） ============
const fullName = computed(() => {
  return `${firstName.value} ${lastName.value}`
})

// fullName.value = '李 四'  // ❌ 报错：只读

// ============ 可写模式（提供 setter） ============
const fullNameWritable = computed({
  get() {
    return `${firstName.value} ${lastName.value}`
  },
  set(newValue: string) {
    // 当外部修改 fullNameWritable.value 时触发
    const parts = newValue.split(' ')
    firstName.value = parts[0] || ''
    lastName.value = parts[1] || ''
  }
})

// 现在可以反向拆解
fullNameWritable.value = '李 四'
// firstName → '李'，lastName → '四'
</script>
```

**典型场景**：

1. **封装复杂状态逻辑**——外部只需操作一个 computed，内部自动同步多个源：

```typescript
// 购物车：选中状态的读写封装
const selectedIds = ref<Set<number>>(new Set())

const isAllSelected = computed({
  get: () => selectedIds.value.size === allItems.value.length,
  set: (checked: boolean) => {
    if (checked) {
      selectedIds.value = new Set(allItems.value.map(i => i.id))
    } else {
      selectedIds.value = new Set()
    }
  }
})

// 模板中直接绑定 v-model
// <input type="checkbox" v-model="isAllSelected" /> 全选
```

2. **Vue 3.4 之前的 v-model 双向绑定**——`defineModel` 出现前，这就是标准做法：

```typescript
const props = defineProps<{ modelValue: string }>()
const emit = defineEmits<{ 'update:modelValue': [value: string] }>()

const model = computed({
  get: () => props.modelValue,
  set: (value) => emit('update:modelValue', value)
})
```

### 二、computed 的依赖追踪原理

这是理解 Vue 响应式系统工作方式的核心知识：

```
执行流程：
1. computed 首次被读取时，执行 getter 函数
2. 执行过程中访问的每个响应式数据（ref/reactive 属性）被自动记录为"依赖"
3. 计算结果被缓存
4. 当任一依赖发生变化时，computed 标记为"脏"（dirty）
5. 下次读取时重新计算并再次缓存
6. 如果依赖没变，重复读取直接返回缓存值

关键：依赖收集是"运行时"而非"声明时"的
```

**条件分支中的依赖追踪**：

```typescript
const showDetail = ref(false)
const count = ref(0)
const name = ref('Vue')

const display = computed(() => {
  if (showDetail.value) {
    // 此时依赖：showDetail + count
    return `计数：${count.value}`
  } else {
    // 此时依赖：showDetail + name
    return `名称：${name.value}`
  }
})
// 依赖是动态的：showDetail 为 true 时，name 变化不会触发重新计算
```

**与 React 对比**：React 的 `useMemo` 需要手动声明依赖数组 `[dep1, dep2]`，遗漏依赖可能产生旧值问题。Vue 的 `computed` 会追踪 getter **同步执行期间读取到的响应式值**，因此通常不需要手写依赖；但异步回调中才读取的值、未纳入响应式系统的数据或被错误解构后失去响应性的值，都不会自动成为依赖。

### 三、watch 的 flush 时机

`watch` 回调在 DOM 更新前执行（默认 `flush: 'pre'`），但你可以控制执行时机：

```vue
<script setup lang="ts">
import { ref, watch, nextTick } from 'vue'

const count = ref(0)
const msg = ref('hello')

// ============ flush: 'pre'（默认） ============
// DOM 更新之前执行，此时访问 DOM 拿到的是旧状态
watch(count, (newVal) => {
  console.log('pre flush:', newVal)
  // 此时 DOM 还是旧值，不要操作 DOM
})

// ============ flush: 'post'（DOM 更新之后） ============
// 适合需要在数据变化后操作 DOM 的场景
watch(count, (newVal) => {
  console.log('post flush:', newVal)
  // 此时 DOM 已更新完成，可以安全操作 DOM
}, { flush: 'post' })

// ============ flush: 'sync'（同步执行） ============
// 数据变化时立即同步执行，不等待 Vue 的异步更新队列
// ⚠️ 慎用！会导致多次不必要的回调，性能差
watch(count, (newVal) => {
  console.log('sync flush:', newVal)
}, { flush: 'sync' })

// ============ 执行顺序演示 ============
function demo() {
  count.value++
  count.value++
  count.value++
  // pre 和 post 只会触发一次（批处理），拿到最终值 3
  // sync 会触发三次
}
</script>
```

**三种 flush 的典型场景**：

| flush | 执行时机 | 典型场景 |
|-------|---------|---------|
| `pre`（默认） | 组件更新前 | 大部分场景，性能最优（批处理） |
| `post` | DOM 更新后 | 需要测量/操作 DOM、滚动到某个位置 |
| `sync` | 值变化时立即 | 极少数场景，如需要在数据变化的瞬间做状态快照 |

**实际上你更常用的是快捷 API**：

```typescript
import { watchPostEffect, watchSyncEffect } from 'vue'

// 等价于 watchEffect(cb, { flush: 'post' })
watchPostEffect(() => {
  // 此处可以安全访问更新后的 DOM
})

// 等价于 watchEffect(cb, { flush: 'sync' })
watchSyncEffect(() => {
  // 同步执行，谨慎使用
})
```

### 四、watchEffect 的自动依赖收集和副作用清理

`watchEffect` 的核心价值在于"你只管写逻辑，依赖追踪由框架处理"：

```typescript
import { ref, watchEffect } from 'vue'

const userId = ref(1)
const userData = ref<any>(null)
const controller = ref<AbortController | null>(null)

// watchEffect 自动追踪：userId 变化时重新执行
const stop = watchEffect((onCleanup) => {
  // 创建新的 AbortController（每次执行时创建）
  const ctrl = new AbortController()
  controller.value = ctrl

  // 注册清理函数（在下一次执行前调用）
  onCleanup(() => {
    ctrl.abort()  // 取消上一次未完成的请求
    console.log('已取消旧请求')
  })

  // 异步请求
  fetch(`/api/user/${userId.value}`, {
    signal: ctrl.signal
  })
    .then(res => res.json())
    .then(data => {
      userData.value = data
    })
    .catch(err => {
      if (err.name !== 'AbortError') {
        console.error('请求失败:', err)
      }
    })
})

// 模拟快速切换 userId
userId.value = 2  // → 清理上一次的请求，发起 userId=2 的新请求
userId.value = 3  // → 再次清理，只保留 userId=3 的请求

// 组件卸载时停止
// stop()  // 或手动停止
```

**副作用清理的执行时机**：
- `watchEffect`**下一次执行前**调用 `onCleanup`
- 组件**卸载时**（onUnmounted）也会调用最后一次 `onCleanup`
- `watch` 也支持副作用清理（回调的第三个参数就是 `onCleanup`）

**常见需要清理的场景**：
- 取消 fetch / axios 请求（AbortController）
- 清除定时器（clearTimeout / clearInterval）
- 移除事件监听（removeEventListener）
- 断开 WebSocket 连接

### 五、生命周期钩子

Vue 3 组件从创建到销毁会经历一系列生命周期钩子：

```
组件创建流程：
setup() 执行
  → onBeforeMount（模板编译完成，即将挂载）
    → onMounted（DOM 挂载完成，可访问 DOM）
      → onBeforeUpdate（数据变化，即将重新渲染）
        → onUpdated（DOM 更新完成）
          → onBeforeUnmount（即将卸载）
            → onUnmounted（卸载完成）

此外还有开发调试用的：
  → onRenderTracked（调试用：追踪到响应式依赖时触发）
  → onRenderTriggered（调试用：响应式依赖触发更新时触发）

服务端渲染专用（SSR only）：
  → onServerPrefetch
```

```vue
<script setup lang="ts">
import {
  ref,
  onBeforeMount,
  onMounted,
  onBeforeUpdate,
  onUpdated,
  onBeforeUnmount,
  onUnmounted,
  onActivated,     // <KeepAlive> 激活
  onDeactivated,   // <KeepAlive> 停用
  onErrorCaptured, // 捕获子组件错误
} from 'vue'

const el = ref<HTMLDivElement | null>(null)

// 此时模板已编译，但 DOM 未挂载
onBeforeMount(() => {
  console.log('1. beforeMount：准备挂载，DOM 尚未创建')
})

// 最常用的钩子：DOM 已挂载，可以安全操作 DOM / 发请求 / 初始化第三方库
onMounted(() => {
  console.log('2. mounted：DOM 已挂载')
  console.log(el.value?.offsetWidth)  // 可以拿到尺寸
  // 适合：发起 API 请求、初始化 ECharts、注册事件监听
})

// 数据变化，即将重新渲染
onBeforeUpdate(() => {
  console.log('3. beforeUpdate：即将更新 DOM')
  // 适合：在 DOM 更新前获取旧状态（如保存滚动位置）
})

// DOM 更新完成
onUpdated(() => {
  console.log('4. updated：DOM 已更新')
  // 适合：根据新 DOM 状态做后续操作
  // ⚠️ 不要在这里修改数据，会导致无限循环
})

// 组件即将卸载
onBeforeUnmount(() => {
  console.log('5. beforeUnmount：即将卸载')
  // 适合：取消定时器前做最后的状态保存
})

// 组件已卸载——最重要的清理钩子
onUnmounted(() => {
  console.log('6. unmounted：已卸载')
  // 必须在此清理：定时器、事件监听、WebSocket、动画
})

// KeepAlive 专用
onActivated(() => { console.log('keep-alive 激活') })
onDeactivated(() => { console.log('keep-alive 停用') })

// 错误边界
onErrorCaptured((err, instance, info) => {
  console.error('子组件错误:', err, info)
  return false  // 阻止错误继续向上冒泡
})
</script>
```

#### 与 React 生命周期的概念对照

| Vue 3 | React（函数组件 Hooks） | 说明 |
|-------|----------------------|------|
| `onMounted` | `useEffect(() => {}, [])` | DOM 挂载后执行 |
| `onUnmounted` | `useEffect(() => { return () => {} }, [])` | 清理副作用 |
| `onUpdated` | `useEffect(() => {})`（无依赖数组） | 每次更新后执行 |
| `onBeforeUpdate` | 「旧状态快照」在 `useEffect` cleanup 中 | Vue 提供更明确的钩子 |
| `onBeforeMount` | 无直接对应 | Vue 特有 |
| `onErrorCaptured` | `componentDidCatch`（class）或 ErrorBoundary | 错误边界 |
| `onActivated/onDeactivated` | 无直接对应 | KeepAlive 缓存机制 |

**关键区别**：React 的 `useEffect` 是异步执行的（commit 阶段之后），而 Vue 的生命周期是**同步**的，但 watch 回调默认在更新前批量处理。这使得 Vue 的执行时序更可预测。

### 六、nextTick

`nextTick` 等待下一次 DOM 更新后执行回调：

```vue
<script setup lang="ts">
import { ref, nextTick } from 'vue'

const count = ref(0)
const message = ref('')

async function incrementAndFocus() {
  count.value++  // 此时 DOM 还没更新

  // 等待 DOM 更新完成
  await nextTick()

  // 现在 DOM 已更新，可以安全操作
  const el = document.querySelector<HTMLElement>('.dynamic-element')
  el?.focus()
}

// 连续修改多个值，nextTick 只会执行一次（批处理）
function batchUpdate() {
  count.value++
  message.value = '新的消息'
  count.value++

  // nextTick 回调中拿到的已经是最终状态 count=2
  nextTick(() => {
    console.log('所有更新完成，count =', count.value)  // 2
  })
}
</script>
```

**使用场景**：
- 修改数据后需要获取更新后的 DOM 尺寸/位置
- 修改数据后需要聚焦某个新渲染的元素
- 在子组件挂载后操作子组件
- 拿到更新后的 `$refs`（Options API 场景）

### 七、实战：自动保存草稿的编辑器

```vue
<script setup lang="ts">
import { ref, watch, onMounted, onUnmounted, computed, nextTick } from 'vue'

// ==================== 编辑器状态 ====================
const title = ref('')
const content = ref('')
const lastSavedTime = ref<string | null>(null)
const saveStatus = ref<'idle' | 'saving' | 'saved' | 'error'>('idle')
const wordCount = computed(() => content.value.length)

// ==================== 防抖保存函数 ====================
let saveTimer: ReturnType<typeof setTimeout> | null = null
const DEBOUNCE_DELAY = 2000  // 2 秒无操作后自动保存

function debouncedSave() {
  // 清除上一次的定时器
  if (saveTimer) clearTimeout(saveTimer)

  saveStatus.value = 'saving'

  saveTimer = setTimeout(() => {
    performSave()
  }, DEBOUNCE_DELAY)
}

// ==================== 执行保存 ====================
function performSave() {
  const data = {
    title: title.value,
    content: content.value,
    timestamp: Date.now()
  }

  try {
    localStorage.setItem('draft_editor', JSON.stringify(data))
    lastSavedTime.value = new Date().toLocaleTimeString()
    saveStatus.value = 'saved'

    // 2 秒后恢复 idle 状态
    setTimeout(() => {
      if (saveStatus.value === 'saved') {
        saveStatus.value = 'idle'
      }
    }, 2000)
  } catch (err) {
    console.error('保存失败:', err)
    saveStatus.value = 'error'
  }
}

// ==================== 加载草稿 ====================
function loadDraft() {
  try {
    const raw = localStorage.getItem('draft_editor')
    if (raw) {
      const data = JSON.parse(raw)
      title.value = data.title || ''
      content.value = data.content || ''
      if (data.timestamp) {
        lastSavedTime.value = new Date(data.timestamp).toLocaleTimeString()
      }
    }
  } catch {
    localStorage.removeItem('draft_editor')
  }
}

// ==================== 快捷键保存 ====================
function handleKeydown(e: KeyboardEvent) {
  // Ctrl/Cmd + S 立即保存
  if ((e.ctrlKey || e.metaKey) && e.key === 's') {
    e.preventDefault()
    if (saveTimer) clearTimeout(saveTimer)
    performSave()
  }
}

// ==================== 自动保存监听 ====================
// 方案一：watch 监听（推荐，可以拿到新旧值对比）
watch(
  [title, content],
  ([newTitle, newContent], [oldTitle, oldContent]) => {
    // 只在内容实际变化时触发（避免初始加载时触发）
    if (newTitle !== oldTitle || newContent !== oldContent) {
      debouncedSave()
    }
  }
)

// 方案二：watchEffect 监听（更简洁，但初始化时会触发）
// 这里注释掉，因为初始加载 loadDraft 也会触发保存
// watchEffect(() => {
//  // 访问 title 和 content 就自动追踪
//  const t = title.value
//  const c = content.value
//  debouncedSave()
// })

// ==================== 生命周期管理 ====================
onMounted(() => {
  // 加载草稿
  loadDraft()

  // 注册快捷键
  window.addEventListener('keydown', handleKeydown)

  // 焦点定位到编辑器
  nextTick(() => {
    const editor = document.querySelector<HTMLTextAreaElement>('.editor-content')
    editor?.focus()
  })
})

onUnmounted(() => {
  // 清理定时器——防止内存泄漏
  if (saveTimer) clearTimeout(saveTimer)

  // 移除事件监听——防止组件卸载后仍触发
  window.removeEventListener('keydown', handleKeydown)

  // 最后执行一次保存——确保不丢失数据
  if (title.value || content.value) {
    performSave()
  }

  console.log('编辑器已卸载，资源已清理')
})

// ==================== 手动操作 ====================
function clearDraft() {
  if (confirm('确定要清除草稿吗？此操作不可恢复！')) {
    title.value = ''
    content.value = ''
    localStorage.removeItem('draft_editor')
    saveStatus.value = 'idle'
    lastSavedTime.value = null
  }
}
</script>

<template>
  <div class="editor-container">
    <div class="editor-header">
      <h2>草稿编辑器</h2>
      <div class="save-indicator">
        <span v-if="saveStatus === 'saving'" class="status saving">保存中...</span>
        <span v-else-if="saveStatus === 'saved'" class="status saved">✓ 已保存</span>
        <span v-else-if="saveStatus === 'error'" class="status error">✗ 保存失败</span>
        <span v-else class="status idle">已就绪</span>

        <span v-if="lastSavedTime" class="last-saved">
          上次保存：{{ lastSavedTime }}
        </span>
      </div>
    </div>

    <!-- 标题 -->
    <input
      v-model="title"
      type="text"
      placeholder="输入标题..."
      class="editor-title"
    />

    <!-- 正文 -->
    <textarea
      v-model="content"
      placeholder="开始写作...（内容会在停止输入 2 秒后自动保存，Ctrl+S 立即保存）"
      class="editor-content"
    ></textarea>

    <!-- 底部信息栏 -->
    <div class="editor-footer">
      <span>字数：{{ wordCount }}</span>
      <div class="footer-actions">
        <button @click="performSave" class="btn-save">立即保存 (Ctrl+S)</button>
        <button @click="clearDraft" class="btn-clear">清除草稿</button>
      </div>
    </div>
  </div>
</template>
```

**要点回顾**：
- `watch` 监听 title 和 content，配合防抖实现自动保存
- `onMounted` 加载草稿、注册键盘事件、nextTick 聚焦

- Ctrl+S 快捷键绕过防抖立即保存

## 常见问题

**Q1：computed 会不会导致无限循环？**

A：正常情况下不会。Vue 内部通过 `_dirty` 标记防止循环计算。但如果在 computed 的 getter 中修改自身依赖的数据，Vue 会警告。可写 computed 的 setter 可以安全地修改依赖数据，因为 setter 和 getter 是分开执行的。

**Q2：watch 和 computed 可以互相替代吗？**

A：不能。`computed` 用于"根据已有数据计算派生值"，它是同步的、有缓存的、作为模板中直接绑定的值。`watch` 用于"数据变化时执行副作用（如发请求、操作 DOM、写 localStorage）"，它是异步批量的、无返回值的。用 computed 做副作用（如发请求）是反模式。

**Q3：为什么不要在 onUpdated 中修改响应式数据？**

A：`onUpdated` 在每次 DOM 更新后调用。如果你在其中修改了响应式数据，会触发新一轮的 DOM 更新 → 再次触发 `onUpdated` → 无限循环。如果确实需要在更新后修改数据，加条件守卫，确保只在必要时才修改。

**Q4：nextTick 和 setTimeout(fn, 0) 有什么区别？**

A：`nextTick` 在 Vue 的 DOM 更新周期后、浏览器重绘前执行，与 Vue 的异步更新队列协作。`setTimeout(fn, 0)` 是宏任务，在浏览器事件循环的下一次迭代执行，无法保证 DOM 已更新。操作 Vue 控制的 DOM 时，始终用 `nextTick` 而不是 `setTimeout`。

**Q5：watchEffect 的初始化执行能不能跳过？**

A：原生 API 不支持跳过。如果你的逻辑中有需要在初始化时跳过的部分，可以用一个 ref 标记：

```typescript
const isInitial = ref(true)
watchEffect(() => {
  const data = someRef.value
  if (isInitial.value) {
    isInitial.value = false
    return  // 跳过首次
  }
  // 正常逻辑
})
```

**Q6：flush: 'sync' 什么情况下必须用？**

A：极少数场景。例如在同一个同步代码块中，你需要在每次赋值后立即执行副作用，而不能等待批处理。典型场景是：你需要记录每一次赋值的历史快照，批处理后中间的赋值会被合并。大多数情况下 `pre` 或 `post` 就够用了。

**Q7：Vue 的生命周期和 React useEffect 最大的心智差异？**

A：最大差异在于执行时序。Vue 的生命周期钩子是**同步**的（钩子函数在组件更新过程中同步调用），而 React 的 `useEffect` 是**异步**的（在浏览器绘制后执行）。这意味着在 Vue 中你能在钩子内拿到"刚刚发生的变化"的完整上下文，而在 React 中需要更小心地处理竞态条件。

**Q8：多个 watch 监听同一个数据，执行顺序是怎样的？**

A：按 `watch` 创建的先后顺序执行。这与 `flush` 配置无关——同 flush 的 watcher 按创建顺序，跨 flush 的 watcher 按 sync → pre → post 的顺序执行。因此如果两个 watch 有依赖关系，应通过 computed 中转，而不是依赖执行顺序。

## 实操作业

### 基础：实时字数统计编辑器

- 用 `computed` 统计字符数、行数、段落数
- 用 `watch` 监听内容变化，超过 1000 字时给出提示
- 添加保存状态提示（保存中 / 已保存）

### 进阶：带版本历史的草稿编辑器

在实战编辑器基础上扩展：
- 用 `watch` 配合深度对比，检测内容是否真实变化
- 保存历史版本（最多保留 10 个版本）
- 用 `nextTick`  + scrollIntoView 在恢复版本后滚动到顶部
- 用 `computed` 生成版本摘要（前 50 字 + 时间）
- 插件系统：用 `onMounted` / `onUnmounted` 管理自定义插件生命周期

### 挑战：防抖/节流 Composable

封装一个通用的 `useDebouncedRef` 和 `useThrottledFn`：
- `useDebouncedRef(sourceRef, delay)`：返回一个 debounced 的 ref，读取实时值，写入延迟生效
- `useThrottledFn(fn, delay)`：返回一个 throttled 的函数
- 内部使用 `watch` + 定时器实现
- 在 `onUnmounted` 中自动清理定时器
- 用 `watchEffect` 打印调试日志（开发环境）

## 本节小结

- **computed 双模式**：getter 计算派生值，setter 反向拆解，缓存机制避免重复计算
- **依赖追踪**：运行时自动收集，条件分支中的依赖在每次重新执行时动态调整，不会漏也不会多
- **watch flush 时机**：`pre`（默认，更新前）、`post`（DOM 更新后）、`sync`（同步）
- **watchEffect**：自动收集依赖 + 立即执行，配合 `onCleanup` 管理副作用（取消请求、清定时器）
- **生命周期**：`onMounted` 做初始化，`onUnmounted` 做清理（定时器、事件、连接），二者对称配对
- **nextTick**：等待 DOM 更新后执行，Vue 特有的批处理机制

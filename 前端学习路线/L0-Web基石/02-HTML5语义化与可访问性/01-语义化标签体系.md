## 内容讲解

### 一、什么是语义化？打个比方

想象你去图书馆找一本《JavaScript 高级程序设计》。你当然希望书架上贴着"编程 → 前端 → JavaScript"的分类标签，而不是满墙都贴着"东西"两个字。

HTML 语义化就是这个道理：**用正确的标签包裹正确的内容，让每个部分"自己会说话"**。

```html
<!-- ❌ 无语义：全是 div，机器和人都不容易理解结构 -->
<div class="header">网站头部</div>
<div class="nav">导航菜单</div>
<div class="main">主要内容</div>
<div class="footer">页脚信息</div>

<!-- ✅ 语义化：标签本身自报家门 -->
<header>网站头部</header>
<nav>导航菜单</nav>
<main>主要内容</main>
<footer>页脚信息</footer>
```

### 二、为什么语义化重要？

#### 1. SEO（搜索引擎优化）

搜索引擎的爬虫是一个"只看代码的盲人用户"。它通过标签来判断内容的层级和重要性：

- `<h1>` 告诉它"这是本页最重要的标题"
- `<article>` 告诉它"这是独立的内容块，值得索引"
- `<nav>` 告诉它"这是导航链接，不用算作正文关键词密度"

一个用 `<div>` 堆出来的页面，在爬虫眼里就是一堆没有优先级的"盒子"，重要内容可能被埋没。

#### 2. 可访问性（Accessibility，简称 a11y）

屏幕阅读器（视障用户依赖的辅助工具）会根据语义标签提供不同的导航模式：

- 用户按 H 键可以在标题之间跳转
- 用户可以列出页面上所有 `<nav>` 区域，快速定位导航
- `<main>` 标签支持"跳到主内容"的快捷操作

如果全用 `<div>`，屏幕阅读器就只能逐字朗读，用户无法高效浏览。

#### 3. 可维护性

```html
<!-- 半年后你回来改代码，哪种更容易看懂？ -->

<!-- ❌ 这是什么？ -->
<div class="box red mt-20">...</div>

<!-- ✅ 一目了然 -->
<aside class="sidebar-ad">...</aside>
```

语义标签减少了"类名猜谜"的成本，新成员加入项目时更容易上手。

### 三、常用语义标签详解

#### `<header>` — 头部区域

不限于"页面顶部"。每个 `<article>` 或 `<section>` 也可以有自己的 `<header>`。

```html
<!-- 页面级 header -->
<header>
  <h1>我的技术博客</h1>
  <p>记录前端学习之路</p>
</header>

<!-- 文章级 header：一篇文章也可以有自己的"头部" -->
<article>
  <header>
    <h2>深入理解 Flexbox</h2>
    <time datetime="2026-10-12">2026 年 10 月 12 日</time>
  </header>
  <p>正文内容……</p>
</article>
```

#### `<nav>` — 主导航

只用于**主要导航块**，不要给页脚中随便几个链接也套 `<nav>`。

```html
<nav aria-label="主导航">
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/blog">博客</a></li>
    <li><a href="/about">关于</a></li>
  </ul>
</nav>
```

> 如果有多个 `<nav>`（比如主导航 + 面包屑导航），用 `aria-label` 区分它们。

#### `<main>` — 主体内容

- **一个页面只能有一个** `<main>`
- 包含页面的核心内容，不包含侧边栏、页脚、导航等重复元素
- 是实现"跳过导航"（skip-link）的关键

```html
<body>
  <header>...</header>
  <nav>...</nav>

  <main>
    <h1>文章标题</h1>
    <p>文章正文……</p>
  </main>

  <aside>...</aside>
  <footer>...</footer>
</body>
```

#### `<article>` vs `<section>` — 最容易混淆的一对

**判断标准：这个内容能不能独立"拿出去发表"？**

- 能 → `<article>`（博客文章、新闻、评论、论坛帖子）
- 不能 / 需要上下文才能理解 → `<section>`（页面中的一章、一个功能区）

```html
<!-- 博客列表页 -->
<main>
  <!-- 每篇博客文章都是独立的 → article -->
  <article>
    <h2>文章一：CSS Grid 入门</h2>
    <p>摘要内容……</p>
  </article>

  <article>
    <h2>文章二：JavaScript 异步编程</h2>
    <p>摘要内容……</p>
  </article>
</main>

<!-- 文章详情页内部 -->
<article>
  <h1>CSS Grid 入门</h1>

  <!-- 文章内的章节，不能独立发表 → section -->
  <section>
    <h2>什么是 CSS Grid</h2>
    <p>……</p>
  </section>

  <section>
    <h2>基本用法</h2>
    <p>……</p>
  </section>
</article>
```

**一个口诀**：`<article>` 可以包含多个 `<section>`，`<section>` 也可以包含多个 `<article>`，关键看"能不能独立存在"。

#### `<aside>` — 侧边栏 / 补充内容

与主体内容**间接相关**的内容：侧边栏广告、相关文章推荐、术语解释。

```html
<main>
  <article>
    <h2>React Hooks 详解</h2>
    <p>useState 是 React 中最基础的 Hook……</p>

    <!-- 文章内的补充说明 -->
    <aside>
      <h3>💡 提示</h3>
      <p>如果你还习惯用 Class 组件，建议先熟悉函数组件的基本写法。</p>
    </aside>
  </article>
</main>

<!-- 页面级的侧边栏 -->
<aside>
  <h3>推荐文章</h3>
  <ul>
    <li><a href="#">Vue 3 组合式 API</a></li>
    <li><a href="#">TypeScript 类型体操</a></li>
  </ul>
</aside>
```

#### `<footer>` — 页脚

同 `<header>`，不仅用于页面底部，`<article>` 和 `<section>` 也可以有。

```html
<article>
  <header><h2>文章标题</h2></header>
  <p>正文……</p>
  <footer>
    <p>作者：张三 | 发布于 <time datetime="2026-10-12">10月12日</time></p>
  </footer>
</article>

<!-- 页面全局页脚 -->
<footer>
  <p>&copy; 2026 我的博客. All rights reserved.</p>
  <address>联系邮箱：hello@example.com</address>
</footer>
```

#### `<time>` — 时间日期

```html
<!-- 机器可读的 datetime 属性是关键 -->
<time datetime="2026-10-12T15:30:00+08:00">
  2026 年 10 月 12 日下午 3:30
</time>

<!-- 只表示日期 -->
<time datetime="2026-10-12">2026 年 10 月 12 日</time>
```

搜索引擎会提取 `datetime` 属性，可能在搜索结果中直接展示发布日期。

#### `<address>` — 联系信息

只能用于**最近的 `<article>` 或 `<body>` 的联系信息**，不是为了标记任意地址。

```html
<footer>
  <address>
    有问题？联系 <a href="mailto:admin@example.com">管理员</a><br>
    地址：北京市海淀区中关村大街 1 号
  </address>
</footer>
```

#### `<figure>` + `<figcaption>` — 图文组合

```html
<figure>
  <img src="flexbox-diagram.png" alt="Flexbox 主轴与交叉轴示意图">
  <figcaption>图 1：Flex 容器的主轴（main axis）和交叉轴（cross axis）</figcaption>
</figure>

<!-- 也适用于代码块 -->
<figure>
  <pre><code>console.log("Hello World");</code></pre>
  <figcaption>示例 1：最简单的 JavaScript 输出语句</figcaption>
</figure>
```

#### `<details>` + `<summary>` — 可折叠内容

无需 JavaScript，纯 HTML 即可实现折叠面板：

```html
<details>
  <summary>点击展开：什么是 Event Loop？</summary>
  <p>Event Loop（事件循环）是 JavaScript 处理异步任务的机制。
     它不断检查调用栈和任务队列，确保代码在合适的时机执行。</p>
</details>

<!-- 默认展开 -->
<details open>
  <summary>常见问题</summary>
  <p>这里是一些说明内容……</p>
</details>
```

### 四、`<div>` vs 语义标签 — 决策指南

| 场景 | 用什么 |
|------|--------|
| 页面头部（logo + 标题） | `<header>` |
| 导航菜单链接组 | `<nav>` |
| 一篇博客文章 | `<article>` |
| 文章内的一个章节 | `<section>` |
| 侧边栏 / 补充说明 | `<aside>` |
| 页面底部版权信息 | `<footer>` |
| 纯样式的包裹容器（没有语义含义） | `<div>` |
| 卡片布局的外层容器（仅用于 CSS） | `<div>` |

**核心原则**：`<div>` 是"语义兜底"——当你确定没有更合适的语义标签时，才用 `<div>`。

### 五、标准 HTML5 文档结构模板

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="一个符合 HTML5 语义化标准的页面模板">
  <title>HTML5 语义化页面模板</title>
</head>
<body>
  <!-- 跳过导航链接（可访问性必备） -->
  <a href="#main-content" class="skip-link">跳到主内容</a>

  <!-- 页面头部 -->
  <header>
    <h1>我的技术博客</h1>
    <p>专注前端技术与工程化实践</p>
  </header>

  <!-- 主导航 -->
  <nav aria-label="主导航">
    <ul>
      <li><a href="/">首页</a></li>
      <li><a href="/blog">文章</a></li>
      <li><a href="/about">关于</a></li>
    </ul>
  </nav>

  <!-- 主内容区 -->
  <main id="main-content">
    <article>
      <header>
        <h2>文章标题</h2>
        <p>
          发布于 <time datetime="2026-10-12">2026年10月12日</time>
        </p>
      </header>

      <section>
        <h3>第一节：背景</h3>
        <p>这是第一节的内容……</p>
      </section>

      <section>
        <h3>第二节：实践</h3>
        <p>这是第二节的内容……</p>
      </section>

      <footer>
        <p>标签：HTML, 语义化, 前端基础</p>
      </footer>
    </article>

    <!-- 评论区：每条评论是独立的 → article -->
    <section>
      <h3>评论（2）</h3>
      <article>
        <p><strong>张三：</strong>写得很清楚，感谢分享！</p>
      </article>
      <article>
        <p><strong>李四：</strong>期待下一篇。</p>
      </article>
    </section>
  </main>

  <!-- 侧边栏 -->
  <aside>
    <h3>关于作者</h3>
    <p>一名热爱前端的开发者。</p>

    <!-- 嵌套 section 表示侧边栏中的不同模块 -->
    <section>
      <h3>标签云</h3>
      <ul>
        <li><a href="/tag/html">HTML</a></li>
        <li><a href="/tag/css">CSS</a></li>
      </ul>
    </section>
  </aside>

  <!-- 页面页脚 -->
  <footer>
    <address>
      联系：<a href="mailto:hello@example.com">hello@example.com</a>
    </address>
    <p>&copy; 2026 我的技术博客</p>
  </footer>
</body>
</html>
```

### 六、搜索引擎如何理解语义化标签

搜索引擎（Google、百度等）的爬虫会做以下几件事：

1. **标题层级分析**：从 `<h1>` 到 `<h6>` 构建内容大纲，`<h1>` 权重最高。
2. **独立内容提取**：`<article>` 内的内容可能作为独立片段出现在搜索结果中。
3. **导航识别**：`<nav>` 中的链接不计入正文关键词密度计算。
4. **结构化数据补充**：结合 [Schema.org](https://schema.org/) 的 JSON-LD，可以进一步告诉搜索引擎你的内容是什么类型（文章 / 产品 / 事件），但这属于进阶内容。

## 常见问题

### Q1：`<article>` 和 `<section>` 到底怎么区分？

**`<article>` = 可以独立发表**。比如一篇博客文章，你把它从页面里摘出来单独看，它仍然是一个完整的、自解释的内容。**`<section>` = 不能独立存在**。比如文章里的"第一章""第二章"，脱离了文章本身就没有意义。

### Q2：一个页面可以有多个 `<h1>` 吗？

语法上可以出现多个 `<h1>`，但浏览器和屏幕阅读器并没有实现早期 HTML5 设想的“每个 section 自动生成独立大纲”算法。生产页面通常使用一个描述页面主题的 `<h1>`，随后按内容嵌套关系使用 `<h2>`、`<h3>`，不要依赖 section 自动修正标题级别。

### Q3：`<b>` / `<i>` 和 `<strong>` / `<em>` 有什么区别？

- `<strong>` = **语义上的重要**（屏幕阅读器会加重语气）
- `<b>` = 纯视觉加粗，无语义
- `<em>` = **语义上的强调**（屏幕阅读器会改变语调）
- `<i>` = 纯视觉斜体，无语义

**优先用 `<strong>` 和 `<em>`**，只在确实不需要语义时用 `<b>` 和 `<i>`。

### Q4：`<header>` 和 `<head>` 是一个东西吗？

完全不同！`<head>` 是 HTML 文档的元数据区（放 `<title>`、`<meta>`、`<link>` 等，用户看不见）。`<header>` 是页面/区块的可见头部内容（logo、标题、导航）。

### Q5：`<div>` 是不是应该尽量少用？

不是。`<div>` 是**合法且必要的**——当你需要一个纯容器来做布局或样式分组，且没有语义标签能准确描述它时，`<div>` 是正确选择。该用 `<div>` 时不用，强套一个不合适的语义标签，反而是"语义污染"。

### Q6：不写语义标签会怎样？

页面照样能显示，不会报错。但 SEO 排名会受影响，屏幕阅读器用户会很难浏览，团队成员理解代码结构会更费时。

### Q7：`<details>` 兼容性如何？

所有现代浏览器都支持，包括 Chrome、Firefox、Safari、Edge。IE 不支持，但 IE 已于 2022 年停止维护。

### 练习二（中级）：搭建一个完整的博客首页

用语义标签搭建一个包含以下元素的博客首页 HTML 结构：

- 页头（博客名称 + 简介）
- 导航栏（首页 / 文章归档 / 关于我）
- 主内容区（3 篇博客文章摘要，每篇包含标题、日期、摘要、标签）
- 侧边栏（作者简介 + 文章分类列表）
- 页脚（版权 + 联系方式）
- 一个可折叠的"关于本站"区域（用 `<details>` + `<summary>`）

**要求**：不使用 `<div>`（除非作为纯布局容器），每篇博客文章用 `<article>`。

3. 它们的导航是否用了 `<nav>`？
4. 找出至少一处"该用语义标签却用了 `<div>`"的例子。

## 本节小结

- **语义化 = 用正确的标签表达正确的含义**，不仅为了 SEO，更为了可访问性和代码可维护性
- 常用标签按用途记忆：结构（`<header>`、`<main>`、`<footer>`）、内容（`<article>`、`<section>`、`<aside>`）、导航（`<nav>`）、辅助（`<time>`、`<address>`、`<figure>`）
- `<article>` 和 `<section>` 的判断标准：**能不能独立发表**
- `<div>` 不是敌人——当你确实没有语义标签可用时，用 `<div>` 是正确的
- 语义元素与显式标题层级共同表达文档结构；不要依赖未实现的自动大纲算法

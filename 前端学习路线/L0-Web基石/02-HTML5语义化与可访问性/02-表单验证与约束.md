## 内容讲解

### 一、`<form>` 表单的基本结构

表单是用户和网站之间最重要的交互桥梁——登录、搜索、提交反馈、在线购物，都离不开表单。

```html
<!-- 最简表单 -->
<form action="/api/submit" method="POST">
  <label for="username">用户名：</label>
  <input type="text" id="username" name="username">

  <label for="password">密码：</label>
  <input type="password" id="password" name="password">

  <button type="submit">登录</button>
</form>
```

关键属性速查：

| 属性 | 作用 | 默认值 |
|------|------|--------|
| `action` | 提交到的后端地址 | 当前页面 URL |
| `method` | HTTP 请求方法 | `GET` |
| `enctype` | 编码类型（上传文件必须设为 `multipart/form-data`） | `application/x-www-form-urlencoded` |
| `novalidate` | 禁用浏览器内置验证 | 无 |
| `autocomplete` | 是否允许浏览器自动填充 | `on` |

> **`<label>` 的 `for` 属性必须和 `<input>` 的 `id` 一致**，这样点击标签文字就能聚焦输入框，屏幕阅读器也能正确关联。

### 二、HTML5 内置表单验证属性

在 HTML5 之前，表单验证全靠 JavaScript。现在，很多场景直接用 HTML 属性就能搞定。

#### `required` — 必填

```html
<input type="text" name="name" required>
<!-- 提交时如果为空，浏览器会阻止提交并提示"请填写此字段" -->
```

#### `pattern` — 正则表达式验证

```html
<!-- 要求输入 11 位中国大陆手机号 -->
<input type="text" name="phone"
       pattern="^1[3-9]\d{9}$"
       required
       placeholder="请输入手机号">

<!-- pattern 中的正则不需要 / / 包裹，浏览器自动加 ^ 和 $ -->
```

#### `min` / `max` — 数值范围

```html
<!-- 年龄：1-120 岁 -->
<input type="number" name="age" min="1" max="120">

<!-- 日期范围：只能选 2020 年到今天 -->
<input type="date" name="event_date" min="2020-01-01" max="2026-12-31">
```

#### `minlength` / `maxlength` — 字符长度

```html
<!-- 密码最短 6 位，最长 20 位 -->
<input type="password" name="password"
       minlength="6" maxlength="20" required>

<!-- 注意：maxlength 会阻止用户输入更多字符；
     minlength 只在提交时验证 -->
```

#### `step` — 数值步进

```html
<!-- 只能输入 0.5 的倍数 -->
<input type="number" name="rating" min="0" max="5" step="0.5">
```

### 三、各种 `<input>` type 详解

HTML5 提供了大量专用 type，除了做验证，**最重要的是在移动端触发不同的键盘类型**。

```html
<!-- ===== 文本类 ===== -->

<!-- email：移动端弹出含 @ 的键盘，自动验证格式 -->
<input type="email" name="email" placeholder="you@example.com">

<!-- url：移动端弹出含 .com 键的键盘，验证 URL 格式 -->
<input type="url" name="website" placeholder="https://example.com">

<!-- tel：移动端弹出数字拨号键盘，不验证格式（各国不同） -->
<input type="tel" name="phone" placeholder="请输入手机号">

<!-- search：外观像搜索框，部分浏览器会在输入时显示清除按钮 -->
<input type="search" name="query" placeholder="搜索……">

<!-- ===== 数值类 ===== -->

<!-- number：右侧带加减箭头，移动端弹出数字键盘 -->
<input type="number" name="quantity" min="1" max="99" value="1">

<!-- range：滑块选择器 -->
<input type="range" name="volume" min="0" max="100" value="50"
       oninput="this.nextElementSibling.textContent = this.value">
<span>50</span>

<!-- ===== 日期时间类 ===== -->

<input type="date" name="birthday">       <!-- 日期选择器：2026-10-12 -->
<input type="time" name="meeting_time">   <!-- 时间选择器：14:30 -->
<input type="datetime-local" name="start"> <!-- 日期+时间（无时区） -->
<input type="month" name="exp_month">     <!-- 月选择器：2026-10 -->
<input type="week" name="week_num">       <!-- 周选择器：2026-W41 -->

<!-- ===== 其他实用 type ===== -->

<input type="color" name="theme_color" value="#3b82f6"> <!-- 颜色选择器 -->

<!-- file：文件上传 -->
<input type="file" name="avatar"
       accept="image/png, image/jpeg"  <!-- 限制文件类型 -->
       multiple>                        <!-- 允许多选 -->

<!-- hidden：用户看不见，但会随表单提交 -->
<input type="hidden" name="csrf_token" value="abc123xyz">
```

**type 速查对照表**：

| type | 移动端键盘 | 自动验证 | 特殊行为 |
|------|-----------|---------|---------|
| `email` | 含 @ 的英文键盘 | 需含 @ | — |
| `url` | 含 .com 的英文键盘 | 需含协议 | — |
| `tel` | 数字拨号键盘 | 无 | — |
| `number` | 数字键盘 | 范围 + 步进 | 有增减箭头 |
| `date` | 原生日期选择器 | 日期合法性 | — |
| `color` | — | — | 弹出取色器 |
| `range` | — | 范围 | 滑块交互 |
| `search` | 常规键盘 | 无 | 可能有清除按钮 |

### 四、CSS 伪类：`:valid` 和 `:invalid`

浏览器会根据约束条件自动给表单元素添加 `:valid` 或 `:invalid` 状态，你可以用 CSS 给出实时反馈：

```html
<style>
  /* 基础样式 */
  input {
    padding: 8px 12px;
    border: 2px solid #ccc;
    border-radius: 4px;
    outline: none;
    transition: border-color 0.3s;
  }

  /* 输入有效时：绿色边框 */
  input:valid {
    border-color: #22c55e;
  }

  /* 输入无效时：红色边框 */
  input:invalid {
    border-color: #ef4444;
  }

  /* 获得焦点且无效时：红色阴影（比纯边框更友好） */
  input:focus:invalid {
    box-shadow: 0 0 0 3px rgba(239, 68, 68, 0.3);
  }

  /* 必填字段背景色提示 */
  input:required {
    background-color: #fefce8;
  }

  /* 可选字段 */
  input:optional {
    background-color: #fff;
  }

  /* 禁用状态 */
  input:disabled {
    background-color: #f3f4f6;
    cursor: not-allowed;
  }

  /* 只读状态 */
  input:read-only {
    background-color: #f9fafb;
  }

  /* 占位符文字样式 */
  input::placeholder {
    color: #9ca3af;
    font-style: italic;
  }
</style>

<form>
  <label for="user-email">邮箱：</label>
  <input type="email" id="user-email" name="email" required
         placeholder="you@example.com">
  <button type="submit">提交</button>
</form>
```

> **注意**：`:invalid` 在页面加载时就会触发（因为空值不满足 `required`），直接使用会让用户一开始就看到一堆红色边框。更好的做法是等用户交互后再显示验证状态——见下文"实战优化"。

### 五、Constraint Validation API

HTML 属性验证虽然方便，但浏览器默认错误提示的样式和文案你无法控制。Constraint Validation API 让你用 JavaScript 接管验证逻辑。

```html
<form id="signup-form" novalidate>
  <!-- novalidate 禁用浏览器默认验证，由 JS 全权接管 -->

  <div class="form-group">
    <label for="signup-email">邮箱：</label>
    <input type="email" id="signup-email" name="email" required>
    <span class="error-message" id="email-error"></span>
  </div>

  <div class="form-group">
    <label for="signup-password">密码：</label>
    <input type="password" id="signup-password" name="password"
           required minlength="6" maxlength="20">
    <span class="error-message" id="password-error"></span>
  </div>

  <button type="submit">注册</button>
</form>

<script>
  const form = document.getElementById('signup-form');
  const emailInput = document.getElementById('signup-email');
  const passwordInput = document.getElementById('signup-password');

  form.addEventListener('submit', function (event) {
    // 先检查整体有效性
    if (!form.checkValidity()) {
      // 阻止提交
      event.preventDefault();
      // 显示所有字段的错误信息
      validateEmail();
      validatePassword();
    }
  });

  // 实时验证：输入时即时反馈
  emailInput.addEventListener('input', validateEmail);
  passwordInput.addEventListener('input', validatePassword);

  function validateEmail() {
    const input = emailInput;
    const errorSpan = document.getElementById('email-error');

    // ValidityState 对象包含了所有验证状态
    const validity = input.validity;

    if (validity.valid) {
      // 通过验证：清除错误
      errorSpan.textContent = '';
      input.classList.remove('invalid');
      input.classList.add('valid');
    } else {
      // 根据具体原因给出不同提示
      if (validity.valueMissing) {
        errorSpan.textContent = '请输入邮箱地址';
      } else if (validity.typeMismatch) {
        errorSpan.textContent = '邮箱格式不正确，请输入如 you@example.com';
      }
      input.classList.add('invalid');
      input.classList.remove('valid');
    }
  }

  function validatePassword() {
    const input = passwordInput;
    const errorSpan = document.getElementById('password-error');
    const validity = input.validity;

    if (validity.valid) {
      errorSpan.textContent = '';
      input.classList.remove('invalid');
    } else {
      if (validity.valueMissing) {
        errorSpan.textContent = '请输入密码';
      } else if (validity.tooShort) {
        errorSpan.textContent = `密码至少 ${input.minLength} 位，当前 ${input.value.length} 位`;
      } else if (validity.tooLong) {
        errorSpan.textContent = `密码最多 ${input.maxLength} 位`;
      }
      input.classList.add('invalid');
    }
  }
</script>

<style>
  .error-message {
    color: #ef4444;
    font-size: 0.875rem;
    display: block;
    margin-top: 4px;
    min-height: 20px; /* 防止无错误时布局抖动 */
  }
  input.valid { border-color: #22c55e; }
  input.invalid { border-color: #ef4444; }
</style>
```

**ValidityState 的完整属性**：

| 属性 | 何时为 true |
|------|------------|
| `valid` | 全部通过 |
| `valueMissing` | required 但为空 |
| `typeMismatch` | type=email/url 但格式不对 |
| `patternMismatch` | pattern 不匹配 |
| `tooShort` | 低于 minlength |
| `tooLong` | 超过 maxlength |
| `rangeUnderflow` | 低于 min |
| `rangeOverflow` | 高于 max |
| `stepMismatch` | 不满足 step |
| `badInput` | 浏览器无法解析输入 |
| `customError` | 调用了 setCustomValidity() |

#### `setCustomValidity()` — 自定义验证逻辑

```html
<form id="booking-form">
  <label for="checkin">入住日期：</label>
  <input type="date" id="checkin" name="checkin" required>

  <label for="checkout">离店日期：</label>
  <input type="date" id="checkout" name="checkout" required>

  <button type="submit">预订</button>
</form>

<script>
  const checkin = document.getElementById('checkin');
  const checkout = document.getElementById('checkout');

  function validateDates() {
    if (checkin.value && checkout.value) {
      if (checkout.value <= checkin.value) {
        // 设置自定义错误消息
        checkout.setCustomValidity('离店日期必须晚于入住日期');
      } else {
        // 清除自定义错误（必须手动清除！）
        checkout.setCustomValidity('');
      }
    }
  }

  checkin.addEventListener('change', validateDates);
  checkout.addEventListener('change', validateDates);
</script>
```

> **关键**：调用 `setCustomValidity('')` 传入空字符串来清除错误，否则即使条件满足了，输入也会一直处于无效状态。

### 六、实战优化：只在交互后显示验证状态

前面提到页面加载时就出现红色边框的问题，解决方案是加一个"用户已经碰过这个字段"的标记：

```html
<style>
  /* 默认不显示验证样式 */
  input { border: 2px solid #ccc; }

  /* 只在有 "touched" 类时才显示验证状态 */
  input.touched:valid { border-color: #22c55e; }
  input.touched:invalid { border-color: #ef4444; }
</style>

<form id="smart-form" novalidate>
  <label for="nickname">昵称（2-10位）：</label>
  <input type="text" id="nickname" name="nickname"
         required minlength="2" maxlength="10">
  <span class="error-message"></span>
  <button type="submit">提交</button>
</form>

<script>
  const inputs = document.querySelectorAll('#smart-form input');

  inputs.forEach(input => {
    // 用户离开字段时标记为"已触碰"
    input.addEventListener('blur', () => {
      input.classList.add('touched');
    });

    // 用户输入时做实时验证，但只在已触碰后才显示样式
    input.addEventListener('input', () => {
      if (input.classList.contains('touched')) {
        showFieldError(input);
      }
    });
  });

  function showFieldError(input) {
    const errorEl = input.nextElementSibling;
    if (input.validity.valid) {
      errorEl.textContent = '';
    } else if (input.validity.valueMissing) {
      errorEl.textContent = '此字段为必填';
    } else if (input.validity.tooShort) {
      errorEl.textContent = `至少需要 ${input.minLength} 个字符`;
    }
  }
</script>
```

## 常见问题

### Q1：`<input type="number">` 为什么还能输入 `e`？

因为 `e` 是科学计数法（如 `1e5 = 100000`），浏览器认为它是合法的数字字符。如果不想允许，可以在 `keydown` 事件中阻止 `e`、`E`、`+`、`-` 键。

### Q2：`required` 和 `aria-required` 有什么区别？

`required` 是 HTML 原生属性，浏览器会强制验证。`aria-required="true"` 只是告诉屏幕阅读器"这个字段必填"，不触发任何浏览器验证。**两者应该同时使用**：`required` 负责验证，`aria-required` 负责可访问性信息。

### Q3：为什么我的 `pattern` 正则不生效？

两个常见原因：1）`<input>` 没有设 `required` — 空值是跳过 `pattern` 验证的；2）正则写了 `/ /` 包裹 — HTML 的 `pattern` 不需要斜杠包裹，浏览器会自动加 `^(?:` 和 `)$`。

### Q4：如何在提交时阻止页面刷新？

在 `submit` 事件中调用 `event.preventDefault()`，然后用 `fetch` 或 `XMLHttpRequest` 手动发送数据（即 AJAX 提交）。

### Q5：`:valid` / `:invalid` 在页面加载时就生效怎么办？

不要在全局使用 `input:invalid`，而是加一个 `.touched` 类，只在用户交互后才添加该类，然后在 CSS 中用 `input.touched:invalid` 控制样式。

### Q6：移动端 `<input type="date">` 的 placeholder 怎么不显示？

`type="date"` 在大多数浏览器中不显示 placeholder，因为原生日期选择器有自己的占位模板。如果你需要提示文字，可以在外面加一个 `<label>` 或用一个额外的元素。

### Q7：如何自定义 `<select>` 下拉框的样式？

原生 `<select>` 的样式定制能力极差，不同浏览器渲染差异巨大。业界常规做法是用 `<div>` + JavaScript 模拟一个"自定义下拉框"，或者使用成熟的 UI 库组件。

## 实操作业

### 练习一（初级）：搭建一个注册表单

创建一个用户注册表单，包含以下字段并启用 HTML5 验证：

- 用户名：必填，3-15 位字母数字
- 邮箱：必填，邮箱格式
- 密码：必填，6-20 位
- 确认密码：必填，需与密码一致（用 `setCustomValidity`）
- 年龄：选填，1-120 之间
- 个人主页：选填，URL 格式

### 练习二（中级）：实时验证反馈

在练习一的基础上，添加以下增强：

1. 使用 Constraint Validation API 接管所有验证（表单加 `novalidate`）
2. 每个字段下面显示具体的中文错误提示（不要只用"请填写此字段"）
3. 实现"只在 blur 后才显示验证状态"的逻辑
4. 通过时显示绿色边框，不通过时红色边框，未触碰时默认灰色

### 练习三（高级）：密码强度指示器

创建一个密码输入框，下方实时显示密码强度（弱/中/强），规则如下：

- **弱**：少于 6 位，或纯数字/纯字母
- **中**：6 位以上，包含字母+数字
- **强**：8 位以上，包含大小写字母+数字+特殊字符

强度指示器用不同颜色的进度条展示，并在密码"弱"时阻止表单提交。

### 作业参考与验收

- **基础**：required、pattern、minlength/maxlength、type=email/url、min/max 组合约束；两次密码变化都重新 setCustomValidity，匹配时清空消息。空年龄应允许，0 和 121 拒绝。
- **进阶**：字段 touched 后才展示错误；novalidate 关闭原生弹框后仍在提交时 checkValidity 并聚焦首错。密码从不匹配改为匹配后，旧自定义错误必须消失。
- **挑战**：强度函数返回等级与中文解释，分别测 123456、abc123、Abc123!x；强度条不只靠颜色。规则是练习策略，不作为生产密码安全评估的完整替代。

## 本节小结

- HTML5 内置验证（`required`、`pattern`、`min`/`max`、`minlength`/`maxlength`、`type`）能覆盖 80% 的常见场景
- 不同的 `<input>` type 不仅验证格式，更重要的是在移动端触发合适的键盘
- `:valid` / `:invalid` 伪类提供纯 CSS 的验证状态反馈，但建议加 `.touched` 控制时机
- Constraint Validation API（`checkValidity()` + `ValidityState`）让你用 JS 接管验证，实现自定义文案和行为
- `setCustomValidity()` 用于处理内置属性无法覆盖的业务逻辑（如"确认密码一致"）

## 内容讲解

### 一、先建立文件系统模型

前端项目首先是磁盘上的一组文件。浏览器、Node.js、编辑器和 Git 都通过路径找到它们。

```text
atlas/
├── package.json
├── public/
│   └── index.html
├── src/
│   ├── app.js
│   └── styles.css
└── tests/
    └── articles.test.js
```

需要区分四个概念：

| 概念 | 示例 | 含义 |
|---|---|---|
| 文件名 | `app.js` | 一个目录中的条目名称 |
| 绝对路径 | `/Users/alice/atlas/src/app.js` | 从文件系统根开始定位 |
| 相对路径 | `./src/app.js` | 从当前工作目录开始定位 |
| 当前工作目录 | `pwd` 输出 | 当前命令默认操作的位置 |

`./` 表示当前目录，`../` 表示父目录。相对路径是否正确取决于命令执行时的工作目录，而不是代码文件“看起来在哪里”。

```bash
pwd
ls
cd 前端学习路线
cd ..
```

Windows PowerShell 对应命令：

```powershell
Get-Location
Get-ChildItem
Set-Location 前端学习路线
Set-Location ..
```

### 二、终端不是“黑色窗口”

终端把你输入的文本交给 Shell 解析。Shell 再根据 `PATH` 环境变量寻找可执行程序，启动进程并把输出返回终端。

```text
你输入 pnpm test
    ↓
Shell 在 PATH 中寻找 pnpm
    ↓
启动 pnpm 进程
    ↓
pnpm 读取 package.json
    ↓
启动 test 脚本对应的子进程
```

先掌握最小命令集：

```bash
# 查看当前位置和文件
pwd
ls -la

# 创建和进入目录
mkdir atlas-lab
cd atlas-lab

# 创建空文件
touch index.html

# 查看文本
cat index.html

# 返回父目录
cd ..
```

删除操作难以恢复。练习时先用 `pwd` 和 `ls` 确认范围，再执行：

```bash
# 只删除空目录
rmdir atlas-lab
```

不要在不理解当前路径时执行递归删除命令。

### 三、Node.js 与包管理器分别负责什么

浏览器负责运行页面中的 JavaScript；Node.js 让 JavaScript 可以在命令行和服务端运行。包管理器负责解析依赖、执行项目脚本和维护锁文件。

```bash
node --version
npm --version
pnpm --version
```

课程基线以 Node.js 24 LTS 为主，并验证 Node.js 22 维护期兼容。版本结果不符合时，不要先“随便装一个最新版”，应先确认项目的 `engines`、锁文件和课程技术基线。

`package.json` 是项目声明，不是依赖代码本身：

```json
{
  "name": "atlas-lab",
  "private": true,
  "type": "module",
  "scripts": {
    "start": "node server.mjs",
    "test": "node --test"
  }
}
```

运行脚本：

```bash
pnpm start
pnpm test
```

### 四、命令、进程与端口

执行 `pnpm start` 后，Shell 通常会启动一个长期运行的开发服务器进程。它监听一个 TCP 端口，例如 `4173`。

```text
浏览器 http://127.0.0.1:4173
          ↓
操作系统把请求交给监听 4173 的进程
          ↓
开发服务器返回 HTML/CSS/JS
```

常见操作：

```bash
# 终止当前前台进程
Ctrl+C

# macOS/Linux 查看端口占用
lsof -i :4173

# 查看环境变量
printenv PATH
```

PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 4173
$env:Path
```

端口占用不是“Node 坏了”，而是已经有另一个进程监听同一地址。解决方式是停止旧进程或换端口，不要随机删除项目文件。

### 五、编辑器只是文件编辑器

使用 VS Code 或其他编辑器打开**项目目录**，不要只打开单个文件：

```bash
code .
```

这样编辑器才能正确发现：

- 项目级 TypeScript 配置
- ESLint 和格式化规则
- 相对导入关系
- Git 仓库边界
- 搜索与重构范围

推荐先开启：

```json
{
  "editor.formatOnSave": true,
  "files.insertFinalNewline": true,
  "files.trimTrailingWhitespace": true
}
```

具体格式规则以后由项目配置接管，编辑器设置不应与仓库配置冲突。

### 六、三类常见故障

#### 1. `command not found`

按顺序确认：

```bash
which node
which pnpm
echo "$PATH"
```

Windows 使用：

```powershell
Get-Command node
Get-Command pnpm
$env:Path
```

原因可能是未安装、安装目录没进入 PATH、Shell 尚未重新加载，或者版本管理器没有激活。

#### 2. `EACCES` / 权限不足

先确认你是否正在修改系统目录，以及文件归属。不要把 `sudo` 当作通用修复，也不要用管理员权限运行日常包管理命令。

#### 3. 端口占用

记录错误中的端口，找到监听进程，再决定停止还是换端口。不要通过重复启动制造更多后台进程。

## 常见问题

### Q1：为什么在编辑器终端能运行，系统终端却不行？

两个终端可能加载了不同的 Shell 配置或 PATH。分别执行版本与路径命令，比较实际输出，不要只比较提示符外观。

### Q2：npm 和 pnpm 能混用吗？

技术上可以调用，但一个项目应固定包管理器和锁文件。混用会产生不同依赖树和多个锁文件，降低复现性。

### Q3：为什么不建议全局安装所有工具？

全局版本不受项目锁文件控制，换机器或 CI 后容易失效。优先使用项目依赖和 `package.json` 脚本。

### Q4：`localhost` 和 `127.0.0.1` 有什么区别？

`localhost` 是主机名，通常解析到回环地址；`127.0.0.1` 是 IPv4 回环地址。某些系统还会把 `localhost` 解析到 IPv6 的 `::1`，排查监听地址时需要区分。

### Q5：为什么路径中有空格时命令失败？

Shell 会把空格当作参数分隔符。使用引号：

```bash
cd "/Users/alice/My Projects/atlas"
```

### Q6：终端卡住是不是崩溃？

可能只是前台服务器正在持续运行。先观察最后输出，再尝试 `Ctrl+C`；不要直接关闭窗口而留下不清楚的后台状态。

## 实操作业

### 基础：建立练习目录

1. 创建 `frontend-labs/lesson-01`。
2. 在目录中创建 `README.md` 和 `package.json`。
3. 分别输出绝对路径与文件列表。
4. 记录 Node.js、npm、pnpm 版本。

验收：重新打开终端后，能只根据记录进入同一目录并复述每条命令的作用。

### 进阶：诊断命令环境

分别在系统终端和编辑器终端运行：

```bash
pwd
which node
node --version
which pnpm
pnpm --version
```

如果输出不同，画出“Shell 配置 → PATH → 可执行文件”的定位链路。

### 挑战：端口冲突实验

1. 启动两个都监听 `4173` 的本地服务器。
2. 记录第二个进程的错误。
3. 使用系统工具找到第一个进程。
4. 分别用“停止旧进程”和“修改端口”两种方式恢复。
5. 写出故障记录：现象、证据、原因、修复、验证。

### 作业参考与验收

- **基础**：mkdir -p frontend-labs/lesson-01 后进入目录；README 记录 pwd、文件列表与 node/npm/pnpm 版本。重新开终端按记录定位；不存在的目录应报错，不悄悄创建到其他位置。

## 本节小结

- 路径必须结合当前工作目录理解
- Shell 通过 PATH 找到命令并启动进程
- Node.js 是运行时，pnpm 是包管理器，`package.json` 是项目声明
- 端口是进程监听的网络入口，冲突应通过进程证据排查
- 零基础阶段最重要的习惯是先确认路径、版本和实际输出，再修改环境

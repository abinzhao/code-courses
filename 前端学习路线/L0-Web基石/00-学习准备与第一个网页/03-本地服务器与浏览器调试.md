## 学习目标

- 理解 `file://` 与 `http://` 的行为差异
- 能启动、停止并验证一个本地静态服务器
- 能解释 URL、端口、状态码、MIME 类型和缓存的基本作用
- 能使用 Elements、Console、Network 定位页面加载故障
- 能区分源代码错误、服务器错误和浏览器缓存问题
- 能提交一份可复现的调试记录

## 内容讲解

### 一、为什么不能长期依赖双击 HTML

双击 HTML 通常得到：

```text
file:///Users/alice/project/index.html
```

实际网站使用：

```text
http://127.0.0.1:4173/index.html
```

两者差异包括：

- `file://` 没有正常 HTTP 请求和响应头
- 模块脚本、Fetch、Service Worker 等能力受源与安全策略约束
- 无法练习状态码、缓存、重定向和 MIME 类型
- 路径在本机可用，不代表部署后可用

课程从这一课开始统一使用 HTTP 服务器。

### 二、启动 Atlas 本地服务器

课程提供的 Atlas 项目不依赖第三方包：

```bash
cd 前端学习路线
npm run atlas:start
```

默认访问：

```text
http://127.0.0.1:4173
```

另开一个终端验证响应：

```bash
curl -i http://127.0.0.1:4173/
```

你应该观察到：

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
```

停止服务器：

```text
Ctrl+C
```

### 三、理解 URL

```text
http://127.0.0.1:4173/articles?id=1#comments
└─┬─┘ └────┬────┘ └┬─┘ └────┬───┘ └─┬─┘ └──┬───┘
 协议      主机      端口      路径      查询    片段
```

- 协议决定通信规则。
- 主机决定请求哪台机器。
- 端口决定交给该机器上的哪个监听进程。
- 路径决定请求哪个资源。
- 查询参数发送给服务器或客户端路由。
- 片段不会随 HTTP 请求发送给服务器，通常用于页内定位。

JavaScript 中不要手工拼接复杂 URL：

```js
const url = new URL('/articles', window.location.origin);
url.searchParams.set('tag', 'javascript');
url.searchParams.set('page', '2');
console.log(url.toString());
```

### 四、状态码是服务器的处理结果

| 状态码 | 含义 | 调试动作 |
|---|---|---|
| 200 | 成功返回 | 检查内容是否正确 |
| 304 | 使用缓存版本 | 查看请求条件与缓存头 |
| 404 | 资源不存在 | 检查 URL、大小写、服务器根目录 |
| 500 | 服务端异常 | 查看服务器终端日志 |

页面空白时不要只看页面，应同时查看：

1. HTML 请求是否成功
2. CSS/JS 子资源是否成功
3. Console 是否存在运行时错误
4. 返回内容是否真的是目标文件

服务器错误配置可能让 `/app.js` 返回 HTML 404 页面。此时状态码甚至可能是 200，但浏览器会因 MIME 类型错误拒绝执行。

### 五、MIME 类型告诉浏览器内容是什么

常见映射：

| 扩展名 | Content-Type |
|---|---|
| `.html` | `text/html; charset=utf-8` |
| `.css` | `text/css; charset=utf-8` |
| `.js` / `.mjs` | `text/javascript; charset=utf-8` |
| `.json` | `application/json; charset=utf-8` |
| `.svg` | `image/svg+xml` |

错误示例：

```http
GET /app.js
Content-Type: text/html
```

即使响应体里确实有 JavaScript，模块脚本也可能被浏览器拒绝。不要通过关闭浏览器安全检查“修复”服务器 MIME 配置。

### 六、Network 面板的最小工作流

1. 打开 DevTools → Network。
2. 勾选 Disable cache，仅用于当前调试阶段。
3. 刷新页面。
4. 按 Status 排查失败请求。
5. 点开请求检查 Headers、Response、Timing。
6. 修复后恢复正常缓存并再次验证。

重点字段：

```text
Request URL
Request Method
Status Code
Content-Type
Cache-Control
Initiator
Timing
```

`Initiator` 能说明是谁触发请求，例如 HTML 的 `<script>`、CSS 的 `url()` 或 JavaScript 的 `fetch()`。

### 七、Console 与 Sources 的分工

Console 适合快速观察：

```js
console.log('启动');
console.table([{ id: 1, title: 'HTML' }]);
console.error(new Error('模拟错误'));
```

Sources 适合逐步执行：

1. 在事件处理器内部打断点。
2. 触发按钮。
3. 观察 Scope 中的局部变量。
4. 使用 Step over，而不是一次跳过整个函数。
5. 查看 Call Stack，确认调用来源。

不要用大量 `console.log` 替代断点，也不要在完成后留下包含敏感数据的调试输出。

### 八、缓存问题要通过请求证据判断

常见误区：

```text
页面没更新 → 一定是浏览器缓存
```

实际还可能是：

- 编辑了另一份同名文件
- 开发服务器根目录错误
- Service Worker 返回旧内容
- 构建产物没有重新生成
- CSS 声明被覆盖
- JavaScript 在更新 DOM 前已报错

Network 中的 Size、Status、Response Headers 和响应体能帮助区分这些情况。强制刷新只能用于验证假设，不能替代根因修复。

## 常见问题

### Q1：`localhost` 页面打不开先查什么？

确认服务器进程仍在运行、终端没有报错、地址和端口匹配，再用 `curl` 验证。不要先重装 Node.js。

### Q2：为什么服务器绑定 `127.0.0.1` 后手机打不开？

`127.0.0.1` 只接受本机访问。局域网调试需要显式绑定合适网卡地址，并同时考虑防火墙和不可信网络风险。

### Q3：404 和前端路由 404 一样吗？

不一样。服务器 404 表示 HTTP 资源没找到；SPA 路由 404 可能是服务器没有回退到入口 HTML，也可能是应用内部没有匹配路由。

### Q4：为什么模块脚本有 CORS 限制？

模块依赖图要求明确的源与 MIME 语义。浏览器用更严格的加载规则阻止来源不明或类型错误的代码进入模块图。

### Q5：什么时候应该关闭缓存？

只在定位资源更新问题时临时关闭。性能、缓存和离线能力测试必须恢复真实缓存条件。

### Q6：DevTools 修改的 CSS 会保存到文件吗？

默认不会。Elements/Styles 中的修改只是当前页面内存状态，刷新即丢失。确认方案后再修改源码。

## 实操作业

### 基础：验证静态资源

启动 Atlas，记录 HTML、CSS、JS 三个请求的：

- URL
- 状态码
- Content-Type
- 传输大小
- Initiator

验收：能解释每个字段来自哪里，并证明页面不是通过 `file://` 打开。

### 进阶：构造四类故障

依次制造：

1. JavaScript 路径 404
2. CSS 选择器不匹配
3. JavaScript 运行时异常
4. 端口被占用

每次只改一个变量，使用对应面板找证据并恢复。

### 挑战：可复现调试报告

选择一个故障，提交：

```text
环境：操作系统、浏览器、Node.js 版本
入口：完整 URL
复现：最少步骤
现象：用户可观察结果
证据：Console / Network / 服务器日志
根因：哪一层违反了什么契约
修复：最小修改
回归：正常路径和失败路径
```

## 本节小结

- HTTP 本地服务器提供与真实网站一致的 URL、状态码和响应头基础
- URL 的协议、主机、端口、路径、查询和片段职责不同
- 页面故障要同时检查请求、响应和 JavaScript 执行状态
- MIME 类型错误不能通过修改前端代码绕过
- 调试不是刷新和猜测，而是缩小变量并保留证据

# 01-盒模型与视觉格式化模型

## 学习目标

- 理解标准盒模型与 IE 盒模型的区别，掌握 `box-sizing` 的正确用法
- 掌握盒模型 4 个区域（content、padding、border、margin）的概念和计算方式
- 理解视觉格式化模型中的 BFC 和 IFC，掌握 BFC 的触发条件和实际应用
- 理解 margin 折叠现象及其解决方案
- 能够用 BFC 解决浮动导致的父容器高度塌陷、防止 margin 折叠等经典布局问题

## 内容讲解

### 一、盒模型基础概念

在 CSS 中，每个 HTML 元素都是一个矩形盒子。浏览器根据盒模型来计算每个元素的尺寸和定位。一个盒子由内到外分为 4 个区域：

```
┌─────────────────────────┐
│        margin           │  ← 外边距（盒子外部，透明，推开其他元素）
│  ┌───────────────────┐  │
│  │      border       │  │  ← 边框（盒子边界）
│  │  ┌─────────────┐  │  │
│  │  │   padding   │  │  │  ← 内边距（内容与边框之间的留白）
│  │  │ ┌─────────┐ │  │  │
│  │  │ │ content │ │  │  │  ← 内容区（文字、图片等）
│  │  │ └─────────┘ │  │  │
│  │  └─────────────┘  │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

**Content（内容区）**：存放元素实际内容的区域，由 `width` 和 `height` 控制（取决于盒模型类型）。

**Padding（内边距）**：内容区到边框之间的空间，继承元素的背景色。

**Border（边框）**：盒子的边界，可以设置宽度、样式和颜色。

**Margin（外边距）**：盒子与其他元素之间的距离，永远是透明的。

### 二、标准盒模型 vs IE 盒模型

这是 CSS 布局中最基础也最容易混淆的概念。

#### 标准盒模型（content-box，默认）

```css
/* 这是浏览器的默认行为 */
.box {
  width: 200px;        /* 仅指 content 的宽度 */
  padding: 20px;       /* 在 content 之外加 20px */
  border: 5px solid;   /* 在 padding 之外加 5px */
  margin: 10px;        /* 在 border 之外加 10px */
  box-sizing: content-box; /* 显式声明（默认值） */
}
```

**实际占位宽度** = 200（content） + 20×2（padding） + 5×2（border） = **250px**

这意味着你写的 `width: 200px`，元素实际占用 250px 的水平空间，margin 的 10px 额外参与布局计算。

#### IE 盒模型（border-box）

```css
.box {
  width: 200px;        /* 指 content + padding + border 的总宽度 */
  padding: 20px;
  border: 5px solid;
  box-sizing: border-box;
}
```

**实际占位宽度** = 200px（total），其中 content 自动收缩为 200 - 20×2 - 5×2 = **150px**

**为什么 border-box 更直观？** 因为你写的 `width` 就是最终可见宽度，不需要心算 padding 和 border。

**最佳实践——全局设置 border-box：**

```css
/* 推荐放在项目最顶部 */
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

这样所有元素的 `width`/`height` 都包含 padding 和 border，布局计算变得直观。

### 三、视觉格式化模型（Visual Formatting Model）

视觉格式化模型是 CSS 布局的底层理论，它定义了浏览器如何将文档树中的每个盒子排列在页面上。其中最重要的两个概念是 **BFC** 和 **IFC**。

#### 3.1 块级格式化上下文（BFC）

BFC（Block Formatting Context）是一个独立的渲染区域，里面的元素布局不会影响外部元素。

**BFC 的布局规则：**

1. 内部盒子在垂直方向一个接一个排列
2. 同一个 BFC 内，相邻盒子的垂直 margin 会折叠
3. 每个盒子的左外边缘与包含块的左边缘相接触（从右向左格式则相反）
4. BFC 区域不会与浮动盒子重叠
5. 计算 BFC 高度时，浮动子元素也参与计算

**触发 BFC 的常见方式：**

| 方式 | 说明 |
|------|------|
| `overflow: hidden / auto / scroll`（非 visible） | 最常用，副作用最小 |
| `display: flow-root` | 现代方案，无副作用 **（推荐）** |
| `display: flex / grid` | 弹性/网格容器自动创建 BFC |
| `position: absolute / fixed` | 脱离文档流 |
| `float: left / right` | 浮动元素本身会创建 BFC |
| `contain: layout / paint / strict` | CSS Containment |

**`display: flow-root` vs `overflow: hidden`：**

```css
/* 旧方案：overflow: hidden 会裁剪内容 */
.bfc-old {
  overflow: hidden;
}

/* 新方案：display: flow-root 专为此目的设计，无副作用 */
.bfc-new {
  display: flow-root;
}
```

#### 3.2 BFC 的三大经典应用

**应用一：清除浮动（解决父容器高度塌陷）**

```html
<!DOCTYPE html>
<html>
<head>
<style>
  /* 场景：父容器内有浮动子元素 */
  .container {
    border: 2px solid #333;
    /* overflow: hidden; */  /* 方案 A */
    /* display: flow-root; */ /* 方案 B：推荐 */
  }

  .float-child {
    float: left;
    width: 100px;
    height: 100px;
    background: #4a90d9;
    margin: 10px;
  }

  /* 触发 BFC 后，父容器会包含浮动子元素 */
  .container.bfc-fix {
    display: flow-root;
  }
</style>
</head>
<body>
  <h3>未触发 BFC：父容器高度塌陷</h3>
  <div class="container">
    <div class="float-child">浮动1</div>
    <div class="float-child">浮动2</div>
  </div>

  <h3>触发 BFC 后：父容器正常包裹</h3>
  <div class="container bfc-fix">
    <div class="float-child">浮动1</div>
    <div class="float-child">浮动2</div>
  </div>
</body>
</html>
```

**应用二：防止 margin 折叠**

```html
<style>
  .parent {
    background: #f0f0f0;
    /* 不触发 BFC 时，子元素的 margin-top 会"穿透"父元素 */
    /* display: flow-root; */ /* 加这个就能防止折叠 */
    min-height: 100px;
  }

  .child {
    margin-top: 30px; /* 这个 margin 会"传递"给父元素 */
    background: #4a90d9;
    padding: 10px;
    color: white;
  }

  /* 解决方案 */
  .parent.bfc {
    display: flow-root; /* 现代方案，推荐 */
  }
</style>
```

**应用三：防止与浮动元素重叠（两栏自适应布局）**

```html
<style>
  .float-left {
    float: left;
    width: 200px;
    height: 150px;
    background: #4a90d9;
    color: white;
    padding: 10px;
  }

  .main-content {
    /* 触发 BFC 后，不会与浮动重叠 */
    display: flow-root;
    background: #e8f4fd;
    padding: 10px;
    min-height: 150px;
  }
</style>

<body>
  <div class="float-left">左侧浮动侧边栏</div>
  <div class="main-content">
    主内容区——触发BFC后自动避开浮动元素，实现自适应宽度
  </div>
</body>
```

#### 3.3 行内格式化上下文（IFC）

IFC（Inline Formatting Context）是行内元素的布局环境。在 IFC 中，盒子水平排列，一行放不下就换行。

```html
<style>
  .ifc-demo {
    width: 300px;
    border: 1px solid #ccc;
    padding: 10px;
  }
</style>
<div class="ifc-demo">
  <span>行内元素</span>
  <strong>自动水平排列</strong>
  <em>超出宽度自动换行</em>
  <span>这些都在同一个 IFC 中</span>
</div>
```

IFC 的关键特性：`vertical-align`、`line-height`、`text-align` 都在 IFC 中起作用。

### 四、margin 折叠（Margin Collapse）

这是 CSS 中最让人困惑的行为之一。

#### 什么是 margin 折叠？

**相邻的块级元素**的上下 margin 会合并，取较大值（而不是相加）。

```html
<style>
  .box-a {
    margin-bottom: 30px;
    background: #4a90d9;
    padding: 10px;
    color: white;
  }
  .box-b {
    margin-top: 20px;
    background: #e8734a;
    padding: 10px;
    color: white;
  }
  /* A 和 B 之间的间距是 max(30px, 20px) = 30px，不是 50px */
</style>
<div class="box-a">盒子 A（margin-bottom: 30px）</div>
<div class="box-b">盒子 B（margin-top: 20px）</div>
<!-- 实际间距：30px，不是 30+20=50px -->
```

#### margin 折叠的 3 种场景

| 场景 | 说明 |
|------|------|
| 相邻兄弟元素 | 上一个的 margin-bottom 与下一个的 margin-top 折叠 |
| 父子元素 | 无 border/padding/BFC 阻隔时，子元素 margin-top 传递给父元素 |
| 空块元素 | 一个空元素自身的 margin-top 和 margin-bottom 折叠 |

#### 防止 margin 折叠的方案

| 方案 | 代码 |
|------|------|
| 父元素触发 BFC | `display: flow-root`（推荐） |
| 加边框或内边距 | `border-top: 1px solid transparent` 或 `padding-top: 1px` |
| 用 Flex/Grid 布局 | flex 和 grid 容器的子元素 margin 不折叠 |
| 加行内内容 | 在父子 margin 之间插入一个不可见字符 |

```css
/* 统一推荐方案 */
.parent {
  display: flow-root; /* 一行解决 */
}
```

## 常见问题

**Q1：`box-sizing: border-box` 会影响 margin 吗？**
不会。`border-box` 让 `width` 包含 content + padding + border，但 margin 始终在 `width` 之外计算。

**Q2：行内元素（inline）可以设置 width/height 吗？**
不可以。行内元素的宽高由内容决定，`width` 和 `height` 无效。需改为 `display: inline-block` 或 `block` 才能设置尺寸。

**Q3：`overflow: hidden` 触发 BFC 有什么副作用？**
会裁剪超出容器的内容（如 tooltip、下拉菜单）。如果不需要裁剪，用 `display: flow-root` 更好。

**Q4：margin 折叠只发生在垂直方向吗？**
是的，水平方向的 margin 从不折叠。只有垂直方向（block 方向）的 margin 才会折叠。

**Q5：为什么设置了 `width: 100%` 的元素反而溢出了？**
因为你用了默认的 `content-box`，`width: 100%` + padding + border 导致总宽度超过父容器。改为 `border-box` 即可解决。

**Q6：flex 子元素的 margin 会折叠吗？**
不会。Flexbox 和 Grid 布局中，子元素的 margin 不会折叠——这是选择现代布局方案的又一好处。

**Q7：BFC 和 IFC 是互斥的吗？**
一个元素要么参与 BFC，要么参与 IFC。块级元素参与 BFC，行内元素参与 IFC。`display: inline-block` 的元素外部参与 IFC（水平排列），内部创建 BFC（内部按块级排列）。

## 本节小结

- **盒模型**是 CSS 布局的基石，推荐全局使用 `box-sizing: border-box`
- **BFC** 是解决浮动塌陷、margin 折叠、自适应两栏布局的利器，优先使用 `display: flow-root`
- **margin 折叠**是 CSS 的"特性"而非 bug，理解和控制它就行
- 现代布局（Flexbox、Grid）天然避开了 margin 折叠问题，能用现代方案就尽量用
- `display: flow-root` 是触发 BFC 的最优方案——专为此设计，无副作用

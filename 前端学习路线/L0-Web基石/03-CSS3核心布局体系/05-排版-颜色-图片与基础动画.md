## 学习目标

- 能建立可读的字体、字号、行高和行宽体系
- 理解字体加载如何影响首屏和布局偏移
- 能选择满足对比度要求的前景色与背景色
- 能用响应式图片避免浪费流量和布局偏移
- 能区分过渡、关键帧动画与 JavaScript 动画
- 能支持 `prefers-reduced-motion` 和强制颜色模式

## 内容讲解

### 一、排版首先解决阅读问题

正文排版至少包含：

```css
:root {
  font-family:
    Inter, "PingFang SC", "Microsoft YaHei",
    system-ui, sans-serif;
  font-size: 100%;
  line-height: 1.5;
}

article {
  max-inline-size: 68ch;
}

h1,
h2,
h3,
p {
  margin-block-start: 0;
}
```

关键关系：

- 字号决定字符基本尺寸。
- 行高决定行盒高度，不只是“文字上下空白”。
- 行宽过长会增加视线回跳成本。
- 中英文混排需要在目标系统字体中实际检查。

不要用固定高度包住可能换行的文字：

```css
/* 容易在放大字体或翻译后溢出 */
.title {
  height: 40px;
}

/* 让内容决定高度 */
.title {
  min-block-size: 40px;
}
```

### 二、字体加载是性能与视觉问题

```css
@font-face {
  font-family: "Atlas Sans";
  src: url("/fonts/atlas-sans.woff2") format("woff2");
  font-display: swap;
  font-weight: 400 700;
}
```

需要同时评估：

- 字体文件体积
- 字符集范围
- fallback 与目标字体宽度差异
- `font-display` 策略
- 字体是否来自受信任域名

字体加载可能引起布局偏移。可使用系统 fallback、字体子集、预加载和字体度量调整降低风险，但不能只凭配置猜测效果，应在 Network 与 Performance 中测量。

### 三、颜色必须传达含义且可辨认

```css
:root {
  --color-surface: #ffffff;
  --color-text: #171717;
  --color-muted: #5f6368;
  --color-action: #075f37;
  --color-danger: #b42318;
}
```

颜色使用规则：

1. 文本与背景需要足够对比。
2. 状态不能只靠颜色区分，还要有文本、图标或形状。
3. 深色模式不是把所有颜色机械反转。
4. 焦点、悬停、禁用和错误状态都要单独验证。

```css
.field-error {
  color: var(--color-danger);
}

.field-error::before {
  content: "错误：";
  font-weight: 700;
}
```

系统强制颜色模式可能覆盖你的配色：

```css
@media (forced-colors: active) {
  .primary-button {
    border: 1px solid ButtonText;
  }
}
```

### 四、响应式图片需要尺寸契约

没有尺寸的图片会在加载后推开内容：

```html
<img
  src="/images/course-800.webp"
  srcset="
    /images/course-400.webp 400w,
    /images/course-800.webp 800w,
    /images/course-1200.webp 1200w
  "
  sizes="(max-width: 48rem) 100vw, 50vw"
  width="800"
  height="450"
  alt="Atlas 课程列表页面"
/>
```

- `width` 和 `height` 提供宽高比，帮助浏览器预留空间。
- `srcset` 提供候选资源。
- `sizes` 告诉浏览器图片预计显示宽度。
- `alt` 描述图片的信息目的；纯装饰图片使用空 `alt=""`。

CSS：

```css
img {
  display: block;
  max-inline-size: 100%;
  block-size: auto;
}

.thumbnail {
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
```

`object-fit: cover` 会裁切内容。商品图、证件图和图表可能不允许裁切，需要改用 `contain` 或展示完整尺寸。

### 五、过渡适合状态变化

```css
.button {
  transition:
    background-color 120ms ease,
    transform 120ms ease;
}

.button:hover {
  transform: translateY(-1px);
}

.button:active {
  transform: translateY(0);
}
```

不要写：

```css
* {
  transition: all 300ms;
}
```

`all` 会让尺寸、位置等意外属性也参与动画，增加调试和性能成本。显式列出允许变化的属性。

### 六、关键帧动画适合自主时间线

```css
@keyframes progress-pulse {
  0%,
  100% {
    opacity: 0.65;
  }
  50% {
    opacity: 1;
  }
}

.loading-indicator {
  animation: progress-pulse 1s ease-in-out infinite;
}
```

持续动画需要停止条件。加载结束、元素离开视口或页面进入后台时，应减少不必要工作。

### 七、减少动画偏好

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

这是一种兜底，不代表所有动画都应瞬间消失。更好的做法是对关键交互提供低运动替代：

```css
@media (prefers-reduced-motion: reduce) {
  .drawer {
    transition-property: opacity;
    transform: none;
  }
}
```

### 八、性能判断不能只背属性名单

`transform` 和 `opacity` 通常更容易由合成器高效处理，但不保证完全不占主线程或一定创建独立图层。动画还可能受以下因素影响：

- 图层尺寸与显存
- 阴影、滤镜和混合
- 动画元素数量
- JavaScript 主线程长任务
- 图片解码和字体加载

必须使用 Performance 与 Layers 面板观察实际管线。

## 常见问题

### Q1：中文正文也适合 `ch` 控制行宽吗？

`ch` 基于数字 0 的宽度，只是近似值。中文内容应在目标字体与实际容器中检查，不要把 68ch 当作固定规范。

### Q2：WebP 一定比 JPEG 小吗？

不一定。结果取决于图像内容、质量参数和编码器。对同一源图在目标视觉质量下比较体积。

### Q3：图片 `loading="lazy"` 应该全部开启吗？

首屏主图通常不应懒加载，否则可能推迟 LCP。视口外图片更适合懒加载。

### Q4：动画只用 transform 和 opacity 就不会卡吗？

不能保证。它们通常避免布局和绘制，但大图层合成、滤镜、过多元素和主线程任务仍可能导致掉帧。

### Q5：深色模式怎么测试？

除视觉检查外，还要测试对比度、图片边缘、表单控件、焦点和系统强制颜色模式。

### Q6：能不能隐藏焦点轮廓？

不能直接移除。可以用 `:focus-visible` 提供符合设计的清晰焦点样式。

## 实操作业

### 基础：阅读页排版

为 Atlas 文章详情页建立：

- 字体栈
- 正文行高与行宽
- 标题层级
- 链接、代码和引用样式
- 200% 文本缩放验证

### 进阶：响应式图片

准备三种宽度的同一张图片，配置 `srcset` 与 `sizes`。在 320px、768px、1440px 下记录浏览器选择的资源和布局偏移。

### 挑战：运动与性能对照

实现两个同视觉效果动画：

1. 修改 `left`。
2. 使用 `transform`。

用 Performance 面板记录 Layout、Paint、Composite 和掉帧情况，同时测试减少动画偏好。结论必须基于 trace，而不是只引用规则。

## 本节小结

- 排版质量由字号、行高、行宽、字体与内容共同决定
- 字体和图片必须提供加载、尺寸与失败策略
- 颜色不能是状态的唯一载体
- Transition 适合状态变化，Animation 适合独立时间线
- `prefers-reduced-motion` 是功能要求，不是装饰选项
- 性能结论必须通过浏览器记录验证

# 01 — 媒体查询与容器查询

## 学习目标

- 理解响应式设计的核心思想 —— 不是"做多个版本"，而是"一套代码适配所有尺寸"
- 掌握 CSS 媒体查询（`@media`）的语法、常见断点和进阶用法
- 学会用 `prefers-*` 系列查询适配用户的系统偏好
- 理解容器查询（`@container`）与媒体查询的本质区别
- 能在实战中选择正确的查询工具

---

## 内容讲解

### 1. 响应式设计的三大支柱

响应式设计不是技术技巧的堆砌，它建立在三个基石之上：

| 支柱 | 含义 | 关键技术 |
|------|------|----------|
| **流式网格** | 布局用相对单位（%、fr）而不是固定 px | Flexbox, Grid |
| **弹性媒体** | 图片/视频随容器缩放 | `max-width: 100%` |
| **媒体查询** | 根据设备特性切换样式 | `@media` |

**核心心态**：你写的不是"手机版 + 平板版 + 桌面版"，而是一个从最小屏到最大屏无缝流动的页面。断点只是为了在关键位置做调整，不是让你重写整个页面。

### 2. CSS 媒体查询（@media）

#### 2.1 基本语法

```css
/* 语法结构 */
@media <媒体类型> and (<媒体特性>) {
  /* 条件满足时生效的样式 */
}

/* 最常用的写法：屏幕宽度 ≤ 768px 时 */
@media screen and (max-width: 768px) {
  .sidebar {
    display: none; /* 窄屏隐藏侧边栏 */
  }
}
```

`media` 这个词本身就暗示了它的本质：它查询的是**整个浏览器视口**（或者说"媒介"）的属性，跟页面上某个具体组件在哪里、有多大无关。

#### 2.2 min-width 与 max-width 的思维模型

这是初学者最容易搞混的地方。记住一个准则：

- **`min-width: 768px`** → "宽度至少要 768px" → **从这个小屏断点往上生效**（宽屏样式）
- **`max-width: 767px`** → "宽度最多到 767px" → **从这个大屏断点往下生效**（窄屏样式）

```css
/* ✅ 移动优先写法（推荐）：基础样式 = 手机，min-width 逐步叠加 */
.card { padding: 12px; }                  /* 手机基准 */

@media (min-width: 768px) {
  .card { padding: 20px; }                /* 平板及以上 */
}

@media (min-width: 1024px) {
  .card { padding: 24px; }                /* 桌面 */
}

/* ❌ 桌面优先写法：基础样式 = 桌面，max-width 逐层覆盖 */
/* 项目已有历史代码时可直接在原有风格上扩展，不必强行统一 */
```

**记忆口诀**：`min-width` = "最小就这么大"，移动优先；`max-width` = "最大就这么大"，桌面优先。

#### 2.3 常见设备断点参考

```css
/* 这不是硬性规范，而是经过大量项目验证的实用参考 */
/* 小手机横屏 */     @media (min-width: 480px)  { ... }
/* 平板竖屏 */       @media (min-width: 768px)  { ... }
/* 平板横屏/小桌面 */  @media (min-width: 1024px) { ... }
/* 常规桌面 */        @media (min-width: 1280px) { ... }
/* 大屏 */           @media (min-width: 1440px) { ... }
```

**关键原则**：断点应该为内容服务，而不是为设备服务。当你看到布局"撑不住了"（文字换行难看、卡片太挤），那里就是你的断点。

#### 2.4 同时使用多个条件

```css
/* 只在 768px 到 1023px 之间生效 */
@media screen and (min-width: 768px) and (max-width: 1023px) {
  .gallery {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* 用逗号表示"或"：横屏或最小宽度 768px */
@media (orientation: landscape), (min-width: 768px) {
  .toolbar { flex-direction: row; }
}
```

### 3. 用户偏好查询（prefers-*）

媒体查询不只是查宽度。`prefers-*` 系列可以直接读取用户在操作系统中的偏好设置，让你的页面更"有礼貌"。

#### 3.1 prefers-reduced-motion（减少动画）

```css
/* 默认动画 */
.hero {
  animation: slideUp 0.6s ease;
}

/* 用户开启了"减少动态效果" → 关掉动画 */
@media (prefers-reduced-motion: reduce) {
  .hero {
    animation: none;
  }
}
```

这不仅仅是"贴心"——对有前庭功能障碍的用户来说，过度动画可能引发眩晕。永远为 `prefers-reduced-motion: reduce` 提供无动画回退。

#### 3.2 prefers-color-scheme（颜色主题）

```css
/* 系统浅色模式（默认） */
:root {
  --bg: #fff;
  --text: #1a1a1a;
}

/* 系统深色模式 */
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #1a1a1a;
    --text: #f0f0f0;
  }
}

body {
  background: var(--bg);
  color: var(--text);
}
```

#### 3.3 prefers-contrast（对比度偏好）

```css
/* 用户需要更高对比度 → 增强边框和文字对比 */
@media (prefers-contrast: high) {
  .button {
    border: 2px solid currentColor;
    background: #000;
    color: #fff;
  }
}
```

#### 3.4 其他值得了解的查询

```css
/* 指针精度：是否有鼠标？ */
@media (pointer: fine)   { /* 鼠标/触控板 */ }
@media (pointer: coarse) { /* 手指触摸 */ }

/* 悬停能力：能否 hover？ */
@media (hover: hover) { /* 支持 hover */ }
@media (hover: none)  { /* 触屏设备 */ }

/* 显示模式：全屏 vs 窗口 */
@media (display-mode: standalone) { /* PWA 独立窗口 */ }
```

### 4. 容器查询（@container）

#### 4.1 问题：媒体查询的局限

媒体查询查的是**视口**大小。但组件不知道自己在哪：

```
┌──────────── 视口 1200px ────────────┐
│  ┌── 侧边栏 300px ──┐ ┌── 主区域 860px ──┐ │
│  │  .card            │ │  .card            │ │
│  │  太窄！堆叠布局     │ │  够宽！水平布局     │ │
│  └──────────────────┘ └──────────────────┘ │
└──────────────────────────────────────────┘
```

同样一个 `.card`，在侧边栏里只有 280px，在内容区有 800px。媒体查询做不到"看卡片自己的宽度来决定样式"，它只能看到视口的 1200px。

这就是容器查询要解决的问题。

#### 4.2 基本语法

三步走：

```css
/* 第 1 步：声明容器 */
.card-wrapper {
  container-type: inline-size; /* 监听行内方向（宽度）尺寸变化 */
  container-name: card-container; /* 给容器起个名字（可选） */
}

/* 第 2 步：查询容器 */
@container card-container (min-width: 400px) {
  .card {
    display: flex;     /* 容器够宽 → 水平布局 */
    gap: 16px;
  }
}

@container card-container (max-width: 399px) {
  .card {
    display: block;    /* 容器窄 → 堆叠布局 */
  }
}
```

**关键心智模型**：
- 媒体查询 = "浏览器窗口多宽？"
- 容器查询 = "我所在的容器多宽？"

#### 4.3 container-type 的取值

```css
/* inline-size：只查询宽度（最常用，性能最好） */
.card-wrapper { container-type: inline-size; }

/* size：同时查询宽度和高度（需要显式给容器设高度） */
.wrapper { container-type: size; }

/* normal：不建立查询容器（默认值） */
```

一般用 `inline-size` 就够了。`size` 需要容器有明确的高度，日常场景较少。

#### 4.4 容器查询简写

```css
.card-wrapper {
  /* 一行同时设置类型和名称 */
  container: card-container / inline-size;
  /*        容器名称      / 容器类型 */
}
```

### 5. 媒体查询 vs 容器查询：决策表

| 场景 | 用什么 | 理由 |
|------|--------|------|
| 全局布局切换（如导航栏变汉堡菜单） | 媒体查询 | 这是页面级别的决策 |
| 组件在不同位置表现不同 | 容器查询 | 组件不知道自己在哪 |
| 断点依赖具体组件宽度 | 容器查询 | 更精确、更可复用 |
| 系统偏好（深色模式、减少动画） | 媒体查询 | 这是用户级偏好，跟尺寸无关 |
| 组件库 / 设计系统 | 容器查询 | 组件复用场景中最合适 |

**两者不是替代关系，而是互补关系。** 大部分项目会同时使用：媒体查询管大局，容器查询管组件。

### 6. 实战：组件级响应式卡片 + 页面级布局切换

下面是一个完整的例子，演示两种查询如何各司其职：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>媒体查询 + 容器查询 实战</title>
<style>
  /* ===== 重置与基础 ===== */
  *, *::before, *::after {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
  }

  body {
    font-family: system-ui, -apple-system, sans-serif;
    background: #f5f5f5;
    padding: 24px;
  }

  /* ===== 页面级：媒体查询管大局 ===== */

  .page-grid {
    display: grid;
    gap: 24px;
  }

  /* 窄屏：侧边栏在上，主区域在下 */
  @media (max-width: 767px) {
    .page-grid {
      grid-template-columns: 1fr;
      grid-template-areas:
        "sidebar"
        "main";
    }
  }

  /* 宽屏：侧边栏在左，主区域在右 */
  @media (min-width: 768px) {
    .page-grid {
      grid-template-columns: 300px 1fr;
      grid-template-areas: "sidebar main";
    }
  }

  .sidebar {
    grid-area: sidebar;
    background: #fff;
    border-radius: 12px;
    padding: 20px;
  }

  .main {
    grid-area: main;
  }

  /* ===== 组件级：容器查询管组件 ===== */

  /* 声明容器 */
  .card-container {
    container: card-container / inline-size;
  }

  /* 卡片基础样式 */
  .card {
    background: #fff;
    border-radius: 12px;
    overflow: hidden;
    box-shadow: 0 2px 8px rgba(0,0,0,0.08);
  }

  .card-img {
    width: 100%;
    height: 200px;
    object-fit: cover;
    background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  }

  .card-body { padding: 16px; }
  .card-title { font-size: 18px; font-weight: 600; margin-bottom: 8px; }
  .card-desc { font-size: 14px; color: #666; line-height: 1.6; }

  /* 容器宽度 ≥ 500px：水平布局（图左文右） */
  @container card-container (min-width: 500px) {
    .card {
      display: flex;
      flex-direction: row;
    }

    .card-img {
      width: 200px;
      height: auto;
      flex-shrink: 0;
    }

    .card-body {
      display: flex;
      flex-direction: column;
      justify-content: center;
    }
  }

  /* 容器宽度 < 500px：垂直布局（图上文下）—— 这是默认，无需显式写 */

  /* ===== 深色模式：用户偏好查询 ===== */
  @media (prefers-color-scheme: dark) {
    body {
      background: #1a1a2e;
    }

    .card, .sidebar {
      background: #16213e;
      color: #e0e0e0;
    }

    .card-desc { color: #aaa; }
  }

  /* ===== 减少动画偏好 ===== */
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      transition-duration: 0.01ms !important;
      animation-duration: 0.01ms !important;
    }
  }
</style>
</head>
<body>

  <div class="page-grid">
    <!-- 侧边栏：窄容器 → 卡片是竖版 -->
    <aside class="sidebar">
      <h2 style="margin-bottom: 16px;">推荐</h2>
      <div class="card-container">
        <div class="card">
          <div class="card-img"></div>
          <div class="card-body">
            <div class="card-title">CSS 容器查询</div>
            <div class="card-desc">组件级响应式的新范式。</div>
          </div>
        </div>
      </div>
    </aside>

    <!-- 主区域：宽容器 → 卡片自动变成横版 -->
    <main class="main">
      <h2 style="margin-bottom: 16px;">最新文章</h2>
      <div class="card-container">
        <div class="card">
          <div class="card-img"></div>
          <div class="card-body">
            <div class="card-title">媒体查询 vs 容器查询</div>
            <div class="card-desc">
              媒体查询查的是浏览器视口，容器查询查的是组件所在的容器。
              两者互补，不是替代。在同一个页面中，同一个 .card 类可以因为
              所处容器的宽度不同而呈现不同布局。
            </div>
          </div>
        </div>
      </div>
    </main>
  </div>

</body>
</html>
```

**运行这段代码，把浏览器窗口从宽拖到窄，你会看到**：
1. 页面布局从"侧边栏+主区域"变成"上下堆叠"（媒体查询在作用）
2. 同一套 `.card` 样式，在窄侧边栏是竖版，在宽主区域变成横版（容器查询在作用）
3. 切换到系统深色模式，颜色自动适配（`prefers-color-scheme` 在作用）

## 常见问题

**Q1：媒体查询的断点应该设多少？每个项目都要自己定吗？**

不需要盲目跟风。主流框架（Bootstrap 576/768/992/1200、Tailwind 640/768/1024/1280）的断点经历了大量项目验证，可以直接用。但更重要的原则是：当你的设计在此处"崩了"，这里就是断点。

**Q2：容器查询的浏览器兼容性怎么样？能上生产吗？**

2023 年起所有现代浏览器均已支持（Chrome 105+, Safari 16+, Firefox 110+）。如果你的用户还在用 IE 或老版本浏览器，可以使用 `@supports (container-type: inline-size)` 做渐进增强。

**Q3：媒体查询和容器查询的性能有差别吗？**

容器查询需要浏览器额外跟踪容器尺寸变化，理论上成本略高。但在实际业务中，这个差异几乎不可感知。不用担心性能，优先考虑语义正确性。

**Q4：min-width 和 max-width 可以混用吗？**

技术上可以，但不建议在同一套断点体系中混用。因为 min-width 是"叠加"思维（往上加），max-width 是"覆盖"思维（往下减），混用会让你的脑子在两种模式间反复横跳，容易写出冲突的样式。

**Q5：`orientation` 查询还值得用吗？**

`orientation: portrait` 和 `orientation: landscape` 在手机/平板场景中偶尔有用。但大多数情况下，用宽度判断比横竖屏更可靠——因为桌面浏览器也可以手动调整窗口宽高比，用 `orientation` 可能产生意外结果。

**Q6：同一个元素可以同时被媒体查询和容器查询影响吗？**

完全可以，而且也推荐这样做：媒体查询负责页面级结构调整（如导航栏），容器查询负责组件级样式（如卡片），它们是同步生效、互不干扰的两个维度。

**Q7：为什么需要 `container-name`？不能直接用匿名容器吗？**

匿名容器可以用 `@container (min-width: 400px)` 查最近祖先容器。但如果你的组件有嵌套容器（比如一个容器里面还有一个容器），匿名查询可能查到错误的祖先。起名字可以精确指定查询目标，代码意图也更清晰。

**Q8：print 媒体类型什么时候用？**

```css
@media print {
  nav, .ad, .sidebar { display: none; }
  body { font-size: 12pt; }
}
```

当你需要为打印优化样式时使用——隐藏导航、广告，调整字体和颜色。这在企业后台、报表页面中很有用。

## 实操作业

### 练习 1（基础）：手写移动端导航栏

用媒体查询实现一个导航栏：宽度 ≥ 768px 时显示横向导航链接，宽度 < 768px 时隐藏链接、只显示一个汉堡图标（可以用 ☰ 文字代替，不需要 JS 交互）。要求：用 `min-width` 做移动优先。

### 练习 2（进阶）：容器查询卡片组件

实现一个 `.product-card` 组件，包含产品图片、标题、价格、描述。当容器宽度 ≥ 400px 时，图片在左、文字在右；当容器宽度 < 400px 时，图片在上、文字在下。把这个组件放到一个 300px 的侧边栏和一个 600px 的主区域中，验证它自动适配。

### 练习 3（挑战）：主题切换 + 动画控制

结合 CSS 变量和 `prefers-color-scheme` 实现页面自动跟随系统深色/浅色模式。同时使用 `prefers-reduced-motion` 为动画提供无动画回退。额外要求：页面首次加载时有淡入动画，但系统开启"减少动态效果"时直接显示。

## 本节小结

- 响应式设计的本质是一套代码流畅适配所有尺寸，不是做多个版本
- 媒体查询查**视口**属性，做页面级决策（布局切换、导航调整）
- 容器查询查**容器**尺寸，做组件级决策（卡片内布局变化）
- `prefers-*` 系列查**用户偏好**，体现对用户的尊重
- 两者不是替代关系，成熟的页面会同时使用：媒体查询管大局，容器查询管组件
- 断点永远为内容服务，不要在内容被"撑坏"之前加断点

## 学习目标

- 能设计适用于人和流水线的 CLI 契约。
- 能解析严格参数、输出机器可读结果并正确失败。

## 内容讲解

### 1. 先定义命令契约

本课工具读取文章 JSON 数组并统计数量：

```text
atlas-count --input articles.json [--json]
atlas-count --help
```

| 结果 | stdout | stderr | 退出码 |
|---|---|---|---:|
| 成功 | 数量或 JSON | 空 | 0 |
| 帮助 | 用法 | 空 | 0 |
| 参数错误 | 空 | 简短原因 | 2 |
| 输入/执行错误 | 空 | 简短原因 | 1 |

退出码 1/2 是本工具约定，不是所有工具必须采用的全球标准。机器输出不能混入进度动画和调试日志。

### 2. 完整的最小 CLI

保存为 `cli.mjs`：

```js
#!/usr/bin/env node
import { parseArgs } from 'node:util';
import { readFile } from 'node:fs/promises';

let args;
try {
  args = parseArgs({
    options: {
      input: { type: 'string', short: 'i' },
      json: { type: 'boolean', default: false },
      help: { type: 'boolean', short: 'h', default: false },
    },
    strict: true, allowPositionals: false,
  }).values;
} catch (error) {
  console.error(`参数错误：${error.message}`);
  process.exitCode = 2;
}

if (args?.help) {
  console.log('用法：node cli.mjs --input articles.json [--json]');
} else if (args && !args.input) {
  console.error('缺少 --input');
  process.exitCode = 2;
} else if (args) {
  try {
    const data = JSON.parse(await readFile(args.input, 'utf8'));
    if (!Array.isArray(data) || data.some((item) =>
      !item || typeof item.id !== 'string' || typeof item.title !== 'string'
    )) throw new Error('输入必须是包含字符串 id/title 的文章数组');
    const output = { count: data.length };
    console.log(args.json ? JSON.stringify(output) : `文章数量：${data.length}`);
  } catch (error) {
    console.error(`执行失败：${error.message}`);
    process.exitCode = 1;
  }
}
```

输入文件：`[{"id":"a1","title":"Atlas"}]`。执行 `node cli.mjs --input articles.json --json`，预期 stdout 为 `{"count":1}`。

### 3. 标准流和文件大小

此例用 readFile 适合小文件；生产导入应设置字节上限，大数据改用 NDJSON 流处理，不能先无界读取再校验大小。

支持 `--input -` 时从 stdin 读取。若 stdin 是 TTY 而用户没传输入，不应无限等待；帮助中明确是否等待管道。stderr 用于错误与进度，stdout 只用于结果。

### 4. 退出与取消

优先设置 `process.exitCode` 并让程序自然结束，立即 `process.exit()` 可能截断尚未写出的输出。存在未结束 timer/连接时仍要清理，exitCode 不会强制结束活跃资源。

SIGINT/SIGTERM 的清理应有时间预算，关闭资源后退出。Windows 的信号行为需要实测；不能只在 macOS 通过就声明跨平台完成。

### 5. 真实进程测试

用 `spawnSync(process.execPath, ['cli.mjs', ...args], { encoding:'utf8' })` 或异步 spawn 验证 stdout、stderr、status。至少测试帮助、未知参数、缺输入、损坏 JSON、合法数组和带空格路径。

不要仅测试 parseArgs 包装函数，真实入口、工作目录和退出码才是 CLI 消费者契约。

## 常见问题

**可以把 token 放参数吗？** 可能出现在 shell 历史或进程列表；凭据按具体平台采用受控输入或凭据存储，日志不回显。

**输出彩色 JSON 可以吗？** 机器模式应禁用 ANSI 和交互提示，保持稳定 schema。

## 实操作业

基础实现计数 CLI；进阶支持 stdin 与 NDJSON；挑战加入 `--version`、帮助和超大输入限制。

### 参考答案与验收

非法参数退出 2，损坏 JSON 退出 1；机器结果可 JSON.parse，stderr 没有秘密。非交互模式不能弹选择菜单或等待确认。

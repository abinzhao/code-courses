## 学习目标

- 能实现不静默覆盖文件的导出工具。
- 能明确配置优先级、dry-run、重复执行与分发验证。

## 内容讲解

### 1. 设计写入契约

```text
atlas-export --input articles.json --output export.json [--dry-run]
```

默认拒绝覆盖已有输出，dry-run 验证输入并展示计划但不写文件。相同输入应得到确定性序列化结果；拒绝覆盖与业务幂等不是一回事。

工具不要默认 `--force`。若未来增加覆盖，必须设计备份、回退与明确交互；流水线中禁止默认自动确认。

### 2. 可复制导出函数

```js
import { readFile, writeFile } from 'node:fs/promises';
import { resolve } from 'node:path';

export async function exportArticles({ input, output, dryRun = false }) {
  const inputPath = resolve(input);
  const outputPath = resolve(output);
  if (inputPath === outputPath) throw new Error('输入输出不能相同');
  const articles = JSON.parse(await readFile(inputPath, 'utf8'));
  if (!Array.isArray(articles)) throw new Error('输入应为数组');
  const ids = new Set();
  const rows = articles.map((article) => {
    if (!article || typeof article.id !== 'string' || !article.id ||
        typeof article.title !== 'string') throw new Error('文章字段无效');
    if (ids.has(article.id)) throw new Error('文章 ID 重复');
    ids.add(article.id);
    return { id: article.id, title: article.title };
  });
  // 明确排序，让输出不依赖输入记录顺序或系统 locale。
  rows.sort((a, b) => a.id < b.id ? -1 : a.id > b.id ? 1 : 0);
  const body = JSON.stringify(rows, null, 2) + '\n';
  if (!dryRun) {
    // wx 原子地拒绝已存在目标，避免先检查再写入的竞态。
    await writeFile(outputPath, body, { flag: 'wx' });
  }
  return { count: rows.length, output: outputPath, written: !dryRun };
}
```

此教学函数仍为小文件，不承诺抗恶意并发文件系统修改，也不保证断电时新文件完整。生产大文件导出应限制输入，临时写入、确认完成后移动，并按平台定义失败清理。

在上一课入口增加对应参数并调用函数，保持 stdout/stderr/退出码契约。函数没有调用 CLI 解析器，因而可独立测试。

### 3. 配置合并

推荐清晰优先级：CLI 参数 > 显式环境变量 > 指定配置文件 > 默认值。配置只含业务选项，不能允许任意 module import 或任意 shell 命令。

对每一层统一 schema 校验；未知 key 报错。`false` 和空字符串不能被 `||` 当成未设置，应区分 undefined 与有意值。

### 4. 安装与分发

```json
{
  "name": "atlas-export-lab",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "bin": { "atlas-export": "./bin/cli.mjs" },
  "files": ["bin", "src"]
}
```

bin 首行是 `#!/usr/bin/env node`。本地 pack 后安装到干净消费者，再用 npm exec 或消费者 scripts 调用。Unix 使用链接，Windows 通常生成 shim；必须在目标系统验证含空格路径、编码和换行。

默认不用 `npm install -g` 修改用户全局环境。独立二进制/Node 单可执行应用是另一分发方式，需另外验证平台、动态资源与签名，不能仅把脚本改后缀。

### 5. 失败恢复测试

| 情形 | 预期 |
|---|---|
| dry-run | 输入校验完成，目标文件不存在 |
| 已有输出 | 非零退出，原文件字节不变 |
| 重复 ID | 非零退出，无新输出 |
| 不可写目录 | 非零退出，有可定位原因 |
| 输入顺序不同 | 内容按 ID 排序一致 |
| 取消大任务 | 不留下被误认为成功的文件 |

## 常见问题

**dry-run 是只打印参数吗？** 应做真实解析与计划校验，但不能触发业务写入。

**原子 rename 能保证整个工作流事务吗？** 不能，多个文件、外部 API 和数据库需分别设计提交与恢复。

## 实操作业

基础连接导出函数与 CLI；进阶添加配置文件并测试优先级；挑战完成 tarball 消费者和 Windows/macOS/Linux 目标验证矩阵。

### 参考答案与验收

默认文件冲突不可覆盖；dry-run 没副作用；所有失败非零退出。只验证当前操作系统时，在交付中明确其他系统尚未实测。

## 学习目标

- 能区分工作目录、模块目录、路径与 URL。
- 能处理文件不存在、权限不足、软链接和写入冲突。
- 能通过参数数组执行已知子进程，传播退出码和超时。

## 内容讲解

### 1. 路径的基准

`process.cwd()` 是启动时工作目录，适合解析用户输入；`import.meta.url` 是当前模块文件 URL，适合定位随包分发的资源。URL 不能直接按操作系统字符串拼接：

```js
import { readFile } from 'node:fs/promises';
const template = await readFile(new URL('./template.txt', import.meta.url), 'utf8');
```

Windows 盘符、UNC、分隔符与大小写规则不同。使用 `node:path`，不要用字符串替换假装跨平台。

### 2. 受限目录读取

以下函数用于课程静态资源实验，不用于高对抗生产沙箱：

```js
import { realpath, readFile } from 'node:fs/promises';
import { resolve, relative, isAbsolute, sep } from 'node:path';

export async function readInside(root, userPath) {
  const base = await realpath(root);
  const target = await realpath(resolve(base, userPath));
  const rel = relative(base, target);
  if (rel === '..' || rel.startsWith(`..${sep}`) || isAbsolute(rel)) {
    throw new Error('路径超出允许目录');
  }
  return readFile(target);
}
```

`startsWith(root)` 不可靠，例如 `/safe-other` 也可能以 `/safe` 开头。realpath 处理已有软链接，但校验与打开之间仍存在 TOCTOU，若攻击者可并发修改目录，需 OS 权限隔离、不可写资源目录或安全文件描述符方案。

对于上传，优先服务端生成资源 ID，保存至固定目录，不把用户文件名当真实路径。

### 3. 写入与一致性

用 `writeFile(path, data, { flag: 'wx' })` 拒绝覆盖已有文件；不能先 exists 再写，因为两步之间有竞态。大文件用流，遵循背压。

单文件更新可写同目录临时文件后 rename，但原子性、覆盖行为、持久化与跨文件一致性取决于 OS/文件系统。多个业务记录需要数据库事务，不能把 rename 描述成万能事务。

### 4. 执行子进程

```js
import { spawn } from 'node:child_process';

export function checkSyntax(file) {
  return new Promise((resolve, reject) => {
    // 固定执行当前 Node；用户输入只作为参数，不拼入 shell。
    const child = spawn(process.execPath, ['--check', file], {
      shell: false, stdio: ['ignore', 'pipe', 'pipe'],
      timeout: 5_000,
    });
    let stderr = '';
    child.stderr.on('data', (chunk) => {
      stderr = (stderr + chunk.toString()).slice(-8192);
    });
    child.on('error', reject);
    child.on('close', (code, signal) => {
      if (code === 0) resolve();
      else reject(new Error(`检查失败：${signal ?? code} ${stderr}`));
    });
  });
}
```

这里仅语法检查，不执行待检查文件。不要将文件、URL 或包名拼到 `exec('命令 ' + input)`；即使 shell false，程序本身仍可能解释以 `-` 开头的输入，必须限制参数语义。

子进程大量 stdout/stderr 不消费可能阻塞。exec 的缓冲上限、spawn 的流式输出和 Windows `.cmd` 行为不同，按实际目标测试。

## 常见问题

**路径规范化能阻止所有越界吗？** 不能，还要考虑软链接、编码、竞态与 OS 权限。

**子进程退出 1，父进程是否自动失败？** 不会，父进程必须传播失败。

## 实操作业

基础测试正常文件、不存在、`../` 与目录外软链接；进阶测试含空格路径和损坏 JS；挑战设计上传目录的权限与并发写入方案。

### 参考答案与验收

越界应拒绝，合法文件可读；损坏 JS 使调用失败；含空格路径是单个参数；输出冲突不能覆盖原文件。高对抗路径安全的剩余竞态必须明确记录。

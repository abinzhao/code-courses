## 内容讲解

### 1. 前端 CI/CD 完整链路概览

一个成熟的前端项目 CI/CD 流水线应该覆盖开发到上线的全流程：

```
开发阶段                              代码审查阶段                      发布阶段
┌──────────┐    git push    ┌──────────────────────────────┐    merge   ┌──────────────┐
│ 开发者    │ ──────────────►│  CI 流水线（PR 触发）          │ ─────────►│ CD 流水线     │
│ 写代码    │               │                             │           │ （main 触发）  │
└──────────┘               │  ① Lint & 格式化检查           │           │              │
                           │  ② TypeScript 类型检查         │           │  ① 构建      │
                           │  ③ 单元测试 + 覆盖率            │           │  ② E2E 测试  │
                           │  ④ 构建验证                    │           │  ③ 部署到生产 │
                           │  ⑤ 预览部署（Preview URL）      │           │  ④ 发送通知   │
                           └──────────────────────────────┘           └──────────────┘
```

两条流水线的分工：

| 维度 | CI 流水线（PR 触发） | CD 流水线（main 合并触发） |
|------|---------------------|--------------------------|
| 目标 | 验证代码质量，拦住 Bug | 将验证通过的代码发布上线 |
| 构建产物 | 用于预览，保留 7 天 | 用于生产，长期留存 |
| 测试范围 | 单元测试 + 类型检查 | E2E 测试 + 冒烟测试 |
| 部署目标 | 预览环境（临时） | 生产环境（正式） |
| 通知 | PR 评论区 | 飞书 / Slack / 钉钉群 |

### 2. 构建阶段：多环境构建

前端项目通常需要针对不同环境构建不同的版本。Vite 为例：

```yaml
# .github/workflows/deploy.yml（CD 流水线）
name: Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:
    inputs:
      environment:
        description: '部署环境'
        required: true
        type: choice
        options:
          - staging
          - production

env:
  NODE_VERSION: '24'
  PNPM_VERSION: '10'

jobs:
  build-and-deploy:
    name: Build & Deploy (${{ github.event.inputs.environment || 'production' }})
    runs-on: ubuntu-latest
    timeout-minutes: 15

    # 根据触发方式决定目标环境
    # 手动触发用选择的环境，push main 默认 production
    environment:
      name: ${{ github.event.inputs.environment || 'production' }}

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      # ============================================
      # 根据环境变量选择构建命令
      # package.json 中预定义了：
      #   "build:dev": "vite build --mode development"
      #   "build:staging": "vite build --mode staging"
      #   "build:prod": "vite build --mode production"
      # ============================================
      - name: 设置环境变量
        id: env-vars
        run: |
          if [ "${{ github.event.inputs.environment || 'production' }}" = "production" ]; then
            echo "BUILD_CMD=build:prod" >> $GITHUB_OUTPUT
            echo "API_BASE=https://api.example.com" >> $GITHUB_ENV
          elif [ "${{ github.event.inputs.environment }}" = "staging" ]; then
            echo "BUILD_CMD=build:staging" >> $GITHUB_OUTPUT
            echo "API_BASE=https://staging-api.example.com" >> $GITHUB_ENV
          else
            echo "BUILD_CMD=build:dev" >> $GITHUB_OUTPUT
            echo "API_BASE=https://dev-api.example.com" >> $GITHUB_ENV
          fi

      - name: 构建项目
        # 注入运行时环境变量，Vite 中通过 import.meta.env.VITE_API_BASE 访问
        env:
          VITE_API_BASE: ${{ env.API_BASE }}
          VITE_APP_VERSION: ${{ github.sha }}
          VITE_BUILD_TIME: ${{ github.event.head_commit.timestamp }}
        run: pnpm run ${{ steps.env-vars.outputs.BUILD_CMD }}

      - name: 上传构建产物
        uses: actions/upload-artifact@v4
        with:
          name: dist-${{ github.event.inputs.environment || 'production' }}
          path: dist/
          retention-days: 30
```

**多环境构建的核心思路：**

- `package.json` 中定义不同的构建脚本，对应不同的 `.env.*` 文件
- CI 中通过 `$GITHUB_OUTPUT` 和 `$GITHUB_ENV` 动态设置环境变量
- Vite 中只有 `VITE_` 前缀的环境变量会暴露给客户端代码

### 3. 测试阶段：分阶段执行

测试不是"跑一遍就完"，而是按成本从低到高分阶段执行，快速失败：

```yaml
jobs:
  # ============ 第一阶段：快速检查（秒级反馈）============
  quick-checks:
    name: ⚡ Quick Checks
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: '9'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - name: ESLint
        run: pnpm run lint
      - name: Prettier
        run: pnpm run format:check
      - name: TypeScript
        run: pnpm run typecheck
      - name: 检查循环依赖
        run: pnpm run check-circular

  # ============ 第二阶段：单元测试（分钟级反馈）============
  unit-tests:
    name: 🧪 Unit Tests
    needs: [quick-checks]         # 第一阶段通过才跑
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: '9'
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - name: 运行单元测试
        run: pnpm run test -- --coverage
      - name: 检查覆盖率阈值
        # 如果覆盖率低于 80%，CI 失败
        run: |
          COVERAGE=$(node -e "const c=require('./coverage/coverage-summary.json'); console.log(c.total.lines.pct)")
          echo "覆盖率: $COVERAGE%"
          if (( $(echo "$COVERAGE < 80" | bc -l) )); then
            echo "❌ 覆盖率 $COVERAGE% 低于 80% 阈值"
            exit 1
          fi

  # ============ 第三阶段：E2E 测试（成本最高，最后跑）============
  e2e-tests:
    name: 🎭 E2E Tests
    needs: [unit-tests]           # 单元测试通过才跑 E2E
    runs-on: ubuntu-latest
    timeout-minutes: 20
    steps:
      # ... 见第 6 节详细配置
```

**测试分层的决策逻辑：**

```
快速检查失败 → 不跑单元测试 → 不跑 E2E → 不构建 → 不部署
        ↓                ↓             ↓         ↓         ↓
    < 1 分钟          < 5 分钟       < 15 分钟   < 5 分钟   < 3 分钟

总失败反馈时间：最快 30 秒（Lint 失败）
总成功时间：约 30 分钟（全部通过）
```

### 4. 产物管理：Artifacts 上传与下载

```yaml
# ===== Job A：构建并上传 =====
build:
  runs-on: ubuntu-latest
  steps:
    - run: pnpm build
    - uses: actions/upload-artifact@v4
      with:
        # 产物名称，后续 Job 用这个名称下载
        name: build-output
        # 要上传的路径，可以是文件或目录
        path: |
          dist/
          !dist/**/*.map            # 排除 sourcemap（节省空间）
        # 如果同名产物已存在，覆盖
        overwrite: true
        # 编译指标报告（可选）
        if-no-files-found: error
        retention-days: 14

# ===== Job B：下载并使用 =====
deploy:
  needs: [build]
  runs-on: ubuntu-latest
  steps:
    - uses: actions/download-artifact@v4
      with:
        name: build-output
        path: ./output           # 解压到 output/ 目录

    # 验证产物完整性
    - name: 验证产物
      run: |
        if [ ! -f ./output/index.html ]; then
          echo "❌ 产物不完整：缺少 index.html"
          exit 1
        fi
        echo "✅ 产物大小：$(du -sh ./output)"

    - name: 部署
      run: pnpm run deploy --dir ./output
```

**Artifacts 最佳实践：**
- 按 `name` 区分不同类型的产物（如 `dist`、`coverage`、`storybook`）
- 设置合理的 `retention-days`，免费仓库默认 90 天
- 排除 sourcemap 减小体积（或在部署时单独上传到监控平台）

### 5. 部署策略

#### 5.1 静态站点托管平台对比

| 平台 | 免费额度 | 预览部署 | 自定义域名 | 适合场景 |
|------|---------|---------|-----------|---------|
| **Cloudflare Pages** | 无限带宽、500次构建/月 | ✅ 分支自动预览 | ✅ 免费 SSL | 最佳性价比 |
| **Vercel** | 100GB 带宽/月 | ✅ 每 PR 一个预览 | ✅ 免费 SSL | Next.js 首选 |
| **Netlify** | 100GB 带宽/月 | ✅ Deploy Previews | ✅ 免费 SSL | 老牌稳定 |

#### 5.2 预览部署（Preview Deploy）

预览部署的核心价值：**每个 PR 都生成一个独立的临时网站，reviewer 可以直接打开看效果，不用拉到本地跑。**

```yaml
# .github/workflows/preview-deploy.yml
name: Preview Deploy

on:
  pull_request:
    types: [opened, synchronize, reopened]
    branches: [main]

jobs:
  deploy-preview:
    name: 🚀 Preview
    runs-on: ubuntu-latest
    # 使用 GitHub Environment 功能管理预览环境的 Secret
    environment:
      name: preview
      # PR 中的预览链接
      url: https://${{ steps.deploy.outputs.preview_url }}

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: '9'

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile
      - run: pnpm run build

      # 部署到 Cloudflare Pages（分支预览）
      - name: 部署到 Cloudflare Pages
        id: deploy
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          # 用 PR 分支名作为部署分支，Cloudflare 自动生成 preview URL
          command: >
            pages deploy dist/
            --project-name=my-frontend-app
            --branch=${{ github.head_ref }}

      # 提取预览 URL
      - name: 获取预览 URL
        id: preview-url
        run: |
          # Cloudflare Pages 的分支预览 URL 格式：
          # https://<branch-name>.<project-name>.pages.dev
          BRANCH_SAFE=$(echo "${{ github.head_ref }}" | tr '/' '-')
          echo "url=https://${BRANCH_SAFE}.my-frontend-app.pages.dev" >> $GITHUB_OUTPUT

      # 在 PR 评论区贴预览链接
      - name: 评论预览链接
        uses: thollander/actions-comment-pull-request@v2
        with:
          message: |
            ## 🚀 预览部署完成
            
            | 项目 | 信息 |
            |------|------|
            | 🔗 预览地址 | [${{ steps.preview-url.outputs.url }}](${{ steps.preview-url.outputs.url }}) |
            | 📦 提交 | ${{ github.event.pull_request.head.sha }} |
            | ⏱️ 构建时间 | ${{ github.event.head_commit.timestamp }} |
            
            > 💡 预览环境会在 PR 关闭后自动销毁
          comment-tag: preview-deploy  # 更新同一条评论而不是创建新评论
```

#### 5.3 生产部署（Production Deploy）

```yaml
# .github/workflows/production-deploy.yml
name: Production Deploy

on:
  push:
    branches: [main]
    # 只监听会影响构建产物的文件变更
    paths:
      - 'src/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
      - 'vite.config.*'

jobs:
  deploy-production:
    name: 🏭 Deploy to Production
    runs-on: ubuntu-latest
    # 使用 Environment 保护规则（需要手动审批或限定分支）
    environment:
      name: production
      url: https://my-frontend-app.pages.dev

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: '9'

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - run: pnpm install --frozen-lockfile

      # 生产构建：注入版本号和构建时间
      - name: 生产构建
        env:
          VITE_APP_VERSION: ${{ github.sha }}
          VITE_BUILD_TIME: ${{ github.event.head_commit.timestamp }}
          VITE_SENTRY_DSN: ${{ secrets.SENTRY_DSN }}
        run: pnpm run build:prod

      # 部署到 Cloudflare Pages（生产环境）
      - name: 部署到 Cloudflare Pages
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          # production 分支部署到主域名
          command: >
            pages deploy dist/
            --project-name=my-frontend-app
            --branch=main

      # 创建 GitHub Release（如果是 tag 推送）
      - name: 创建 Release
        if: startsWith(github.ref, 'refs/tags/')
        uses: softprops/action-gh-release@v2
        with:
          generate_release_notes: true
          files: dist.zip
```

**生产部署的安全措施：**

在 GitHub 仓库 Settings → Environments 中为 `production` 环境设置：
- **Required reviewers**：至少 1 人审批才能部署
- **Wait timer**：部署前等待 N 分钟（冷静期）
- **Deployment branches**：限制只有 main 分支可以部署到生产

### 6. 通知集成

部署完成后自动通知团队，支持飞书、Slack、钉钉：

```yaml
  # ===== 部署状态通知（放在 deploy Job 的最后） =====
  notify:
    name: 📢 发送部署通知
    needs: [deploy-production]
    runs-on: ubuntu-latest
    # 无论部署成功或失败都发送通知
    if: always()

    steps:
      # ===== 方式一：飞书自定义机器人 =====
      - name: 发送飞书通知
        if: always()
        run: |
          STATUS="${{ needs.deploy-production.result }}"
          if [ "$STATUS" = "success" ]; then
            COLOR="green"
            STATUS_TEXT="✅ 部署成功"
          else
            COLOR="red"
            STATUS_TEXT="❌ 部署失败"
          fi

          curl -X POST "${{ secrets.FEISHU_WEBHOOK_URL }}" \
            -H "Content-Type: application/json" \
            -d "{
              \"msg_type\": \"interactive\",
              \"card\": {
                \"header\": {
                  \"title\": { \"content\": \"${STATUS_TEXT}\", \"tag\": \"plain_text\" },
                  \"template\": \"${COLOR}\"
                },
                \"elements\": [
                  {
                    \"tag\": \"div\",
                    \"text\": {
                      \"content\": \"**项目：** my-frontend-app\\n**分支：** main\\n**提交：** ${{ github.event.head_commit.message }}\\n**作者：** ${{ github.event.head_commit.author.name }} \\n**时间：** $(date '+%Y-%m-%d %H:%M:%S')\",
                      \"tag\": \"lark_md\"
                    }
                  },
                  {
                    \"tag\": \"action\",
                    \"actions\": [
                      {
                        \"tag\": \"button\",
                        \"text\": { \"content\": \"查看部署详情\", \"tag\": \"plain_text\" },
                        \"url\": \"${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}\",
                        \"type\": \"primary\"
                      }
                    ]
                  }
                ]
              }
            }"

      # ===== 方式二：Slack =====
      - name: 发送 Slack 通知
        uses: slackapi/slack-github-action@v1.26.0
        with:
          payload: |
            {
              "text": "${{ needs.deploy-production.result == 'success' && '✅' || '❌' }} Deployment ${{ needs.deploy-production.result }}",
              "blocks": [
                {
                  "type": "section",
                  "text": {
                    "type": "mrkdwn",
                    "text": "*Deployment ${{ needs.deploy-production.result }}*\n• Repository: ${{ github.repository }}\n• Commit: ${{ github.sha }}\n• Author: ${{ github.actor }}"
                  }
                }
              ]
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK_URL }}

      # ===== 方式三：钉钉 =====
      - name: 发送钉钉通知
        run: |
          curl -X POST "${{ secrets.DINGTALK_WEBHOOK_URL }}" \
            -H "Content-Type: application/json" \
            -d '{
              "msgtype": "markdown",
              "markdown": {
                "title": "部署通知",
                "text": "### 部署状态：${{ needs.deploy-production.result }}\n> 项目：my-frontend-app\n> 分支：main\n> 提交：${{ github.sha }}"
              }
            }'
```

### 7. 完整 CI/CD 流水线实战

将前面所有知识点整合成一套完整的流水线配置：

```yaml
# .github/workflows/full-pipeline.yml
# ============================================================
# 前端项目完整 CI/CD 流水线
# 覆盖 PR 预览 → 合并 → 生产部署 → E2E → 通知 的全链路
# ============================================================

name: Full CI/CD Pipeline

on:
  pull_request:
    types: [opened, synchronize, reopened]
    branches: [main]
    paths:
      - 'src/**'
      - 'tests/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
      - '.github/workflows/**'
      - 'vite.config.*'
  push:
    branches: [main]
    paths:
      - 'src/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
      - 'vite.config.*'

env:
  NODE_VERSION: '24'
  PNPM_VERSION: '10'

# PR 事件取消旧运行
concurrency:
  group: ${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: true

jobs:
  # ==================== 阶段 1：快速检查（PR + push 都跑）====================
  quick-checks:
    name: ⚡ Lint & Type Check
    runs-on: ubuntu-latest
    timeout-minutes: 8

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      - name: ESLint 检查
        run: pnpm run lint

      - name: TypeScript 类型检查
        run: pnpm run typecheck

  # ==================== 阶段 2：单元测试（仅 PR 事件，Matrix 并行）====================
  unit-tests:
    name: 🧪 Unit Tests
    needs: [quick-checks]
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    timeout-minutes: 15

    strategy:
      fail-fast: false
      matrix:
        node-version: [22, 24]

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      - name: 运行单元测试
        run: pnpm run test -- --coverage

  # ==================== 阶段 3：构建 ====================
  build:
    name: 📦 Build
    needs: [quick-checks]
    if: github.event_name == 'push' || (github.event_name == 'pull_request' && success())
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      - name: 构建
        env:
          VITE_BUILD_TIME: ${{ github.event.head_commit.timestamp }}
        run: pnpm run build

      - name: 上传构建产物
        uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/
          retention-days: ${{ github.event_name == 'push' && 30 || 7 }}

  # ==================== 阶段 4：E2E 测试（仅 PR 事件）====================
  e2e-tests:
    name: 🎭 E2E Tests
    needs: [build]
    # 只在 PR 事件且有构建产物时运行
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    timeout-minutes: 20

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: ${{ env.PNPM_VERSION }}

      - uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      # 安装 Playwright 浏览器
      - name: 安装 Playwright 浏览器
        run: pnpm exec playwright install --with-deps chromium

      # 下载构建产物（用来启动预览服务器做 E2E）
      - name: 下载构建产物
        uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/

      # 启动预览服务器 + 运行 E2E
      - name: 运行 E2E 测试
        run: |
          # 后台启动预览服务器
          pnpm exec vite preview --port 4173 &
          # 等服务器就绪
          npx wait-on http://localhost:4173 --timeout 30000
          # 运行 Playwright 测试
          pnpm exec playwright test

      # E2E 失败时上传截图和 trace 辅助排查
      - name: 上传 Playwright 报告
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            playwright-report/
            test-results/
          retention-days: 7

  # ==================== 阶段 5a：预览部署（仅 PR） ====================
  deploy-preview:
    name: 🚀 Preview Deploy
    needs: [build, e2e-tests]
    if: github.event_name == 'pull_request'
    runs-on: ubuntu-latest
    timeout-minutes: 5

    environment:
      name: preview
      url: https://${{ steps.sanitize-branch.outputs.branch }}.my-app.pages.dev

    steps:
      - uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/

      - name: 处理分支名（Cloudflare 不允许特殊字符）
        id: sanitize-branch
        run: |
          BRANCH=$(echo "${{ github.head_ref }}" | tr '/' '-' | tr -cd 'a-zA-Z0-9-')
          echo "branch=$BRANCH" >> $GITHUB_OUTPUT

      - name: 部署到 Cloudflare Pages
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          accountId: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
          command: >
            pages deploy dist/
            --project-name=my-app
            --branch=${{ steps.sanitize-branch.outputs.branch }}

      - name: 评论预览链接到 PR
        uses: thollander/actions-comment-pull-request@v2
        with:
          comment-tag: preview
          message: |
            ## 🚀 预览部署完成
            
            | 项目 | 信息 |
            |------|------|
            | 🔗 预览地址 | https://${{ steps.sanitize-branch.outputs.branch }}.my-app.pages.dev |
            | 📦 Commit | `${{ github.event.pull_request.head.sha }}` |
            | 🧪 单元测试 | ${{ needs.unit-tests.result }} |
            | 🎭 E2E 测试 | ${{ needs.e2e-tests.result }} |
            
            > 💡 PR 合并或关闭后预览环境会自动销毁。

  # ==================== 阶段 5b：生产部署（仅 push main） ====================
  deploy-production:
    name: 🏭 Production Deploy
    needs: [build]
    if: github.event_name == 'push' && github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    timeout-minutes: 10

    environment:
      name: production
      url: https://my-app.pages.dev

    steps:
      - uses: actions/download-artifact@v4
        with:
          name: dist
          path: dist/

      - name: 部署到 Cloudflare Pages（生产）
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}

          command: pages deploy dist/ --project-name=my-app --branch=main

      # 发送生产部署通知
      - name: 发送飞书通知
        if: always()
```

### 8. Playwright E2E CI 配置详解

Playwright 在 CI 中需要额外的浏览器依赖安装和配置：

```yaml
# .github/workflows/playwright-e2e.yml
name: Playwright E2E Tests

on:
  pull_request:
    branches: [main]
  # 定时运行：每天早上检查生产环境是否正常
  schedule:
    - cron: '0 1 * * *'  # UTC 1:00 = 北京时间 9:00

jobs:
  e2e:
    name: 🎭 E2E Tests (${{ matrix.browser }})
    runs-on: ubuntu-latest
    timeout-minutes: 25

    strategy:
      fail-fast: false
      matrix:
        # 在多个浏览器上并行测试
        browser: [chromium, firefox, webkit]
        # 多个视口尺寸
        viewport:
          - { width: 1280, height: 720 }
          - { width: 375, height: 812 }  # iPhone 尺寸

    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: '9'

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - name: 安装依赖
        run: pnpm install --frozen-lockfile

      # ============================================
      # 关键：安装 Playwright 浏览器及系统依赖
      # ============================================
      - name: 安装 Playwright 浏览器
        run: |
          # --with-deps：安装系统级依赖（libgtk、libnss 等）
          # ${{ matrix.browser }}：只安装当前 Matrix 需要的那一个浏览器
          pnpm exec playwright install --with-deps ${{ matrix.browser }}

      # 缓存 Playwright 浏览器（避免每次都下载 ~500MB）
      - name: 缓存 Playwright 浏览器
        uses: actions/cache@v4
        id: playwright-cache
        with:
          path: ~/.cache/ms-playwright
          key: playwright-${{ runner.os }}-${{ matrix.browser }}-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: |
            playwright-${{ runner.os }}-${{ matrix.browser }}-

      # 如果没有命中缓存，重新安装浏览器
      - name: 安装 Playwright 浏览器（缓存未命中时）
        if: steps.playwright-cache.outputs.cache-hit != 'true'
        run: pnpm exec playwright install --with-deps ${{ matrix.browser }}

      - name: 构建项目（如果 E2E 需要本地服务器）
        run: pnpm run build

      - name: 运行 Playwright 测试
        env:
          # 指定浏览器和视口（从 Matrix 传入）
          PLAYWRIGHT_BROWSER: ${{ matrix.browser }}
          PLAYWRIGHT_VIEWPORT_WIDTH: ${{ matrix.viewport.width }}
          PLAYWRIGHT_VIEWPORT_HEIGHT: ${{ matrix.viewport.height }}
        run: |
          # 后台启动预览服务器
          pnpm exec vite preview --port 4173 &
          # 等服务器就绪
          npx wait-on http://localhost:4173 --timeout 30000
          # 运行测试
          pnpm exec playwright test --project=${{ matrix.browser }}

      # 上传测试报告（包括截图、视频、trace）
      - name: 上传 Playwright 报告
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report-${{ matrix.browser }}-${{ matrix.viewport.width }}x${{ matrix.viewport.height }}
          path: |
            playwright-report/
            test-results/
          retention-days: 7

      # 在 PR 上展示测试结果摘要
      - name: 评论 E2E 结果
        if: github.event_name == 'pull_request'
        uses: thollander/actions-comment-pull-request@v2
        with:
          comment-tag: e2e-results
          message: |
            ## 🎭 E2E 测试结果
            
            | 浏览器 | 视口 | 结果 |
            |--------|------|------|
            | ${{ matrix.browser }} | ${{ matrix.viewport.width }}×${{ matrix.viewport.height }} | ${{ job.status == 'success' && '✅' || '❌' }} |
```

**Playwright CI 配置文件（playwright.config.ts）：**

```typescript
// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  // 测试文件目录
  testDir: './e2e',
  // 全局超时时间
  timeout: 30 * 1000,
  expect: { timeout: 5000 },

  // CI 中推荐使用 'github' reporter，在 Actions 界面友好展示
  reporter: process.env.CI
    ? [['github'], ['html', { open: 'never' }]]   // CI 中不自动打开浏览器
    : [['list'], ['html']],                         // 本地开发时用 list

  // 失败时保留截图和 trace（辅助排查）
  use: {
    screenshot: 'only-on-failure',
    trace: 'retain-on-failure',
    video: 'retain-on-failure',
  },

  projects: [
    {
      name: 'chromium',
      use: { ...devices['Desktop Chrome'] },
    },
    {
      name: 'firefox',
      use: { ...devices['Desktop Firefox'] },
    },
    {
      name: 'webkit',
      use: { ...devices['Desktop Safari'] },
    },
    // 移动端测试
    {
      name: 'mobile-chrome',
      use: { ...devices['Pixel 5'] },
    },
  ],

  // 用 vite preview 作为本地服务器
  webServer: {
    command: 'pnpm exec vite preview --port 4173',
    port: 4173,
    reuseExistingServer: !process.env.CI,   // CI 中每次重建
  },
});
```

**Playwright 与前端 CI 的集成要点：**

1. **浏览器安装**：必须 `playwright install --with-deps`，Ubuntu Runner 缺少浏览器所需的系统库
2. **缓存浏览器**：Playwright 浏览器包约 500MB，缓存后每次节省 2-3 分钟
3. **CI reporter**：用 `github` reporter，失败时直接在 PR Files Changed 中展示差异
4. **失败产出**：上传 trace/screenshot/video 到 Artifacts，可在 Playwright Trace Viewer 中回放

## 常见问题

### Q1：预览部署的 URL 会跟其他人冲突吗？

不会。Cloudflare Pages / Vercel 的分支预览机制会为每个分支生成独立 URL。你用 `--branch=feat-login`，别人用 `--branch=feat-payment`，互不影响。同一分支的多次推送会覆盖上一次的预览。

### Q2：生产部署失败了怎么办？能自动回滚吗？

Cloudflare Pages 和 Vercel 都支持一键回滚到上一个部署版本。GitHub Actions 本身不自动回滚，但你可以：
- 在 Cloudflare Pages 控制台点 "Rollback"
- 或者写一个 `rollback` workflow，用 `workflow_dispatch` 手动触发，指定要回滚到的 commit

### Q3：`environment` 字段具体是干什么的？

它是 GitHub 的环境管理功能。在你仓库 Settings → Environments 中创建 `production` 环境后，可以设置：
- **保护规则**：要求审批、限定分支、等待时间
- **Secrets 隔离**：`production` 环境的 Secret 只在引用 `environment: production` 的 Job 中可用
- **部署历史**：记录每次部署的 commit、时间、状态

### Q4：E2E 测试太慢了，怎么优化？

1. **用 Matrix 按浏览器拆分**：三个浏览器并行跑，总时间 = 最慢的那个
2. **用 `test.describe.serial` 时谨慎**：串行会阻塞其他测试
3. **合理使用 Mock**：对不稳定的第三方 API 做拦截（`page.route()`）
4. **缓存 Playwright 浏览器**：见文中缓存配置
5. **只在关键路径跑全量 E2E**：PR 只跑核心流程，定时任务跑全量

### Q5：多个环境怎么管理不同的 Secrets？

两种方式：
- **GitHub Environments**：`staging` 和 `production` 各自有一套 Secrets，Job 中通过 `environment: production` 切换
- **命名约定**：`SECRET_STAGING`、`SECRET_PRODUCTION`，在 Job 中根据条件读取

### Q6：怎么做到"合并前必须先通过 CI"？

在 GitHub 仓库 Settings → Branches → Branch protection rules 中：
1. 添加 `main` 分支保护规则
2. 勾选 "Require status checks to pass before merging"
3. 搜索并选中你 CI 中的 Job 名称（如 `Lint & Type Check`、`Unit Tests`）
4. 勾选 "Require branches to be up to date before merging"

### Q7：免费额度用完了会发生什么？

GitHub 不会直接停掉你的 CI，而是**排队等待**。开源仓库没有限制。私有仓库超出后：
- 可以购买额外的 CI 分钟数
- 或者用自托管 Runner（Self-hosted Runner），在自己服务器上运行，不消耗 GitHub 额度

### Q8：有没有更简单的方式，不用写这么多 YAML？

有，但各有取舍：
- **Vercel / Netlify Git 集成**：连接仓库后自动部署，几乎零配置，但灵活性低
- **Cloudflare Pages Git 集成**：同上，自动构建和部署
- 直接用托管平台自带 CI：适合简单项目。需要多步骤检查（Lint、Type Check、Matrix 测试）时，GitHub Actions 是最合适的选择

## 实操作业

### 基础：配置 PR 预览部署

给你当前的前端项目添加预览部署：

1. 创建 `.github/workflows/preview.yml`
2. 在 PR 打开和更新时触发构建
3. 将构建产物部署到 Cloudflare Pages 或 Vercel（二选一）
4. 在 PR 评论区自动贴上预览链接

验证方式：创建一个测试 PR，确认预览链接自动生成且页面可访问。

### 进阶：完整 CI/CD + 通知

在基础之上：

1. 添加 `production` 部署 Job（push main 触发）
2. 给 `production` 环境设置保护规则（至少 1 人审批）
3. 添加部署状态通知到飞书/钉钉（任选一个）
4. 如果部署失败，通知中要包含失败原因

验证方式：合并一个 PR 到 main，确认自动部署到生产环境并收到飞书/钉钉通知。

### 挑战：Playwright E2E 集成到 CI

在进阶之上：

1. 给项目安装 Playwright 并写 3 个核心 E2E 测试用例
2. 创建 `.github/workflows/e2e.yml`，用 Matrix 在 chromium 和 firefox 上并行跑
3. 配置 Playwright 浏览器缓存
4. 失败时自动上传 trace 和 screenshot 到 Artifacts
5. 定时每天跑一次全量 E2E（`schedule`）

验证方式：故意写一个会失败的 E2E 测试并提交 PR，确认 CI 失败、Artifacts 上传了 trace，且能在 Playwright Trace Viewer 中回放失败过程。

## 本节小结

- **CI/CD 全链路**：PR 触发 CI（检查 + 测试 + 预览），合并到 main 触发 CD（构建 + 部署 + 通知）
- **多环境构建**：通过 `--mode` 参数和 `VITE_*` 环境变量区分 development / staging / production 构建
- **测试分阶段**：Quick Checks（秒级） → Unit Tests（分钟级） → E2E Tests（十分钟级），快速失败降低反馈时间
- **产物管理**：`upload-artifact` / `download-artifact` 实现 Job 间数据传递，注意排除 sourcemap 减体积
- **预览部署**：每个 PR 自动生成独立 URL，Reviewer 无需本地启动就能验收
- **生产部署**：合并到 main 自动部署，用 Environment Protection 加审批和冷静期
- **通知集成**：飞书/钉钉/Slack 的 Webhook 在部署完成后推送状态卡片
- **Playwright CI**：必须 `playwright install --with-deps`，缓存浏览器省时间，失败时上传 trace 辅助排查

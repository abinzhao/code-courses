## 学习目标

- 能让小程序接入统一 API，而不信任前端传来的身份。
- 能处理弱网、会话过期、分包和真机差异。

## 内容讲解

### 1. 最小主路径

Atlas 小程序完成文章列表 → 详情 → 收藏 → 重新打开恢复。先用本地 mock 验证页面状态，再接入已有服务端契约。

```js
Page({
  data: { state: 'loading', articles: [], error: '' },
  onLoad() { this.load(); },
  load() {
    this.setData({ state: 'loading', error: '' });
    wx.request({
      url: 'https://api.example.invalid/articles',
      success: (res) => {
        if (res.statusCode !== 200 || !Array.isArray(res.data.items)) {
          this.setData({ state: 'error', error: '接口返回异常' });
          return;
        }
        this.setData({
          articles: res.data.items,
          state: res.data.items.length ? 'success' : 'empty',
        });
      },
      fail: () => this.setData({ state: 'error', error: '网络不可用，请重试' }),
    });
  },
});
```

示例域名为占位地址，需换为自己授权 API 并登记合法域名；不能写成直接复制即可请求真实服务。模板按 state 提供 loading、空态、错误重试和列表。

### 2. 登录链路

`wx.login` 获取临时 code → 自己服务端交换平台会话 → 服务端关联内部用户 → 返回自己的会话。AppSecret、session_key 留在服务端；客户端 openid/role 不可信。

code 有时效和使用约束，失败后重新发起登录；自己的会话要有过期与撤销，服务端每次写入授权。不要让客户端自行解码或保存平台秘密。

### 3. 分包与性能

按用户路径拆分公开阅读与管理/编辑等低频包，减少首包体积。分包不能解决请求慢、setData 过大或图片资源过重。

setData 只传必要变化，避免高频传完整列表。测量首屏、包体积、低端机和弱网，开发者工具流畅不等于真机流畅。

### 4. 离线与生命周期

应用被回收不能保证最后保存；收藏与草稿提前持久化。请求退出页面时取消或忽略过期回调，避免写入已销毁页面。

会话过期保留草稿，重新登录后按原 mutationId 恢复；弱网下重试不能重复收藏/发布。

### 5. 交付

真机检查布局、键盘遮挡、返回、权限拒绝、网络切换和平台 API。体验版与正式发布需合法域名、版本、隐私说明和平台审核；真实发布需明确确认。

## 常见问题

**开发工具关闭域名校验后能上线吗？** 不能替代正式合法域名与 HTTPS。

**Taro 能统一所有平台行为吗？** 可以复用部分逻辑，登录、组件和生命周期差异仍要测试。

## 实操作业

基础实现四种列表状态；进阶接入服务端登录；挑战分包并记录真机弱网和会话过期路径。

### 参考答案与验收

秘密不进客户端；403 不靠页面隐藏；会话恢复不丢草稿；工具与真机证据分开。没有平台账号/设备时明确未实测。

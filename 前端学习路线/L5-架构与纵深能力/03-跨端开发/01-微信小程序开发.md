## 内容讲解

### 一、小程序的技术架构：双线程模型

微信小程序最底层不同于传统 Web 的根本原因是它的**双线程模型**：

```
┌──────────────────────────────────────┐
│              微信客户端                │
│  ┌─────────────┐  ┌───────────────┐  │
│  │   渲染层      │  │    逻辑层      │  │
│  │  (WebView)   │  │   (JSCore)    │  │
│  │              │  │               │  │
│  │  WXML/WXSS   │  │   App Service │  │
│  │  组件渲染     │  │   业务逻辑     │  │
│  └──────┬───────┘  └───────┬───────┘  │
│         │                  │          │
│         └──── Native Bridge ─┘        │
│               (setData)               │
│  ┌──────────────────────────────────┐ │
│  │           原生层                  │ │
│  │  网络请求/文件系统/设备能力/支付   │ │
│  └──────────────────────────────────┘ │
└──────────────────────────────────────┘
```

**关键区别**：

| 维度 | 传统 Web | 微信小程序 |
|------|----------|-----------|
| 渲染引擎 | 浏览器内核（单线程） | WebView（渲染层）+ JSCore（逻辑层）双线程 |
| DOM 操作 | 直接操作真实 DOM | 无 DOM，通过 `setData` 走 Native Bridge |
| 页面栈 | 浏览器 Tab / History API | 原生页面栈（最多 10 层） |
| 网络请求 | `fetch` / `XMLHttpRequest` | `wx.request`（服务端域名白名单制） |
| 存储 | `localStorage` / `indexedDB` | `wx.setStorageSync`（上限 10MB） |
| 包大小 | 不限 | 主包 ≤ 2MB，总包 ≤ 20MB（含分包） |

> **避坑提示**：`setData` 是同步调用、异步渲染。一次性传大量数据（如整个列表）会导致通信阻塞，应始终只传变化的部分。

### 二、小程序与 Web 开发的异同

#### WXML vs HTML

```xml
<!-- WXML：类似 HTML 但语法更严格 -->
<view class="container">
  <!-- 条件渲染：使用 wx:if，注意花括号语法 -->
  <text wx:if="{{isLogin}}">欢迎回来，{{nickname}}</text>
  <text wx:else>请先登录</text>

  <!-- 列表渲染：wx:for，必须指定 wx:key -->
  <view wx:for="{{list}}" wx:key="id">
    <text>第 {{index + 1}} 项：{{item.name}}</text>
  </view>
</view>
```

| 特性 | HTML | WXML |
|------|------|------|
| 标签 | 标准 HTML 标签（div, span, p...） | 小程序专用标签（view, text, image...） |
| 属性绑定 | `class="foo"` | `class="{{foo}}"` 必须加花括号 |
| 条件渲染 | `v-if` / `ngIf` / JS 控制 | `wx:if` / `wx:elif` / `wx:else` |
| 列表渲染 | `v-for` / `*ngFor` | `wx:for`，必须配 `wx:key` |
| 事件绑定 | `onclick` / `@click` | `bind:tap` / `catch:tap` |
| 模板 | 无 | `<template name="xxx">` + `<import>` |

#### WXSS vs CSS

```css
/* WXSS：CSS 的子集，增加了尺寸单位和样式导入 */
.container {
  /* rpx：响应式像素，750rpx = 屏幕宽度，自动适配所有机型 */
  width: 750rpx;
  padding: 30rpx;

  /* 不支持：vw/vh（但有 rpx 替代）、CSS Grid（部分支持） */
  display: flex;           /* ✅ 推荐 flex 布局 */
  flex-direction: column;
}

/* @import 引入公共样式 */
@import "./common.wxss";
```

> **避坑提示**：WXSS 不支持 `*` 通配选择器、属性选择器 `[attr]`、部分伪类（`:hover` 无意义——触屏设备）。背景图只能用 base64 或网络图片，不支持本地相对路径。

### 四、页面生命周期

```javascript
// pages/index/index.js — 完整生命周期演示
Page({
  // 页面初始化数据（页面第一次使用时的默认数据）
  data: {
    userInfo: null,
    list: []
  },

  // 1. onLoad：页面加载时触发，只执行一次
  //    适合做：接收路由参数、发起初始数据请求
  onLoad(options) {
    // options 携带页面跳转时传入的参数
    const { id } = options;
    this.fetchData(id);
  },

  // 2. onShow：页面显示/切入前台时触发
  //    每次页面可见都会执行（包括从其他页面返回）
  onShow() {
    // 适合做：刷新数据、检查登录态
    console.log('页面显示了');
  },

  // 3. onReady：页面初次渲染完成，只执行一次
  //    适合做：获取节点信息（需渲染完成后才能查询）
  onReady() {
    const query = wx.createSelectorQuery();
    query.select('#title').boundingClientRect(rect => {
      console.log('元素高度:', rect.height);
    }).exec();
  },

  // 4. onHide：页面隐藏/切入后台时触发
  //    适合做：暂停音视频播放、保存草稿
  onHide() {
    console.log('页面隐藏了');
  },

  // 5. onUnload：页面卸载时触发
  //    适合做：清理定时器、移除事件监听
  onUnload() {
    clearInterval(this.timer);
  },

  // 下拉刷新
  onPullDownRefresh() {
    this.fetchData().then(() => wx.stopPullDownRefresh());
  },

  // 触底加载更多
  onReachBottom() {
    this.loadMore();
  },

  // 自定义方法
  fetchData(id) {
    // 业务逻辑...
  }
});
```

**生命周期执行顺序**：`onLoad → onShow → onReady`

**页面切换时**：
- A → B（navigateTo）：A `onHide` → B `onLoad` → B `onShow` → B `onReady`
- B → A（navigateBack）：B `onUnload` → A `onShow`

> **避坑提示**：`onReady` 中才能安全获取节点尺寸；`onLoad` 中节点尚未渲染，`createSelectorQuery` 可能返回 null。

#### 内置组件

| 组件 | 用途 | 关键属性 |
|------|------|---------|

<swiper autoplay interval="3000" circular indicator-dots>

#### 自定义组件

```javascript
// components/card/card.js
Component({
  // 外部传入的属性
  properties: {
    title: { type: String, value: '默认标题' },
    imageUrl: String,
    // 是否显示删除按钮
    showDelete: { type: Boolean, value: false }
  },

  // 组件内部数据
  data: { isLiked: false },

  // 组件生命周期
  lifetimes: {
    attached() { console.log('组件挂载'); },
    detached() { console.log('组件卸载'); }
  },

  // 方法
  methods: {
    onTap() {
      this.setData({ isLiked: !this.data.isLiked });
      // 向父组件抛出自定义事件
      this.triggerEvent('cardtap', { title: this.properties.title });
    }
  }
});
```

```json
// components/card/card.json — 必须声明自身为组件
{
  "component": true
}
```

> **避坑提示**：组件和页面的 `.json` 文件区分：页面不需要 `"component": true`，组件必须声明。忘了声明的话组件注册会失败，不渲染且不易排查。

### 六、数据绑定和事件处理

```xml
<!-- WXML -->
<view class="counter">
  <!-- 数据绑定：{{}} 内可做简单运算 -->
  <text>计数：{{count}}</text>
  <text>双倍：{{count * 2}}</text>

  <!-- 事件绑定：bind:事件名="方法名" -->
  <button bind:tap="increment">+1</button>

  <!-- catch 阻止事件冒泡（bind 不阻止） -->
  <view catch:tap="onOuterTap">
    <button bind:tap="onInnerTap">点击</button>
  </view>

  <!-- data-* 传参到事件处理函数 -->
  <view
    wx:for="{{items}}"
    wx:key="id"
    data-id="{{item.id}}"
    data-name="{{item.name}}"
    bind:tap="onItemTap"
  >
    {{item.name}}
  </view>
</view>
```

```javascript
// index.js
Page({
  data: { count: 0, items: [{ id: 1, name: 'A' }, { id: 2, name: 'B' }] },

  increment() {
    // setData 更新视图——永远不要直接修改 this.data.xxx
    this.setData({ count: this.data.count + 1 });
  },

  onItemTap(e) {
    // e.currentTarget.dataset 获取 data-* 传参
    const { id, name } = e.currentTarget.dataset;
    wx.navigateTo({ url: `/pages/detail/detail?id=${id}` });
  }
});
```

> **避坑提示**：`data-*` 传参的 key 会自动转为小写驼峰：`data-user-name` → `e.currentTarget.dataset.userName`。直接 `this.data.count = 10` 不会触发视图更新，必须用 `setData`。

### 七、API 调用

```javascript
// utils/request.js — 封装网络请求
const BASE_URL = 'https://api.example.com';

function request(options) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data,
      header: {
        'Content-Type': 'application/json',
        // 登录态 token 通过 header 传递
        'Authorization': wx.getStorageSync('token') || ''
      },
      success(res) {
        if (res.statusCode === 200) {
          resolve(res.data);
        } else {
          reject(res);
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常', icon: 'none' });
        reject(err);
      }
    });
  });
}

// 使用示例
request({ url: '/user/info' }).then(data => {
  console.log(data);
});
```

**常用 API 速查**：

| API | 用途 | 注意 |
|-----|------|------|
| `wx.navigateTo({ url })` | 保留当前页，跳转到新页 | 页面栈最多 10 层 |
| `wx.redirectTo({ url })` | 关闭当前页，跳转到新页 | 无法返回 |
| `wx.navigateBack({ delta })` | 返回上一页或多级页面 | delta 默认为 1 |
| `wx.switchTab({ url })` | 跳转 tabBar 页面 | 关闭所有非 tabBar 页面 |
| `wx.request({ url })` | 网络请求 | 域名必须在后台配置白名单 |
| `wx.setStorageSync(key, data)` | 同步写入本地缓存 | 上限 10MB |
| `wx.getStorageSync(key)` | 同步读取本地缓存 | |
| `wx.showToast({ title })` | 轻提示 | `icon: 'none'` 可不带图标 |
| `wx.showLoading({ title })` | 加载提示 | 需手动 `wx.hideLoading()` |
| `wx.login()` | 获取临时 code | 需后端换 openid/session_key |

> **避坑提示**：`wx.request` 要求服务器域名在微信后台配置为合法域名，且仅支持 HTTPS。开发阶段可在开发者工具中勾选「不校验合法域名」绕过。

### 八、Taro 跨端框架简介

Taro 让你用 React/Vue 语法写一套代码，编译到微信、支付宝、百度、字节、QQ、京东等多端小程序，以及 H5 和 React Native。

**核心原理**：编译时的 AST 转换——将 React DSL 编译为各平台原生代码：

```
React 代码 → Taro CLI → 微信 WXML/WXSS/JS
                       → 支付宝 AXML/ACSS/JS
                       → H5 HTML/CSS/JS
```

**关键差异点**：

| 特性 | 原生小程序 | Taro + React |
|------|-----------|-------------|
| 语法 | WXML/WXSS 专用语法 | JSX + CSS/SCSS |
| 状态管理 | `this.setData()` | React state / Hooks |
| 组件化 | 小程序自定义组件 | React 组件 |
| 生态 | 小程序专属 | React 生态 + npm |
| 条件渲染 | `wx:if="{{condition}}"` | `{condition && <View />}` |
| 列表渲染 | `wx:for="{{list}}"` | `{list.map(item => <View />)}` |

> **避坑提示**：Taro 中不能直接用 HTML 标签，必须用 Taro 提供的跨平台组件：`<View>` 代替 `<div>`、`<Text>` 代替 `<span>`、`<Image>` 代替 `<img>`。

### 九、分包加载策略

小程序启动时默认下载**主包**。主包限制 2MB，超出必须用分包。

**分包配置**：

```json
{
  "pages": ["pages/index/index"],           // 主包页面
  "subPackages": [
    {
      "root": "packageA",                    // 分包根目录
      "name": "order",                       // 分包别名
      "pages": [
        "pages/order-list/order-list",
        "pages/order-detail/order-detail"
      ],
      "independent": false                   // 是否独立分包
    }
  ],
  "preloadRule": {                           // 预加载规则
    "pages/index/index": {
      "network": "all",                      // all / wifi
      "packages": ["order"]                  // 进入首页时预加载 order 分包
    }
  }
}
```

**分包策略建议**：

| 策略 | 说明 |
|------|------|
| 主包精简 | 只放首页和公共组件，目标 < 1.5MB |
| 按功能拆分 | 订单、个人中心、活动等独立分包 |
| 独立分包 | 不依赖主包即可运行，启动速度最快（适合分享页） |
| 预加载 | 在关键页面对即将访问的分包做预下载 |
| 公共库分包 | 多个分包共用的模块抽到独立分包 |

> **避坑提示**：主包和分包之间不能循环引用。分包不能引用主包中未声明的模块。独立分包不能依赖主包资源。

### 十、发布审核流程注意事项

```
开发完成 → 上传代码 → 提交审核 → 审核中（1-7 个工作日） → 审核通过 → 发布上线
                                                          ↓
                                                      审核拒绝 → 修改 → 重新提交
```

**审核避坑清单**：

1. **类目选择**：必须选择与实际功能匹配的服务类目，如「社交-社区/论坛」需要《增值电信业务经营许可证》
2. **用户隐私**：收集用户信息前必须弹出隐私协议弹窗，调用 `wx.getPrivacySetting` 检查授权状态
3. **测试账号**：提交审核时必须提供可登录的测试账号
4. **功能完整**：不能有「开发中」「敬请期待」等空白页面
5. **内容合规**：UGC 内容必须有审核/举报机制
6. **小程序名称**：不能包含"最""第一"等绝对化用语，不能与已有小程序重名
7. **iOS 虚拟支付**：iOS 端不能出现引导虚拟支付的文案（如"去网页充值"），否则被拒

> **避坑提示**：审核期间可在「版本管理」中设置**灰度发布**，先向 5% 用户发布，观察无问题后全量。

## 常见问题

**Q1：小程序和 H5 到底有什么区别？**
小程序运行在微信内置的 App 容器中，双线程架构，无 DOM/BOM，能力由微信 SDK 提供。H5 运行在浏览器中，有完整的 DOM/BOM API。小程序性能更好、能力更强，但受平台规则约束多。

**Q2：为什么要用 Taro 而不是直接写原生？**
如果你的产品需要在微信、支付宝、H5 等多端同步上线，Taro 可以节省 60%+ 的开发量。但如果只做微信小程序，原生开发更轻量，调试链路更短。

**Q3：setData 传 1000 条数据会卡吗？**
会。`setData` 每次传输有大小限制（建议 < 256KB），且大量数据通过 Native Bridge 序列化传输耗时。解决方案：分页加载、只更新变化的字段、使用 `this.selectComponent` 直接操作子组件数据。

**Q4：小程序可以做 WebSocket 长连接吗？**
可以。`wx.connectSocket` 支持 WebSocket，但最多同时维护 2 个连接，且后台运行 5 秒后会被挂起（`setKeepAlive` 可延长到 30 分钟）。

**Q5：Taro 项目如何调试？**
Taro CLI 编译后，用对应平台的开发者工具打开 `dist` 目录。小程序端用微信开发者工具调试，H5 端用浏览器 DevTools。Taro 支持 React DevTools 实时查看组件树。

**Q6：小程序的最大包体积是多少？**
主包 ≤ 2MB，总包（含所有分包）≤ 20MB。单个分包 ≤ 2MB。超过限制会被编译工具直接拦截。

**Q7：小程序中的图片资源放哪里？**
推荐放 CDN 上，通过 HTTPS 引用。本地图片会增加包体积，大图极易超 2MB 限制。SVG 图标优先用 `iconfont`。

**Q8：Taro 编译到多端时，如何做平台差异化？**
通过文件后缀：`index.weapp.tsx`（微信）、`index.alipay.tsx`（支付宝）、`index.h5.tsx`（H5）。运行时可用 `Taro.getEnv()` 判断当前平台。

### 基础练习：原生小程序 Todo List

用微信原生开发方式编写一个 Todo List 小程序：

## 本节小结

微信小程序的双线程模型是其与 Web 开发最根本的差异，这决定了开发模式上的三个关键转变：
1. **无 DOM 操作**——所有视图更新通过 `setData` 走 Native Bridge
2. **平台能力替代 Web API**——网络、存储、设备能力全部由 `wx.*` 系列 API 提供
3. **严格的包体积和域名管控**——需要在架构阶段就考虑分包和接口白名单

Taro 框架在原生小程序之上提供了一层 React/Vue 开发体验，核心价值在于跨多端复用代码。但不要把它当成"写 React 就是写小程序"——编译产物的调试、平台差异处理、性能优化仍然需要理解底层原理。

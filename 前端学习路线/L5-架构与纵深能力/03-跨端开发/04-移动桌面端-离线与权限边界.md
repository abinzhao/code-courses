## 学习目标

- 能把共享业务逻辑与平台适配分开。
- 能完成一个离线阅读/编辑端，验证权限拒绝与恢复。
- 能设计桌面 IPC 的有限能力边界。

## 内容讲解

### 1. 共享与不共享

共享数据 schema、搜索、校验与同步协议；分别适配路由、存储、系统文件、登录和 UI。浏览器 DOM 组件不能直接在 React Native 使用，Electron 也不能因 UI 是网页就放开所有 Node 权限。

```text
shared: types / validation / sync
adapters: web / mobile / desktop
screens: 各平台导航、交互与状态
```

只抽真实重复逻辑，不为一个单次页面建立复杂平台框架。

### 2. React Native 主路径

阅读列表 → 缓存详情 → 离线收藏 → 重连同步。列表用适当虚拟列表，图片明确尺寸与缓存，避免全部记录进 ScrollView。

权限在用户点击相关功能时申请，拒绝后提供替代；敏感凭据按平台使用安全存储，不默认放普通键值存储。应用后台、被杀和重新启动都要恢复已确认记录。

同步使用 mutationId/baseRevision，冲突规则复用 Web 契约。平台网络异常、超时与会话过期保持明确状态。

### 3. Electron 安全边界

窗口默认使用 contextIsolation 与 sandbox，关闭 nodeIntegration；renderer 通过 preload 暴露有限 API：

```js
// preload：示意已有主进程 downloadArticle handler 的调用契约。
const { contextBridge, ipcRenderer } = require('electron');
contextBridge.exposeInMainWorld('atlas', {
  downloadArticle: (id) => ipcRenderer.invoke('article:download', { id }),
});
```

不能暴露任意 `ipcRenderer.send`、fs 或 shell。主进程检查消息 schema、sender frame URL、资源权限和目标路径；从 renderer 来的 id 仍是不可信数据。

此片段不是完整应用，需配合主进程 handler、窗口配置与测试。不要为省事关闭 sandbox 让远端页面具备系统能力。

### 4. 系统文件与更新

用户通过系统对话框选择导出位置，默认拒绝静默覆盖。文件名、归档路径和内容限制由主进程执行。

打包、签名、自动更新与回滚按目标平台验证；更新包需要可信分发和完整性校验。应用可启动不代表签名、Gatekeeper 或系统权限已通过。

### 5. 验证矩阵

移动端：低端机、软键盘、横竖屏、返回、权限拒绝、弱网、后台恢复。桌面端：安装、窗口恢复、键盘、文件冲突、未知 IPC、外部导航、更新失败。

目标是完成其中一个实际端，不能把两份概览文字当跨端作品。

## 常见问题

**共享 UI 越多越好吗？** 平台交互差异可能使维护和体验成本更高，按重复逻辑和验证成本判断。

**本地数据是否天然安全？** 文件和存储权限、XSS/IPC 与设备丢失都影响安全。

## 实操作业

基础选择实际平台完成阅读；进阶实现离线收藏与冲突恢复；挑战验证 IPC 或移动权限拒绝并交付平台包。

### 参考答案与验收

实际安装运行；离线修改不丢失、重试不重复；未知 IPC/拒绝权限不突破边界；未测平台不宣称兼容。

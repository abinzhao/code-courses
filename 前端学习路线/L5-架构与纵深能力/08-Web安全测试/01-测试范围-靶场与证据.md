## 学习目标

- 能把威胁模型变成有范围、预期和证据的测试。
- 能运行本地靶场并区分漏洞版、修复版与未验证项。
- 能交付开发者可以复现、修复和回归的报告。

## 内容讲解

### 1. 测试契约

本课程唯一默认目标是 [Atlas 本地安全靶场](../../projects/security-lab/README.md)。如果改为其他环境，先取得明确授权并记录域名、端口、角色、测试窗口、允许动作、数据处理和停止条件。

测试不以“能打开网站”作为授权。重点验证应用行为，不进行第三方目标扫描、真实账号尝试或数据获取。

### 2. 从功能建立攻击面

| 功能 | 不可信输入 | 信任跨越 | 预期控制 |
|---|---|---|---|
| 文章预览 | title/正文 | 数据 → HTML | 文本渲染/净化 |
| 草稿读取 | 资源 ID | 用户 → 他人资源 | 对象授权 |
| returnTo | URL | 本站 → 外部导航 | 路由允许列表 |
| 资料修改 | Cookie/表单 | 跨源 → 状态写入 | CSRF 约束 |
| 附件 | 文件内容 | 上传 → 存储/执行 | 大小、格式、隔离 |

先观察正常业务请求，再只改变一个变量。一次改十个字段得到失败，无法确定控制在哪一层生效。

### 3. 运行靶场

```bash
cd 前端学习路线/projects/security-lab
npm test
npm run start:vulnerable
```

只监听回环地址，重启重置虚构数据。停止后运行 `npm start` 切换修复版，重复完全相同输入。

自动测试证明 HTTP 与服务端分支；XSS 执行、Cookie 和浏览器来源策略需真实浏览器验证。不能从 HTML 字符串出现 `<img>` 就推断脚本执行成功。

### 4. 证据分层

1. 请求：方法、URL、测试身份、必要头、脱敏 body。
2. 响应：状态码、Content-Type、关键头和最小相关正文。
3. 行为：DOM marker、资料变化或不应可读的虚构资源。
4. 根因：入口到危险 sink/缺失授权的位置。
5. 修复：最小控制与兼容影响。
6. 回归：同一请求失效，正常请求仍成功。

“扫描器提示高危”只是线索。报告必须区分已确认、待复现、误报、未覆盖，给出真实业务影响而非工具等级照抄。

### 5. 参考资料的版本

WSTG 的测试编号和章节会随版本改变，报告引用版本化地址。ASVS 用于验证要求，WSTG 用于测试思路，OWASP Top 10 是风险概览，三者不能当同一本“漏洞清单”。

## 常见问题

**渗透测试是否等于跑扫描器？** 不等于，业务权限和状态变化通常需要手工验证与代码追踪。

**没有发现漏洞能否写“系统安全”？** 只能说明本次范围内未确认问题，需列明范围和未覆盖项。

## 实操作业

基础运行靶场并记录版本模式；进阶为四个入口建立测试表；挑战完成一份有请求、影响、修复和复测的报告。

### 参考答案与验收

每个已确认问题需要漏洞版成立、修复版不成立、正常功能保留；只绑定回环地址；报告没有真实敏感数据。使用[报告模板](../../阶段考核/安全测试报告模板.md)。

## 学习目标

- 能捕获并最小化本地请求，使用 curl 或代理重复验证。
- 能区分认证、功能授权、对象授权与租户授权。
- 能建立覆盖读写接口的权限矩阵。

## 内容讲解

### 1. 工具职责

DevTools Network 可观察浏览器发送什么；Copy as curl 可重放同一请求；ZAP/Burp 的代理与 Repeater 等能力便于逐字段修改。重放工具不受浏览器 CORS，因而不适合证明浏览器响应可读。

本课可只用 curl，不强制安装代理。使用代理时建立专用测试浏览器资料，只访问本地靶场；不要把工作浏览器、真实 Cookie 或账号流量混入测试。

HTTPS 代理会涉及本机测试证书信任，只在隔离测试资料配置并在结束后移除，不修改全局工作信任设置。

### 2. 最小请求

```bash
curl -i -H 'x-lab-user: alice' http://127.0.0.1:4185/api/drafts/draft-a
curl -i -H 'x-lab-user: alice' http://127.0.0.1:4185/api/drafts/draft-b
curl -i http://127.0.0.1:4185/api/drafts/draft-a
```

漏洞版预期 200/200/401，修复版 200/403/401。`x-lab-user` 是虚构身份模拟，真实业务中身份应来自服务端验证的会话。

### 3. 权限矩阵

| 身份 | 自己草稿 | 他人草稿 | 审核文章 | 其他租户 |
|---|---:|---:|---:|---:|
| 未登录 | 拒绝 | 拒绝 | 拒绝 | 拒绝 |
| 作者 | 允许 | 拒绝 | 按规则 | 拒绝 |
| 审核员 | 按职责 | 按职责 | 允许 | 拒绝 |
| 管理员 | 按规则 | 按规则 | 按规则 | 默认拒绝 |

资源 ID 不可预测只能降低枚举，不能替代授权。隐藏按钮、路由守卫和客户端 role 字段也不是服务端授权。

测试每个 GET/POST/PUT/DELETE，列表和导出同样要过滤权限；批量操作不能只验证第一条。GraphQL、tRPC、Server Actions 和 WebSocket 消息也是远程入口。

### 4. 状态变化测试

先创建虚构资源，再以其他身份修改、发布、删除；拒绝响应后检查数据库/状态没有变化。状态码 403 但业务已经写入仍是漏洞。

检验会话撤销、角色改变、转移归属后旧请求能否继续访问。跨租户共享缓存是另一条泄漏路径，需验证缓存命中时也执行正确隔离。

### 5. 代理练习步骤

1. scope 仅包含 `http://127.0.0.1:4185`。
2. 用正常页面产生请求，确认代理历史中的身份与路径。
3. 将自己的草稿请求发送到重放界面，只改 draft ID。
4. 保存最小请求和响应，切换修复版重试。
5. 退出测试资料，清理仅本课产生的临时证据与测试会话。

无需主动扫描即可完成本课。主动扫描是有副作用的测试，另行设范围、速率和数据恢复。

## 常见问题

**403 与 404 哪个安全？** 由资源可发现性和产品规则决定，重点是不返回内容或写入，并保持一致契约。

**管理员是否自然可以跨租户？** 不应推断，权限需显式定义。

## 实操作业

基础重放三个请求；进阶对 Atlas 读写接口填写矩阵；挑战测试批量操作与会话撤销后的请求。

### 参考答案与验收

未登录 401、已登录无权限 403（或项目规定的隐藏资源响应）；越权无数据与副作用。每项证据注明测试身份，不能凭 UI 按钮判断权限。

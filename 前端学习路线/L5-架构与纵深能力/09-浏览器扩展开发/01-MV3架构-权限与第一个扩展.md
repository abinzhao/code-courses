## 学习目标

- 能区分 popup、内容脚本、扩展 worker 与网页的职责。
- 能加载一个 MV3 扩展，用最小权限完成本地采集。
- 能处理受限页面和权限失败，而不要求全站访问。

## 内容讲解

### 1. 上下文

```text
用户点击 action → popup → runtime 消息 → service worker
                                      ↓ scripting
                           页面 isolated world → 数据
                                      ↓
                               storage.local
```

popup 有 DOM，但关闭后页面销毁；内容脚本访问网页 DOM，但 JS 环境通常隔离；worker 没有 window/document，不是永久后台页；网页是低可信数据来源。

现代扩展与 Flash/NPAPI 插件不同。本课程“浏览器插件”指 WebExtensions/MV3。

### 2. 运行起点

加载[本地采集器](../../projects/browser-extension/README.md)，先运行：

```bash
npm --prefix projects/browser-extension test
npm --prefix projects/browser-extension run check
```

然后从 `chrome://extensions` 加载其目录，在本地 Atlas 页选择文字并点击采集。完整源码位于 `projects/browser-extension`；不是只有伪代码的概览。

### 3. 清单

```json
{
  "manifest_version": 3,
  "name": "Atlas 本地采集练习",
  "version": "0.1.0",
  "permissions": ["activeTab", "scripting", "storage"],
  "background": { "service_worker": "background.js", "type": "module" },
  "action": { "default_popup": "popup.html" }
}
```

`activeTab` 是用户操作触发的临时页面访问能力；scripting 是执行注入的 API 权限；storage 是扩展持久化。三者不能互相代替。受限内置页面和商店页面仍不能任意注入。

不需要自动读取所有站点就不要申请 `<all_urls>`。host 权限、普通 API 权限和 optional 权限应按产品功能分别解释。

### 4. 调试与失败

popup、worker 和网页各有独立 Console。popup 看不到 worker 局部变量；网页 Console 的错误也不等于扩展代码失败。

检查清单加载错误、文件路径、Promise 拒绝和当前 tab 变化。受限页面给出错误状态；popup 关闭后任务结果保存到 storage，下一次打开恢复。

## 常见问题

**后台脚本能操作 DOM 吗？** MV3 worker 无 DOM；页面读取在内容脚本，特殊 DOM 任务可评估 offscreen document，但不应先加复杂上下文。

**有 activeTab 就能长期后台采集吗？** 不能，权限来源、生命周期和导航都有约束。

## 实操作业

基础加载并采集；进阶在受限页和无选中文字时验证；挑战画四个上下文的数据流并列出各自可用 API。

### 参考答案与验收

普通页保存标题与最多 2000 码元选中文字；受限页显示失败；清单无全站权限。提交截图和 storage 记录，Node 测试不能替代扩展加载验证。

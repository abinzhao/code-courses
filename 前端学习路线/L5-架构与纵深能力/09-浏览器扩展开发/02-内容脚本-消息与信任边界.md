## 学习目标

- 能区分 isolated world、MAIN world 与共享 DOM。
- 能建立消息 schema、发送者检查与有限特权操作。
- 能处理版本不同的异步响应与序列化。

## 内容讲解

### 1. 隔离不是数据可信

isolated world 不直接共享网页 JS 变量，但共享 DOM。页面可改变标题、文本和属性，扩展必须把读取结果当不可信输入。

MAIN world 可以与网页脚本交互，也更容易被页面影响。默认用 isolated world，不能为取一个标题就注入 MAIN 或运行远端脚本。

### 2. 消息协议

```js
{ type: 'clip:current', tabId: 7 } // 本地起点协议；requestId 是进阶作业
{ ok: true, clip: { url, title, text } }
{ ok: false, error: '稳定的用户可读原因' }
```

不要提供“替我 Fetch 任意 URL”“执行任意代码”“读任意文件”的通用特权消息。内容脚本可以被恶意页面影响，worker 只允许产品需要的有限操作。

起点 popup 查询自己窗口中的活动 tab，将 ID 发给 worker。worker 检查 `sender.id`、自己 popup URL、type 和整数 tabId，再通过 tabs.get 检查标签仍活跃；页面返回数据经过 validateClip。worker 未必有可用的“当前窗口”，不能把窗口查询直接从 popup 搬过去。tab ID 也不授予权限，executeScript 仍受 activeTab 控制。

后续接收内容脚本消息时还要校验 sender.tab、frame 和 origin，并核对目标资源。

### 3. 异步响应

```js
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  if (message?.type !== 'status:get') return;
  chrome.storage.local.get('status').then((value) => {
    sendResponse({ ok: true, value });
  }).catch(() => {
    sendResponse({ ok: false, error: '读取失败' });
  });
  return true;
});
```

字面量 true 保持异步响应通道。新 Chrome 已开始支持监听器返回 Promise，官方说明从 Chrome 148 起逐步推出；面向旧版本或未启用该行为的用户，继续使用以上模式。不要写成“Chrome 永远不能 async onMessage”。

多个监听器竞争响应时可能得到首个响应；把 type 分发集中或明确路由，避免无关 async 监听器返回 undefined 抢占结果。

Chrome 消息按 JSON 序列化，与部分浏览器的 structured clone 不同。不要传函数、DOM、循环引用或直接假设 Date/Map 的形状保留；跨浏览器统一使用明确 JSON schema。

### 4. 渲染与资源

popup 用 textContent 输出采集结果，不能 innerHTML。内容脚本添加 UI 时可用 Shadow DOM 减少样式冲突，但 Shadow DOM 不是安全沙箱。

web_accessible_resources 只开放需要被网页读取的资源和匹配范围，不能公开内部配置或秘密。

## 常见问题

**检查 sender.id 就够了吗？** 同一扩展不同上下文权限不同，还要检查来源上下文、消息类型与字段。

**postMessage 给页面安全吗？** 需 origin/source/schema 校验，且不能把敏感扩展数据回传页面。

## 实操作业

基础逐项测试 validateClip；进阶给消息加 requestId 与稳定错误码；挑战从网页构造伪消息，验证不能触发 worker 特权操作。

### 参考答案与验收

拒绝未知 type、危险协议、异常字段和非登记 sender；HTML 只显示文本。消息失败可恢复，不无限保持 pending。

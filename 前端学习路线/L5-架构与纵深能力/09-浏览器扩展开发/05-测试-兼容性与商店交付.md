## 学习目标

- 能区分纯逻辑测试、加载测试与生命周期测试。
- 能验证 Chrome/Firefox 差异并交付最小分发包。
- 能说明权限、隐私与远程代码政策，而不把“可加载”当可发布。

## 内容讲解

### 1. 测试矩阵

| 层次 | 验证 |
|---|---|
| 单元 | URL/schema/截断/迁移纯函数 |
| 清单 | 权限、入口、文件存在、版本 |
| 真实扩展 | activeTab 注入、消息、popup 与 storage |
| 生命周期 | popup 关闭、worker 停止、浏览器重启、更新 |
| 安全 | 非登记 sender、危险协议、HTML 文本、权限拒绝 |
| 兼容 | 每个目标浏览器与 API 差异 |

Node 测试不提供 chrome API；用假 chrome 对象只能验证调用意图，不能证明权限与生命周期。

### 2. 自动加载

Playwright 等方案通常需要持久浏览器上下文并以专用资料加载扩展。Chrome/Edge 新版本对命令行侧载有额外限制，使用工具官方支持的 Chromium/channel 方式，不沿用旧启动参数假设。

保持 profile 在临时目录，不借用用户工作资料。测试记录 browser/channel/version、扩展路径和构建版本。不要启用关闭所有安全策略的参数。

### 3. 手工主路径

1. 本地 HTTP 页面选择文字。
2. action 打开 popup 并采集。
3. 关闭再开验证持久化。
4. 停止 worker 后再采集。
5. 在受限页验证错误。
6. 网页含 HTML 风格文字时验证不执行。
7. 更新 schema 后保留旧数据。

可见 popup 的真实 action 路径和直接导航 popup.html 是不同测试，报告中分开记录。

### 4. 浏览器兼容

Chrome 使用 chrome 命名空间，其他浏览器常使用 browser 与 Promise 风格；可评估维护良好的 polyfill，但先列具体 API 差异。MV3 后台形式、消息序列化、DNR 和 host 权限行为不完全相同。

Safari 涉及平台封装与分发，不能只改 manifest 就承诺支持。只测 Chromium 时明确其他浏览器未验证。

### 5. 商店交付

分发包只含运行文件，不含 node_modules、测试缓存、账号和无关构建资源。逐项解释权限与数据用途，提供隐私说明、保存期、导出与删除入口。

MV3 对远程托管代码有限制，不能通过 CDN/eval 绕开审查；远端数据与远端可执行代码必须区分。

商店提交是外部写入，本课程要求完成可审查包与交付说明，真实提交需单独确认。商店审核通过也不替代安全测试。

## 常见问题

**开发者模式加载成功能代表商店通过吗？** 不能，还涉及政策、权限说明、产品完整性和分发资料。

**新版本能直接删除旧 storage 吗？** 不能默认丢失用户记录，必须迁移或显式导出/确认。

## 实操作业

基础完成测试矩阵；进阶记录 worker 重启与 schema 升级；挑战给出 Chromium/Firefox 差异和最小交付包。

### 参考答案与验收

测试证据注明是否真实 action、浏览器版本与资料目录；无全站过度权限；升级保留记录；包内无凭据。未测平台明确列出。

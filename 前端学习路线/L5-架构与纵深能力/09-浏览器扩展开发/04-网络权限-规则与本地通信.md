## 学习目标

- 能区分 host 权限、页面 CORS 与内容脚本网络边界。
- 能选择声明式规则或本地通信，并控制特权接口。

## 内容讲解

### 1. 网络职责

起点不发请求，无 host 权限。增加“发送到 Atlas”前先定义固定服务 URL、身份、隐私说明、大小与超时。

扩展 worker 在具备 host 权限时可进行对应跨源请求；内容脚本的请求仍有网页来源相关限制。不要把“扩展有权限”误认为所有上下文自动绕过 CORS。

可选 host 权限应由明确用户动作触发申请，拒绝后仍可本地保存/导出。origin pattern 的权限匹配与 URL 路径业务限制不同，服务端仍需校验 endpoint 和数据。

### 2. 避免通用代理

错误协议：内容脚本传任意 URL，worker 帮忙 fetch 并回传结果。这样让恶意页面借扩展访问高权限资源。

正确协议：内容脚本提交经过校验的 clip，worker 根据固定配置访问登记 API；身份不回传网页，响应只包含完成状态与资源 ID。

URL、重定向、响应大小和超时都需限制；不要让网页通过消息决定请求 Authorization 或任意 headers。

### 3. declarativeNetRequest

MV3 的 DNR 让浏览器按声明规则匹配和执行阻断/重定向/头修改，适合有限规则。规则数量、条件和权限限制随版本变化，按官方文档核对。

它不是“读取所有请求正文并执行任意同步 JS”的替代品。规则优先级、静态/动态/session 规则和 allow/block 冲突需要测试。起点采集器不需要 DNR，不能为教学完整性先申请权限。

### 4. Native Messaging

Native host 是单独注册到操作系统的本地程序，不是访问任意系统能力的后门。消息使用带长度前缀的 JSON 协议，stdout 只写协议，日志写 stderr。

host 配置限制 allowed_origins，程序只处理明确命令并限制文件路径。扩展来源身份不自动等于用户授权，敏感动作仍需确认。

安装注册路径、允许来源字段与支持范围因 OS/浏览器不同。课程可用已有 CLI 设计协议，但没有注册和真实消息验证不能称 Native Messaging 已实现。

### 5. 本地 HTTP 与原生通信选择

| 方式 | 优点 | 成本 |
|---|---|---|
| 固定本地 HTTP | 调试简单、复用服务 | 端口、身份、来源与浏览器本地网络策略 |
| Native Messaging | 不暴露普通监听端口 | 安装注册、平台分发与严格帧协议 |
| 手工 JSON 导出 | 无常驻通信与额外权限 | 需要用户导入 |

低预算本地优先产品可先完成导出，确认实际需要再增加通道。回环服务也必须鉴权并限制 origin/host，不能假设“本机请求都可信”。

## 常见问题

**host 权限能替代登录吗？** 不能，服务端照常认证授权。

**DNR 能实现任意抓包器吗？** 能力有明确范围，不能假设全部正文可见。

## 实操作业

基础设计固定 endpoint 同步；进阶模拟权限拒绝与超时；挑战为 CLI 与 Native host 写有限消息 schema 和平台验证清单。

### 参考答案与验收

网页无法控制目标 URL；拒绝权限后仍能本地保存；超时重试保持幂等。Native host 未运行时注明只完成协议设计。

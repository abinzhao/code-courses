# 前端工程师完整学习路线

这是一套从 Web 基础到生产级架构能力的前端工程师教程，目标读者是零基础学员，最终目标是具备独立设计、开发、测试、部署和维护中型生产系统的能力。

课程按 `L0-L5` 六个层级递进：

```text
L0 Web 基石
  ↓
L1 JavaScript 与 TypeScript
  ↓
L2 框架与组件化
  ↓
L3 工程化与质量保障
  ↓
L4 全栈与服务端
  ↓
L5 架构与纵深能力
```

## 推荐学习顺序

### 第一阶段：L0-L1

先掌握浏览器、HTML、CSS、网络、JavaScript 和 TypeScript。不要在 JavaScript 基础薄弱时直接跳到 React 或 Vue。

- L0 全部完成后，再进入 L1。
- L1 中先学语法核心，再学异步和进阶机制。
- TypeScript 可以从 L1 开始与 JavaScript 同步使用，不必等到最后才接触。
- 模块化与包管理是 L1 的收尾，完成后再进入框架层。

### 第二阶段：L2-L3

选择 React 或 Vue 作为主框架深入，另一套框架用于建立迁移能力。组件设计模式、状态管理和路由需要结合真实页面练习。

- React 和 Vue 不要求同时作为主线深入。
- L2 的模式文档要用至少一个 React 项目和一个 Vue 小练习验证。
- L3 的测试、Git、CI/CD 不应被当作“项目做完再补”的内容。

### 第三阶段：L4

以 Next.js 为主线完成全栈项目，同时补齐 Node.js、REST/tRPC、PostgreSQL、Prisma、Docker 和 Nginx。

- 先掌握 Node.js 运行时，再学习 Next.js 的服务端边界。
- API 校验必须放在服务端，前端校验只负责改善交互体验。
- 数据库迁移、事务、索引和部署必须实际运行，不能只阅读配置。

### 第四阶段：L5

以 L4 的全栈项目为基础，逐步加入性能预算、安全门禁、错误监控、RUM、设计系统和架构文档。

- L5 不是额外堆技术名词，而是把已有项目提升到可长期维护的质量标准。
- 性能、安全和可观测性应该进入项目设计，而不是出现事故后再补。
- 架构治理文档应以 ADR 和 RFC 的形式留下决策依据。

## L0-L5 贯穿项目方案

### 项目名称：Atlas 知识协作平台

Atlas 是一个逐层演进的知识协作平台，功能主线保持不变，技术复杂度随课程层级提升：

```text
静态知识主页
  → TypeScript 模块化应用
  → React/Vue 组件化前端
  → 组件库与自动化交付
  → Next.js 全栈知识平台
  → 具备性能、安全、观测和治理能力的生产系统
```

最终产品至少包含：

- 知识文章列表、分类、标签和全文搜索
- 文章详情、目录、代码块、收藏和阅读进度
- 用户登录、个人工作台和草稿编辑
- 评论、审核、发布和版本记录
- 管理后台、权限控制、操作审计

项目数据可以使用本地种子数据，不要求一开始接入真实业务。每个阶段都必须提交可运行版本和验证记录。

### L0：静态知识主页

**目标**：用原生 HTML、CSS 和浏览器能力完成一个可访问、响应式、可部署的知识主页。

**功能范围**：

- 首页、文章列表、文章详情三个页面。
- 语义化导航、主内容、侧栏、页脚。
- 响应式布局：至少覆盖 320px、768px、1440px。
- 搜索框交互、文章标签筛选、目录锚点跳转。
- 暗色模式、减少动画偏好和键盘导航。

**技术要求**：

- 不使用前端框架。
- 使用 HTML5 语义标签、表单约束、CSS Grid/Flex 和容器查询。
- 使用 DevTools 分析 Network、Performance 和 Storage。
- 用一个简单静态服务器运行，不能依赖 `file://`。

**交付物**：

1. 可部署的静态站点。
2. 一份页面语义与可访问性检查表。
3. 一份 Network 和 Performance 面板分析记录。
4. Lighthouse 移动端审计结果。

**验收标准**：

- 键盘可以完成导航、搜索和文章目录跳转。
- 320px 宽度下没有横向滚动。
- 图片和内容区域不会造成明显布局偏移。
- 主要请求、缓存命中和错误状态可以在 DevTools 中解释清楚。

### L1：模块化知识工作台

**目标**：把 L0 静态站点升级为 TypeScript 驱动的模块化应用，建立可靠的数据模型和异步流程。

**功能范围**：

- 文章数据、标签数据和搜索状态使用 TypeScript 类型描述。
- 通过 ESM 拆分 `article`、`search`、`storage`、`render` 模块。
- 搜索输入使用防抖和 `AbortController`，避免过期请求覆盖新结果。
- 收藏和阅读进度保存到 LocalStorage。
- 文章详情支持动态加载和错误恢复。
- 使用 Web Worker 处理一批文章的索引或摘要计算。

**技术要求**：

- 开启严格 TypeScript 配置。
- 不依赖全局变量传递业务状态。
- 至少写出一个生成器或异步生成器，用于分页模拟。
- 对核心工具函数编写边界测试。
- 使用 pnpm 管理依赖，并把项目拆成至少一个可复用包。

**交付物**：

1. TypeScript 模块化应用。
2. 文章、用户偏好、搜索结果的类型定义。
3. 一个可复用的 `@atlas/shared` 包。
4. 异步请求取消和竞态处理说明。
5. Worker 前后对比的性能记录。

**验收标准**：

- `tsc --noEmit` 无错误。
- 搜索快速输入时，旧请求不能覆盖新结果。
- 刷新页面后收藏和阅读进度仍然存在。
- 删除一个模块导出时，所有受影响调用点能在编译阶段暴露。

### L2：组件化知识平台

**目标**：使用 React 作为主实现，将知识工作台重构为可维护的组件系统；用 Vue 完成关键页面迁移练习。

**功能范围**：

- React 版本包含布局、文章卡片、搜索栏、标签筛选、目录、Modal、Tabs、表单和分页组件。
- 状态按客户端状态与服务端状态分离。
- 路由支持文章详情、用户工作台和管理入口。
- 文章列表支持加载态、空态、错误态和分页。
- 表单同时覆盖受控组件和非受控组件。
- 选择一个核心页面，用 Vue 3 + Composition API 重写。

**技术要求**：

- 统一 Props、事件、children/slots 和组件边界。
- 不把所有状态放进全局 store，优先就近放置。
- 使用 React Router 或 Vue Router 实现嵌套路由和权限守卫。
- 使用 TanStack Query 或等价方案处理服务端状态。
- 至少完成一个复合组件，例如 `Tabs`、`Select` 或 `Modal`。

**交付物**：

1. React 主应用。
2. Vue 关键页面迁移版本。
3. 组件 API 说明和状态归属表。
4. 路由结构图和权限入口说明。
5. 一份组件渲染性能分析记录。

**验收标准**：

- 组件可以在不同页面组合使用，而不是复制粘贴。
- 路由刷新、动态参数、未授权访问和不存在页面均有正确状态。
- 服务端请求有缓存、错误和重试策略。
- 组件的 loading、empty、error、disabled 状态完整。

### L3：可交付的前端工程

**目标**：把 Atlas 变成一个具备工程规范、测试和自动化交付能力的项目。

**功能范围**：

- 使用 Vite 构建，配置开发代理、环境变量、代码分割和资源处理。
- 建立 ESLint、Prettier、Husky、lint-staged 和 commitlint。
- 建立公共 UI 包和共享配置包。
- 编写工具函数单元测试、核心组件测试和关键用户路径 E2E。
- Pull Request 自动执行 lint、类型检查、测试和构建。
- 每个 Pull Request 生成一个可访问的预览产物。

**技术要求**：

- 测试行为和业务契约，不测试实现细节。
- 核心业务逻辑覆盖率目标为 90% 以上，关键路径必须有 E2E。
- CI 使用 `pnpm install --frozen-lockfile`。
- 失败的质量门禁不得自动绕过。
- 为构建产物设置基础体积预算。

**交付物**：

1. Monorepo 目录和包依赖图。
2. ESLint/Prettier/Husky 配置。
3. 单元、组件和 E2E 测试套件。
4. GitHub Actions CI 配置。
5. PR 预览部署配置。

**验收标准**：

- 新成员按照文档可以完成安装、开发、测试和构建。
- 提交不符合规范时会被 hook 拦截。
- 主流程测试失败时 CI 为失败状态。
- 一个只修改共享 UI 的 PR 会触发相关消费者的构建和测试。

### L4：全栈知识协作平台

**目标**：让 Atlas 具备真实用户、数据持久化、服务端渲染和生产部署能力。

**功能范围**：

- 使用 Next.js App Router 实现公开文章、登录、工作台和管理后台。
- 使用 Server Components、Server Actions、Route Handlers 和 Middleware。
- 使用 Node.js 实现需要独立运行的服务端能力或脚本。
- 使用 PostgreSQL 存储用户、文章、标签、评论和审计记录。
- 使用 Prisma 管理 schema、迁移、事务和索引。
- 使用 Zod 在服务端完成请求校验和错误分类。
- 使用 Docker Compose 启动应用、PostgreSQL 和可选 Redis。
- 使用 Vercel/Cloudflare 或 Nginx 完成一次可复现部署。

**交付物**：

1. 数据库 ER 图和迁移文件。
2. REST 或 tRPC API 契约。
3. 登录、文章发布、评论和权限控制闭环。
4. Dockerfile、Compose 文件和环境变量说明。
5. 预发布环境部署记录和回滚步骤。

**验收标准**：

- 未登录用户不能进入工作台和管理后台。
- 服务端拒绝非法输入，数据库错误不会直接暴露给用户。
- 文章发布和评论写入使用明确的事务边界。
- 数据库迁移可在全新环境重复执行。
- 部署后具备健康检查、日志和基本错误恢复能力。

### L5：生产级 Atlas 平台

**目标**：在 L4 的系统上建立可量化的性能、安全、可观测性和架构治理能力。

**功能范围**：

- 为首页、文章详情和工作台建立 LCP、INP、CLS 性能预算。
- 对路由和重型编辑器实施代码分割、预加载和图片优化。
- 配置 CSP、CSRF 防护、Cookie 安全策略、依赖审计和供应链门禁。
- 接入 Sentry 错误监控、Web Vitals RUM、业务埋点和版本关联。
- 建立 Design Tokens 和 Storybook 组件库。
- 把关键页面迁移到小程序、React Native 或 Electron 中的一个端。
- 用 ADR 记录技术选型，用 RFC 设计一次跨项目能力，用技术债清单管理遗留问题。

**交付物**：

1. 性能预算表、测量脚本和优化前后数据。
2. 前端安全检查表和 CI 安全门禁。
3. Sentry/RUM 接入配置和告警规则。
4. Design Tokens、组件库和 Storybook 页面。
5. 一个跨端最小可用版本。
6. 至少 3 篇 ADR、1 篇 RFC 和一份技术债路线图。

**验收标准**：

- 核心页面在目标设备上达到既定 Web Vitals 预算。
- 关键错误能够定位到 release、页面和用户操作面包屑。
- 安全扫描发现高风险依赖时 CI 阻断。
- 组件库拥有稳定 API、无障碍属性和交互测试。
- 重大架构决策能够从文档中追溯背景、备选方案和后果。

## 每篇文档的学习方法

每篇文档按相同节奏完成：

1. 先读“学习目标”，把目标改写成自己的验收问题。
2. 阅读“内容讲解”，同步运行代码，不只复制代码。
3. 先独立回答“常见问题”，再对照答案找漏洞。
4. 完成基础、进阶、挑战三级作业；至少提交挑战题中的一部分。
5. 在 Atlas 项目中找到对应落点，把孤立练习合并到主线项目。
6. 记录一个“现象—原因—验证—结论”，训练排查能力。

## 阶段完成标准

| 阶段 | 不满足以下条件，不建议进入下一阶段 |
|---|---|
| L0 | 能独立做出响应式、可访问页面，并解释一次请求到渲染的完整链路 |
| L1 | 能不用框架写出类型安全的异步模块，并处理取消、错误和边界 |
| L2 | 能设计组件边界、状态归属和路由结构，覆盖 loading/error/empty 状态 |
| L3 | 能让团队通过规范、测试和 CI 稳定交付，而不是靠个人记忆 |
| L4 | 能完成认证、数据、API、迁移、容器和部署闭环 |
| L5 | 能用数据解释性能和稳定性，用文档解释架构决策和技术债 |

## 技术基线

课程示例按 2026 年的现代 Web 工程实践组织，涉及具体版本时以文档中的版本说明、官方文档和项目锁文件为准。版本敏感内容包括：

- ECMAScript、TypeScript、Node.js
- React、Vue、Next.js
- Vite、Rspack、Webpack
- PostgreSQL、Prisma
- Vitest、Testing Library、Playwright
- Sentry、Storybook、Changesets

生产项目不要只因为课程中的版本号就直接升级。升级前应检查运行时兼容性、依赖变更、迁移说明、构建结果和回滚方案。

## 范围边界

这套路线重点培养 Web 前端和全栈工程能力，不把以下方向作为主线展开：

- 原生 iOS/Android 应用开发
- 大规模后端分布式系统
- 机器学习模型训练
- 专业图形学和游戏引擎开发
- 企业级云平台运维

这些方向可以在完成 L4 后按实际岗位或项目需要扩展。课程的完成标志不是记住所有 API，而是能够验证系统行为、解释设计取舍，并把功能稳定交付出去。

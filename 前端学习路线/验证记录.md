## 浏览器验证

在独立测试资料使用 Chrome for Testing 153.0.8010.12，通过实际浏览器运行：

| 行为 | 观察与结果 |
|---|---|
| XSS 漏洞模式 | 本地 marker 执行，`document.body.dataset.lab` 为 `xss` |
| XSS 修复模式 | marker 未执行，h1 原样显示输入文本 |
| 同站跨源 POST：漏洞模式 | 浏览器实际携带虚构 Cookie，Origin 为另一回环端口；200 且资料变化 |
| 同站跨源 POST：修复模式 | 同样携带 Cookie/Origin；403 且资料未变化 |
| MV3 action → popup → worker → isolated world → storage | 采集 Atlas 标题和选中文字，保存本机记录 |
| popup 关闭再打开 | 从 storage 恢复相同记录 |
| worker 停止后重新采集 | 停止 worker 后再次发送消息，重新唤醒并采集成功 |

扩展 action 由 CDP 触发，浏览器授予真实 activeTab 权限；没有增加 host_permissions，也没有 Mock chrome API 来代替这组运行证据。另有 Node Mock 测试仅负责消息门禁回归，两类证据分别记录。

浏览器实验使用虚构身份、无害 DOM marker 和本地页面。端口不同为跨源但仍同站，结果证明 Origin 控制的作用，不能推广为所有跨站 SameSite 策略均已测试。

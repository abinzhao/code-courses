## 内容讲解

### 1. 为什么要学 TypeScript

你写过 JavaScript，一定遇到过这些场景：

1. 调用一个函数时传错了参数类型，程序静默地产生错误结果，直到用户反馈才发现。
2. 访问 `obj.someProperty`，拼写错误时得到 `undefined`，没有任何提示。
3. 重构代码改了函数签名，但漏掉了几个调用点，运行时才报 `xxx is not a function`。

TypeScript 就是 JavaScript 加了一套 **静态类型系统**。它在编译阶段（你敲代码的时候）就能发现这些问题，而不是等到运行时。

**核心价值**：

| 维度 | JavaScript | TypeScript |
|------|-----------|------------|
| 类型检查时机 | 运行时 | 编译时（写代码时就报错） |
| 代码提示 | 弱，只能靠 JSDoc 辅助 | 强大，IDE 能精确推断出每个变量上的可用属性与方法 |
| 重构安全性 | 依赖人工审查 | 改函数签名后，全项目未同步的调用点全部标红 |
| 大型项目维护 | 心智负担重，bug 多 | 类型即文档，新人也能安全修改 |

> TypeScript 的本质不是「给 JS 加类型」，而是「给 JS 加了一套在编译期验证代码正确性的证明系统」。

### 2. 基本类型注解

```typescript
// ---------- 原始类型（Primitive Types）----------
// string：任意字符串
let username: string = '张三';

// number：整数、浮点数、NaN、Infinity 全部是 number
let age: number = 25;
let price: number = 19.9;
let notANumber: number = NaN;     // 合法，NaN 的类型也是 number

// boolean：只有 true / false
let isLoggedIn: boolean = false;

// null 和 undefined：既是值，也是类型
let empty: null = null;
let notAssigned: undefined = undefined;

// symbol：创建唯一标识（常用于对象属性 key）
let uniqueKey: symbol = Symbol('id');

// bigint：超大整数，ES2020 引入
let hugeNumber: bigint = 9007199254740991n;
```

**易错点**：

```typescript
// ❌ 不能把其他类型赋给 null/undefined 类型的变量
let a: null = undefined;  // strict 模式下报错

// ✅ 正常场景：联合类型
let maybeString: string | null = null;  // 合法的可选值模式
```

### 3. 数组与元组

```typescript
// ---------- 数组（Array）----------
// 两种写法等价
let list1: string[] = ['a', 'b', 'c'];
let list2: Array<number> = [1, 2, 3];

// 混合类型：用联合类型
let mixed: (string | number)[] = ['hello', 42, 'world'];

// ---------- 元组（Tuple）：固定长度、固定类型的数组 ----------
// 典型场景：React useState 的返回值 -> [状态值, setter函数]
let user: [string, number] = ['张三', 25];

// 可选元素（元组尾部）
let config: [string, number, boolean?] = ['server', 8080];   // 第三个可以省略

// 具名元组（TS 4.0+）：给每个位置加标签，纯粹为了可读性
let httpResponse: [status: number, body: string] = [200, 'OK'];

// ❌ 固定元组的字面量索引越界会报错，现代 TypeScript 也不会允许这次赋值。
// @ts-expect-error：长度为 2 的元组不存在索引 2
user[2] = 'extra';
```

**对比表**：

| 特性 | 数组 | 元组 |
|------|------|------|
| 长度 | 不固定 | 固定 |
| 类型分布 | 所有元素同一类型或联合 | 每个位置独立类型 |
| 典型场景 | 同质数据集合 | `useState` 返回值、CSV 行、坐标对 |

### 4. 枚举（Enum）

```typescript
// ---------- 数字枚举（默认从 0 自增）----------
enum Direction {
  Up,       // 0
  Down,     // 1
  Left,     // 2
  Right     // 3
}

// 手动指定起始值
enum StatusCode {
  OK = 200,
  Created = 201,
  NotFound = 404
}

// ---------- 字符串枚举（没有自增，每个必须初始化）----------
enum LogLevel {
  Debug = 'DEBUG',
  Info = 'INFO',
  Error = 'ERROR'
}

// ---------- const enum：编译时内联，零运行时开销 ----------
const enum Colors {
  Red = '#FF0000',
  Green = '#00FF00'
}
let color = Colors.Red;   // 编译后直接变成 let color = '#FF0000';

// ⚠️ const enum 的坑：如果作为库发布，消费者无法引用 const enum。
// 库作者请用普通 enum 或在 tsconfig 中设置 preserveConstEnums。
```

### 5. any、unknown、never、void：四种「特殊类型」

这是初学者最容易混淆的概念。一句话总结：

| 类型 | 含义 | 何时使用 |
|------|------|----------|
| `any` | 关闭类型检查，可以赋值给任何变量，可以做任何操作 | **尽量不要用**，除非在渐进迁移 JS 项目时的临时兜底 |
| `unknown` | 「我不知道这是什么类型」——安全的 top type，必须先类型收窄才能操作 | 处理第三方 API 返回值、JSON.parse 结果 |
| `never` | 「这个值永远不会出现」——表示不可能 | 永远抛出异常的函数、穷尽性检查 |
| `void` | 「没有返回值」 | 没有 return 语句的函数、忽略返回值 |

```typescript
// ---------- any：逃逸类型检查 ----------
let anything: any = 123;
anything.nonExistent.method();   // 编译不报错，运行时爆炸 💥
let s: string = anything;        // any 可以赋值给任何类型，破坏类型安全

// ---------- unknown：安全版本的 any ----------
let data: unknown = fetchData();

// ❌ 直接操作 unknown 会报错
// data.toUpperCase();  // Error: Object is of type 'unknown'

// ✅ 必须先收窄类型
if (typeof data === 'string') {
  console.log(data.toUpperCase());   // 安全，TS 知道这里 data 是 string
}

// ---------- never：表示不可能的类型 ----------
// 场景1：永远抛错或死循环的函数
function throwError(message: string): never {
  throw new Error(message);
}

// 场景2：穷尽性检查（switch 遗漏会编译报错）
type Animal = 'dog' | 'cat' | 'bird';
function handleAnimal(animal: Animal) {
  switch (animal) {
    case 'dog': return '汪';
    case 'cat': return '喵';
    case 'bird': return '啾';
    default:
      // 如果 Animal 新增了成员但这里没处理，编译报错
      const _exhaustive: never = animal;
      return _exhaustive;
  }
}

// ---------- void：函数无返回值 ----------
function log(msg: string): void {
  console.log(msg);
  // 没有 return 语句
}
```

**`any` vs `unknown` 对比**：

```typescript
let a: any = 'hello';
let b: unknown = 'hello';

let x: string = a;     // ✅ any 可以赋值给任何类型（危险）
// let y: string = b;  // ❌ unknown 不能直接赋值给 string（安全）

if (typeof b === 'string') {
  let y: string = b;   // ✅ 收窄之后才允许
}
```

**实用建议**：如果你不知道一个值的类型，永远用 `unknown` 而不是 `any`。`unknown` 只是推迟了类型判断，`any` 是放弃了类型检查。

### 6. 类型推断（Type Inference）

TypeScript 有一套聪明的推断机制。**原则：能推断的就不写注解，这会让代码更干净。**

```typescript
// 变量初始化时自动推断
let name = '张三';         // 推断为 string
let count = 42;            // 推断为 number
let items = [1, 2, 3];    // 推断为 number[]

// 函数返回值自动推断
function add(a: number, b: number) {
  return a + b;            // 推断返回值为 number，不用手动写 : number
}

// 什么情况下必须写注解？
// 1. 函数参数（无法推断）
function greet(name: string) { }   // name 必须写

// 2. 声明但不初始化
let result: string;        // 不写就是 any（noImplicitAny 开启时报错）

// 3. 联合类型想收窄
let status: 'success' | 'error' = 'success';  // 不写会推断为 string

// 4. 对象字面量想锁住结构
const config = { host: 'localhost', port: 8080 };
// config 类型是 { host: string; port: number }，但 port 是 number 不是 8080
```

**最佳实践**：函数参数必写类型，返回值通常靠推断，变量能推断就不写——但公开 API 的返回值建议明确写注解。

### 7. 字面量类型（Literal Types）

```typescript
// 不是所有 string 都叫 string——精确到某个值
let direction: 'up' | 'down' = 'up';   // 只能取这两个值
// direction = 'left';  // ❌ 报错

// 数字也可以做字面量
let dice: 1 | 2 | 3 | 4 | 5 | 6 = 3;

// 对象字面量：as const 把所有属性锁死为字面量类型
const config = {
  host: 'localhost',
  port: 8080,
  debug: true
} as const;

// config 的类型变成：
// { readonly host: "localhost"; readonly port: 8080; readonly debug: true; }
```

### 8. 联合类型（Union Types）与类型守卫

```typescript
// 联合类型：值可以是多种类型之一
type ID = string | number;

function printId(id: ID) {
  // ❌ id.toUpperCase()  // 报错：number 没有这个方法

  // ✅ 类型守卫收窄
  if (typeof id === 'string') {
    console.log(id.toUpperCase());   // 这里 id 是 string
  } else {
    console.log(id.toFixed(0));      // 这里 id 是 number
  }
}

// 除了 typeof，还有这些收窄方式：
// instanceof：
function handleError(err: Error | string) {
  if (err instanceof Error) {
    console.log(err.message);
  } else {
    console.log(err);
  }
}

// 自定义类型守卫（is 关键字）：
interface Dog { bark(): void; }
interface Cat { meow(): void; }

function isDog(animal: Dog | Cat): animal is Dog {
  return 'bark' in animal;
}

// in 运算符：
function interact(animal: Dog | Cat) {
  if ('bark' in animal) {
    animal.bark();  // TS 知道这里是 Dog
  }
}
```

### 9. 交叉类型（Intersection Types）

```typescript
interface Nameable {
  name: string;
}
interface Ageable {
  age: number;
}

// 交叉类型：同时满足多个类型
type Person = Nameable & Ageable;

const p: Person = {
  name: '张三',
  age: 25
  // 必须同时有 name 和 age
};

// 交叉类型的实用场景：组合已有类型
type RequestConfig = {
  url: string;
  method: 'GET' | 'POST';
} & {
  headers?: Record<string, string>;
  timeout?: number;
};

// ⚠️ 冲突属性：如果交叉的类型有同名属性但类型不兼容
type A = { x: string };
type B = { x: number };
// type AB = A & B;  // x 变成 string & number → never，基本无法赋值
```

**联合 vs 交叉**：

| 特性 | 联合 `A \| B` | 交叉 `A & B` |
|------|---------------|--------------|
| 语义 | 要么 A，要么 B | 既是 A，又是 B |
| 属性 | 只能访问 A 和 B 共有的 | 拥有 A 和 B 全部的 |
| 类比 | 「或」 | 「且」 |

### 10. 实战：用 TypeScript 重写 JS 小项目

假设你有下面这个 JS 版本的 Todo 工具函数：

```javascript
// todos.js（无类型，隐患多）
let todos = [];

function addTodo(text) {
  todos.push({ id: Date.now(), text, done: false });
}

function toggleTodo(id) {
  const todo = todos.find(t => t.id === id);
  if (todo) todo.done = !todo.done;
}

function getStats() {
  const done = todos.filter(t => t.done).length;
  return { total: todos.length, done, pending: todos.length - done };
}
```

用 TypeScript 重写后的版本：

```typescript
// ---------- 定义数据类型 ----------
interface TodoItem {
  id: number;
  text: string;
  done: boolean;
}

// 数组类型明确，避免混入非法数据
let todos: TodoItem[] = [];

function addTodo(text: string): void {
  todos.push({ id: Date.now(), text, done: false });
}

function toggleTodo(id: number): void {
  const todo = todos.find(t => t.id === id);
  if (todo) {
    todo.done = !todo.done;
  }
}

// 返回值类型让调用方获得精确提示
interface TodoStats {
  total: number;
  done: number;
  pending: number;
}

function getStats(): TodoStats {
  const done = todos.filter(t => t.done).length;
  return { total: todos.length, done, pending: todos.length - done };
}
```

> 迁移前后对比：TS 版本在 IDE 中输入 `addTodo(` 就会提示参数类型为 `string`，`getStats()` 的返回值点一下就能看到三个字段。任何地方如果把 `boolean` 误传给 `addTodo`，编译直接报错——不再依赖人工代码审查。

## 常见问题

**Q1: TypeScript 的类型在运行时还存在吗？**

不存在。TypeScript 是纯编译时技术，编译产物就是普通 JavaScript，所有类型注解都会被擦除。这意味着 `typeof`、`instanceof` 这些运行时检查仍然是 JS 的行为，不是 TS 的类型系统行为。

**Q2: `string` 和 `String`（大写）有什么区别？**

`string` 是 TypeScript 的基本类型，`String` 是 JavaScript 的内置构造函数类型。永远用 `string` 注解变量类型。

```typescript
let a: string = 'hello';    // ✅
let b: String = 'hello';    // 不推荐，虽然能编译通过
```

**Q3: 什么时候该用 `as const`？**

当你希望对象的每个属性都保持最精确的字面量类型时。典型场景：配置对象、枚举替代、Redux action type 定义。

**Q4: 为什么我的 `const` 变量自动推断出了 `string` 而不是字面量类型？**

只有基本类型的 `const` 声明才会推断为字面量类型。对象属性默认推断为宽泛类型，必须用 `as const` 才能锁死。

```typescript
const a = 'hello';         // 类型是 "hello"（字面量）
const obj = { a: 'hello' };// obj.a 类型是 string（不是 "hello"）
```

**Q5: `void` 和 `undefined` 有什么关系？**

返回 `void` 的函数可以 `return undefined` 或不返回，但不应该 `return` 其他值。严格模式下，声明为 `void` 的函数不能把返回值赋给别的变量。

**Q6: `never` 类型有什么实际用途？**

除了标识永不返回的函数，`never` 最重要的用途是**穷尽性检查**（exhaustiveness check），确保 switch 语句覆盖了所有可能的分支。参考上面 `Animal` 的例子。

**Q7: 类型推断和显式注解，到底哪个更好？**

函数参数：必须显式注解。函数返回值：公开 API 建议显式注解，内部函数可以靠推断。变量：能推断的就不写。原则是「让类型系统帮你干活，而不是编写冗余的注解」。

## 实操作业

### 基础：给购物车添加类型

将下面的 JS 代码用 TypeScript 重写，补充完整的类型注解：

```javascript
// 购物车功能
const cart = [];

function addItem(name, price, quantity) {
  cart.push({ name, price, quantity });
}

function getTotal() {
  return cart.reduce((sum, item) => sum + item.price * item.quantity, 0);
}

function removeItem(name) {
  const idx = cart.findIndex(item => item.name === name);
  if (idx !== -1) cart.splice(idx, 1);
}
```

**验收标准**：`addItem(123, 'abc', 'xxx')` 这样的调用在 TS 中编译报错。

### 挑战：实现一个类型安全的 fetch 封装

创建一个泛型 `apiFetch<T>` 函数，要求：

1. 将 JSON 结果视为 `unknown`，接受运行时校验函数 `(value: unknown) => T`，校验成功后才能返回 `T`；泛型本身不能证明远端数据类型
2. 用 `unknown` 处理 `catch` 中的 error，而不是 `any`
3. 用联合类型区分成功/失败两种情况

```typescript
// 期望调用方式
const result = await apiFetch('/api/users', parseUsers);
// parseUsers 检查数组和每个 User 字段；返回判别联合，而非直接类型断言。
if (result.ok) {
  const data: User[] = result.data;
}
```

## 本节小结

TypeScript 的类型系统建立在 JavaScript 之上，不是另起炉灶。学完这节你应该掌握：

- **基本类型注解**是地基，`string/number/boolean/null/undefined/symbol/bigint` 必须烂熟。
- **数组和元组**的区别在于固定长度和位置类型——元组特别适合 `useState` 返回值这类固定结构。
- **`any` vs `unknown` vs `never` vs `void`** 不是玄学，而是四种明确的语义：放弃检查、暂时未知、绝不可能、没有返回值。
- **类型推断**让你少写冗余注解，但函数参数和公开 API 建议显式写。
- **联合类型 + 类型守卫**是日常开发中最高频的组合技。
- **交叉类型**适合组合多个已有类型，注意同名属性冲突。

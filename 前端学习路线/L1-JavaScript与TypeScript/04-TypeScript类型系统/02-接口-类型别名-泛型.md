## 内容讲解

### 1. interface vs type：两大类型定义工具

TypeScript 提供了两种定义对象形状的方式。先看各自的语法：

```typescript
// ---------- interface ----------
interface User {
  name: string;
  age: number;
  greet(): string;          // 方法签名
}

// ---------- type（类型别名）----------
type UserAlias = {
  name: string;
  age: number;
  greet(): string;
};

// 基本类型也可以用 type，interface 做不到
type ID = string | number;          // ✅ type 可以
// interface ID = string | number;  // ❌ interface 只能描述对象形状
```

**核心差异对比**：

| 维度 | interface | type |
|------|-----------|------|
| 描述对象形状 | ✅ | ✅ |
| 描述联合/交叉/元组/基本类型 | ❌ | ✅ |
| 声明合并（同名自动合并） | ✅ | ❌（报重复声明） |
| extends 扩展 | `extends` | `&`（交叉） |
| 性能 | 对对象类型更优（TS 内部有缓存优化） | 对复杂联合类型更灵活 |
| IDE 错误提示 | 显示接口名 | 展开显示完整结构 |

**选择策略**（业界共识）：

1. **默认用 `interface`**：描述对象形状、组件 Props、API 返回数据结构。
2. **必须用 `type` 的场景**：联合类型、元组类型、映射类型、需要重映射键名。
3. **库开发**：优先 `interface`，让消费者可以声明合并扩展你的类型。

```typescript
// 用 extends（interface 风格）
interface Animal { name: string; }
interface Dog extends Animal { bark(): void; }

// 用 &（type 风格）
type AnimalType = { name: string; };
type DogType = AnimalType & { bark(): void; };

// 混合使用也完全 OK
interface Cat extends AnimalType { meow(): void; }
```

### 2. 接口的声明合并（Declaration Merging）

这是 `interface` 独有的特性：多次声明同名接口，它们会自动合并成一个。

```typescript
// 同一作用域中声明两次同名 interface
// TypeScript 会自动合并它们
interface WindowConfig {
  title: string;
}

interface WindowConfig {
  width: number;
  height: number;
}

// 等效于：
// interface WindowConfig {
//   title: string;
//   width: number;
//   height: number;
// }

// ❌ type 做不到
// type WindowConfig = { title: string };
// type WindowConfig = { width: number };  // 报错：标识符重复
```

**实际应用场景——扩展第三方库的类型**：

```typescript
// 给 Express 的 Request 对象增加自定义属性
declare namespace Express {
  interface Request {
    currentUser?: { id: number; name: string };
    traceId: string;
  }
}

// 之后在所有路由处理函数中，req.currentUser 和 req.traceId 都有类型提示
```

> 这是 interface 最强大的特性之一。如果第三方库用 interface 暴露类型，你可以不修改源码就能扩展它。

### 3. 可选属性、只读属性、索引签名

```typescript
interface Product {
  id: number;
  name: string;
  description?: string;           // 可选属性：可以没有
  readonly createdAt: Date;       // 只读属性：初始化后不可修改
}

const p: Product = {
  id: 1,
  name: '键盘',
  createdAt: new Date()
};

// p.createdAt = new Date();  // ❌ 报错：只读属性不能赋值
p.name = '机械键盘';          // ✅ 非只读可以改

// ---------- 索引签名：允许动态属性名 ----------
interface StringMap {
  [key: string]: string;     // 任意字符串 key，值必须是 string
}

const dict: StringMap = {
  hello: '你好',
  world: '世界'
};

// 索引签名 + 已知属性可以并存
interface Config {
  version: number;                // 已知属性
  [key: string]: string | number; // 必须兼容已知属性的类型
}
```

**只读属性的陷阱**：

```typescript
interface ReadonlyUser {
  readonly name: string;
  readonly hobbies: string[];
}

const user: ReadonlyUser = {
  name: '张三',
  hobbies: ['coding', 'reading']
};

// user.name = '李四';   // ❌ 报错
user.hobbies.push('gaming'); // ✅ 不报错！readonly 只保护引用，不保护内容
```

### 4. 函数类型：调用签名与构造签名

```typescript
// ---------- 调用签名（Call Signature）：描述函数类型的 interface ----------
interface GreetFn {
  (name: string): string;           // 调用签名
  description: string;              // 函数也可以有自己的属性
}

const greet: GreetFn = (name) => `Hello, ${name}`;
greet.description = '一个问候函数';

// ---------- 构造签名（Construct Signature）：描述构造函数 ----------
interface PointConstructor {
  new (x: number, y: number): { x: number; y: number };
}

class Point {
  constructor(public x: number, public y: number) {}
}

// 验证 Point 的构造函数满足 PointConstructor
const PointClass: PointConstructor = Point;

// ---------- 函数类型更常见的写法 ----------
// type 写法（更简洁）
type EventHandler = (event: Event) => void;

// interface 写法（更啰嗦，少用）
interface EventHandlerInterface {
  (event: Event): void;
}
```

### 5. 泛型（Generics）：类型的参数化

泛型是 TypeScript 最核心的抽象工具。把类型当作参数传入——就像函数的参数一样。

```typescript
// ---------- 泛型函数 ----------
// 不使用泛型：类型信息丢失
function identity1(value: any): any { return value; }
const r1 = identity1('hello');  // r1 类型是 any，丢了 "string"

// 使用泛型：保留类型信息
function identity<T>(value: T): T {
  return value;
}
const r2 = identity('hello');      // r2 类型是 "hello"
const r3 = identity(42);           // r3 类型是 42

// ---------- 泛型约束（extends）：限制 T 的范围 ----------
// 约束 T 必须有 length 属性
function logLength<T extends { length: number }>(item: T): T {
  console.log(item.length);
  return item;
}

logLength('hello');      // ✅ string 有 length
logLength([1, 2, 3]);   // ✅ 数组有 length
// logLength(123);       // ❌ number 没有 length

// ---------- 泛型接口 ----------
interface ApiResponse<T> {
  code: number;
  data: T;
  message: string;
}

// 类型安全地描述不同 API 的返回值
type UserResponse = ApiResponse<User>;
type ListResponse = ApiResponse<User[]>;

// ---------- 多个泛型参数 ----------
function pair<T, U>(first: T, second: U): [T, U] {
  return [first, second];
}

const p2 = pair('张三', 25);  // 类型：[string, number]

// ---------- 泛型默认值 ----------
interface Container<T = string> {
  value: T;
}

const c1: Container = { value: 'hello' };     // T 默认为 string
const c2: Container<number> = { value: 42 };  // 显式指定 number
```

### 6. keyof 操作符

`keyof` 取出一个对象类型的所有键名，返回它们的联合类型。

```typescript
interface Person {
  name: string;
  age: number;
  address: string;
}

type PersonKey = keyof Person;  // "name" | "age" | "address"

// 实际应用：类型安全的属性访问
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const person: Person = { name: '张三', age: 25, address: '北京' };
getProperty(person, 'name');   // ✅ 返回值类型是 string
getProperty(person, 'age');    // ✅ 返回值类型是 number
// getProperty(person, 'email'); // ❌ 编译报错："email" 不在 "name" | "age" | "address" 中
```

### 7. typeof（类型层面）

JavaScript 的 `typeof` 在运行时用。TypeScript 在类型上下文中也可以使用 `typeof`，含义完全不同：**获取一个值的类型**。

```typescript
// ---------- 类型层面的 typeof ----------
const config = {
  host: 'localhost',
  port: 8080,
  debug: true
};

// 拿到 config 这个「值」的类型
type ConfigType = typeof config;
// ConfigType = { host: string; port: number; debug: boolean; }

// 实际场景：提取已有函数的返回值类型
function getConfig() {
  return { host: 'localhost', port: 8080 };
}

type ReturnedConfig = ReturnType<typeof getConfig>;
// { host: string; port: number; }

// ⚠️ 区分运行时 typeof 和类型 typeof
let value = 'hello';
type ValueType = typeof value;  // 类型层面：string
console.log(typeof value);      // 运行时： "string"（这是 JS）
```

**`keyof` + `typeof` 组合技**：

```typescript
const STATUS_MAP = {
  pending: '待处理',
  processing: '处理中',
  done: '已完成'
} as const;

// 从值推导出键的联合类型
type Status = keyof typeof STATUS_MAP;  // "pending" | "processing" | "done"

// 从值推导出值的联合类型（使用索引访问）
type StatusLabel = (typeof STATUS_MAP)[Status];  // "待处理" | "处理中" | "已完成"
```

### 8. 实战：类型安全的通用 localStorage 封装

```typescript
// ---------- 定义存储项的类型映射 ----------
interface StorageSchema {
  userToken: string;
  settings: {
    theme: 'light' | 'dark';
    fontSize: number;
  };
  cartItems: Array<{ id: number; quantity: number }>;
}

// 约束 T 必须是 StorageSchema 的键
type ValidKey = keyof StorageSchema;

// 泛型约束：K 只能是 StorageSchema 的合法键
function getStorageItem<K extends ValidKey>(
  key: K
): StorageSchema[K] | null {
  try {
    const raw = localStorage.getItem(key);
    return raw ? (JSON.parse(raw) as StorageSchema[K]) : null;
  } catch {
    return null;
  }
}

function setStorageItem<K extends ValidKey>(
  key: K,
  value: StorageSchema[K]
): void {
  localStorage.setItem(key, JSON.stringify(value));
}

function removeStorageItem(key: ValidKey): void {
  localStorage.removeItem(key);
}

// ---------- 使用效果 ----------
const token = getStorageItem('userToken');
// token 类型：string | null，IDE 自动提示 string 的方法

const settings = getStorageItem('settings');
// settings 类型：{ theme: 'light' | 'dark'; fontSize: number } | null

// ❌ 编译报错：无效的 key
// getStorageItem('invalidKey');

// ❌ 编译报错：value 类型不匹配
// setStorageItem('settings', 'wrong type');
```

## 常见问题

**Q1: `interface` 和 `type` 到底选哪个？**

口诀：描述对象用 `interface`，其他用 `type`。如果写的库需要被别人扩展，必须用 `interface`（声明合并）。

**Q2: 泛型 `<T>` 里的 `T` 是什么？可以换别的字母吗？**

`T` 只是一个约定俗成的占位符（代表 Type），你也可以写 `U`、`V`、`K`、`V`。常见惯例：`T`=Type、`K`=Key、`V`=Value、`E`=Element、`R`=Return。

**Q3: `keyof any` 的结果是什么？**

`keyof any` 得到 `string | number | symbol`——这是 JavaScript 中所有可能的对象键类型。

**Q4: 为什么用 `extends` 约束泛型，而不是其他关键字？**

这里的 `extends` 不是「继承」，而是「兼容」或「子类型」。`T extends { length: number }` 的含义是：T 必须是 `{ length: number }` 的子类型。

**Q5: 索引签名同时用到 `string` 和 `number` key 会怎样？**

`number` 索引的值类型必须是 `string` 索引值类型的子类型。因为 JS 会把数字键转为字符串。

```typescript
interface Mixed {
  [key: string]: string;   // string 索引
  [key: number]: string;   // ✅ number 的值类型必须是 string 的子类型
}
```

**Q6: 泛型默认值和函数默认参数是同一回事吗？**

概念类似但层面不同——泛型默认值作用于类型层面，函数默认参数作用于值层面。

**Q7: 可选属性 `?` 和 `| undefined` 有什么区别？**

`key?: string` 表示这个属性可以不存在；`key: string | undefined` 表示这个属性必须存在（哪怕值是 `undefined`）。在 `strictNullChecks` 下差异明显。

## 实操作业

### 基础：用类型描述配置对象

定义一个 `AppConfig` interface，包含：

- `appName`（必填 string）
- `version`（必填 number）
- `debug`（可选 boolean，默认 false）
- `database`（必填对象，有 `host`、`port`、`username`、`password` 四个 string 属性）
- `features`（用索引签名，key 为 string，value 为 boolean）

### 进阶：实现泛型工具函数

```typescript
// 实现 pick 函数：从一个对象中选取指定的属性，要求类型安全
function pick<T, K extends keyof T>(obj: T, keys: K[]): Pick<T, K> {
  // 你的实现
}

// 测试
const user = { id: 1, name: '张三', age: 25, email: 'zhangsan@example.com' };
const picked = pick(user, ['id', 'name']);
// picked 的类型应为 { id: number; name: string; }
// picked.email 应该编译报错
```

### 挑战：实现泛型管道函数

```typescript
// 实现 pipe 函数：串行执行多个函数，要求：
// 1. 第一个函数的输出类型 = 第二个函数的输入类型
// 2. 最终返回类型 = 最后一个函数的输出类型
// 3. 支持至少 2~5 个函数的管道

declare function pipe<A, B>(a: (x: A) => B): (x: A) => B;
declare function pipe<A, B, C>(a: (x: A) => B, b: (x: B) => C): (x: A) => C;
// 补全 3~5 个重载

// 测试
const double = (x: number) => x * 2;
const toString = (x: number) => `结果是：${x}`;
const fn = pipe(double, toString);
// fn 类型应为 (x: number) => string
```

### 作业参考与验收

- **基础**：必填与可选字段分开，debug 默认值在运行代码赋值；interface 不会初始化对象。用 satisfies 检查示例配置，错字段/缺字段应编译失败。
- **进阶**：pick<T,K extends keyof T> 遍历 keys 拷贝选中键；返回 Pick<T,K>。空键返回 {}，原对象不改，编译拒绝未知键；类型断言只限已证明的构造内部。
- **挑战**：为 2-5 段函数提供泛型重载，前输出连接后输入。合法管道推断最终类型，插入不兼容函数编译失败；同步版不默认支持 Promise。

## 本节小结

这一节你接触了 TypeScript 类型系统的三大抽象利器：

- **interface** 适合描述对象形状，独有**声明合并**能力，是扩展第三方库类型的利器。
- **type** 比 interface 更灵活，能表达联合、交叉、元组、映射等 interface 做不到的类型。
- **泛型** 让类型「参数化」，是编写可复用、类型安全代码的核心手段。
- **`keyof` + 泛型约束** 的组合让属性访问也变得类型安全。
- **类型层面的 `typeof`** 让你可以从值推导类型，减少重复定义。

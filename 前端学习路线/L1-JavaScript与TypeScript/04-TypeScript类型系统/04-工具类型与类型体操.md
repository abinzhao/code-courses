## 内容讲解

### 1. 内置工具类型详解

TypeScript 自带了一系列工具类型，它们的实现源码就在 `lib.es5.d.ts` 中。我们来逐个拆解：

#### 对象操作类

```typescript
// ---------- Partial<T>：所有属性变可选 ----------
// 源码：type Partial<T> = { [K in keyof T]?: T[K] };
interface User {
  name: string;
  age: number;
}
type PartialUser = Partial<User>;
// { name?: string; age?: number; }
// 典型场景：更新操作，只需要传一部分字段

// ---------- Required<T>：所有属性变必填 ----------
// 源码：type Required<T> = { [K in keyof T]-?: T[K] };
type RequiredUser = Required<PartialUser>;
// { name: string; age: number; }

// ---------- Readonly<T>：所有属性变只读 ----------
// 源码：type Readonly<T> = { readonly [K in keyof T]: T[K] };
type ReadonlyUser = Readonly<User>;
// { readonly name: string; readonly age: number; }

// ---------- Pick<T, K>：从 T 中选出 K 指定的属性 ----------
// 源码：type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type UserNameOnly = Pick<User, 'name'>;
// { name: string; }

// ---------- Omit<T, K>：从 T 中排除 K 指定的属性 ----------
// 源码：type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
type UserWithoutAge = Omit<User, 'age'>;
// { name: string; }
```

#### 联合类型操作类

```typescript
// ---------- Record<K, V>：构造一个键为 K、值为 V 的对象类型 ----------
// 源码：type Record<K extends keyof any, V> = { [P in K]: V };
type PageInfo = Record<'home' | 'about' | 'contact', { title: string }>;
// { home: { title: string }; about: { title: string }; contact: { title: string }; }

// ---------- Exclude<T, U>：从联合类型 T 中排除 U ----------
// 源码：type Exclude<T, U> = T extends U ? never : T;
type NonNull = Exclude<string | number | null, null>;
// string | number

// ---------- Extract<T, U>：从联合类型 T 中提取 U ----------
// 源码：type Extract<T, U> = T extends U ? T : never;
type OnlyString = Extract<string | number | boolean, string>;
// string

// ---------- NonNullable<T>：排除 null 和 undefined ----------
// 源码：type NonNullable<T> = T extends null | undefined ? never : T;
type Clean = NonNullable<string | null | undefined>;
// string
```

#### 函数类型操作类

```typescript
// ---------- ReturnType<T>：提取函数返回值类型 ----------
// 源码：type ReturnType<T extends (...args: any) => any> = T extends (...args: any) => infer R ? R : any;
function fetchUser(): Promise<{ id: number; name: string }> {
  return Promise.resolve({ id: 1, name: '张三' });
}
type FetchResult = ReturnType<typeof fetchUser>;
// Promise<{ id: number; name: string }>

// ---------- Parameters<T>：提取函数参数类型（元组）----------
// 源码：type Parameters<T extends (...args: any) => any> = T extends (...args: infer P) => any ? P : never;
function createUser(name: string, age: number): User {
  return { name, age };
}
type CreateUserParams = Parameters<typeof createUser>;
// [name: string, age: number]

// ---------- InstanceType<T>：提取构造函数的实例类型 ----------
class MyClass {
  constructor(public id: number) {}
}
type MyInstance = InstanceType<typeof MyClass>;
// MyClass

// ---------- Awaited<T>：递归解包 Promise（TS 4.5+）----------
type A = Awaited<Promise<string>>;              // string
type B = Awaited<Promise<Promise<number>>>;     // number
```

**速查表**：

| 工具类型 | 功能 | 输入 → 输出示例 |
|---------|------|-----------------|
| `Partial<T>` | 全部可选 | `{a:1,b:2}` → `{a?:1,b?:2}` |
| `Required<T>` | 全部必填 | `{a?:1}` → `{a:1}` |
| `Readonly<T>` | 全部只读 | `{a:1}` → `{readonly a:1}` |
| `Pick<T,K>` | 选取属性 | `Pick<{a,b,c}, 'a'｜'b'>` → `{a,b}` |
| `Omit<T,K>` | 排除属性 | `Omit<{a,b,c}, 'a'>` → `{b,c}` |
| `Record<K,V>` | 构造对象 | `Record<'a'｜'b', number>` → `{a:number,b:number}` |
| `Exclude<T,U>` | 排除联合成员 | `Exclude<'a'｜'b'｜'c', 'a'>` → `'b'｜'c'` |
| `Extract<T,U>` | 提取联合成员 | `Extract<'a'｜1, string>` → `'a'` |
| `NonNullable<T>` | 去 null/undefined | `string｜null` → `string` |
| `ReturnType<T>` | 函数返回值 | `() => string` → `string` |
| `Parameters<T>` | 函数参数元组 | `(a:string,b:number)` → `[string,number]` |
| `Awaited<T>` | 解包 Promise | `Promise<number>` → `number` |

### 2. 类型断言与 satisfies

```typescript
// ---------- as 断言：告诉编译器「我知道这是什么类型」----------
// 场景1：DOM 操作（你比 TS 更清楚元素类型）
const canvas = document.getElementById('canvas') as HTMLCanvasElement;

// 场景2：JSON.parse 结果
const data = JSON.parse('{"name":"张三"}') as User;

// 场景3：类型收窄（从宽泛到精确）
let value: unknown = 'hello';
(value as string).toUpperCase();   // 告诉 TS 你确定这是 string

// ⚠️ as 是危险的——如果判断错误，运行时照样爆炸
const num = 'not a number' as unknown as number;  // 编译不报错，运行时 num 是 string！

// ---------- as const：把值锁死为最精确的字面量类型 ----------
const colors = ['red', 'green', 'blue'] as const;
// 类型：readonly ["red", "green", "blue"]（不是 string[]）

const config = { theme: 'dark', port: 3000 } as const;
// 类型：{ readonly theme: "dark"; readonly port: 3000; }
// 这样 config.theme 的类型是 "dark" 而不是 string

// ---------- satisfies（TS 4.9+）：检查类型但不改变推断 ----------
// 场景：既想确保对象符合类型，又想保留字面量的精确推断
interface ColorConfig {
  theme: 'light' | 'dark';
  accent: string;
}

// ❌ 用冒号注解：accent 类型变成 string，丢失了 "#ff0000" 这个精确信息
const bad: ColorConfig = { theme: 'dark', accent: '#ff0000' };
// bad.accent 的类型是 string

// ✅ 用 satisfies：既检查了类型，又保留了 "#ff0000" 字面量类型
const good = { theme: 'dark', accent: '#ff0000' } satisfies ColorConfig;
// good.accent 的类型是 "#ff0000"（精确！）

// ---------- 非空断言 !：告诉 TS「这个值不会是 null/undefined」----------
let username: string | null = '张三';
console.log(username!.toUpperCase());  // 告诉 TS：我确定 username 有值

// ⚠️ 滥用非空断言是 TypeScript 代码中最常见的隐患之一
// 如果 username 实际是 null，运行时照样报 TypeError
```

**`as` vs `!` vs `satisfies` 对比**：

| 用法 | 作用 | 风险 |
|------|------|------|
| `as Type` | 强制转换类型，可以跨越不兼容的类型 | 高，可能骗过编译器 |
| `!` | 仅排除 null/undefined | 中，运行时可能为 null |
| `satisfies Type` | 检查兼容性但不改变推断类型 | 无，纯编译时检查 |

### 3. 类型编程的核心思维

类型编程不是炫技，而是解决实际问题。核心思路：

1. **从需求出发**：想达到什么类型安全效果？
2. **选择基础操作**：映射类型？条件类型？泛型约束？
3. **组合**：把简单操作组合成复杂类型。
4. **测试**：用具体的类型用例验证推导结果。

```typescript
// 思维示例：「我想实现一个类型，把对象中所有 number 属性变成 string，其他不变」

// 步骤1：遍历所有属性                  → [K in keyof T]
// 步骤2：判断值类型是否为 number       → T[K] extends number
// 步骤3：是 → string，否 → 保持原样    → 条件类型
// 步骤4：组合

type NumberToString<T> = {
  [K in keyof T]: T[K] extends number ? string : T[K];
};

type Input = { a: number; b: string; c: boolean };
type Output = NumberToString<Input>;
// { a: string; b: string; c: boolean; }
```

### 4. 经典类型编程模式

```typescript
// ---------- DeepPartial：递归版 Partial ----------
type DeepPartial<T> = {
  [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
};

interface Config {
  server: { host: string; port: number };
  database: { url: string; pool: number };
}

type PartialConfig = DeepPartial<Config>;
// 所有属性都是可选的，且嵌套对象的属性也是可选的

// ---------- DeepReadonly：递归版 Readonly ----------
type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};

// ---------- Merge<A, B>：深度合并两个对象类型（B 覆盖 A 的同名属性）----------
type Merge<A, B> = {
  [K in keyof A | keyof B]: K extends keyof B
    ? B[K]
    : K extends keyof A
      ? A[K]
      : never;
};

// ---------- Overwrite<A, B>：用 B 覆盖 A 的属性（更安全的 Merge）----------
type Overwrite<A, B> = Omit<A, keyof B> & B;

// ---------- Nullable<T>：把所有属性变为 T | null ----------
type Nullable<T> = { [K in keyof T]: T[K] | null };

// ---------- ValueOf<T>：提取所有值类型的联合 ----------
type ValueOf<T> = T[keyof T];

const user = { name: '张三', age: 25 } as const;
type UserValues = ValueOf<typeof user>;  // "张三" | 25
```

### 5. 实战：实现 DeepPick 和 DeepOmit 工具类型

```typescript
// ---------- 需求分析 ----------
// DeepPick：从嵌套对象中按路径选取属性
// DeepPick<{ a: { b: { c: number; d: string } } }, 'a.b.c'>
// → { a: { b: { c: number } } }

// DeepOmit：从嵌套对象中按路径排除属性
// DeepOmit<{ a: { b: { c: number; d: string } } }, 'a.b.c'>
// → { a: { b: { d: string } } }

// ---------- 辅助类型：按点号拆分路径 ----------
type SplitPath<T extends string> =
  T extends `${infer Head}.${infer Tail}`
    ? [Head, ...SplitPath<Tail>]
    : [T];

// ---------- DeepPick 实现 ----------
type DeepPick<T, Path extends string> = {
  [K in keyof T & SplitPath<Path>[0]]:
    SplitPath<Path> extends [K, ...infer Rest]
      ? Rest extends [string]
        ? Rest[0] extends `${infer Next}.${string}`
          ? DeepPick<T[K], Rest[0]>     // 还有更深路径
          : T[K]                          // 到达叶子
        : never
      : T[K];
};

// 简化版（更实用）：
type SimpleDeepPick<T, K extends string> = K extends `${infer First}.${infer Rest}`
  ? First extends keyof T
    ? { [P in First]: SimpleDeepPick<T[First], Rest> }
    : never
  : K extends keyof T
    ? Pick<T, K>
    : never;

// ---------- DeepOmit 实现 ----------
type DeepOmit<T, Path extends string> = Path extends `${infer First}.${infer Rest}`
  ? First extends keyof T
    ? Omit<T, First> & { [P in First]: DeepOmit<T[First], Rest> }
    : T
  : Omit<T, Path>;

// 测试
interface DeepObj {
  a: { b: { c: number; d: string }; e: boolean };
  f: string;
}

type Picked = SimpleDeepPick<DeepObj, 'a.b.c'>;
// { a: { b: { c: number } } }

type Omitted = DeepOmit<DeepObj, 'a.b.d'>;
// { a: { b: { c: number }; e: boolean }; f: string }
```

## 常见问题

**Q1: `Partial<T>` 和 `?` 有什么区别？**

`?` 只能用在定义 interface 时标记可选属性。`Partial<T>` 可以把一个已有类型（哪怕属性都是必填的）的所有属性批量变为可选——适合「复用已有类型但所有字段可选」的场景。

**Q2: `Record<string, V>` 和 `{ [key: string]: V }` 一样吗？**

功能上一样，但 `Record` 是泛型工具类型，更语义化。而且 `Record` 可以用联合类型限制键名范围（如 `Record<'a'｜'b', number>`），索引签名不行。

**Q3: `as` 断言的两种写法 `as` 和 `<Type>` 有什么区别？**

`<Type>value` 是旧式写法，在 `.tsx` 文件中会与 JSX 语法冲突，所以推荐统一用 `value as Type`。

**Q4: 什么时候用 `satisfies` 而不是 `:` 注解？**

当你需要**同时做到**这两件事时：(1) 验证值符合某个类型，(2) 保留每个属性的精确字面量类型。典型场景是配置对象。

**Q5: `Exclude` 和 `Omit` 有什么区别？**

`Exclude` 作用于**联合类型的成员**（如 `Exclude<'a'｜'b', 'a'>`）。`Omit` 作用于**对象类型的属性**（如 `Omit<{a:1,b:2}, 'a'>`）。不要混用。

**Q6: 为什么 `ReturnType` 有时返回 `unknown`？**

如果传给 `ReturnType` 的不是函数类型（比如普通的对象类型），条件类型匹配失败，返回 `never`。实际中常见原因是没有用 `typeof`——`ReturnType(fn)` 是错的，应该写 `ReturnType<typeof fn>`。

## 本节小结

工具类型不是给面试准备的题型，而是日常开发中的生产力工具：

- **内置工具类型**是基础词汇，`Partial`、`Pick`、`Omit`、`Record`、`ReturnType` 是日常使用最频繁的。
- **类型断言**要谨慎使用——`as` 和 `!` 都在绕开编译器的保护，过度使用会抵消 TS 的价值。`satisfies` 是最安全的新选项。
- **类型编程的核心**是「需求 → 基础操作 → 组合」——不要为了炫技把类型写得过于复杂，解决实际问题才是目标。
- **经典模式**如 `DeepPartial`、`Merge` 等是常见的可复用模版，不需要每次都从头推导。

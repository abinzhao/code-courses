## 内容讲解

### 1. 条件类型（Conditional Types）

条件类型的语法和 JavaScript 的三元运算符一模一样，但它作用于**类型层面**：

```typescript
// 语法：T extends U ? X : Y
// 含义：如果 T 是 U 的子类型，则取 X，否则取 Y
```

**基础示例**：

```typescript
// 判断类型是否为 string
type IsString<T> = T extends string ? 'yes' : 'no';

type A = IsString<string>;   // "yes"
type B = IsString<number>;   // "no"
type C = IsString<'hello'>;  // "yes"（字面量类型也是 string 的子类型）

// 实际应用：提取数组元素类型
type ElementType<T> = T extends (infer U)[] ? U : T;

type E1 = ElementType<string[]>;      // string
type E2 = ElementType<number>;        // number（不是数组，原样返回）
```

### 2. infer 关键字：类型层面的「解构赋值」

`infer` 只能在条件类型的 `extends` 子句中使用，作用是**声明一个待推断的类型变量**。

```typescript
// ---------- 提取函数返回值类型 ----------
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type Fn = (name: string) => { id: number };
type Result = MyReturnType<Fn>;  // { id: number }

// ---------- 提取 Promise 包裹的类型（递归解包）----------
type Unwrap<T> = T extends Promise<infer U> ? Unwrap<U> : T;

type P1 = Unwrap<Promise<string>>;           // string
type P2 = Unwrap<Promise<Promise<number>>>;  // number（递归解包）

// ---------- 提取函数第一个参数的类型 ----------
type FirstParam<T> = T extends (first: infer F, ...rest: any[]) => any ? F : never;

type F = (name: string, age: number) => void;
type P = FirstParam<F>;  // string
```

**infer 的位置可以灵活放置**：

```typescript
// 提取数组元素
type ArrayItem<T> = T extends (infer Item)[] ? Item : never;

// 提取对象的某个属性值类型（模式匹配）
type GetName<T> = T extends { name: infer N } ? N : never;

type N1 = GetName<{ name: string; age: number }>;  // string
type N2 = GetName<{ id: number }>;                   // never（没有 name）

// 提取字符串中的部分（模板字面量 + infer）
type SplitByDot<T> = T extends `${infer First}.${infer Rest}` ? [First, Rest] : never;

type S1 = SplitByDot<'hello.world'>;  // ["hello", "world"]
```

### 3. 分布式条件类型（Distributive Conditional Types）

当条件类型作用于**裸泛型联合类型**时，TypeScript 会自动把联合类型拆开，逐个应用条件，再把结果合并。

这是初学者最容易踩的坑：

```typescript
// 分布式：T 是联合类型，会拆开逐个判断
type ToArray<T> = T extends any ? T[] : never;

type Result = ToArray<string | number>;
// 等价于：ToArray<string> | ToArray<number>
// 结果是：string[] | number[]

// ---------- 如何阻止分布式（用元组包裹）----------
type ToArrayNoDistribute<T> = [T] extends [any] ? T[] : never;

type Result2 = ToArrayNoDistribute<string | number>;
// 结果是：(string | number)[]   ← 不再拆开
```

**分布式条件类型的实际用途——过滤联合类型**：

```typescript
// 从联合类型中排除某个类型（模拟 Exclude 工具类型）
type MyExclude<T, U> = T extends U ? never : T;

type Result = MyExclude<'a' | 'b' | 'c', 'a'>;
// 拆解过程：
//   'a' extends 'a' ? never : 'a'  → never
//   'b' extends 'a' ? never : 'b'  → 'b'
//   'c' extends 'a' ? never : 'c'  → 'c'
// 结果：'b' | 'c'（never 在联合中被自动吞掉）

// 提取可调用的类型
type ExtractCallable<T> = T extends (...args: any[]) => any ? T : never;

type Source = string | (() => void) | number;
type Callables = ExtractCallable<Source>;  // () => void
```

### 4. 模板字面量类型（Template Literal Types）

TypeScript 4.1 引入，允许在类型层面拼接字符串——和 JavaScript 的模板字面量语法一模一样。

```typescript
// ---------- 基础拼接 ----------
type Greeting = `Hello, ${string}`;     // "Hello, 任意字符串"
const g1: Greeting = 'Hello, World';    // ✅
// const g2: Greeting = 'Hi, World';    // ❌ 必须以 "Hello, " 开头

// ---------- 联合类型自动展开（笛卡尔积）----------
type Direction = 'top' | 'bottom';
type Side = 'left' | 'right';
type Position = `${Direction}-${Side}`;
// "top-left" | "top-right" | "bottom-left" | "bottom-right"

// ---------- 实用场景：事件系统类型化 ----------
type EventName = 'click' | 'focus' | 'blur';
type HandlerName = `on${Capitalize<EventName>}`;
// "onClick" | "onFocus" | "onBlur"

// ---------- 结合 infer 做模式提取 ----------
type ParseRoute<T extends string> =
  T extends `/${infer Resource}/${infer Id}`
    ? { resource: Resource; id: Id }
    : never;

type R1 = ParseRoute<'/users/42'>;      // { resource: "users"; id: "42" }
type R2 = ParseRoute<'/posts/hello'>;   // { resource: "posts"; id: "hello" }
```

### 5. 内置字符串操作类型

TypeScript 提供了四个内置的字符串类型工具：

```typescript
type S = 'hello world';

type A = Uppercase<S>;    // "HELLO WORLD"
type B = Lowercase<S>;    // "hello world"
type C = Capitalize<S>;   // "Hello world"
type D = Uncapitalize<S>; // "hello world"

// 实际应用：自动生成 getter/setter 方法名
type PropName = 'userName' | 'userAge';
type GetterName = `get${Capitalize<PropName>}`;
// "getUserName" | "getUserAge"
```

### 6. 映射类型（Mapped Types）

映射类型是 TypeScript 中最优雅的批量操作能力——遍历一个类型的键，对每个属性施加转换。

```typescript
// ---------- 基础语法：{ [K in 联合类型]: 值类型 } ----------
// 把所有属性变成只读
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

interface User {
  name: string;
  age: number;
}

type ReadonlyUser = MyReadonly<User>;
// { readonly name: string; readonly age: number; }

// 把所有属性变成可选
type MyPartial<T> = {
  [K in keyof T]?: T[K];
};

// 去掉 readonly 修饰符（用 - 前缀）
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// 去掉可选修饰符
type Required2<T> = {
  [K in keyof T]-?: T[K];
};
```

**映射类型的修饰符规则**：

| 修饰符 | 添加 | 移除 |
|--------|------|------|
| readonly | `readonly [K in ...]` | `-readonly [K in ...]` |
| 可选 `?` | `[K in ...]?` | `[K in ...]-?` |

### 7. as 子句：键重映射

TypeScript 4.1 引入的 `as` 子句让你在遍历键的同时可以重命名键名。

```typescript
// ---------- 给所有属性名加 get 前缀 ----------
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
  //                    ^^^^^^^^^^^^^^^^
  //                    as 后面的表达式计算新的键名
};

interface Person {
  name: string;
  age: number;
}

type PersonGetters = Getters<Person>;
// {
//   getName: () => string;
//   getAge: () => number;
// }

// ---------- 过滤掉某种类型的属性 ----------
type OnlyStringProps<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
  //                ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  //                只保留值类型为 string 的属性
};

interface Mixed {
  name: string;
  age: number;
  email: string;
}

type StringOnly = OnlyStringProps<Mixed>;
// { name: string; email: string; }  ← age 被过滤掉了
```

### 8. 实战：类型安全的 API 路由类型系统

```typescript
// ---------- 定义 API 路由表 ----------
interface ApiRoutes {
  '/users':                    { list: User[]; total: number };
  '/users/[id]':               User;
  '/posts':                    { list: Post[] };
  '/posts/[id]':               Post;
  '/posts/[id]/comments':      Comment[];
}

// ---------- 工具类型：提取路由参数 ----------
// 从 '/users/[id]' 中提取出 { id: string }
type ExtractParams<T extends string> =
  T extends `${infer _}[${infer Param}]${infer Rest}`
    ? { [K in Param]: string } & ExtractParams<Rest>
    : {};

type Params = ExtractParams<'/posts/[id]/comments/[commentId]'>;
// { id: string } & { commentId: string } → { id: string; commentId: string }

// ---------- 类型安全的 API 调用函数 ----------
declare function apiGet<Path extends keyof ApiRoutes>(
  path: Path,
  params: ExtractParams<Path>
): Promise<ApiRoutes[Path]>;

// 使用
const users = await apiGet('/users', {});
// users 类型：{ list: User[]; total: number }

const user = await apiGet('/users/[id]', { id: '42' });
// user 类型：User

// ❌ 编译报错：'/users/[id]' 需要 id 参数，但这里没传
// apiGet('/users/[id]', {});

// ❌ 编译报错：无效的路由
// apiGet('/invalid', {});
```

## 常见问题

**Q1: 分布式条件类型什么时候触发？什么时候不触发？**

触发条件：T 是**裸泛型参数**且是**联合类型**。不触发的情况：T 被包裹在元组、数组、Promise 等容器类型中（如 `[T] extends [U]`）。

**Q2: `infer` 可以出现在哪些位置？**

只能在条件类型 `extends` 的真分支或假分支中使用，不能单独使用。可以出现在任何需要推断类型的位置：函数参数、返回值、数组元素、Promise 泛型参数、模板字面量等。

**Q3: 模板字面量类型拼接大量联合类型会不会卡死？**

会。如果两个联合类型各有 N 和 M 个成员，笛卡尔积会生成 N×M 个结果。项目中出现 10000+ 成员的模板字面量类型会让 TS 编译器明显变慢。建议控制联合类型成员数量。

**Q4: 映射类型能遍历数组吗？**

可以。因为 `keyof` 作用于数组时得到的是索引（`number`）和 `length` 等属性。但一般用 `[K in keyof T]` 来遍历更安全。

**Q5: `never` 在联合类型中会被自动忽略，这个特性有什么用？**

这是实现过滤操作的基础——在映射类型或条件类型中，把不需要的键映射成 `never`，它们就从结果中消失了。参考上面 `OnlyStringProps` 的例子。

**Q6: 映射类型中 `string & K` 是什么意思？**

`keyof T` 返回的类型包括 `string | number | symbol`，而 `Capitalize` 只接受 `string`。`string & K` 过滤掉 `number` 和 `symbol` 类型，确保传给 `Capitalize` 的一定是 `string`。

## 本节小结

这一节进入了 TypeScript 类型系统的进阶领域，核心收获应该包括：

- **条件类型**本质是类型层面的 `if/else`，配合分布式特性可以优雅地过滤联合类型。
- **`infer`** 是类型层面的模式匹配——从复杂类型中提取你需要的部分。
- **模板字面量类型**把字符串处理能力带到了类型层面，事件命名、路由解析、状态机标签生成都靠它。
- **映射类型**让你批量转换对象属性的形状，是 `Partial`、`Readonly` 等内置工具类型的底层机制。
- **`as` 子句**进一步解锁了键重映射和属性过滤。

这些能力组合起来，就是所谓的「类型体操」——下一节你将系统学习内置工具类型和经典类型编程模式。

## 内容讲解

### 1. 三角关系：`__proto__`、`prototype`、`constructor`

这是 JavaScript 最核心也最容易混淆的三者关系。先看图，再看代码。

```js
function Person(name) {
  this.name = name;
}

Person.prototype.greet = function() {
  return `你好，我是 ${this.name}`;
};

const alice = new Person('Alice');

// 三角关系验证
console.log(alice.__proto__ === Person.prototype);        // true
console.log(Person.prototype.constructor === Person);     // true
console.log(alice.constructor === Person);                // true（沿原型链找到的）
```

**一句话总结：**

| 属性 | 谁有 | 指向 |
|------|------|------|
| `prototype` | 只有函数有 | 该函数创建的实例共享的原型对象 |
| `__proto__` | 所有对象都有 | 该对象的原型（即创建它的构造函数的 `prototype`） |
| `constructor` | 原型对象上有 | 指向关联的构造函数 |

```js
// 更直观的理解
// Person.prototype    → { greet: fn, constructor: Person }
// alice.__proto__     → Person.prototype
// 所以 alice.greet()  → 先找 alice 自身 → 没有 → 沿 __proto__ 找 → 在 Person.prototype 上找到！
```

> **避坑提示**：`__proto__` 是历史遗留的访问器属性，生产代码中应用 `Object.getPrototypeOf()` 和 `Object.setPrototypeOf()`。

### 2. 原型链查找机制

当你访问 `alice.greet` 时，引擎会：

1. 在 `alice` 自身属性中查找 `greet` → 没找到
2. 沿 `alice.__proto__` → `Person.prototype` → 找到了 `greet`！
3. 如果没找到，继续沿 `Person.prototype.__proto__` → `Object.prototype` 查找
4. 终点是 `Object.prototype.__proto__` → `null`

```js
// 完整的原型链演示
const arr = [1, 2, 3];

// arr → Array.prototype → Object.prototype → null
console.log(arr.__proto__ === Array.prototype);           // true
console.log(arr.__proto__.__proto__ === Object.prototype);// true
console.log(arr.__proto__.__proto__.__proto__);           // null

// 所以数组才能用 push、map 等方法——它们定义在 Array.prototype 上
console.log(arr.push === Array.prototype.push);           // true

// hasOwnProperty 不在 arr 上，也不在 Array.prototype 上
// 是沿原型链在 Object.prototype 上找到的
console.log(arr.hasOwnProperty === Object.prototype.hasOwnProperty); // true
```

**重要区分：**

```js
const alice = new Person('Alice');

// hasOwnProperty：只检查自身属性
alice.name = 'Alice';
alice.hasOwnProperty('name');   // true —— 自身属性
alice.hasOwnProperty('greet');  // false —— 来自原型

// in 运算符：检查自身 + 原型链
'name' in alice;   // true
'greet' in alice;  // true
'toString' in alice; // true —— 来自 Object.prototype
```

### 3. `new` 关键字做了什么（5 步）

```js
// 当我们写：
const alice = new Person('Alice');

// 引擎实际执行了以下步骤：
function myNew(constructor, ...args) {
  // 1. 创建一个全新的空对象
  const obj = {};

  // 2. 将这个对象的 [[Prototype]] 指向构造函数的 prototype
  Object.setPrototypeOf(obj, constructor.prototype);

  // 3. 将 this 绑定到新对象，执行构造函数
  const result = constructor.apply(obj, args);

  // 4. 如果构造函数返回了对象，用那个对象；否则返回新对象
  return result instanceof Object ? result : obj;
}

// 验证
const bob = myNew(Person, 'Bob');
console.log(bob.name);           // 'Bob'
console.log(bob instanceof Person); // true
```

### 4. 继承的演化路径

#### 4.1 原型链继承

```js
function Parent() {
  this.colors = ['red', 'blue'];
}

function Child() {}

// 让 Child.prototype 指向 Parent 的实例
Child.prototype = new Parent();

const c1 = new Child();
const c2 = new Child();

c1.colors.push('green');
console.log(c2.colors); // ['red', 'blue', 'green'] —— 共享了引用！
// ❌ 问题：所有子实例共享父实例的引用类型属性
```

#### 4.2 构造函数继承（借用构造函数）

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

function Child(name) {
  Parent.call(this, name); // 在子构造函数中调用父构造函数
}

const c1 = new Child('c1');
const c2 = new Child('c2');

c1.colors.push('green');
console.log(c2.colors);    // ['red', 'blue'] —— 不共享了！
// ✅ 解决了引用共享问题
// ❌ 问题：方法无法复用，每次 new 都创建新函数
```

#### 4.3 组合继承（最常用）

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

Parent.prototype.sayName = function() {
  return this.name;
};

function Child(name, age) {
  Parent.call(this, name);  // 第2次调用 Parent
  this.age = age;
}

Child.prototype = new Parent(); // 第1次调用 Parent
Child.prototype.constructor = Child;

// ✅ 优点：实例属性独立 + 方法复用
// ❌ 缺点：Parent 构造函数被调用了两次
```

#### 4.4 寄生组合继承（最优方案）

```js
function Parent(name) {
  this.name = name;
  this.colors = ['red', 'blue'];
}

Parent.prototype.sayName = function() {
  return this.name;
};

function Child(name, age) {
  Parent.call(this, name);    // 只调用一次 Parent
  this.age = age;
}

// 关键：用 Object.create 创建中间原型，避免调用 Parent
Child.prototype = Object.create(Parent.prototype);
Child.prototype.constructor = Child;

const child = new Child('Alice', 25);
console.log(child.sayName()); // 'Alice'
console.log(child instanceof Parent); // true
```

#### 4.5 class extends（ES6，语法糖）

```js
class Parent {
  constructor(name) {
    this.name = name;
    this.colors = ['red', 'blue'];
  }

  sayName() {
    return this.name;
  }

  // 静态方法
  static create(name) {
    return new Parent(name);
  }
}

class Child extends Parent {
  constructor(name, age) {
    super(name);       // 必须先调用 super，否则访问 this 会报错
    this.age = age;
  }

  sayName() {
    return `${super.sayName()}，今年 ${this.age} 岁`;
  }
}

const child = new Child('Alice', 25);
console.log(child.sayName());            // 'Alice，今年 25 岁'
console.log(child instanceof Child);     // true
console.log(child instanceof Parent);    // true
```

> **避坑提示**：`class` 本质仍然是原型继承。`typeof Child === 'function'`。下面我们验证这一点。

```js
// class 就是语法糖的证明
class Foo {}
typeof Foo;                                      // 'function'
Foo.prototype.constructor === Foo;               // true
Object.getPrototypeOf(new Foo()) === Foo.prototype; // true
```

### 5. Object.create() 和 Object.setPrototypeOf()

#### 5.1 Object.create()

```js
// 创建一个以指定对象为原型的空对象
const parent = {
  greet() { return 'hello'; }
};

const child = Object.create(parent);
console.log(child.greet());              // 'hello' —— 沿原型链找到
console.log(child.hasOwnProperty('greet')); // false

// 与 {} 的区别
const plain = { __proto__: parent };     // 不推荐
const better = Object.create(parent);    // 推荐方式

// 实际应用：安全的原型继承（上面 4.4 中用过）
Child.prototype = Object.create(Parent.prototype);
```

#### 5.2 Object.setPrototypeOf() / Object.getPrototypeOf()

```js
const a = { x: 1 };
const b = { y: 2 };

Object.setPrototypeOf(b, a);
console.log(b.x); // 1 —— b 现在可以访问 a 的属性
console.log(Object.getPrototypeOf(b) === a); // true

// ⚠️ 性能警告：修改已有对象的原型非常慢！
// 如果可能，在创建对象时就通过 Object.create() 设置原型
```

### 6. instanceof 的原理

```js
// instanceof 检查右侧构造函数的 prototype 是否在左侧对象的原型链上
function myInstanceof(obj, constructor) {
  let proto = Object.getPrototypeOf(obj);

  while (proto !== null) {
    if (proto === constructor.prototype) return true;
    proto = Object.getPrototypeOf(proto);
  }

  return false;
}

// 验证
class Animal {}
class Dog extends Animal {}

const dog = new Dog();

console.log(myInstanceof(dog, Dog));    // true
console.log(myInstanceof(dog, Animal)); // true（继承链中存在）
console.log(myInstanceof(dog, Object)); // true
console.log(myInstanceof(dog, Array));  // false

// 但原型链可以被"伪造"
const fake = Object.create(Array.prototype);
console.log(fake instanceof Array); // true —— 即使它不是真正的数组
```

> **避坑提示**：`instanceof` 只在同一个执行上下文（realm）中可靠。跨 iframe 或跨 window 时，各有一套独立的原型链，`arr instanceof Array` 可能为 `false`。此时用 `Array.isArray(arr)` 更可靠。

## 常见问题

### Q1：`__proto__` 和 `prototype` 总是让我搞混，怎么记？

- **`prototype`**：函数特有的属性，指向"该构造函数生产的实例的原型对象"。把它想象成"模具"。
- **`__proto__`**：所有对象都有的属性，指向"我自己的原型"。把它想象成"我的爸爸是谁"。
- 实例的 `__proto__` === 构造函数的 `prototype`。

### Q2：`class` 和原型继承到底有什么区别？

`class` 是原型继承的语法糖，但它们有重要差异：
1. `class` 必须用 `new` 调用，普通函数可以直接调用
2. `class` 内部自动严格模式
3. `class` 的方法不可枚举
4. `class` 没有变量提升（与函数声明不同）
5. 子类构造函数中必须先调用 `super()` 才能访问 `this`

### Q3：`for...in` 会遍历原型上的属性吗？

会！`for...in` 遍历自身 + 原型链上所有可枚举属性。如果不想要原型属性，加 `hasOwnProperty` 过滤：

```js
for (const key in obj) {
  if (obj.hasOwnProperty(key)) {
    console.log(key); // 只输出自身属性
  }
}
```

### Q4：`null` 有原型吗？

没有。`null` 是原型链的终点：`Object.getPrototypeOf(Object.prototype) === null`。

### Q5：为什么 `Function instanceof Object` 返回 `true`？

```js
// Function.__proto__ → Function.prototype
// Function.prototype.__proto__ → Object.prototype
// Object.prototype 在 Function 的原型链上 → true
```

同理 `Object instanceof Function` 也返回 `true`，因为 `Object` 本身是函数（构造函数）。

### Q6：为什么说"方法不推荐直接定义在构造函数内部"？

```js
// ❌ 每次 new 都创建一个新的 sayHi 函数
function Person(name) {
  this.name = name;
  this.sayHi = function() { return 'Hi, ' + this.name; };
}

// ✅ sayHi 只创建一次，所有实例共享
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function() { return 'Hi, ' + this.name; };
```

前者浪费内存，且 `p1.sayHi !== p2.sayHi`；后者所有实例引用同一个函数，`p1.sayHi === p2.sayHi`。

### Q7：`Object.create(null)` 有什么用？

创建一个"完全干净"的对象，没有任何原型链上的属性（没有 `toString`、`hasOwnProperty` 等），非常适合用作纯字典/哈希表：

```js
const dict = Object.create(null);
dict.key1 = 'value1';
// dict.hasOwnProperty ?? → 没有！因为原型是 null
// 适合存键值对且不担心命名冲突
```

### Q8：如何判断一个属性是自身的还是原型的？

```js
const obj = new Person('Alice');

// 自身属性
obj.hasOwnProperty('name');          // true

// 原型属性
obj.hasOwnProperty('greet');         // false
'greet' in obj;                      // true（in 检查原型链）
```

## 本节小结

- **三角关系**：`实例.__proto__ === 构造函数.prototype`，`原型.constructor === 构造函数`
- **原型链**：属性访问沿 `__proto__` 链查找，止于 `null`
- **new 的 5 步**：建空对象 → 绑原型 → 绑 this → 执行 → 返回
- **继承演进**：原型链 → 构造函数 → 组合 → 寄生组合 → `class extends`
- **class**：语法糖但更严格（必须 new、use strict、不可枚举方法）
- **instanceof**：检查 `prototype` 是否在原型链上，跨 realm 不可靠
- **最佳实践**：用 `class extends` 实现继承，用 `Object.create()` 创建以指定对象为原型的对象

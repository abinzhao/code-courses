## 内容讲解

### 一、控制流先表达业务规则

```js
function getAccessMessage(user) {
  if (!user) return '请先登录';
  if (user.status === 'disabled') return '账号已停用';
  if (!user.permissions.includes('article:read')) return '没有阅读权限';
  return '允许访问';
}
```

提前返回减少嵌套，但不应隐藏状态转换。条件较多时先建立决策表：

| 登录 | 账号状态 | 权限 | 结果 |
|---|---|---|---|
| 否 | - | - | 登录提示 |
| 是 | disabled | 任意 | 拒绝 |
| 是 | active | 无 | 拒绝 |
| 是 | active | 有 | 允许 |

`switch` 适合对同一个离散值分支：

```js
function getStatusLabel(status) {
  switch (status) {
    case 'draft':
      return '草稿';
    case 'published':
      return '已发布';
    case 'archived':
      return '已归档';
    default:
      throw new Error(`未知状态: ${status}`);
  }
}
```

`default` 不应静默吞掉未知业务状态。

### 二、循环的选择取决于目标

```js
for (const article of articles) {
  console.log(article.title);
}
```

适合需要 `break`、`continue` 或 `await` 的顺序流程。

```js
for (let index = 0; index < articles.length; index += 1) {
  console.log(index, articles[index]);
}
```

适合确实需要索引和步长的算法。

不要用 `forEach(async () => {})` 等待异步任务：

```js
// 错误：外层不会等待回调
articles.forEach(async article => {
  await save(article);
});

// 串行
for (const article of articles) {
  await save(article);
}

// 并行，并明确等待整体结果
await Promise.all(articles.map(article => save(article)));
```

串行和并行不是语法偏好，而是并发、顺序和失败策略的选择。

### 三、数组方法按意图分类

#### 变换

```js
const titles = articles.map(article => article.title);
```

`map` 应返回与输入一一对应的新数组。不要用它只做日志或写入外部变量。

#### 筛选

```js
const published = articles.filter(article => article.status === 'published');
```

#### 查找

```js
const article = articles.find(item => item.id === targetId);
const index = articles.findIndex(item => item.id === targetId);
```

#### 判断

```js
const hasDraft = articles.some(article => article.status === 'draft');
const allValid = articles.every(article => article.title.trim().length > 0);
```

#### 聚合

```js
const countByStatus = articles.reduce((result, article) => {
  result[article.status] = (result[article.status] ?? 0) + 1;
  return result;
}, {});
```

当 `reduce` 让意图更难读时，普通循环更合适。代码短不是唯一质量指标。

### 四、原地修改与新值

会修改原数组：

```js
sort();
reverse();
splice();
push();
pop();
```

返回新数组：

```js
toSorted();
toReversed();
toSpliced();
map();
filter();
```

```js
const original = [3, 1, 2];
const sorted = original.toSorted((a, b) => a - b);

console.log(original); // [3, 1, 2]
console.log(sorted);   // [1, 2, 3]
```

原地修改并不天然错误，但必须明确所有权。如果数组仍被其他状态或缓存引用，修改会制造难以追踪的共享状态。

### 五、对象属性不是简单的键值表

```js
const article = {
  id: 'a-1',
  title: '事件循环',
  status: 'draft',
};

Object.keys(article);
Object.values(article);
Object.entries(article);
Object.hasOwn(article, 'title');
```

`for...in` 会遍历可枚举字符串属性，包括继承链上的属性：

```js
for (const key in article) {
  if (!Object.hasOwn(article, key)) continue;
  console.log(key, article[key]);
}
```

处理普通业务对象时，`Object.entries()` 往往更清晰。

对象展开是浅复制：

```js
const copy = { ...article };
```

嵌套对象仍共享引用：

```js
const state = { profile: { name: 'Ada' } };
const next = { ...state };
next.profile.name = 'Grace';
console.log(state.profile.name); // Grace
```

需要更新嵌套状态时复制被修改路径：

```js
const nextState = {
  ...state,
  profile: {
    ...state.profile,
    name: 'Grace',
  },
};
```

### 六、Object、Map、Set 如何选择

| 结构 | 适合 |
|---|---|
| Object | 固定字段的数据记录、JSON |
| Map | 动态键集合、非字符串键、频繁增删 |
| Set | 唯一值集合、成员判断 |

```js
const articleById = new Map(
  articles.map(article => [article.id, article])
);

const selectedTags = new Set(['javascript', 'browser']);
selectedTags.add('performance');
selectedTags.has('browser');
```

不要为了“查找快”盲目把所有数组改成 Map。数据规模、构建成本、更新频率和序列化需求都要考虑。

### 七、字符串、数字与空值边界

```js
const title = input.trim();
const page = Number(searchParams.get('page'));

if (!Number.isInteger(page) || page < 1) {
  throw new RangeError('page 必须是正整数');
}
```

`Number('')` 是 `0`，`parseInt('12px', 10)` 是 `12`。它们表达不同解析策略，不能互换使用。

空值合并：

```js
const pageSize = config.pageSize ?? 20;
```

`??` 只在 `null`/`undefined` 时使用默认值；`||` 会把 `0`、空字符串和 `false` 也当作缺失。

### 八、日期与国际化

不要手工拼接用户可见日期和数字：

```js
const dateFormatter = new Intl.DateTimeFormat('zh-CN', {
  dateStyle: 'medium',
  timeStyle: 'short',
  timeZone: 'Asia/Shanghai',
});

const numberFormatter = new Intl.NumberFormat('zh-CN', {
  style: 'percent',
  maximumFractionDigits: 1,
});

console.log(dateFormatter.format(new Date()));
console.log(numberFormatter.format(0.856));
```

存储和传输时间时必须明确时区语义。`2026-10-12` 是日历日期，`2026-10-12T08:00:00Z` 是时间点，两者不能机械互换。

### 九、正则只解决有限文本模式

```js
const safeKeyword = RegExp.escape(userInput);
const matcher = new RegExp(safeKeyword, 'iu');
```

正则适合匹配局部模式，不适合完整解析 HTML、URL 或编程语言。已有结构化解析器时应优先使用。

## 常见问题

### Q1：什么时候用 `for...of`，什么时候用数组方法？

需要中断、顺序 await 或复杂控制流时用 `for...of`；需要表达变换、筛选和聚合时用数组方法。

### Q2：`map` 能修改原数组吗？

`map` 返回新数组，但回调接收的对象元素仍可能被修改。新数组不等于深复制。

### Q3：Object 和 Map 哪个更快？

没有脱离场景的统一答案。先按数据语义选择，再针对真实规模做基准测试。

### Q4：为什么不能直接比较两个对象？

对象使用引用相等：

```js
{} === {}; // false
```

需要根据业务键或结构化比较规则判断。

### Q5：`JSON.stringify` 能做深复制吗？

它会丢失 `undefined`、函数、Symbol，并改变 Date、Map、Set 等类型，还不能处理循环引用。不要把序列化副作用当通用复制方案。

### Q6：`Intl` 会让包体积变大吗？

现代运行时通常内置 Intl，但可用 locale 数据取决于运行环境。目标为精简 Node 镜像或嵌入式运行时时需要验证。

## 实操作业

### 基础：文章统计

给定文章数组，输出：

- 已发布文章
- 每个状态数量
- 所有唯一标签
- 按更新时间倒序的新数组
- 指定 ID 的文章

要求原数组不被修改。

### 进阶：索引与筛选

实现：

```js
createArticleIndex(articles);
filterArticles(articles, { keyword, tags, status });
```

为缺失字段、重复 ID、空关键词和多标签组合定义明确行为。

### 挑战：日期适配与国际化

实现 Atlas 阅读历史：

1. 内部保存 ISO 时间点。
2. 根据传入 locale 和 timeZone 格式化。
3. 按“用户所在时区的自然日”分组。
4. 覆盖夏令时切换和非法日期输入。

### 作业参考与验收

- **基础**：filter 取已发布，reduce 统计，Set 去重标签，toSorted 或复制后 sort，find 按 ID 查询。空数组返回空结果；冻结原数组后运行证明没有原地修改。
- **进阶**：索引用 Map 且明确重复 ID 拒绝或覆盖策略；筛选组合先规定标签 AND/OR。测试大小写、空 keyword、未知 status 与缺失字段，禁止依赖偶然 truthy 值。
- **挑战**：内部存 ISO 时间点，用 Intl.DateTimeFormat 指定 locale/timeZone；按该时区年月日分组。夏令时日不总长 24 小时，非法日期返回明确错误。

## 本节小结

- 控制流应先表达业务决策，再追求简短
- 数组方法各自表达变换、筛选、查找、判断与聚合
- 对象展开是浅复制，原地修改要先确认所有权
- Object、Map、Set 分别适合记录、动态映射和唯一集合
- 日期、数字和文本格式化应使用结构化 API，并明确 locale 与时区

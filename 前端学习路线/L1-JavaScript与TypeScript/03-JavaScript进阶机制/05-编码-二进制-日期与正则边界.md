## 学习目标

- 能区分字符串长度、Unicode 码点、用户感知字符与字节数。
- 能正确解码分块 UTF-8，处理日期时区和不可信正则输入。

## 内容讲解

### 1. 长度不是同一个单位

JavaScript 字符串以 UTF-16 码元表示。`'😀'.length === 2`，展开迭代得到一个码点。组合字符与多码点 emoji 仍可能表现为一个用户感知字符。

```js
const value = 'A😀';
console.log(value.length); // 3 个 UTF-16 码元
console.log([...value].length); // 2 个码点
console.log(new TextEncoder().encode(value).byteLength); // 5 个 UTF-8 字节
const segmenter = new Intl.Segmenter('zh', { granularity: 'grapheme' });
console.log([...segmenter.segment(value)].length); // 2 个字素簇
```

界面截断可按 grapheme，HTTP 限流与文件大小按字节，数据库限制按其实际字符/字节语义。不要用前端 length 直接证明服务器请求大小满足限制。

### 2. 分块解码

UTF-8 多字节字符可能横跨网络分块，不能每块独立解码：

```js
const bytes = new TextEncoder().encode('中');
const decoder = new TextDecoder('utf-8', { fatal: true });
const first = decoder.decode(bytes.slice(0, 1), { stream: true });
const second = decoder.decode(bytes.slice(1), { stream: true });
const tail = decoder.decode(); // 最后刷新，检测残缺字符
console.log(first + second + tail); // 中
```

二进制文件使用 ArrayBuffer/Uint8Array/DataView，明确大小端。Base64 是编码，不是加密；URL 编码也不能替代 HTML 或 SQL 安全处理。

### 3. 时间模型

区分瞬时时刻、用户当地日期与持续时长。存审计时间用带时区的 ISO 字符串或 epoch；“每周当地 9 点”还需要 IANA 时区和夏令时规则。

```js
const instant = new Date('2026-10-12T08:00:00Z');
console.log(new Intl.DateTimeFormat('zh-CN', {
  timeZone: 'Asia/Shanghai',
  dateStyle: 'medium', timeStyle: 'short',
}).format(instant));
```

日期输入 `2026-10-12` 不应未经业务建模就转换成某个瞬间。性能测量用 `performance.now()` 的单调时钟；系统墙钟可能调整。禁止接受含糊的 `10/12/26` 作为跨地区 API 日期。

### 4. 正则与验证

`/^(a+)+$/` 一类嵌套量词在某些输入下可能大量回溯，造成 ReDoS。避免让用户提供无限制正则，限制输入长度与功能，优先字符串查找或经过评估的模式。

使用带 `g` 或 `y` 的正则重复调用 test 时注意 `lastIndex` 状态。业务校验不能只用宽松正则：URL 用 URL 解析器，日期解析后还要检查合法性，文件类型还要验证实际内容。

```js
export function parseHttpUrl(raw) {
  const url = new URL(raw);
  if (!['http:', 'https:'].includes(url.protocol)) {
    throw new Error('只允许 HTTP(S)');
  }
  if (url.username || url.password) throw new Error('不允许 URL 凭据');
  return url;
}
```

此函数只完成 URL 语义校验，不防止 SSRF；服务端请求还需域名、IP、重定向和网络出口限制。

## 常见问题

**为什么按字符切割会破坏 emoji？** UTF-16 码元与 grapheme 不相同。

**UTC 能解决所有时间问题吗？** 只能表达瞬间，排班、账期和当地日期仍需业务时区。

**URL 能解析就安全吗？** 能解析仅代表格式成立，不代表协议、目标地址或业务权限允许。

## 实操作业

1. 基础：测试 ASCII、中文、emoji 与组合字符的四种长度。
2. 进阶：将一个 UTF-8 文件拆在多字节字符中间，流式解码后与原文比较。
3. 挑战：为 URL 校验和时间格式写正常、无效、时区三类测试。

### 参考答案与验收

`A😀` 是 3 码元、2 码点、5 UTF-8 字节、2 grapheme；分块解码必须使用 stream 并刷新。URL 测试应拒绝 javascript、凭据和非法字符串。危险正则只分析复杂度，不在主浏览器线程执行无界压力实验。

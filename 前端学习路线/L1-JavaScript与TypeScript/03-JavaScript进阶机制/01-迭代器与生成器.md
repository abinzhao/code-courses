# 01-迭代器与生成器

## 学习目标

- 理解可迭代协议和迭代器协议，能手动实现一个符合规范的迭代器
- 掌握 `Symbol.iterator` 在 `for...of` 中的核心作用
- 理解生成器的执行模型：暂停-恢复，`yield` 的双向通信
- 掌握异步迭代器（`Symbol.asyncIterator`）和 `for await...of` 的使用场景
- 能把生成器用于实际场景：状态机、惰性求值、分页数据流

---

## 内容讲解

### 一、从 `for...of` 说起：为什么会有一个「迭代协议」？

你每天都在写 `for (const item of arr)`，但你是否想过：为什么 `for...of` 能遍历 `Array`，却不能遍历普通对象？为什么它也能遍历 `Map`、`Set`、字符串？

答案藏在两个协议里：**可迭代协议（Iterable Protocol）**和**迭代器协议（Iterator Protocol）**。

JavaScript 不检查一个对象「是什么类型」，而是检查它「是否实现了某个协议」——这就是鸭子类型（Duck Typing）。

### 二、迭代器协议（Iterator Protocol）

一个对象要成为迭代器，必须实现一个 `next()` 方法，该方法返回 `{ value, done }` 格式的对象：

- `value`：本次迭代的值
- `done`：布尔值，`true` 表示迭代结束

```javascript
// 手动实现一个迭代器
function createRangeIterator(start, end) {
  let current = start;
  return {
    next() {
      if (current <= end) {
        return { value: current++, done: false };
      }
      return { value: undefined, done: true };
    }
  };
}

const it = createRangeIterator(1, 3);
console.log(it.next()); // { value: 1, done: false }
console.log(it.next()); // { value: 2, done: false }
console.log(it.next()); // { value: 3, done: false }
console.log(it.next()); // { value: undefined, done: true }
```

这个迭代器可以直接用 `while` 循环消费，但不能用 `for...of`——因为它还没有告诉 JS 引擎「我是可迭代的」。

### 三、可迭代协议（Iterable Protocol）

可迭代协议要求对象（或其原型链上的某个对象）实现 `Symbol.iterator` 方法，该方法**无参数，返回一个迭代器对象**。

```javascript
// 给 range 对象加上 Symbol.iterator，就变成了可迭代对象
const range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {
    // 返回一个迭代器
    let current = this.from;
    const last = this.to;
    return {
      next() {
        if (current <= last) {
          return { value: current++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

// 现在可以用 for...of 了！
for (const num of range) {
  console.log(num); // 依次输出 1, 2, 3, 4, 5
}

// 也可以用展开运算符
console.log([...range]); // [1, 2, 3, 4, 5]
```

**关键理解**：可迭代对象（Iterable）和迭代器（Iterator）是两个不同的角色：

```
[Symbol.iterator]()  →  迭代器对象
    ▲                       ▲
    │                       │
  可迭代对象              实现 next() 方法
（可以被 for...of 消费）   （负责游标推进）
```

你可以把它们合二为一——让对象同时作为可迭代对象和迭代器：

```javascript
const range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {
    this.current = this.from; // 每次调用重置游标
    return this;              // 返回自身作为迭代器
  },

  next() {
    if (this.current <= this.to) {
      return { value: this.current++, done: false };
    }
    return { done: true };
  }
};
```

> **避坑提示**：当迭代器和可迭代对象是同一个对象时，每次 `for...of` 都会先调用 `[Symbol.iterator]()`，你必须在其中重置游标。否则第二次遍历的结果为空（游标已经到末尾了）。

### 四、`for...of` 的完整工作机制

当你写 `for (const item of obj)` 时，JS 引擎实际做了这些事：

```
1. 调用 obj[Symbol.iterator]()，获取迭代器 it
2. 调用 it.next()，得到 { value, done }
3. 如果 done === false，将 value 赋给 item，执行循环体
4. 重复步骤 2-3，直到 done === true
5. 如果迭代过程中出错，调用 it.return()（如果存在）做清理
```

这意味着任何实现了 `Symbol.iterator` 的对象都可以被 `for...of` 遍历。

### 五、内置可迭代对象

以下对象已经内置了 `Symbol.iterator`：

```javascript
// Array
for (const item of [1, 2, 3]) { /* ... */ }

// String
for (const char of 'hello') { /* h, e, l, l, o */ }

// Map — 每次迭代返回 [key, value]
const map = new Map([['a', 1], ['b', 2]]);
for (const [key, value] of map) { /* key='a', value=1 ... */ }

// Set — 每次迭代返回元素本身
for (const item of new Set([1, 2, 3])) { /* 1, 2, 3 */ }

// TypedArray
for (const num of new Uint8Array([10, 20])) { /* 10, 20 */ }

// arguments（在非箭头函数中）
function demo() {
  for (const arg of arguments) { /* ... */ }
}

// NodeList（DOM 查询结果）
for (const el of document.querySelectorAll('div')) { /* ... */ }
```

**注意**：普通对象 `{}` **不是**可迭代对象。如果你确实需要遍历对象属性，用 `Object.keys()`、`Object.values()` 或 `Object.entries()`，它们返回的是数组。

### 六、生成器（Generator）：迭代器的语法糖

生成器是一个能中途暂停、然后从中断处恢复执行的函数。语法是 `function*` + `yield`：

```javascript
// 用生成器重写上面的 range
function* rangeGenerator(from, to) {
  for (let i = from; i <= to; i++) {
    yield i; // 交出值，暂停执行
  }
}

const gen = rangeGenerator(1, 3);
console.log(gen.next()); // { value: 1, done: false }
console.log(gen.next()); // { value: 2, done: false }
console.log(gen.next()); // { value: 3, done: false }
console.log(gen.next()); // { value: undefined, done: true }

// 生成器返回的对象既是迭代器，也是可迭代对象
for (const num of rangeGenerator(1, 3)) {
  console.log(num); // 1, 2, 3
}
```

**执行模型**：生成器函数调用时**不会立即执行函数体**，而是返回一个生成器对象。每次调用 `.next()`，函数执行到下一个 `yield` 后暂停，并将 `yield` 后的值作为返回的 `value`。

```
调用 gen.next() →
  ┌─────────────────┐
  │ 执行到 yield    │ → 暂停，返回 { value: xxx, done: false }
  └─────────────────┘
调用 gen.next() →
  ┌─────────────────┐
  │ 从暂停处恢复    │ → 执行到下一个 yield / return → 暂停/结束
  └─────────────────┘
```

#### 6.1 `yield*`：委托给另一个可迭代对象

```javascript
function* combined() {
  yield* [1, 2, 3];      // 逐个产出数组元素
  yield* 'ab';           // 逐个产出字符串字符
  yield '单独值';
}

console.log([...combined()]); // [1, 2, 3, 'a', 'b', '单独值']
```

`yield*` 等价于：

```javascript
function* combined() {
  for (const item of [1, 2, 3]) yield item;
  for (const char of 'ab') yield char;
  yield '单独值';
}
```

#### 6.2 `.next()` 的双向通信：向生成器内部传值

这是生成器最强大也最容易被忽视的特性——`next()` 的参数会成为上一个 `yield` 表达式的返回值：

```javascript
function* twoWay() {
  const a = yield '请给我 a 的值';      // next() 的参数赋给 a
  console.log('收到 a =', a);
  const b = yield '请给我 b 的值';      // 下一个 next() 的参数赋给 b
  console.log('收到 b =', b);
  return a + b;
}

const gen = twoWay();
console.log(gen.next().value);    // '请给我 a 的值'  （启动生成器，参数被忽略）
console.log(gen.next(10).value);  // '请给我 b 的值'  （a = 10）
console.log(gen.next(20).value);  // 30               （b = 20, return 30）
```

输出：
```
请给我 a 的值
收到 a = 10
请给我 b 的值
收到 b = 20
30
```

### 七、异步迭代器（Async Iterator）

当你需要遍历异步数据源（比如逐页拉取 API 数据）时，同步迭代器不够用。ES2018 引入了异步迭代器协议：

```javascript
// 手动实现一个异步可迭代对象
const asyncRange = {
  from: 1,
  to: 3,

  [Symbol.asyncIterator]() {
    let current = this.from;
    return {
      async next() {
        // 模拟异步操作
        await new Promise(resolve => setTimeout(resolve, 100));
        if (current <= this.to) {
          return { value: current++, done: false };
        }
        return { done: true };
      }.bind(this) // 注意：next 中的 this 需要绑定
    };
  }
};
```

更优雅的方式是用**异步生成器**（`async function*` + `for await...of`）：

```javascript
// 异步生成器：完美处理分页数据流
async function* fetchPages(apiUrl, totalPages) {
  for (let page = 1; page <= totalPages; page++) {
    const response = await fetch(`${apiUrl}?page=${page}`);
    const data = await response.json();
    yield data; // 每拉取一页，就产出数据
  }
}

// 消费异步生成器
(async () => {
  const pages = fetchPages('/api/users', 5);
  for await (const pageData of pages) {
    console.log('当前页数据：', pageData.length, '条');
    pageData.forEach(user => console.log(user.name));
  }
})();
```

### 八、实战：用生成器实现状态机

生成器的「暂停-恢复」机制天然适合实现状态机：

```javascript
// 一个简单的红绿灯状态机
function* trafficLight() {
  while (true) {
    yield '🟢 绿灯 — 通行';
    yield '🟡 黄灯 — 减速准备停车';
    yield '🔴 红灯 — 停车';
  }
}

const light = trafficLight();
// 每次调用 next() 切换到下一个状态
console.log(light.next().value); // 🟢 绿灯 — 通行
console.log(light.next().value); // 🟡 黄灯 — 减速准备停车
console.log(light.next().value); // 🔴 红灯 — 停车
console.log(light.next().value); // 🟢 绿灯 — 通行 （循环）

// 实际使用：定时切换
setInterval(() => {
  console.log(light.next().value);
}, 2000);
```

### 九、实战：用异步生成器处理分页数据流

```javascript
// 通用的分页数据拉取器：边拉边处理，不等全部加载完
async function* paginatedFetcher(url, pageSize = 20) {
  let page = 1;
  let hasMore = true;

  while (hasMore) {
    const res = await fetch(`${url}?page=${page}&size=${pageSize}`);
    const { items, total } = await res.json();

    if (items.length === 0) {
      hasMore = false;
      break;
    }

    yield items;                // 逐页产出数据
    page++;
    if (page * pageSize >= total) hasMore = false;
  }
}

// 使用：大规模数据处理不爆内存
(async () => {
  for await (const batch of paginatedFetcher('/api/large-dataset', 50)) {
    // 每次只处理 50 条，不会一次性把所有数据加载到内存
    batch.forEach(item => processRecord(item));
  }
  console.log('全部处理完成');
})();
```

## 常见问题

**Q1：`for...of` 和 `for...in` 有什么区别？**

`for...of` 遍历**值**（value），要求对象实现了 `Symbol.iterator`。`for...in` 遍历**可枚举的键**（key），适用于任意对象，但会遍历原型链上的属性。遍历数组用 `for...of`，遍历对象属性用 `for...in` 或 `Object.keys()`。

**Q2：为什么普通对象 `{}` 不能被 `for...of` 遍历？**

因为普通对象没有实现 `Symbol.iterator`。这是有意为之——对象属性的遍历顺序没有明确的迭代语义（key 的顺序受属性类型影响），强行加迭代协议反而会造成歧义。需要遍历时用 `Object.entries()`。

**Q3：`yield*` 和 `yield` 在行为上有什么本质区别？**

`yield*` 会将迭代控制权**委托**给另一个可迭代对象，逐个产出其元素。在 `yield*` 期间，`.next()` 的返回值会传递到被委托的迭代器中。而 `yield` 只产出单个值。

**Q4：生成器和普通函数在内存上有什么区别？**

生成器在暂停时会保留其执行上下文（局部变量、调用栈等），所以一个暂停中的生成器会比普通函数占用更多内存。不要创建大量长时间暂停不消费的生成器。

**Q5：异步迭代器和 `Promise.all` 在分页场景中该选哪个？**

`Promise.all` 一次性并发请求所有页，适合页面总数已知且后端支持高并发的场景。异步迭代器串行逐页拉取，适合边拉边处理的大数据流场景——它不会把全部数据同时加载到内存，是内存友好的。

**Q6：`for await...of` 能在普通同步可迭代对象上用吗？**

不能。`for await...of` 要求对象实现 `Symbol.asyncIterator`，不是 `Symbol.iterator`。如果对象只有 `Symbol.iterator`，用普通 `for...of`。

**Q7：生成器的 `.return()` 和 `.throw()` 方法是干什么的？**

`.return(value)` 会强制终止生成器，在 `yield` 处抛出一个特殊的完成信号，使 `done` 变为 `true`。`.throw(error)` 会在生成器暂停的 `yield` 处抛出一个错误，你可以在生成器内部 `try...catch` 捕获它，实现错误注入。

**Q8：如何判断一个对象是不是可迭代对象？**

检查 `obj != null && typeof obj[Symbol.iterator] === 'function'`。注意 `null` 和 `undefined` 没有 `Symbol.iterator`。

## 本节小结

- JavaScript 通过**可迭代协议**（`Symbol.iterator`）和**迭代器协议**（`next()` 返回 `{ value, done }`）实现统一的遍历机制
- `for...of` 消费实现了可迭代协议的对象，Array、Map、Set、String 等都内置了该协议
- **生成器**（`function*`）是迭代器的语法糖，`yield` 暂停执行，`.next()` 恢复并双向传值
- `yield*` 将迭代委托给另一个可迭代对象，逐个产出其元素
- **异步迭代器**（`Symbol.asyncIterator`）和 `for await...of` 适合串行处理异步数据流
- **异步生成器**（`async function*`）结合了两者优势，是处理分页数据、流式数据的优雅方案
- 生成器的暂停-恢复模型天然适合状态机、惰性求值和流式处理等场景

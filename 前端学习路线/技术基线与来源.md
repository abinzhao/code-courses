# 技术基线与来源

> - 最后核对：2026-10-12
> - 适用范围：`前端学习路线/` 全部课程
> - 原则：具体项目以锁文件、运行时输出和版本匹配的官方文档为准。

## 课程基线

| 领域 | 教学基线 | 兼容或验证范围 |
|---|---|---|
| JavaScript | ECMAScript 2026 | Stage 4 不等于已进入当年标准，按 TC39 发布年份核对 |
| TypeScript | TypeScript 6.x | 不依赖实验性编译器选项 |
| Node.js | Node.js 24 LTS | Node.js 22 维护期兼容；Node 18/20 不作为新项目基线 |
| 包管理 | pnpm 10 | CI 使用锁文件和 `--frozen-lockfile` |
| React | React 19 | 框架集成以项目实际锁定的小版本为准 |
| Next.js | Next.js 16 | 使用 async Request APIs、`proxy.ts` 和默认 Turbopack |
| Vue | Vue 3 | 使用 Composition API 与 `<script setup>` |
| PostgreSQL | PostgreSQL 18 | SQL 与执行计划在 PostgreSQL 18 环境验证 |
| 浏览器 | 当前稳定版 Chrome、Firefox、Safari | Web 平台兼容性以 Baseline/MDN 数据为准 |

## 版本敏感规则

1. 示例不得只写“最新版本”，必须给出主版本或能力检测方式。
2. 文档中的运行时顺序必须注明浏览器/Node.js、CJS/ESM、调用位置。
3. Stage 3 提案只能放入“前瞻”部分；Stage 4 仍需核对预计标准发布年份。
4. 框架内部行为不得写成 Web 标准行为。
5. 安全示例必须区分教学简化与生产要求，不提供默认密钥、明文密码或仅靠客户端校验的实现。
6. 版本升级先阅读迁移文档，再更新示例和验证命令。

## 核对记录格式

修改版本敏感课程时，在文档元数据中记录：

```text
技术基线：Node.js 24 / Next.js 16
最后验证：2026-10-12
验证方式：pnpm test；pnpm build；目标浏览器手工路径
一手资料：官方文档 URL
```

“最后验证”只表示对应命令或行为确实执行过。只完成文本审阅时，应写“文档审阅”，不能写成“运行验证通过”。

# Course Batch Writing

把「已确认的知识地图」批量落成课程单元正文，并完成校验、链接收口与提交推送。核心立场：**知识地图是唯一契约，done 由校验证据说了算，不由子代理自评说了算。**

## 适用与前提

- 适用于一次编写多个课程单元（典型：一门课 N 周、每周 2 单元），或补齐一门课的全部剩余正文。
- 只改一个单元时直接写，不启用本流程。
- 开始前必须已有（或先产出并经用户确认）一份知识地图：每单元的编号、标题、所属阶段目录、周次、主线项目与技术背景。地图未确认不得批量落正文。

## 流程总览

```text
0 锁定知识地图契约（顶层文档 + 单元清单），用户确认
1 按周切分任务，确定文件边界（每个子代理只写独立文件）
2 并行派发子代理批量写作（一周 2 单元/代理）
3 收口校验：行数 / 六段结构 / 断链 / 占位符 / 机密
4 更新框架文档链接与状态
5 Git 提交并推送
```

## Stage 0 · 知识地图契约

1. 课程为独立子目录，顶层三份框架文档：`README.md`（定位/技术基线/单元总目录）、`00-课程总纲与培养标准.md`（能力标准/评分/不通过条件）、`XX-N周教学计划.md`（逐周重点/实践/验收点）。
2. 单元清单必须逐项列出：周次、编号 Uxx、标题、阶段目录、每个单元的具体知识范围。
3. 技术基线写“当前稳定版”，不写死小版本；开课时以官方文档为准。
4. 把方案与关键决策点交给用户确认（可用结构化选项），**确认后再写正文**。
5. 框架文档中单元先以纯文本列出，避免提前产生断链。

## Stage 1 · 切分任务与文件边界

- 以“一周 2 个单元”为一个子代理任务；单次并行 4 个左右子代理，分批推进（如每 4 周一批）。
- 每个子代理的目标文件路径必须互不重叠；禁止多个代理改同一文件。
- 明确告知子代理：只 Write 指定新文件，**不得修改框架文档、不更新链接、不动他人文件**。
- 链接与状态由主代理在收口阶段统一更新，保证单点控制。

## Stage 2 · 并行子代理写作

用 general_purpose_task 派发。每个子代理 prompt 必须自包含以下要素：

1. 课程目录绝对路径、技术背景（年份/框架/主线项目/学员前置基础）。
2. 两个目标文件的**精确绝对路径**与标题。
3. 六段式结构与顺序（见下）。
4. 硬性要求：
   - 单篇 ≥600 行（写完 `wc -l` 自查），无注水、无占位符（禁“略/TODO/待补充”）；
   - 首行 `# 标题` 与文件名一致；
   - 目标 8-10 条行为化能力点；技术栈用表格；
   - 理论 10-15 个 `###` 小节，每节讲“是什么 / 与开发关系 / 可运行示例 / 常见误区”，代码用真实语法、禁止 HTML 标签与 DOM 假设；
   - 课后题恰好 10 道（含场景题）；实践练习恰好 3 个，每个含任务/伪代码或参考代码/步骤约束/提交物/验收标准；
   - 阶段验收作业含任务/完成标准/100 分评分表/强制不通过条件。
5. 逐个单元给出具体知识范围，避免子代理自由发挥偏离地图。
6. 术语红线（如逻辑层无 window/document、setData 跨线程异步、密钥不放前端）。
7. 最终只回报：文件绝对路径、`wc -l`、六段标题是否齐全。

可直接复制的 prompt 骨架见 assets/unit-template.md。

## Stage 3 · 收口校验（主代理执行）

全部子代理返回后，不信任其自评，逐项用证据核验：

1. **文件齐全**：用 Glob 确认每个地图单元文件都已创建。
2. **行数**：`wc -l` 全部单元，单篇 ≥600。
3. **六段结构**：Grep 六个固定 `##` 标题，每单元命中 6 个。
4. **占位符/HTML/机密**：Grep `TODO|待补充|占位`、`div|span` 等非法标签、`secret|password|private key` 等机密痕迹。
5. **断链**：框架文档链接更新后，运行 `node scripts/check-links.js <框架文档...>` 校验相对链接目标存在，要求 0 断链。
6. 子代理报告的异常（误建文件、笔误）逐一核实处理；误建文件删除。

校验命令示例：

```bash
wc -l <course>/**/*.md
```

## Stage 4 · 更新链接与状态

1. 把框架文档中纯文本单元项替换为真实相对链接（README 与教学计划两处保持一致）。
2. 更新课程状态（规划中/编写中 → 已完成）及仓库根 README 的课程索引。
3. 链接更新后必须重跑断链脚本。

## Stage 5 · Git 提交推送

1. `git status`、`branch --show-current`、`remote -v` 确认分支与远端；识别用户已有改动，不混入无关文件。
2. 提交前扫描：无 `.DS_Store`、个人 private 配置、密钥或证书文件；确认 `.gitignore` 覆盖机密与构建产物。
3. `git add` 指定课程目录与相关 README（不用 `git add -A`）。
4. 约定式提交信息（feat/fix/docs/test），正文概述课程与阶段构成。
5. `git push origin <branch>`；推送后 `git status -s` 确认工作区干净。
6. 未经用户明确要求不推送；本流程在用户要求“提交到远端”时才执行 Stage 5。

## 六段式单元规范（顺序固定）

1. `## 目标` — 8-10 条行为化、可观察的能力点。
2. `## 技术栈` — 表格列出工具/技术、用途、学习要求。
3. `## 详细的理论知识讲解和示例伪代码` — 10-15 小节，机制 + 真实代码示例 + 误区。
4. `## 课后题` — 恰好 10 道，含场景分析。
5. `## 实践练习题` — 恰好 3 个，递进式，提交物与验收标准明确。
6. `## 阶段验收作业` — 任务/完成标准/100 分评分表/强制不通过条件。

## 反模式

- 知识地图未确认就批量生成，导致方向错、整体返工。
- 子代理之间文件边界重叠，或让子代理更新框架链接。
- 只因子代理自称完成就收口，不做行数/结构/断链校验。
- 产出占位符、HTML 标签、DOM 假设或前端密钥。
- `git add -A` 混入无关或机密文件；未确认就推送。
- 为单一单元启用整套批量流程。

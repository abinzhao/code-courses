# 00-课程总纲与培养标准

本文件是课程的顶层培养契约，规定培养目标、结业能力标准、技术路线、阶段路径、节奏与评分方式。它是框架文档，不是知识单元；具体教学内容以五个阶段目录中的 60 个单元为准。

## 课程定位

本课程培养的是**能独立交付完整 Web 系统的初中级全栈工程师**。结业学员面对一个中等复杂业务需求时，应能独立完成从需求拆解、前端界面（React 主线 + Vue 对照）、工程化质量体系、后端接口、数据库设计、认证授权、测试质量到部署上线和文档交付的完整闭环，而不是只能在他人搭好的架子里填充页面。

- 周期：30 周，每周 2 个知识单元，共 60 个单元。
- 建议投入：学员每周约 30 小时，导师每周约 15 小时。
- 产出要求：每周有编码提交，按 W4/W14/W18/W26/W30 五个里程碑验收，结业时系统可通过公网访问并完成答辩。
- 主线项目：团队协作工单系统，五个阶段持续演进同一业务。

## 全栈结业能力标准

结业学员应在以下九个维度达到行为化标准，即“能当场做出”，而不是“听说过”。

| 维度 | 结业行为标准 |
|---|---|
| 需求拆解 | 能把产品需求拆成页面、组件、状态、资源实体、接口、权限点和测试点，并识别边界场景与异常流程 |
| 前端开发（React 主线） | 能用 React 当前稳定版、React Router、TanStack Query、React Hook Form 与 TypeScript 独立完成中等复杂单页应用，正确处理状态、表单、错误边界与性能 |
| 前端开发（Vue 对照） | 能用 Vue 当前稳定版、Vue Router 与 Pinia 独立实现核心业务模块，讲清组合式 API 与 Proxy 响应式机制，具备接手 Vue 项目与跨框架迁移能力 |
| 前端工程化 | 能独立搭建与维护工程化体系：基于 Vite 的开发与生产构建、ESLint/Prettier 规范与提交门禁、环境变量与多环境配置、pnpm Monorepo 工作区、npm 包开发与 Changesets 发布、前端 CI（GitHub Actions），并理解微前端与模块联邦 |
| 后端开发 | 能用 Node.js 与 Express 按分层结构实现 RESTful API，正确使用中间件、统一错误模型、日志、缓存与异步队列 |
| 数据库 | 能用 PostgreSQL 与 Prisma 完成建模、迁移、关系查询、事务、分页与索引优化，能借助 EXPLAIN 分析慢查询 |
| 认证授权 | 能实现密码哈希加盐、JWT 签发与刷新、基于 RBAC 的角色权限控制和资源归属、组织隔离校验 |
| 测试 | 能编写后端单元与集成测试、React/Vue 组件测试、基于真实数据库的 API 测试和 Playwright 端到端测试，并用覆盖率与关键流程门禁质量 |
| 部署交付与文档表达 | 能用 Docker 与 Compose 容器化多服务，用 GitHub Actions 建立 CI/CD，部署到云主机并配置 Nginx 反向代理与 HTTPS；能编写需求说明、OpenAPI 契约、README、运行测试指南、部署记录和复盘，并在答辩中清晰解释架构与权衡 |

结业通过条件：结业项目部署可访问、测试与质量门禁通过、九个维度均有对应证据，且结业答辩评分达到合格线；任一维度缺失证据不予通过。

## 学习原则

1. 先理解机制，再记 API：能讲清底层原理后才使用框架封装。
2. 所有知识点必须落到可运行代码，不接受只写笔记的学习方式。
3. 所有代码必须进入 Git 仓库；Git 分支协作、提交规范与 Code Review 贯穿全程，不单独占用单元。
4. 每个单元按“目标 → 理论 → 伪代码 → 练习 → 验收”五步闭环完成。
5. 评审不只看能否运行，还要看命名、边界、异常处理、类型设计、测试与安全性。
6. 不追逐实验性 API，也不使用已被主流新项目放弃的技术作为主线。
7. 安全默认内置：密钥只走环境变量与密钥管理，最小权限、输入校验、限流与安全头从第一个真实项目开始执行。
8. 先自评再送审：对照评分表能解释每一分的得失，返工是正常学习环节。
9. 双框架对照学习：React 求深、建立完整交付链路，Vue 求通、用对照理解框架共性与差异，不把 Vue 降级为“看一遍语法”。
10. 工程化能力必须动手搭建：规范、构建、多环境、Monorepo、包发布与前端 CI 均要求在自有项目中真实落地，不接受“能看懂配置”。

所有版本统一表述为当前稳定版，开课时按官方渠道确认具体版本号。

各阶段里程碑：

- **W4 里程碑**：能用命令行和网络证据排查问题，读懂 HTTP/HTTPS 报文，写出类型正确的 JS/TS 程序。
- **W14 里程碑**：具备 React 与 Vue 双框架交付能力，独立交付带路由、数据请求、表单、错误处理、测试与门禁的工单系统前端原型，并完成 Vue 对照实现。
- **W18 里程碑**：具备完整前端工程化能力——Vite/构建、规范、多环境、Monorepo、包发布、前端 CI，工程化改造成果可运行、可复现。

## 作业提交规范

每次作业必须包含以下内容：

- 需求说明与本次改动说明；
- 本地运行方式与测试方式；
- 提交物清单（代码、测试、文档、截图或录屏）；
- 自评结果：评分表逐项得分与依据；
- 已知问题与下一步计划；
- Git 提交记录，提交信息使用约定格式。

提交信息格式示例：

```text
feat: add ticket create flow
fix: handle unauthorized board access
test: cover ticket status transition
docs: add local setup steps
```

提交要求：

1. 以分支加 Pull Request 或 Merge Request 提交，不直接向主分支推送作业。
2. 一个提交只做一件事，提交信息能让评审者不看代码也知道改动意图。
3. 密钥、连接串、令牌一律通过环境变量注入，严禁写入仓库或出现在截图、日志中。
4. PR 描述须包含自评得分与测试证据；命中强制不通过条件的作业先自行返工。
5. 工程化类作业须附“从零复现”步骤，评审者按步骤能在干净环境重建构建、规范、工作区与流水线配置。

## 评分标准权重

单元与阶段作业统一采用 100 分制，权重如下：

| 维度 | 权重 | 判断标准 |
|---|---:|---|
| 功能完成度 | 25% | 需求与边界场景完整，主流程与异常流程均可工作 |
| 代码与设计质量 | 20% | 命名、分层、模块边界、类型设计、异常处理 |
| 测试质量 | 20% | 分层测试合理，关键路径覆盖，断言有效，测试可重复 |
| 安全与正确性 | 15% | 认证授权、输入校验、密钥管理、注入与限流防护 |
| 工程规范 | 10% | Git 提交、目录组织、Lint/格式化、CI 门禁 |
| 文档与表达 | 10% | README、契约、运行测试说明、复盘与答辩表达 |

结业成绩由阶段里程碑（40%）、结业项目实现（35%）、部署与答辩（25%）综合构成；评分表中列明的强制不通过条件具有一票否决效力。五个里程碑（W4/W14/W18/W26/W30）共同构成里程碑成绩，其中 W18 工程化里程碑与 W14 双框架里程碑是新增的独立证据点，不得以其他阶段成果替代。

## 导师关注点

- 不替学员写完整答案，用追问让学员解释自己的代码与权衡。
- 每周至少组织一次“从报错到根因”的调试训练，要求学员用证据而非猜测定位问题。
- 每个阶段安排一次重构训练，让学员为可维护性修改自己过去的代码。
- 每个阶段保留一个边界复杂问题，用于训练排查、日志分析与压力下的表达。
- 持续检查认证授权、资源归属、输入校验与密钥管理，不让安全问题留到结业前。
- 双框架阶段重点检查“对照理解”：学员能否讲清 React 与 Vue 在响应式、状态与副作用上的机制差异，而不是只会照抄语法。
- 工程化阶段重点检查可复现性与真实落地：构建、规范、多环境、Monorepo、包发布与前端 CI 是否由学员亲手搭建并在项目中生效，防止“配置能跑但不理解、或只在教程里跑过”。
- 关注阶段衔接：前端阶段检查数据契约意识，工程化阶段检查交付链路完整性，后端阶段检查接口可用性，集成阶段重点看联调、环境一致性与部署自动化。
- 版本差异出现时以官方文档和项目实际依赖为准，不用过时教程照本宣科。

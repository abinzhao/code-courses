# 第二课：终端、Git 与调试习惯

> 本章目标：让邻里集市首页具备可复现的启动方式、范围清楚的本地历史和一套证据驱动的故障恢复流程。

## 本章任务

页面“在我这里能运行”不足以交接。你要把它变成另一人可重复验证的工作：

```text
确认目录与命令
  → 识别进程和端口
  → 用 Git 选择并记录变化
  → 稳定复现一个缺陷
  → 用证据定位并最小修复
  → 回归正常与错误路径
```

本章不连接远端、不推送、不修改教材仓库 Git 历史。全部实验在个人 `market-learning` 下完成。

## 必要前置

- 完成[电脑、文件与第一张网页](03-computer-first-page.md)。
- 保留个人 `market-start/index.html` 与 `market-start/server.mjs`。
- 准备 Node.js 24 LTS、Git、代码编辑器和浏览器 DevTools。
- 能确认终端当前目录并安全停止前台服务。

## 顺序学习路线

| 顺序 | 教程 | 建议时间 | 可见产出 | 核心证据 |
| ---: | --- | ---: | --- | --- |
| 1 | [终端、进程与端口](04-terminal-git-debugging/01-terminal-processes-ports.md) | 90～120 分钟 | 可交接启动/停止说明 | cwd、PID、监听端口、退出状态 |
| 2 | [Git 三棵树、提交与分支](04-terminal-git-debugging/02-git-three-trees-commits-branches.md) | 120～150 分钟 | 范围清楚的本地提交 | working/cached diff、分支图、冲突恢复 |
| 3 | [证据驱动的调试闭环](04-terminal-git-debugging/03-evidence-driven-debugging-loop.md) | 120～150 分钟 | 完整缺陷报告 | 稳定复现、变量证据、最小修复、回归矩阵 |

三篇教程有依赖关系：先知道命令和进程边界，才能安全做 Git 与运行实验；先能区分代码状态，才能证明调试改动范围。

## 命令安全边界

本章只允许在个人练习目录执行写操作。每次 `git init`、`git add`、`git commit` 或分支实验前，先检查当前目录与状态。

禁止把下列动作当作普通清理：

```text
终止所有 Node.js 进程
git reset --hard
git clean -fd
强制推送
删除未知目录
修改全局 Git 身份以完成练习
```

端口冲突先查监听 PID 并确认归属，优先回原终端按 `Ctrl+C`。Git 变化优先使用精确暂存、实验分支、`git restore --staged`、stash 和 `git merge --abort` 保留工作。

## 三步邻里集市实操

### 第一步：交接运行环境

为个人项目写清：

```text
项目目录：从 market-learning 开始的相对路径
运行时：实际 node --version 输出
启动：进入 market-start 后执行 node server.mjs
地址：http://127.0.0.1:3000/
停止：原服务终端 Ctrl+C
端口冲突：查询 3000 监听者，确认归属后处理
```

验证首页 200、错误路径 404、停止服务后连接失败。

### 第二步：建立本地历史

只在个人 `market-learning` 根目录初始化 Git。提交范围至少包括：

- `.gitignore`；
- `README.md`；
- `market-start/index.html`；
- `market-start/server.mjs`；
- `learning-log.md`。

提交前检查普通 diff、cached diff、未跟踪文件和空白错误。提交后再运行页面；Git 状态干净与功能正确是两项独立证据。

### 第三步：完成调试闭环

在独立 `debug-lab` 中运行教程给出的故障页面：

1. 新加载后稳定复现 3 次；
2. Network 证明 HTML 文档为 200；
3. Console 记录 TypeError；
4. Sources 证明字符串 ID 被转换成 `NaN`；
5. 保持 ID 为字符串并增加未知 ID 保护；
6. 回归正常 ID、未知 ID、刷新、404 和连接失败；
7. 删除临时调试噪声，保留报告与必要错误日志。

## 综合验收

### 终端与进程

- [ ] 能说出实际 Shell 和当前目录。
- [ ] 能正确引用含空格路径。
- [ ] 能区分标准输出、标准错误和退出状态。
- [ ] 能记录 Node 进程的 PID、cwd、脚本位置与监听地址。
- [ ] 能查询 3000 端口所有者并确认归属。
- [ ] 能安全停止自己的服务并证明端口释放。

### Git 状态与历史

- [ ] 能画出 working tree、index、HEAD 的关系。
- [ ] 能解释普通 diff 与 cached diff 的不同。
- [ ] 能精确暂存本次文件并复核提交内容。
- [ ] 能解释 `.gitignore` 对已跟踪文件无效。
- [ ] 能创建实验分支并读取历史图。
- [ ] 能制造冲突、`merge --abort`、再次合并并清除冲突标记。
- [ ] 没有执行远端推送或破坏性恢复命令。

### 调试证据

- [ ] 缺陷描述含环境、前置、步骤、期望、实际和复现率。
- [ ] 根因由变量值、类型、调用位置和最小复现共同支持。
- [ ] 修复与根因对应，没有吞异常、放宽比较或写死结果。
- [ ] 原复现步骤通过。
- [ ] 正常、错误、刷新和 HTTP 相邻路径完成回归。
- [ ] 报告明确列出未验证浏览器与真实环境边界。

## 章级交付

提交或现场展示以下个人练习证据：

| 类别 | 最低交付 |
| --- | --- |
| 环境 | Node.js、Git、Shell 与日期 |
| 运行 | 启动、停止、PID、端口和 200/404 |
| Git | 首次提交、两份 diff、分支图和冲突恢复 |
| 调试 | 三次复现、断点变量表、最小差异和回归矩阵 |
| 报告 | 现象、证据、原因、修复、复验、剩余风险 |

只有最终成功截图不通过；只有 Git 提交但无法运行不通过；通过删除测试、吞异常或关闭检查制造的“成功”不通过。

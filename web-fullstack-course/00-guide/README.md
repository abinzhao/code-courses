## 章入口与详细教程怎样分工

上表 9 项仍是本卷的治理与学习入口，不因详细教程增加而改变。第 3、4 章采用“章入口统筹、详细教程实作”的两层结构：

| 页面层级 | 负责什么 | 不替代什么 |
|---|---|---|
| 章入口 | 说明章目标、前置条件、学习顺序、邻里集市集成任务、章级综合验收与能力边界 | 不替代逐步运行、故障注入和单元练习 |
| 详细教程 | 围绕一个主题给出理论、完整代码、运行与停止方式、刻意故障、练习、答案要点和阶段验收 | 单篇通过不等于整章通过，也不等于 W1 可以交接 |

使用方式是：先读章入口确认目标与个人目录，再按顺序完成 3 篇详细教程；每篇保留失败和修复证据，最后回到章入口做综合验收。不要只读章入口后直接勾选完成，也不要把教材仓库当作个人应用工作区。

| 顺序 | 详细教程的职责 | 完成后应留下的证据 |
|---:|---|---|
| 1 | 解释命令在哪个目录、由哪个进程运行，以及谁监听端口 | Shell、cwd、PID、脚本位置、端口归属、退出状态与安全停止 |
| 2 | 区分 working tree、index 与 HEAD，练习本地提交、分支和冲突恢复 | working/cached diff、精确提交、分支图、`merge --abort` 与冲突清理 |

Git 写操作只在个人练习仓库中进行；本章不要求远端、不推送，也不使用硬重置、强制清理或全局杀进程来制造“通过”。

## 起步实操怎样验收

验收按“单元 → 章级 → W1 交接”逐层进行，后一级不会自动补齐前一级缺失的证据。

| 层级 | 最低通过条件 | 入口 |
|---|---|---|
| 6 篇单元 | 完成每篇“阶段验收”，保留运行结果、一次刻意失败及修复后的相同步骤复验 | 使用上面的两条顺序路线 |
| 第 3 章 | 个人首页能从磁盘走到 HTTP 与 DevTools；能解释 200、404、连接失败、MIME、源文件、响应和 DOM 的边界 | [第 3 章综合验收](03-computer-first-page.md#综合验收) |
| 第 4 章 | 能交接启动与停止，证明 PID 和端口归属；能复核本地提交范围；能用证据完成一次最小修复与相邻回归 | [第 4 章综合验收](04-terminal-git-debugging.md#综合验收) |
| W1 交接 | 另一人或稍后的自己只按个人 README 就能从停止状态恢复首页，并复核 200、404、连接失败、本地提交和一份完整排错记录 | [W1 综合验收](09-w01-checkpoint.md) |

最终证据应来自个人 `market-learning` 工作区，并记录实际工具版本、命令、地址和观察时间。只展示最终截图、只提交代码、只保持 Git 状态干净，或只说“在我这里能运行”，都不能单独通过。

### 当前仍需手动补齐的缺口

- 首周验收以可重复的手动操作和证据记录为主，尚未把 6 篇教程变成自动化测试套件；自动回归会在 JavaScript 与工程化阶段建立。
- DevTools 路线以当前 Chromium 的面板名称为主。Firefox、Safari、真实手机、屏幕阅读器和仅键盘完整流程仍需在目标环境手动复核，不能由一次 Chromium 通过外推。
- macOS/zsh 与 Windows/PowerShell 的命令虽有对应说明，但学习者仍需在自己的系统实跑版本、路径、Shell、退出状态和端口查询。
- 当前服务只绑定本机回环地址，数据是静态或内存演示；远程访问、TLS、真实 API、数据库、账号、权限、持久化、部署与生产安全不属于起步验收。
- Git 只验收本地历史、分支和冲突恢复；远端协作、托管 CI、评审、发布与回滚要到对应卷验证。

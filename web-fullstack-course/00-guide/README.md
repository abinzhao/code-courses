# 00 · 出发前，把方向和工具装进背包

先不用认识 React。你需要知道文件在哪里、代码由谁执行、错误在哪里看，以及学习成果怎样验收。

## 本卷定位与阅读方式

目标是从空的个人目录做出可通过本机 HTTP 访问的邻里集市静态首页，留下文件、请求、进程、本地 Git 和故障恢复证据。不需要编程基础、框架、数据库或云服务。

本 README 直接统筹详细教程、前置、学习顺序和综合验收；治理参考解释路线、版本和交付规则，不再通过独立章入口中转。详细教程负责完整理论、文件、运行、故障和练习；只读目录或复制最终代码不能通过。

教材只保存 Markdown。应用文件、依赖、锁文件和运行产物都在个人 `market-learning` 工作区，具体职责见[教材结构](course-structure.md)。

不会终端导航时，可提前阅读第 4 篇的 Shell、cwd 和路径部分，再回到第 2 篇运行 HTTP；其余依赖按表顺序完成。

## 学习与运行

准备纯文本编辑器、现代桌面浏览器、Node.js 24 LTS 和 Git。首周无第三方依赖，不强制 pnpm。先按[版本页最小检查](version-baseline.md#6-最小可运行案例)保存原始输出，版本不一致时如实记录。

运行前确认终端当前目录、脚本位置和页面 URL。主线服务使用 `node server.mjs`，绑定 `127.0.0.1:3000`；进程、最小 HTTP 与调试实验各用教程明确的端口，不混用文件或观察对象。停止优先在原服务终端按 `Ctrl+C`，再复查端口释放。

macOS/zsh 与 Windows/PowerShell 使用各篇对应的变量、目录和端口命令。W1 的 macOS `curl` 与 PowerShell `curl.exe` 检查首页、错误路径和非 GET，结果应为 200、404、405/`Allow: GET`；停止后应连接失败且无监听。

Git 写操作只在个人练习仓库进行，不要求远端或推送；不使用硬重置、强制清理或全局杀进程制造“通过”。

## 从文件到请求证据

第一组集成任务是让王阿姨的自行车说明从磁盘走到浏览器：

1. 在个人 `market-start` 创建 UTF-8 `index.html`，展示商品、整数分机器值、UTC 机器时间、联系片段和静态边界。
2. 用完整 `server.mjs` 固定读取首页；首页返回 HTML，错误路径返回 404，其他方法返回 405。
3. 比较磁盘源文件、Network Response、Sources 和 Elements；保留未保存、同名副本或 MIME 故障并恢复。

### 文件与请求综合验收

- [ ] 文件与应用源码都在个人目录，地址栏和编辑器能证明同一来源。
- [ ] UTF-8、完整扩展名、相对路径基准、机器金额和时间能解释。
- [ ] 首页 200 与正确 HTML MIME、`/missing` 404、POST 405 有独立证据。
- [ ] 停止服务后没有 HTTP 响应，不把连接失败写成 404 或 500。
- [ ] Elements 临时改价后刷新恢复，磁盘、响应和 DOM 的区别能解释。
- [ ] URL 路径、查询和片段能拆解，片段不被当作新服务路由。
- [ ] 至少一份五阶段故障报告含复现、证据、原因、最小恢复与同路径复验。

现场用 5 分钟解释上面机制；只展示画面而不能解释请求链路不通过。提交文件树、真实版本、启动与停止方式、正常/失败请求、DOM 对照和故障记录。

## 从运行现场到可追踪修复

第二组任务是让同伴能接手运行并复核改动：

1. 从两个目录基准启动同一脚本，记录 cwd、脚本 URL、PID 与端口；制造端口冲突后只停止自己的旧服务。
2. 在独立 `git-lab` 观察 working tree、index、HEAD，完成精确提交、分支与冲突中止/解决，再给主线建立本地历史。
3. 在独立 `debug-lab` 复现字符串 ID 被数值转换的故障，用值与类型证明根因，实施最小修复并做相邻回归。

### 运行与修复综合验收

- [ ] 启动记录包含 Shell、cwd、脚本、PID、地址与退出状态。
- [ ] 端口查询可证明进程归属；停止后释放，只操作本人教学进程。
- [ ] 三棵树对照与暂存清单明确；首次提交和后续小改动不夹带无关内容。
- [ ] 分支历史、`merge --abort` 和再次解决冲突有记录，无残留标记。
- [ ] 故障修复前稳定复现三次，断点记录输入值、类型与失败来源。
- [ ] 修复对应根因，没有吞异常、写死结果或放宽错误比较。
- [ ] 正常 ID、未知 ID、刷新、404 和停止服务均复验；无调试残留与无关 diff。
- [ ] 报告明确已验证环境与剩余风险，本地 Git 不是远端备份或功能证明。

## 起步实操怎样验收

验收按“单元 → 本页综合验收 → W1 交接”逐层进行，后一级不会自动补齐前一级缺失的证据。

| 层级 | 最低通过条件 | 入口 |
|---|---|---|
| 六篇单元 | 完成各篇“阶段验收”，保留运行、一次刻意失败和相同步骤复验 | [六篇详细教程](#六篇详细教程) |
| 文件到请求 | 首页能从磁盘走到 HTTP 与 DevTools，机制和错误类型可解释 | [文件与请求综合验收](#文件与请求综合验收) |
| 运行到修复 | 进程归属、停止、本地提交范围、最小修复与回归可复核 | [运行与修复综合验收](#运行与修复综合验收) |
| W1 交接 | 另一人或稍后自己仅凭个人 README 从停止状态恢复，复核 200/404/405、端口、本地提交与排错 | [W1 综合验收](w01-checkpoint.md) |

最终证据来自个人 `market-learning`，记录实际工具版本、Shell、命令、地址和观察时间；共享记录脱敏。只展示最终截图、只提交代码、只保持 Git 干净，或只说“在我这里能运行”，都不能单独通过。

## 验证范围与未覆盖能力

首周以可重复的手动操作与证据为主，不宣称六篇已成为自动测试套件；自动回归在 JavaScript 与工程化阶段建立。全书文档和运行验证结论以 [VALIDATION](../VALIDATION.md) 为汇总入口。

DevTools 以 Chromium 面板名称为主。Firefox、Safari、手机、屏幕阅读器与完整仅键盘流程仍需在目标环境复核，不能由 Chromium 通过外推。macOS/zsh 与 Windows/PowerShell 命令也需学习者在自己的系统实跑，不以文档对应说明冒充双平台运行证据。

主线服务仅绑定本机回环地址，数据是静态或内存演示；远程访问、TLS、真实 API、数据库、账号、对象授权、持久化、部署与生产安全不属于本卷验收。Git 只验证本地历史、分支和冲突恢复；远端协作、托管 CI、发布和回滚在相应卷另验。

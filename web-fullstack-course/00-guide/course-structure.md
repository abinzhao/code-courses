# 教材结构：找到知识，也找到练习的位置

教材与个人应用是两个不同的工作区。教材只保存 Markdown 解释和围栏示例；个人应用保存你亲手创建、运行和提交的成果。本页供第一次建立练习目录的学习者，以及新增详细教程的维护者核对文件职责。

## 1. 全书目录的职责

| 目录 | 主要职责 | 阅读时关注什么 |
|---|---|---|
| `00-guide` | 起步、路线、版本与项目验收 | 从哪里开始，怎样判断学会 |
| `01-html` | 内容语义、元素、属性与无障碍 | 不加样式也能理解内容 |
| `02-css` | 层叠、属性、布局与动效 | 页面在不同空间怎样保持秩序 |
| `03-browser` | 网络、渲染、存储与平台 API | 怎样观察请求和执行过程 |
| `04-javascript-typescript` | 编程、模块、DOM、异步与类型 | 输入如何变成可验证的输出 |
| `05-react` | React 组件与应用 | 状态、数据和渲染边界 |
| `06-vue` | Vue 组件与应用 | 响应式依赖与组合复用 |
| `07-engineering` | 构建、质量、工作区与 CI | 别人能否复现和维护 |
| `08-backend` | API、SQL、权限与业务一致性 | 数据与权限由谁保证 |
| `09-fullstack` | 集成、部署与故障恢复 | 系统怎样交付和持续运行 |
| `10-ai-agent` | 模型、工具、执行、检索与评测 | 非确定性输出与副作用怎样受控 |
| `11-mini-program` | 平台运行时、身份、适配与交付 | 原生生命周期与真机证据 |
| `12-browser-extension` | 上下文、消息、权限与插件交付 | 不可信网页与扩展能力的边界 |

这是职责地图，具体学习顺序以各卷 README 为准。物理文件、详细教程与覆盖矩阵的统计口径统一由[交付与验证说明](../VALIDATION.md)维护；文件数量只证明交付形状，不替代学习成果或运行证据。

除治理参考外，阅读路径统一为：

```text
根 README → 分卷 README → 详细教程
                       ↘ 分卷覆盖矩阵
                       ↘ 分卷验证账本（如该卷提供）
```

分卷 README 直接负责课序、前置、业务集成、综合验收和学习边界；详细教程负责完整理论、案例、故障与练习；覆盖矩阵负责审计知识点归属。

起步卷的 `03-computer-first-page/` 与 `04-terminal-git-debugging/` 是组织详细教程的目录，不是同名 `.md` 页面。路线、版本、项目契约、覆盖地图、教材结构、写作标准和 W1 验收使用单页参考。工程卷的 `SELF-CHECK.md` 是验证账本，不属于学习导航层；全书验证结论以 `VALIDATION.md` 汇总。

各分卷 README 可以沿用“定位、学习路线、学习与运行、连续项目与边界、验收、验证范围、资料与导航”的骨架。框架卷可增加对等契约、命令矩阵和 Capstone 所有权；进阶卷可增加模型、平台或权限说明，但不重复维护全书计数和其他卷的精确版本表。

## 2. 首周的最小结构

```text
教材工作区/
└── web-fullstack-course/
    ├── README.md
    └── 00-guide/
        ├── README.md
        ├── learning-path.md
        ├── version-baseline.md
        ├── project-contract.md
        ├── coverage-map.md
        ├── course-structure.md
        ├── unit-writing-template.md
        ├── w01-checkpoint.md
        ├── 03-computer-first-page/
        │   ├── 01-files-paths-editors.md
        │   ├── 02-url-http-first-page.md
        │   └── 03-devtools-first-request-evidence.md
        └── 04-terminal-git-debugging/
            ├── 01-terminal-processes-ports.md
            ├── 02-git-three-trees-commits-branches.md
            └── 03-evidence-driven-debugging-loop.md

个人学习工作区/
└── market-learning/
    ├── market-start/
    │   ├── index.html
    │   └── server.mjs
    ├── README.md
    ├── environment.md
    ├── week-01-plan.md
    ├── learning-log.md
    └── .gitignore
```

个人目录由学习者跟随正文创建；教材只提供 Markdown 中的代码。先不要建立框架、数据库和容器的全部目录。后续依赖、锁文件、测试文件、图片、生成产物和平台配置也放在个人项目，不添加到教材目录。

`index.html` 描述商品，`server.mjs` 响应请求，README 帮别人启动，环境记录保存实际工具输出，学习记录保存观察，Git 保存选定的变化。每个文件都有可直接说明的责任。

### 创建与核对

用文件管理器在自己明确管理的位置新建 `market-learning`，再用编辑器打开整个目录。按[文件与路径第一课](03-computer-first-page/01-files-paths-editors.md)创建首页，按[HTTP 第二课](03-computer-first-page/02-url-http-first-page.md)创建服务。每篇的独立实验目录与主线目录分开，避免替换已验收首页。

核对编辑器打开的根目录、终端当前目录和浏览器地址。通过标准是三者能由文件树解释：Shell 找到入口脚本，脚本定位同目录首页，HTTP 返回该文件。应用源码不在教材中、教材的链接不指向个人电脑的应用路径。

## 3. 文件与链接规则

详细教程在知识组目录内使用两位顺序号和英文短名，例如 `03-computer-first-page/01-files-paths-editors.md`。治理参考使用职责名，例如 `learning-path.md`；中文标题用于阅读，路径避免空格与大小写歧义。

新增或迁移详细教程时完成：

1. 建立职责清楚的 Markdown 文件，保留完整教学和验收结构。
2. 从所属卷 README 直接添加教程入口和课序。
3. 添加真实相邻教程与分卷 README 导航。
4. 核对该卷覆盖矩阵、相关前置和跨卷引用。
5. 只有学习能力或时间安排改变时才更新路线和地图，不在多页重复计数。
6. 从当前文件位置计算相对链接，并核对目标标题的真实锚点。

路径示例：从 `00-guide` 到 HTML 入口使用 `../01-html/README.md`；从起步详细教程返回卷入口使用 `../README.md`。要定位整个知识组时链接分卷 README，要开始实作时链接详细教程。文件目标必须存在，锚点须对应真实标题。

维护者检查时打开每条改过的相对链接，尤其检查带片段的标题；代码围栏里的个人文件路径是示例内容，不当作教材实际存在的链接。文档审计脚本、提取工具和临时运行项目置于教材外，教材仍只保留 `.md`。

## 4. 课程主线与示例边界

[项目契约](project-contract.md)规定邻里集市的业务模型、会话、金额与预约规则。局部示例必须说明所处阶段：

- 静态价格是文本，不是交易权威数据。
- 模拟登录必须注明演示状态。
- 前端类型不能替代输入校验。
- 隐藏按钮不能替代后端授权。
- 首页服务器不会因新增磁盘文件而自动提供所有资源。

业务规则有变化时，先核对契约，再评估受影响例子；不让 React、Vue 和后端各自形成不同业务定义。进阶卷如果有显式领域扩展，在该卷注明差异和验证范围，不默默替换核心模型。

## 5. 进阶工作区与证据归属

| 进阶 | 工作区安排 | 验收边界 |
|---|---|---|
| [AI Agent](../10-ai-agent/README.md) | 按该卷创建个人服务、客户端与评测；凭据由运行环境提供 | 模型替身、真实模型与真实工具分开记录，写操作需确认 |
| [小程序](../11-mini-program/README.md) | 原生实验、Taro 项目与平台配置按正文分别建立 | 不把 H5 构建当真机验收，不在客户端写 AppSecret |
| [浏览器插件](../12-browser-extension/README.md) | 源码、构建目录和加载用包都在个人项目 | 网页替身、真实扩展、后台重启与权限分别验收 |

操作顺序是选卷、核对 README 的前置和版本、创建个人目录、运行最小案例、注入故障、停止或卸载本次实验、整理证据。依赖安装成功不等于平台通过；外部模型费用、上传、审核和商店发布都需另行授权。

通过标准是另一人仅凭个人 README 能识别文件责任、重建同一实验、定位失败并安全结束；教材中没有依赖、锁文件、应用源码或构建产物。

## 6. 首周交付清单

| 交付物 | 完成证据 |
|---|---|
| 第一张网页 | 保存、刷新后商品可读，联系片段可定位 |
| 本机 HTTP 页面 | 首页 200，错误路径 404，非 GET 为 405 |
| 文件与 DOM 的区别 | DevTools 修改后刷新恢复源文件内容 |
| 可追踪工作区 | 目录、说明、首次本地提交与精确变化 |
| 排错记录 | 现象、证据、原因、修复与复验 |
| 安全结束 | 停止自己启动的服务，端口无监听，再按说明恢复 |

后续写作遵循[单元写作标准](unit-writing-template.md)。每篇需要可独立理解的运行说明；复用前篇完整文件时给真实链接、所需版本和具体文件，不只写“参考上一课”。

按[W1 验收](w01-checkpoint.md)交付时，不需要远端推送或上线；只在个人项目建立本地 Git 证据。

# 邻里集市：统一项目契约与阶段验收

## 1. 一个需求，贯穿前后端

王阿姨想卖掉一辆自行车，小林想预约验车。系统必须回答：商品是否还在售、谁有权修改它、两个人同时预约怎么办、失败后页面如何告诉用户。

这些问题足够承载中小型业务系统的关键能力，又不会让零基础阶段陷入复杂支付、微服务与云厂商配置。

本书主线包含：

- 发布、查看、编辑和筛选商品。
- 注册、登录、会话过期与退出。
- 收藏、取消收藏、预约、取消预约与卖家确认。
- 本人操作权限、管理员管理与审计。
- 并发控制、错误恢复与自动化测试。
- 本地容器运行、部署、日志与备份恢复。

活动、评价与图片处理可作为结业扩展，但必须先完成主线。真实支付和复杂推荐不作为基础毕业要求。

## 2. 持续演进，而不是每卷推倒重来

| 版本 | 技术能力 | 数据来源 | 验收 |
|---|---|---|---|
| V0 摆摊 | HTML | 文本 | 语义、表单、媒体、键盘 |
| V1 装修 | CSS | 文本 | 响应式、布局、动画降级 |
| V2 营业 | 原生 JS/TS | 内存与本地实验数据 | 筛选、事件、异步与类型 |
| V3 双门面 | React 与 Vue | 同一 API 契约/阶段模拟 | 同等页面与状态 |
| V4 业务服务 | Nest + PostgreSQL | 真实数据库 | 权限、事务、持久化 |
| V5 可交付 | CI、Docker、Nginx | 实际运行环境 | 可复现部署与恢复 |

阶段模拟数据必须明确标成演示；不能在没有服务端认证时显示“已安全登录”。假数据只用于还没有建立的那一层。

## 3. 工作区边界

后续工程化阶段组织成：

```text
market/
  apps/
    react-web/
    vue-web/
    api/
  packages/
    contracts/
  migrations/
  docs/
  package.json
  pnpm-workspace.yaml
  pnpm-lock.yaml
```

这是一份学习项目约定。前几周不需要先建立全部目录，也不需要把教材目录误当应用工作区。教程在 Markdown 中提供示例和路径，练习项目由学员按章节创建。

前端不共享框架组件：React 和 Vue 组件机制不同。可以共享领域类型、数据校验、金额格式和 API 契约；共享前先确认两边真正需要。

## 4. 领域对象

| 对象 | 职责 | 关键约束 |
|---|---|---|
| User | 用户身份和角色 | 不向浏览器返回密码散列 |
| Listing | 商品 | 标题非空、价格非负、状态受控、只能本人编辑 |
| Favorite | 收藏关系 | `(userId, listingId)` 唯一 |
| Reservation | 预约 | `pending/cancelled/confirmed` 状态受控；同一商品只能有一个有效预约，不能预约自己的商品 |
| Review | 已完成交易后的评价 | 基于合法交易关系，不能随意评价陌生商品 |

主线 Listing：

```ts
export type ListingStatus = "available" | "reserved" | "sold";

export interface Listing {
  id: string;
  title: string;
  description: string;
  priceCents: number;
  status: ListingStatus;
  ownerId: string;
  version: number;
  createdAt: string;
}
```

金额按整数分保存，280元是28000。`createdAt` 为 UTC ISO8601 字符串；界面按用户时区展示。`version` 用于发现用户基于旧数据提交的修改，不能靠浏览器自行决定最新版本。

前端类型描述预期数据，不替代服务端校验和数据库约束。对外 JSON 还需要运行时验证。

## 5. HTTP 契约

API 前缀统一 `/api/v1`：

| 方法与路径 | 成功行为 | 重要边界 |
|---|---|---|
| GET `/listings?page=1&pageSize=20&q=` | 分页商品列表 | 参数整数、最大页尺寸、固定排序 |
| GET `/listings/:id` | 商品详情 | 不存在404 |
| POST `/listings` | 创建商品，201 | 登录、输入合法 |
| PATCH `/listings/:id` | 编辑商品 | 本人权限、携带 version、冲突409 |
| POST `/listings/:id/reservations` | 创建预约，201 | 不能自己预约、并发只能一个成功 |
| POST `/reservations/:id/cancel` | 取消 pending 预约 | 仅买家或商品 owner；终态与重复操作409 |
| POST `/reservations/:id/confirm` | 确认 pending 预约 | 仅商品 owner；预约 confirmed、商品 sold 同事务 |
| PUT `/favorites/:listingId` | 设置为收藏 | 重复调用保持同一状态 |
| DELETE `/favorites/:listingId` | 取消收藏 | 重复调用不新增副作用 |
| POST `/auth/register` | 接受注册请求，202 `{"accepted":true}` | 输入限制、密码散列；存在与新邮箱保持相同外部响应 |
| POST `/auth/login` | 建立会话 | 无效凭据、速率限制 |
| GET `/auth/me` | 当前用户 | 会话不存在或过期401 |
| POST `/auth/logout` | 撤销会话 | Cookie 与服务端状态同时处理 |

列表响应：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 0
}
```

错误响应形状：

```json
{
  "code": "VERSION_CONFLICT",
  "message": "商品已被更新，请刷新后再提交",
  "requestId": "demo-request-id"
}
```

`requestId` 关联服务端日志；不向用户暴露 SQL、堆栈或密钥。`message` 服务于恢复行为，`code` 服务于稳定判断。401表示未认证，403表示已知身份但无权操作，409表示状态冲突；不能全返回200再靠文本判断成功。

## 6. 会话和安全主线

浏览器端主线为同源 **HttpOnly Cookie 会话**。浏览器自动发送 Cookie，因此需要明确的 CSRF 防护；`SameSite` 是其中一层，不能代替所有检查。生产使用 HTTPS 与 Secure Cookie；本地 HTTP 演示必须说明差异。

前端隐藏“编辑”按钮只是用户体验，后端仍检查当前用户和 `ownerId`。不要接受浏览器传来的角色作为授权依据。

外部 API 客户端使用 Bearer Token 可以作为扩展比较；采用另一种认证机制时必须说明生命周期、吊销和存储，不与主线悄悄混用。

## 7. 每个页面必须覆盖的状态

| 状态 | 列表页 | 提交表单 | 预约 |
|---|---|---|---|
| 初始 | 明确入口 | 可填写 | 显示商品状态 |
| 加载 | 不误显示“暂无商品” | 禁止重复提交 | 显示处理中 |
| 空数据 | 说明可调整筛选 | 不适用 | 不适用 |
| 失败 | 重试与错误信息 | 保留输入 | 不假装成功 |
| 成功 | 展示列表 | 成功提示或跳转 | 更新商品与按钮 |
| 无权限 | 登录入口或说明 | 不允许操作 | 解释原因 |
| 冲突 | 刷新数据 | 提示旧版本 | 展示已被预约 |

除鼠标操作外，要能用键盘完成主路径。焦点、错误关联、状态朗读和减少动画是实现的一部分，不是最后可选装饰。

## 8. 分阶段评分

每阶段至少80分，并且无核心阻断项，才能进入下一阶段。

| 阶段 | 分项 | 必需证据 |
|---|---|---|
| HTML/CSS | 语义25、布局25、表单20、无障碍20、解释10 | 手机/桌面、键盘、长内容与错误表单 |
| JS/TS | 正确性30、异步20、类型20、测试20、解释10 | 数据边界、取消请求、失败测试 |
| React | 功能30、状态20、路由数据20、测试无障碍20、解释10 | 可刷新深链、请求竞态与错误恢复 |
| Vue | 与 React 相同维度和权重 | 同一业务用例，同等自主实现 |
| 工程化 | 复现25、质量25、构建20、测试20、说明10 | 全新安装、错误门禁与构建预算 |
| 后端 | 建模20、权限25、事务20、接口测试25、日志10 | 两用户越权、并发预约、重启持久化 |
| 交付 | 部署20、回滚20、恢复20、监控20、答辩20 | 全新环境运行与恢复演练 |

阻断项包括：业务越权、重复预约破坏数据、真实密钥进入代码、失败假报成功、测试通过但实际请求路径不可用、无法从数据库备份恢复。它们来自项目的具体完成标准，不是额外扩张的功能。结业的 100 分维度、下限和八项否决条件以[评分、复审与独立修改](../09-fullstack/06-graduation-project/02-scoring-review-independent-change.md)为准；选修 Review 最多另加 5 分，不抵消基础下限或否决项。

## 9. 结业与“中级”证据

结业时，应能在不照抄教材的情况下：

1. 从业务描述拆出模型、状态和 API。
2. 用 React 与 Vue 分别实现等价应用。
3. 用真实数据库实现权限与并发约束。
4. 编写能够发现错误的测试。
5. 发布、回滚、定位慢请求并恢复数据。
6. 向别人解释为何选择某个实现，以及它何时失效。

由另一个人复核比自评更可靠。请对方使用不同账号、错误输入、慢网、刷新深链和并发请求，不只点击一次正常按钮。

## 10. 小测

**为什么收藏用 PUT/DELETE，而不是“点击一次反转状态”的 POST？**
答：重复请求能保持目标状态，重试更可控；反转操作会在网络重试时再次反转。

**为什么预约需要数据库约束？**
答：多个进程和用户可以同时操作；单个前端的按钮状态无法锁住其他请求。

**为什么 React 和 Vue 不直接共用组件文件？**
答：组件与渲染机制不同；领域契约可共享，界面实现保留各自自然模式。

# 学习路线：从零开始，逐渐承担一个系统

> 建议核心投入：50 周 × 每周 22 小时 ≈ 1,100 小时。
> 分卷逐课时间还包含完整参考索引、重复实验与扩展练习，不能与核心路线机械相加；选择全部扩展时应延长周期，不压缩作业验收。
> AI Agent、小程序和浏览器插件是核心路线之后的三条独立进阶路线，不挤入第 50 周，也不要求同时开始。
> 全部完成进阶路线需另排 16 + 12 + 10 = 38 周；核心与三卷路线合计 88 周。进阶按每周 18–22 小时另计约 684–836 小时，不因并行安排而减少学习投入，扩展与补练另加弹性时间。

## 任务卡

你准备第一次打开编辑器。先给自己一张可完成的任务单：本周做出一个商品页，能通过本机服务访问，留下一个清楚的 Git 提交，并解释一次失败。

建议用 45–60 分钟读本页、制定首周安排。先写出第一周作品，不必记住全部技术名称。已有全栈基础的读者可以用阶段证据判断前置能力，再选择一条进阶路线，而不是仅凭工作年限跳过验收。

## 1. 任务背景

想象邻居说：“我想发布一辆二手自行车，其他人可以预约，但不能两个人同时抢到。”刚入门时，你会想到图片和按钮；进入中级阶段，你还会想到登录、权限、状态、事务、失败提示、测试、日志和部署。

课程的任务，是把这种思考逐步建立起来。不要第一周就同时安装所有框架和数据库。每个阶段只增加已经能理解的一层。

| 层次 | 当下的问题 | 新增能力 |
|---|---|---|
| 内容 | 这是什么商品？ | HTML 与语义 |
| 表现 | 在手机上能看清吗？ | CSS 与响应式 |
| 交互 | 能搜索、收藏吗？ | JavaScript、DOM 与异步 |
| 应用 | 状态和页面越来越多怎么办？ | React、Vue 与架构 |
| 数据 | 关掉网页后，数据还在吗？ | 后端、SQL 与持久化 |
| 业务 | 两个人同时预约怎么办？ | 权限、事务与幂等 |
| 交付 | 换台机器、上线、出故障怎么办？ | 工程化、测试与运维 |
| 进阶 | 换成智能助手、平台客户端或插件，哪些边界改变？ | 模型工具治理、平台运行时与浏览器权限 |

## 2. 学习目标

- 说清楚首周作品与最终系统之间的能力差距。
- 把时间分给阅读、复现、独立练习和复盘。
- 根据作品和证据判断进度，而不是根据阅读页数。
- 识别一个当前薄弱动作，并缩小练习范围。
- 写出能交给别人复核的首周学习记录。
- 为一条进阶路线安排独立时间，区分本地替身、真实平台和发布证据。

## 3. 预备知识

首周不需要编程基础。准备一个能保存文字的工具，找出自己每周可持续投入的时间即可。不会创建文件时，先在纸上记录；完成[文件、路径与编辑器](03-computer-first-page/01-files-paths-editors.md)后再整理到个人项目。

三条进阶路线的前置能力和实际工具条件以各卷 README 为准；不把整张版本表或一套框架的安装结果当成所有卷已兼容。

## 4. 核心理论

### 4.1 每周的节奏

每周 22 小时可以拆成：

- 理论与预测实验：5 小时。
- 示例复现和调试：5 小时。
- 独立项目练习：8 小时。
- 测试、代码评审与复盘：4 小时。

如果每周只有 10 小时，把时间线延长至约两年，不要删掉后端和练习来制造“完成”。如果每周 30 小时，也要保留间隔复习；疲劳时连续复制代码效率很低。

一天不需要背 50 个标签。完成一个表单，解释 `name`、`id`、`label`、`required` 各自的作用，比背熟它们的拼写更有价值。

### 4.3 什么情况下应暂停进度

发现“示例看得懂，空白文件写不出来”时，不是再读一遍就能解决。把任务缩小到能独立完成的动作。例如先写“输入商品价格，输出格式化金额”，再加过滤，再加 DOM。

| 现象 | 补练方法 | 通过证据 |
|---|---|---|
| 用 `div` 做所有按钮 | 用原生表单和按钮重做一个发布页 | 键盘 Enter、Space 与焦点工作 |
| CSS 反复加 `!important` | 在 DevTools 找覆盖来源 | 能说明最终生效规则 |
| 不知道函数返回什么 | 画参数、局部变量、返回值 | 不运行也能预测三个输入 |
| Effect/watch 到处同步状态 | 把派生值改为计算 | 无循环更新，状态源更少 |
| 前端决定用户角色 | 用两个用户直接调用 API | 非本人修改被拒绝 |
| 测试只断言“存在” | 增加失败、边界、并发场景 | 错误实现能被测试抓住 |

### 4.4 学习记录写什么

在个人练习项目中建立 `learning-log.md`。这是学习建议，不要求提交真实用户信息。

```markdown
# 本周：预约按钮为何重复发送

## 现象
快速点击两次，Network 出现两个 POST。

## 解释
按钮禁用发生在异步更新后；客户端防重复不能替代服务端约束。

## 实验
把网络改为 Slow 3G，连续点击；再直接调用接口两次。

## 修复与证据
前端显示 pending；服务端使用事务与唯一约束。
重复预约返回冲突，数据库只保留一条有效预约。
```

这种记录会成为面试和团队协作中的证据。只写“学了事务”无法说明你是否掌握它。

### 4.5 怎样使用 AI

可以让 AI 解释一条错误、生成更多边界输入、检查命名或提出方案。第一次实现练习时，先自己写关键逻辑，然后用 AI 对照。

如果 AI 给了一段代码，至少回答：

1. 输入能否不合法？在哪里校验？
2. 异步操作失败后会怎样？
3. 权限在哪里检查？
4. 哪个测试能证明这段代码有效？
5. 当前依赖是否支持该 API？

无法回答时，把它视为待理解的参考，不直接当作自己的成果。不要把真实密钥、个人信息或生产数据放进提问。

### 4.6 AI Agent 独立 16 周路线

入口：[AI Agent 卷 README](../10-ai-agent/README.md)。先能独立完成类型校验、HTTP 接口、授权、持久化和测试，再建立本地私有资料助手。本卷处理用户明确导入的帮助资料和经确认的本地任务，不修改邻里集市商品或预约；远程 BYOK 保持禁用。每周建议 18–22 小时，包含一次失败实验；各主题可在该卷连续项目中跨周复验，具体课序和版本以该卷为准。

| 周 | 实作重点 | 操作与通过证据 |
|---|---|---|
| AI-01 | Token、上下文与答案契约 | 先用纯函数解析带来源的答案与拒答；非法 JSON、额外字段和未知引用被拒绝 |
| AI-02 | 本地运行时与硬件探针 | 记录 runtime、已安装模型 digest、内存和能力实测；无模型时不把替身写成真实推理 |
| AI-03 | Provider 与本地 Profile | 区分 fixture 和 local-model；远程配置在 I/O 前拒绝，不自动云端兜底 |
| AI-04 | 显式图与受限执行 | 记录节点、条件边和终止原因；步数、单次截止与迟到结果资格分别检查 |
| AI-05 | 工具契约与授权 | 定义只读资料搜索参数；未知工具、越界 docId 和未授权调用都不执行 |
| AI-06 | MCP 与 Host 信任 | 建立真实 stdio client/server；核对能力快照与批准权限，关闭连接不遗留子进程 |
| AI-07 | 持久状态与记忆 | 演示 checkpoint 中断恢复；隔离 actor/thread，记录到期和删除边界 |
| AI-08 | 检索与来源 | 对明确导入的帮助资料建立检索；回答注明来源，找不到依据时拒答 |
| AI-09 | 审批与幂等写入 | 将只读回答和本地任务写入分开；确认绑定身份与意图，重复请求返回同一回执 |
| AI-10 | 不可信内容 | 向资料或工具描述加入提示注入；它不能改变角色、工具权限或读取范围 |
| AI-11 | 流式呈现与取消 | 逐段显示时保留完成状态；取消和截断不冒充完整答案，已提交本地任务不被宣称撤销 |
| AI-12 | 故障恢复与隔离 | 注入超时、工具失败和进程中断；只重试安全操作，区分回环地址门禁与物理断网证据 |
| AI-13 | 评测集 | 建立正常、无依据、越权和注入样本；记录预期、实际与失败分类 |
| AI-14 | 可观测与资源预算 | 记录耗时、实际 token 用量、失败和预算中止；未知 usage 不填零，不伪造远程价格 |
| AI-15 | 独立项目 | 接通从用户输入到受控工具的完整链；替身回归与真实调用分别验收 |
| AI-16 | 交付答辩 | 按 README 重建，演示取消、越权拒绝与恢复；交代模型不确定性和未验证范围 |

不能用一次回答正确证明 Agent 可靠。最终证据需包含脱敏输入样本、模型或替身标识、工具轨迹、评测结果、资源预算与人工确认记录；本地替身不证明模型质量或物理断网。远程调用不属于本卷实现，新增外部副作用必须另行设计与授权。

| MP-06 | 草稿与文件存储 | 隔离用户草稿；制造迁移、损坏、配额失败，清理本次临时文件 |
| MP-07 | 权限、隐私与降级 | 使用时申请权限；拒绝后仍有手工输入或无能力态，不循环弹窗 |
| MP-08 | 媒体、位置与订阅 | 校验上传，处理拒绝位置和通知；授权不被当作预约成功 |
| MP-09 | 第二平台适配 | 对比微信、抖音与支付宝能力；H5 仅作降级对照，不替代客户端验收 |
| MP-10 | 多层测试与弱网 | 分开提交 Node、组件、工具、真机证据；测隐藏页面、弱网和重复操作 |
| MP-11 | 包体、预览与审核 | 干净构建，核对隐私和平台配置；上传、提审、灰度另行授权 |
| MP-12 | 双平台项目交付 | 完成列表到预约恢复的链路；按 README 重建并记录平台差异、回退与未验证项 |

构建成功不能证明平台登录、真实 TLS、隐私弹窗或真机体验成功。离线只保存草稿；教学服务与真实后端授权的证据分开，不能以本地收藏偏好冒充服务端同步。

### 4.8 浏览器插件独立 10 周路线

入口：[浏览器插件卷 README](../12-browser-extension/README.md)。先具备 DOM、异步、消息校验、存储和工程化基础。把网页商品信息整理成用户明确触发的辅助工具，不默认抓取所有网站或在后台执行交易。

| 周 | 实作重点 | 操作与通过证据 |
|---|---|---|
| EXT-01 | 插件组成与最小权限 | 创建可加载的实验；核对 manifest 与权限说明，不申请无用途的广泛站点访问 |
| EXT-02 | 页面脚本与隔离 | 比较网页、content script 与扩展上下文；只读取约定字段，不信任页面内容 |
| EXT-03 | 消息契约 | 校验消息类型、发送者和参数；伪造或越界消息被拒绝 |
| EXT-04 | 后台生命周期 | 模拟后台暂停与重启；恢复任务状态，不依赖长期内存变量 |
| EXT-05 | 存储与迁移 | 保存用户偏好与草稿；损坏数据可恢复，删除动作限定本插件拥有的数据 |
| EXT-06 | 用户入口与交互 | 从 popup 或该卷规定入口触发整理；空、错、加载、取消和键盘路径明确 |
| EXT-07 | 网络与隐私 | 请求仅访问明确允许的服务；取消和断网可恢复，不把秘密注入网页 |
| EXT-08 | 安全与平台差异 | 注入恶意文本和错误消息；核对 CSP、权限拒绝与目标浏览器差异 |
| EXT-09 | 测试与打包 | 从干净目录构建、加载、重启复验；自动替身与真实扩展环境分开记账 |
| EXT-10 | 独立交付 | 演示安装、启用、拒绝权限、恢复和卸载；商店发布另行授权并注明未验证范围 |

最终提交最小权限理由、上下文与消息关系、正常和恶意输入结果、后台恢复记录及安装/卸载说明。网页演示页通过不等于扩展通过，Chromium 通过也不自动代表其他浏览器兼容。

## 6. 最小可运行案例

### 创建自己的 W1 任务单

本例是文档练习，不运行程序。把下面内容保存为个人学习项目的 `week-01-plan.md`，或先写在纸上：

```markdown
# W1：让邻里集市第一次开张

## 作品
一个商品页，一份启动说明，一次本地 Git 提交。

## 操作顺序
1. 创建 HTML，保存后打开。
2. 修改价格，检查源文件和浏览器 DOM。
3. 启动本机服务，观察首页 200 与错误路径 404。
4. 在个人工作区记录并提交指定文件。
5. 关闭服务，再按 README 重新启动。

## 成功证据
页面可读；请求状态有记录；提交范围清楚；启动可复现。

## 出错时
写下现象，先查文件位置、终端和 Network，再修复并复验。
```

操作方式：在编辑器保存并重新打开任务单，不需要 Node.js 命令。预期能指出每步的输入、动作和证据；写不出时回到首周六篇的任务卡。任务单保存后不等于任务完成，需要实际执行。

## 7. 项目集成案例

W1 建立的个人工作区将持续保存邻里集市成果。下一周把同一商品内容组织得更清楚，再增加样式和交互；不必每周换项目。

先保留 `index.html`、服务示例、README 和学习记录。多包目录、数据库迁移和部署配置在相应阶段再建立，具体边界见[教材结构](course-structure.md)与[项目契约](project-contract.md)。

进入进阶时，先写清哪些领域规则复用、哪些客户端或工具契约需要扩展，再按所选卷创建独立个人项目。不要把模拟登录、模型建议或平台本地存储混写成核心系统的权威状态。

## 8. 常见错误与排查路径

| 现象 | 证据 | 原因判断 | 修复与复验 |
|---|---|---|---|
| 读懂但写不出 | 空白文件无法开始 | 只复现，没有提取步骤 | 先独立写标题与段落，再扩展 |
| 安装很多工具却没作品 | 无可访问页面 | 准备工作替代交付 | 只用首周必需工具做最小页面 |
| 记录只有术语 | 无路径、输入和结果 | 把笔记当成证据 | 重做一个实验，写实际表现 |
| 为赶进度跳过错误实验 | 正常路径可用，失败不会解释 | 没验证理解边界 | 制造一次错误地址并恢复 |
| 把三卷塞进最后一周 | 没有独立平台证据 | 把进阶当作简介 | 选一条完整路线，逐周通过后再切换 |

复验时关闭教程，再独立完成一个小动作。做不到就继续缩小任务，不需要立即重读整本书。

## 9. 课后题

**题 1：为什么两套框架要做同一个业务？**
答：保持需求和后端相同，差异才集中在组件、状态、路由、性能和测试模型；否则容易把业务熟悉度误认为框架能力。

**题 2：每周学了三课，为什么不能直接说水平提高了？**
答：阅读是投入，独立实现和可重复验证是成果。应记录完成的业务链、故障定位和测试，而不是页数。

**题 3：为什么保留浏览器与 SQL，而不全靠库？**
答：库能简化操作，却不能替代对执行环境和数据约束的理解；缓存、请求、渲染与事务问题仍需要依据底层机制诊断。

**题 4：完成本地模型替身或 H5 构建，能否跳过进阶真实环境验收？**
答：不能。它们分别证明确定性逻辑或 Web 构建，不证明模型输出、平台生命周期、真实权限或扩展后台行为。

## 10. 实践练习

**基础：安排第一周。**在个人 `week-01-plan.md` 中列出可用时段与对应任务。保存后逐项阅读，预期每项都有成果和证据；只有“学习两小时”时补上具体动作。

**提升：做一次交接预测。**在同一文件写出别人启动页面需要哪些信息。完成首周后让同伴按说明执行，预期不靠口头补充也能访问；失败时记录缺失的路径、版本或命令。

**故障：缩小模糊目标。**把“学会 Web”改写成三个可独立验收的动作。无需运行命令，预期能逐项回答完成条件；仍无法判断时，回到字段表继续拆分。

**进阶选择：安排一条独立路线。**在个人 `advanced-plan.md` 中选择 AI、MP 或 EXT，逐周填入对应成果、前置证据和未验证的平台。打开所选卷 README 核对课序；有凭据或设备缺口时保留待验证项，不将替身结果改写成真机通过。

## 11. 阶段验收

写出自己的每周时间、第一阶段作品、验收方法和复盘时间。完成第一张网页后，能告诉另一位初学者：文件是什么、浏览器如何打开它、接下来哪一步会新增服务器。

课程范围不是就业承诺。不同岗位的中级要求不同；结业标准提供的是独立交付中小型 Web 系统的可观察能力。

- [ ] 首周计划包含作品、时间与证据。
- [ ] 能分辨阅读、复现和独立实现。
- [ ] 写明一个需要补练的小动作。
- [ ] 能说出进入下一周的完成条件。
- [ ] 选择进阶时另排完整路线，不删减核心验收。

提交个人任务单路径、可用时间、第一件作品的验收方式和复盘安排。实际 W1 综合验收见[首周成果交接](w01-checkpoint.md)。

## 12. 常见问题

**每周不足 22 小时就不能学吗？**
可以延长周期。按同一完成标准推进，先保证持续练习，不必压缩必要的验证。

**第一周要独立写服务器吗？**
本阶段可以跟做完整示例，重点是文件、执行位置与请求观察。异步和 HTTP 服务编程在后续学习。

**做完正常页面后还要制造错误吗？**
需要。能预测和解释失败，才能区分理解机制与碰巧运行成功。

**进阶三卷必须按 10、11、12 顺序全部学吗？**
可以按目标独立选择；每卷都要满足自己的前置和完整验收。选择全部时另排三段时间，不能把路线周数当成全书文件统计。

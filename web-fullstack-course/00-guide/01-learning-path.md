# 学习路线：从零开始，逐渐承担一个系统

> 建议核心投入：50 周 × 每周 22 小时 ≈ 1,100 小时。
> 分卷逐课时间还包含完整参考索引、重复实验与扩展练习，不能与核心路线机械相加；选择全部扩展时
> 应延长周期，不压缩作业验收。

## 任务卡

你准备第一次打开编辑器。先给自己一张可完成的任务单：本周做出一个商品页，能通过本机服务访问，留下一个清楚的 Git 提交，并解释一次失败。

建议用 45–60 分钟读本章、制定首周安排。先写出第一周作品，不必记住全部技术名称。

## 1. 任务背景

想象邻居说：“我想发布一辆二手自行车，其他人可以预约，但不能两个人同时抢到。”刚入门时，你会想到图片和按钮；进入中级阶段，你还会想到登录、权限、状态、事务、失败提示、测试、日志和部署。

课程的任务，是把这种思考逐步建立起来。不要第一周就同时安装所有框架和数据库。每个阶段只增加已经能理解的一层。

| 层次 | 当下的问题 | 新增能力 |
|---|---|---|
| 内容 | 这是什么商品？ | HTML 与语义 |
| 表现 | 在手机上能看清吗？ | CSS 与响应式 |
| 交互 | 能搜索、收藏吗？ | JavaScript、DOM 与异步 |
| 应用 | 状态和页面越来越多怎么办？ | React、Vue 与架构 |
| 数据 | 关掉网页后，数据还在吗？ | 后端、SQL 与持久化 |
| 业务 | 两个人同时预约怎么办？ | 权限、事务与幂等 |
| 交付 | 换台机器、上线、出故障怎么办？ | 工程化、测试与运维 |

## 2. 学习目标

- 说清楚首周作品与最终系统之间的能力差距。
- 把时间分给阅读、复现、独立练习和复盘。
- 根据作品和证据判断进度，而不是根据阅读页数。
- 识别一个当前薄弱动作，并缩小练习范围。
- 写出能交给别人复核的首周学习记录。

## 3. 预备知识

本章不需要编程基础。准备一个能保存文字的工具，找出自己每周可持续投入的时间即可。不会创建文件时，先在纸上记录；完成[第一张网页](03-computer-first-page.md)后再整理到个人项目。

## 4. 核心理论

### 4.1 每周的节奏

每周 22 小时可以拆成：

- 理论与预测实验：5 小时。
- 示例复现和调试：5 小时。
- 独立项目练习：8 小时。
- 测试、代码评审与复盘：4 小时。

如果每周只有 10 小时，把时间线延长至约两年，不要删掉后端和练习来制造“完成”。如果每周 30 小时，也要保留间隔复习；疲劳时连续复制代码效率很低。

一天不需要背 50 个标签。完成一个表单，解释 `name`、`id`、`label`、`required` 各自的作用，比背熟它们的拼写更有价值。

### 4.3 什么情况下应暂停进度

发现“示例看得懂，空白文件写不出来”时，不是再读一遍就能解决。把任务缩小到能独立完成的动作。例如先写“输入商品价格，输出格式化金额”，再加过滤，再加 DOM。

以下情况应在进入下一阶段前补练：

| 现象 | 补练方法 | 通过证据 |
|---|---|---|
| 用 `div` 做所有按钮 | 用原生表单和按钮重做一个发布页 | 键盘 Enter、Space 与焦点工作 |
| CSS 反复加 `!important` | 在 DevTools 找覆盖来源 | 能说明最终生效规则 |
| 不知道函数返回什么 | 画参数、局部变量、返回值 | 不运行也能预测三个输入 |
| Effect/watch 到处同步状态 | 把派生值改为计算 | 无循环更新，状态源更少 |
| 前端决定用户角色 | 用两个用户直接调用 API | 非本人修改被拒绝 |
| 测试只断言“存在” | 增加失败、边界、并发场景 | 错误实现能被测试抓住 |

### 4.4 学习记录写什么

在个人练习项目中建立 `learning-log.md`。这是学习建议，不要求提交真实用户信息。

```markdown
# 本周：预约按钮为何重复发送

## 现象
快速点击两次，Network 出现两个 POST。

## 解释
按钮禁用发生在异步更新后；客户端防重复不能替代服务端约束。

## 实验
把网络改为 Slow 3G，连续点击；再直接调用接口两次。

## 修复与证据
前端显示 pending；服务端使用事务与唯一约束。
重复预约返回冲突，数据库只保留一条有效预约。
```

这种记录会成为面试和团队协作中的证据。只写“学了事务”无法说明你是否掌握它。

### 4.5 怎样使用 AI

可以让 AI 解释一条错误、生成更多边界输入、检查命名或提出方案。第一次实现练习时，先自己写关键逻辑，然后用 AI 对照。

如果 AI 给了一段代码，至少回答：

1. 输入能否不合法？在哪里校验？
2. 异步操作失败后会怎样？
3. 权限在哪里检查？
4. 哪个测试能证明这段代码有效？
5. 当前依赖是否支持该 API？

无法回答时，把它视为待理解的参考，不直接当作自己的成果。不要把真实密钥、个人信息或生产数据放进提问。

## 6. 最小可运行案例

### 创建自己的 W1 任务单

本例是文档练习，不运行程序。把下面内容保存为个人学习项目的 `week-01-plan.md`，或先写在纸上：

```markdown
# W1：让邻里集市第一次开张

## 作品
一个商品页，一份启动说明，一次本地 Git 提交。

## 操作顺序
1. 创建 HTML，保存后打开。
2. 修改价格，检查源文件和浏览器 DOM。
3. 启动本机服务，观察首页 200 与错误路径 404。
4. 在个人工作区记录并提交指定文件。
5. 关闭服务，再按 README 重新启动。

## 成功证据
页面可读；请求状态有记录；提交范围清楚；启动可复现。

## 出错时
写下现象，先查文件位置、终端和 Network，再修复并复验。
```

操作方式：在编辑器保存并重新打开任务单，不需要 Node.js 命令。预期能指出每步的输入、动作和证据；写不出时回到首周两课的任务卡。任务单保存后不等于任务已经完成，需要实际执行。

W1 建立的个人工作区将持续保存邻里集市的成果。下一周把同一商品内容组织得更清楚，再增加样式和交互；不必每周换一个项目。

## 8. 常见错误与排查路径

| 现象 | 证据 | 原因判断 | 修复与复验 |
|---|---|---|---|
| 读懂但写不出 | 空白文件无法开始 | 只复现，没有提取步骤 | 先独立写标题与段落，再扩展 |
| 安装很多工具却没作品 | 无可访问页面 | 准备工作替代交付 | 只用首周必需工具做最小页面 |
| 记录只有术语 | 无路径、输入和结果 | 把笔记当成证据 | 重做一个实验，写实际表现 |
| 为赶进度跳过错误实验 | 正常路径可用，失败不会解释 | 没验证理解边界 | 制造一次错误地址并恢复 |

复验时关闭教程，再独立完成一个小动作。做不到就继续缩小任务，不需要立即重读整本书。

## 9. 课后题

**题 1：为什么两套框架要做同一个业务？**
答：保持需求和后端相同，差异才集中在组件、状态、路由、性能和测试模型；否则容易把业务熟悉度误认为框架能力。

**题 2：每周学了三课，为什么不能直接说水平提高了？**
答：阅读是投入，独立实现和可重复验证是成果。应记录完成的业务链、故障定位和测试，而不是页数。

**题 3：为什么保留浏览器与 SQL，而不全靠库？**
答：库能简化操作，却不能替代对执行环境和数据约束的理解；缓存、请求、渲染与事务问题仍需要依据底层机制诊断。

## 10. 实践练习

**基础：安排第一周。**在个人 `week-01-plan.md` 中列出可用时段与对应任务。保存后逐项阅读，预期每项都有成果和证据；只有“学习两小时”时补上具体动作。

**提升：做一次交接预测。**在同一文件写出别人启动页面需要哪些信息。完成首周后让同伴按说明执行，预期不靠口头补充也能访问；失败时记录缺失的路径、版本或命令。

**故障：缩小模糊目标。**把“学会 Web”改写成三个可独立验收的动作。无需运行命令，预期能逐项回答完成条件；仍无法判断时，回到本章字段表继续拆分。

## 11. 阶段验收

写出自己的每周时间、第一阶段作品、验收方法和复盘时间。完成第一张网页后，能告诉另一位初学者：文件是什么、浏览器如何打开它、接下来哪一步会新增服务器。

课程范围不是就业承诺。不同岗位的中级要求不同；结业标准提供的是独立交付中小型 Web 系统的可观察能力。

## 12. 常见问题

**每周不足 22 小时就不能学吗？**
可以延长周期。按同一完成标准推进，先保证持续练习，不必压缩必要的验证。

**第一周要独立写服务器吗？**
本阶段可以跟做完整示例，重点是文件、执行位置与请求观察。异步和 HTTP 服务编程在后续学习。

**做完正常页面后还要制造错误吗？**
需要。能预测和解释失败，才能区分理解机制与碰巧运行成功。

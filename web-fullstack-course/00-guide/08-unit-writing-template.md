# 单元写作模板：把知识写成一次可完成的任务

本页供后续章节写作使用。每个知识单元围绕一个可交付任务，包含下列 13 个板块；正文可以增加小节，但不要用篇幅代替深度。

## 任务卡

用邻里集市中的具体人物和需求开场。写明本次成果、建议时间、一个可见成功结果和验收证据。开场只介绍当前需要解决的困难，不预先堆叠后续技术。

## 1. 任务背景

说明谁遇到了什么问题、已有能力是什么、为什么现在增加这一层。把新技术绑定到产品行为，例如预约冲突、搜索结果或发布表单。

## 2. 学习目标

用可观察行为描述能力：解释机制、完成操作、预测输出、识别故障、说明取舍。目标应能在第 11 节逐条检查。

## 3. 预备知识

列出前置章节的真实链接、必要工具和版本范围。区分必需能力与扩展阅读；不把后面才教授的语法作为隐藏前提。

## 4. 核心理论

先展示结果，再解释输入、处理、状态和输出。短类比之后回到准确术语，配合表格或流程图。每个核心概念至少给一个观察方法。

如果需要反例，明确标成错误案例，并与正确版本分开。主流程必须提供可以直接复制的完整版本，不让学习者连续修补多段代码才能运行。

## 5. 标签、属性、API 或配置清单

表格使用四列：名称、作用、最小用法、边界。只列本课需要理解的项目；大型参考索引放在专门章节。

## 6. 最小可运行案例

交代个人练习目录、文件位置、完整代码、运行命令、预期结果、停止方式与失败诊断。教材中的代码由学习者在个人工作区创建，教程仓库不自动提供同名源码。

每个可执行代码块都回答：

| 问题 | 必须给出的信息 |
|---|---|
| 放哪里？ | 相对个人项目的文件路径 |
| 在哪里运行？ | 当前目录与所需工具 |
| 怎样成功？ | 页面文本、状态码、输出或测试结果 |
| 失败看哪里？ | 具体面板、日志、文件或输入 |
| 怎样结束？ | 停止、恢复或退出动作 |

## 7. 项目集成案例

说明该能力如何进入邻里集市、复用什么、改变哪个用户行为、哪些能力仍未实现。遵循[项目契约](05-project-assessment.md)，不能把局部示例描述成完整生产系统。

## 8. 常见错误与排查路径

按“现象 → 证据 → 原因 → 修复 → 复验”组织。至少覆盖一个可以重复制造的故障，区分路径、版本、运行状态和业务逻辑问题。

## 9. 课后题

包括理解、预测与取舍。参考答案可用 `details` 折叠，让学习者先尝试。答案应解释依据，不只提供输出。

## 10. 实践练习

设置基础、提升和故障三类任务。每项说明文件或记录位置、运行方式、预期行为、失败观察点与完成标准。

练习要求基于当前知识能独立完成。不要突然要求还没有教过的认证、数据库或部署。

## 11. 阶段验收

列出功能、解释和恢复证据。提交材料包含路径、命令、正常结果、失败记录、复验和已知边界。只读完章节不能替代验收。

## 12. 常见问题

回答真实学习卡点：工具找不到、行为与预期不符、为什么这样组织、哪些能力下一阶段再做。提供读者可自行观察的步骤。

## 13. 扩展阅读

优先官方文档、标准和项目契约。每个链接说明带着什么问题阅读；涉及发布版本时记录核验日期与实际来源，未验证内容不写成确定结论。

## 我现在能做到什么

用两三句回顾新增能力，并说明下一单元将怎样复用它。成就感来自能独立完成与解释，不来自“掌握全部知识”的口号。

## 写作检查

- [ ] 目标、示例和验收互相对应。
- [ ] 主流程代码完整，错误版本单独标识。
- [ ] 示例说明文件、命令、结果与诊断。
- [ ] 与邻里集市业务契约一致。
- [ ] 前置和导航链接指向真实文件。
- [ ] 正文不含对话过程与进度流水账。
- [ ] 无真实凭据、无无解释的破坏性命令。

# 教材结构：找到知识，也找到练习的位置

教材与个人应用是两个不同的工作区。教材保存解释和示例；个人应用保存你亲手创建、运行和提交的成果。

## 1. 全书目录的职责

| 目录 | 主要职责 | 阅读时关注什么 |
|---|---|---|
| `00-guide` | 起步、路线、版本与项目验收 | 从哪里开始，怎样判断学会 |
| `01-html` | 内容语义、元素、属性与无障碍 | 不加样式也能理解内容 |
| `02-css` | 层叠、属性、布局与动效 | 页面在不同空间怎样保持秩序 |
| `03-browser` | 网络、渲染、存储与平台 API | 怎样观察请求和执行过程 |
| `04-javascript-typescript` | 编程、模块、DOM、异步与类型 | 输入如何变成可验证的输出 |
| `05-react` | React 组件与应用 | 状态、数据和渲染边界 |
| `06-vue` | Vue 组件与应用 | 响应式依赖与组合复用 |
| `07-engineering` | 构建、质量、工作区与 CI | 别人能否复现和维护 |
| `08-backend` | API、SQL、权限与业务一致性 | 数据与权限由谁保证 |
| `09-fullstack` | 集成、部署与故障恢复 | 系统怎样交付和持续运行 |

这是职责地图，具体章节入口以各卷 README 为准。物理文件、正文、详细教程与覆盖矩阵的统计
口径统一由[交付与验证说明](../VALIDATION.md)维护；文件数量只证明交付形状，不替代学习成果或
运行证据。

除治理文档外，阅读路径统一为：

```text
根 README → 分卷 README → 稳定章入口 → 详细教程
                              ↘ 分卷覆盖矩阵
```

章入口负责顺序、依赖和综合验收；详细教程负责完整理论、案例、故障与练习；覆盖矩阵负责审计
知识点归属。三者不能互相替代。

起步卷包含两种形态：第 3、4 章采用“章入口 + 详细教程”，路线、版本、项目契约、覆盖地图、
教材结构、写作模板和 W1 验收使用单页治理文档。工程卷的 `SELF-CHECK.md` 是详细验证账本，
不属于学习导航层；全书验证结论以根目录 `VALIDATION.md` 为汇总入口。

各分卷 README 使用同一主骨架：本卷定位与教材结构、学习路线、学习与运行、连续项目与边界、
验收、验证范围、资料与导航。框架卷可以增加对等契约、命令矩阵和 Capstone 所有权等专属内容，
但不在卷入口重复维护全书计数、精确版本表或完整验证日志。

## 2. 首周的最小结构

```text
教材工作区/
└── web-fullstack-course/
    ├── README.md
    └── 00-guide/
        ├── 03-computer-first-page.md
        ├── 04-terminal-git-debugging.md
        ├── 07-course-structure.md
        └── 08-unit-writing-template.md

个人学习工作区/
└── market-learning/
    ├── market-start/
    │   ├── index.html
    │   └── server.mjs
    ├── README.md
    ├── learning-log.md
    └── .gitignore
```

个人目录由学习者跟随正文创建；教材只提供 Markdown 中的代码。先不要建立框架、数据库和容器的全部目录。

`index.html` 描述商品，`server.mjs` 响应请求，README 帮别人启动，学习记录保存观察，Git 保存选定的变化。每个文件都有可以直接说明的责任。

## 3. 文件与链接规则

正文使用两位顺序号和英文短名，例如 `03-computer-first-page.md`。中文标题用于阅读，英文路径保持稳定，避免空格和大小写差异。

新增正文需要同时完成：

1. 在所属卷中建立一个职责清楚的章节。
2. 从该卷 README 添加入口。
3. 在前后章节中添加导航。
4. 更新学习路线和覆盖地图中涉及的内容。
5. 从当前文件位置计算相对链接。

路径示例：从 `00-guide` 到 HTML 入口使用 `../01-html/README.md`；同卷下一课直接使用文件名。不要链接尚不存在的练习源码。

## 4. 课程主线与示例边界

[项目契约](05-project-assessment.md)规定邻里集市的业务模型、会话、金额与预约规则。局部示例必须说明处于哪一阶段：

- 静态价格是文本，不是交易权威数据。
- 模拟登录必须注明演示状态。
- 前端类型不能替代输入校验。
- 隐藏按钮不能替代后端授权。
- 首页服务器不能因新增文件就自动提供所有资源。

业务规则有变化时，先更新契约，再核对受影响的例子。不要让 React、Vue 和后端各自形成不同业务定义。

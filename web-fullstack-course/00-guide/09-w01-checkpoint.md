# W1 综合验收：把第一张网页交给另一位邻居

> 建议时间：2–3 小时。成果：一个别人能按说明启动、你能解释并恢复的本地商品页。

## 任务卡

同伴准备接手邻里集市的第一张页面。你需要交出内容、启动说明、环境记录和变更记录，并展示一次失败怎样恢复。

| 关卡 | 成果 | 通过证据 |
|---|---|---|
| 开张 | 商品页可访问 | HTTP 200、内容可读 |
| 找路 | 联系说明可定位 | 链接目标与 ID 对应 |
| 留痕 | 改动可追踪 | 提交标题与指定文件 |
| 恢复 | 停止后能重新启动 | 连接恢复、首页仍正确 |

## 1. 任务背景

“刚才能运行”与“能交接”之间，还差文件位置、运行条件和操作记录。本次综合练习不增加框架或数据库，把首周已经学过的动作连接起来。

## 2. 学习目标

- 从个人项目根目录找到并运行页面。
- 分辨磁盘文件、浏览器 DOM 和 HTTP 响应。
- 展示首页 200、错误路径 404、非 GET 请求 405 与服务停止后的连接失败。
- 检查提交范围，记录一次本地 Git 提交。
- 根据交接说明独立重新启动并复验。

## 3. 预备知识

先完成[学习路线](01-learning-path.md)、[版本基线](02-version-baseline.md)、[第一张网页](03-computer-first-page.md)和[终端与 Git](04-terminal-git-debugging.md)。

复用首周的完整 HTML 与服务器代码，放在自己的个人项目。没有同伴时，关闭教程与编辑器后，稍后仅凭 README 自己验收。

## 4. 核心理论

### 四种证据各证明什么

| 证据 | 能证明 | 不能证明 |
|---|---|---|
| 文件内容 | 保存了哪些源代码 | 当前服务已运行 |
| Network | 请求、状态、响应 | 所有业务规则正确 |
| Git 提交 | 选定文件的历史快照 | 页面功能没有错误 |
| 重新启动 | 命令与文件路径可复现 | 任意机器与浏览器都兼容 |

```text
保存文件 → 启动服务 → 观察响应 → 修复错误
    → 检查差异 → 本地提交 → 按说明重新启动
```

顺序可以调整，但不能省去证据。发现问题后先描述复现路径，再判断原因，最后修改与复验。

## 5. 标签、属性、API 或配置清单

| 名称 | 本次作用 | 观察点 | 边界 |
|---|---|---|---|
| `a[href]`、`id` | 联系说明导航 | 片段与目标对应 | 不产生预约 |
| `node server.mjs` | 启动本机服务 | 终端启动提示 | 需位于正确目录 |
| `Ctrl+C` | 停止前台服务 | 返回提示符 | 不删除文件 |
| `git diff` | 检查工作区差异 | 只改预期内容 | 未追踪文件另查 |
| `git diff --cached` | 检查下一提交 | 暂存文件与内容 | 后续编辑不自动加入 |
| `git log --oneline -1` | 找到提交 | 标题与短哈希 | 不等于远端备份 |

## 6. 最小可运行案例

### 个人项目位置

```text
market-learning/
├── market-start/
│   ├── index.html
│   └── server.mjs
├── README.md
├── environment.md
├── week-01-plan.md
├── learning-log.md
└── .gitignore
```

教材只提供 Markdown；这份目录由学习者在个人工作区创建。服务代码使用
[URL、HTTP 与第一张服务页面第 7 节](03-computer-first-page/02-url-http-first-page.md#7-邻里集市集成案例)
的完整版本，不重新引入另一套服务器。

### 执行与观察

先确认当前目录是个人项目，再执行：

```bash
cd market-start
node --check server.mjs
node server.mjs
```

预期语法检查成功，服务监听 `127.0.0.1:3000`。浏览器访问首页并打开 Network，记录状态、
响应类型和商品文本；再访问 `/missing`，预期 404。

服务运行时另开终端，复核首页、错误路径和方法边界。macOS 或 Linux 执行：

```bash
curl -i http://127.0.0.1:3000/
curl -i http://127.0.0.1:3000/missing
curl -i -X POST http://127.0.0.1:3000/
```

Windows PowerShell 执行：

```powershell
curl.exe -i http://127.0.0.1:3000/
curl.exe -i http://127.0.0.1:3000/missing
curl.exe -i -X POST http://127.0.0.1:3000/
```

三条命令的状态依次为 200、404、405；第三条响应头还包含 `Allow: GET`。这证明服务已响应但
拒绝了不支持的方法，不是连接失败。

按 `Ctrl+C` 停止服务后刷新，预期连接失败；再检查 3000 端口没有监听进程。macOS 或 Linux
执行：

```bash
curl --max-time 2 -i http://127.0.0.1:3000/
lsof -nP -iTCP:3000 -sTCP:LISTEN
```

Windows PowerShell 执行：

```powershell
curl.exe --max-time 2 -i http://127.0.0.1:3000/
Get-NetTCPConnection -LocalPort 3000 -State Listen
```

每组第一条命令都应以连接失败结束，第二条应无输出。只终止自己启动的教学进程，不结束无法
确认归属的进程。

### 保存一处明确改动

停止服务，回到个人项目根目录：

```bash
cd ..
git status
git diff
```

在编辑器里修改商品描述并保存，复核文件。只暂存本次内容：

```bash
git add market-start/index.html
git diff --cached
git commit -m "docs: clarify first listing description"
git log --oneline -1
```

预期提交包含商品描述变化。提交身份或文件状态异常时，按终端教程处理，不重置或删除历史。

## 7. 项目集成案例

邻里集市 V0 的第一件可交付成果是静态商品展示，不包括真实收藏、支付或预约。下一周会继续把同一份内容整理成语义正确的商品页与帮助页。

此时最重要的接口是交接说明：对方知道去哪个目录、执行什么命令、访问什么地址，以及遇到什么结果时查看哪里。

## 8. 常见错误与排查路径

| 现象 | 证据 | 原因判断 | 修复与复验 |
|---|---|---|---|
| 运行找不到脚本 | 当前目录没有文件 | 路径错误 | 进入页面目录重新运行 |
| 无法连接 | 服务终端已停止 | 没有响应进程 | 启动服务，首页复验 |
| 只有 `/missing` 失败 | HTTP 404 | 不支持该路径 | 回到首页，保留正确 404 |
| 页面价格只在检查工具里变了 | 源文件未变 | 只改运行时 DOM | 刷新对照，实际需求在编辑器修改 |
| 提交夹带其他内容 | cached diff 有额外文件 | 暂存范围不明确 | 复核选择，提交前重新检查 |

## 9. 课后题

<details>
<summary>为什么重启成功与 Git 状态干净都不能单独证明交付完整？</summary>

重启证明运行路径可复现；Git 状态描述文件变化。还需要验证页面内容、请求结果、导航与错误恢复，并说明验证范围。

</details>

**预测题：**服务器停止后，已打开的页面还留在屏幕上，说明服务仍然运行吗？
参考答案：不说明。已有 DOM 仍可显示；重新发请求才能观察当前服务是否响应。

## 10. 实践练习

**基础：交付记录。**在个人 `learning-log.md` 记录首页、错误路径、非 GET 请求与停止后的结果。
按第 6 节运行，预期分别是 200、404、405 加 `Allow: GET`、连接失败与端口无监听；不符合时
查服务、方法、URL 与进程。

**提升：只靠 README 接手。**让同伴或稍后自己按个人 README 启动。预期无需额外口头解释；路径或命令缺失时补充说明。完成标准是从停止状态恢复页面。

**故障：错目录。**在项目根运行 `node server.mjs`，观察文件找不到，再恢复到页面目录。记录实际错误与修复命令，不修改正确源码来迁就错误运行位置。

## 11. 阶段验收

- [ ] 商品名、价格、描述与联系说明可读。
- [ ] 联系链接能用鼠标和键盘激活。
- [ ] 磁盘源文件与运行时 DOM 的区别能解释。
- [ ] 200、404、405/`Allow: GET` 与连接失败分别有证据。
- [ ] 停止服务后 3000 端口没有监听进程。
- [ ] 首次提交与一次小改动的范围清楚。
- [ ] README 足以从停止状态重新启动。
- [ ] 环境记录使用实际输出。

提交记录应包含：个人目录、工具与浏览器版本、运行命令、访问地址、状态结果、提交标题与短哈希、一个完整排错案例，以及未验证范围。

遇到未通过项时只补练对应动作。例如不知道目录就重练路径，不需要安装新框架。通过后进入 W2。

## 12. 常见问题

**必须推送 GitHub 才算完成吗？**
不。本周要求本地记录；远端协作在对应阶段进行。

**一个页面会不会太简单？**
页面小，便于独立解释每层职责。作品大小不是理解深度的替代。

**可以把教程里的代码直接算成自己的作品吗？**
可以跟做，但验收还要独立修改、复验和解释。不能只展示复制结果。

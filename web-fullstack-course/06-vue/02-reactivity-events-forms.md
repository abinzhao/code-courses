# 02 响应式、事件与可提交表单

> 本章目标：把静态商品页升级为可搜索、可验证、可在浏览器内存中发布商品的教学应用，并让每次状态变化都有明确所有者。

## 本章任务

沿用第 1 章工程，加入标题搜索、只看可预约、发布表单、空状态和失败保稿。输入
“二手书架 / 可拆卸，配件齐全 / 120.00”后，成功提交应新增 `12000` 分的完整商品；
非法金额或注入的保存失败必须保留草稿。

本章没有 HTTP。刷新页面后新增商品消失是设计边界，不是持久化缺陷。

## 前置与产出

- 前置：[SFC、模板与商品组件](./01-sfc-templates.md)及其中三课。
- 输入：搜索文字、可预约筛选、标题、描述和金额字符串。
- 输出：派生列表、类型化组件事件、可等待发布命令和浏览器内存商品。
- 建议投入：5 至 6 小时；每课约 100 至 120 分钟。
- 业务约束：金额严格转为整数分；时间用 `new Date().toISOString()` 写入 UTC。

## 章级邻里集市任务

页面必须覆盖以下可观察状态：

1. 初始两件商品；
2. 搜索“台灯”只显示 `lamp-1`；
3. 搜索不存在文字显示成功的空状态；
4. 发布“二手书架”得到服务端阶段之前的本地 UUID、`12000` 分和 UTC 时间；
5. 发布失败显示 `role="alert"`，按钮恢复、草稿保留；
6. 成功后才清空草稿；
7. 刷新后回到固定种子，并明确说明数据只存在于浏览器内存。

## 综合验收

- [ ] `0` 与 `1000000.00` 合法；负数、指数、前导零、三位小数和超限输入拒绝。
- [ ] `35.10` 精确得到 `3510`，不使用 `parseFloat(text) * 100`。
- [ ] `computed` 只派生，不发送请求、不写源状态。
- [ ] 点击与 Enter 都通过表单 submit 路径，Tab 顺序和焦点样式可见。
- [ ] pending 阶段阻止重复提交；失败保稿；成功才重置。
- [ ] 筛选导致新商品暂时不可见时，能用当前条件解释，不创建第二份列表。
- [ ] `pnpm typecheck`、纯金额测试和 `pnpm build` 均退出 `0`。

## 能力边界

内存商品、前端 UUID 和成功提示都不是后端持久化证据。前端字段校验不能替代 API 校验，
隐藏按钮不能替代授权，单标签页 pending 不能阻止其他客户端并发写入。

# 考核与毕业标准

## 评价原则

课程评价的中心问题是：

> 学习者能否独立交付一个功能，并解释它为什么这样设计、如何验证以及失败时如何恢复？

每次阶段验收都提交四类材料：

- 可运行代码
- 功能演示或命令输出
- 关键设计说明
- 测试结果、已知问题和改进计划

完整评分细则见[根目录考核与毕业标准](../../04-assessment-rubric.md)。

## W1 验收标准

第一周通过条件：

1. 能从课程入口进入 U01 和 U02。
2. 能启动 U01 静态服务器，并在浏览器中打开首页和文章页。
3. 能在 Network 面板中找到文档和 CSS 请求，解释状态码与响应类型。
4. 能解释浏览器、服务器、终端和 Git 的职责边界。
5. 能运行 U02 环境检查，并对版本或命令错误给出诊断。
6. 能在实验工作区完成一次 Git 提交，提供 `git status` 和 `git log` 证据。
7. 能写出一条完整排查记录：现象、证据、原因、修复和复验。

W1 不以 Node.js 24 或 pnpm 12 在本机已经安装为前提。若环境不满足基线，学习者需要提交失败输出和修复计划；这是环境诊断能力的一部分。

## 后续阶段验收重点

### M1：W4

- 使用语义化标签重构一页内容。
- 使用正确表单标签和原生校验。
- 页面支持键盘操作和窄屏。
- 能解释一个可访问性问题的证据。

### M2：W12

- 页面支持手机、平板和桌面。
- 至少实现三种有明确目的的动画。
- 动画支持 `prefers-reduced-motion`。
- 使用 DevTools 解释一个布局问题和一个性能问题。

### M3：W20

- 完成三个不依赖框架的 JavaScript 案例。
- 能解释 Promise、事件循环、模块和 Node.js API 边界。
- 类型检查、测试和构建命令可以从干净目录运行。

### M4：W26 与 M5：W32

React 和 Vue 各自完成登录、列表、搜索筛选、编辑表单、加载/空/错/权限状态、路由保护、组件测试和一条 Playwright 主流程。

### M6：W37

- 仓库具备 pnpm Monorepo、类型检查、Lint、测试和 CI 门禁。
- 能分析 Bundle、Core Web Vitals 和资源加载。
- 能说明制品、缓存和回滚策略。

### M7：W43

- API 具备 OpenAPI、输入校验、统一错误响应和测试。
- 数据库具备迁移、约束、索引、事务和查询分析。
- 登录、Refresh Token 轮换、组织隔离、RBAC 和审计日志通过验证。

### M8：W48

- 使用 Docker 启动完整系统。
- 通过一条完整 E2E 测试。
- 演示一个日志定位和一次故障恢复。
- 解释一个数据库索引和一个缓存策略。
- 说明一次失败部署如何回滚。

## 一票否决项

以下任一情况不能通过阶段或毕业验收：

- 提交真实密钥、Token、密码或生产数据。
- 只隐藏前端按钮，服务端没有权限校验。
- 不同组织之间出现数据越权。
- 直接拼接用户输入生成 SQL 或命令。
- 关键业务没有数据库迁移或自动化测试。
- 从干净环境无法启动项目。
- 将异常堆栈、数据库细节或敏感信息直接返回用户。

| 等级 | 可观察表现 |

| 达标 | 能按既有架构完成模块开发并修复常见错误 |
| 中级 | 能从不完整需求设计边界、数据模型、权限规则、测试计划和部署方案 |

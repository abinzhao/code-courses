## 4. 核心理论

### 4.1 `figure` 与 `figcaption`

`figure` 表示可作为一个整体引用的内容，内部可以是图片、图表、代码、引用或数据示意。`figcaption` 是这个整体的说明，位于 `figure` 的开头或末尾。

```html
<figure>
  <pre><code>{
  "title": "阅读台灯",
  "priceCents": 3900
}</code></pre>
  <figcaption>商品数据最小示例：价格使用整数分。</figcaption>
</figure>
```

`figcaption` 不是图片 `alt` 的替代：

- `alt` 在图片不可见时替代图片信息；
- `figcaption` 给整个 figure 提供可见说明。

一张纯装饰图不需要为了使用新标签而强行包进 `figure`。

### 4.2 `blockquote` 与引用来源

长引用使用 `blockquote`：

```html
<blockquote cite="https://community.example/rules/handoff">
  <p>交接前应在光线充足的公共地点检查商品状态。</p>
</blockquote>
<p>
  来源：
  <cite>社区闲置物品交接守则</cite>
</p>
```

`blockquote[cite]` 记录来源 URL，但浏览器不会自动把它显示成链接。需要让读者访问来源时，再提供真实 `a[href]`。

`cite` 元素表示作品名称，不是通用的人名标签。

### 4.3 `pre`：保留空白，不停止 HTML 解析

`pre` 保留源文件中的空格和换行，适合代码、日志和字符图：

```html
<pre><code>商品：阅读台灯
价格：3900 分
状态：available</code></pre>
```

它不会让 HTML 语法失效。要显示 `<strong>` 文字，仍需字符引用：

```html
<pre><code>&lt;strong&gt;请检查电源线&lt;/strong&gt;</code></pre>
```

直接写真实 `<strong>` 会创建强调元素，而不是显示标签文本。

### 4.4 `div`：没有更合适语义时的容器

`div` 是无专属语义的流内容容器。它适合：

- 只为布局包裹一组已经拥有内部语义的内容；
- 给脚本或 CSS 提供结构边界；
- 暂时没有更合适语义的普通分组。

不要因为 `div` 容易加 class，就把列表、导航、文章、分节和表格全部替换成 `div`。

```html
<div class="listing-layout">
  <article>...</article>
  <aside>...</aside>
</div>
```

这里 `div` 表达布局容器，内部仍保留文章与补充信息语义。

### 4.5 `hr`：主题转折

`hr` 表示段落层面的主题转折：

```html
<p>以上是商品实际状况。</p>
<hr>
<p>下面是平台统一的安全提醒。</p>
```

如果只想画一条装饰线，应以后使用 CSS 边框或背景，而不是给文档添加不存在的主题转折。

## 8. 常见错误与排查路径

### 8.1 把来源 URL 只写在 `cite` 属性

- **现象**：读者看不到可点击来源。
- **证据**：页面没有链接，只有 DOM 属性。
- **原因**：`cite` 属性记录来源，不负责展示导航。
- **修复**：需要访问时添加有描述文字的 `a[href]`。
- **复验**：键盘可以聚焦并打开来源。

### 8.2 在 `pre` 中直接写未转义标签

- **现象**：标签没有作为代码文字完整显示。
- **证据**：Elements 出现真实子元素。
- **原因**：`pre` 只保留空白，不关闭 HTML 解析。
- **修复**：使用 `&lt;` 和 `&gt;`。
- **复验**：页面显示标签文本，Elements 中没有意外元素。

## 12. 常见问题

### Q3：每张图片都应该使用 `figure` 吗？

不应该。只有图片、代码或图表作为一个可独立引用的整体，并需要图注或明确边界时才考虑 `figure`。

### Q4：为什么不用 `div` 加 class 模拟所有元素？

class 不会自动提供列表、引用或名称值语义。需要相应关系时使用原生元素，CSS 仍可以改变它们的外观。

### Q6：`hr` 能不能只用来画线？

它会在文档中表达主题转折。仅为装饰时应由 CSS 实现，避免增加错误语义。

# 列表、图注与内容分组：把“放在一起”变成明确关系

> 所属章节：页面结构、链接与列表
> 建议学习时间：4–6 小时
> 阶段成果：为商品特点、交接步骤、状态解释和规则引用选择正确结构

## 任务卡

王阿姨的台灯详情已经有标题和导航，但正文仍是一串段落：

```text
灯臂可调。开关正常。先约地点。再检查电源线。
状态 available 是可预约。价格 39 元。
```

读者能看到文字，却很难判断哪些是特点、哪些有先后顺序、哪些是名称与解释。你的任务是把它们整理成浏览器、键盘用户和辅助技术都能理解的关系。

**完成本课后，你将交付：**

- 一组无序商品特点；
- 一组有顺序的交接步骤；
- 一份状态名称与含义的描述列表；
- 一段带来源说明的社区规则引用；
- 一份可以独立引用的价格数据图注；
- 一次错误嵌套的诊断和恢复记录。

## 1. 任务背景

视觉上连续出现的内容，不一定具有相同关系：

- “灯臂可调、开关正常”是一个集合，顺序改变不影响含义；
- “预约地点、检查商品、确认交接”是一个流程，顺序影响结果；
- “available、reserved、sold”是机器值与解释的对应关系；
- 一段社区守则是引用内容，不是作者自己的商品描述；
- 一个价格图或代码片段可能需要自己的说明。

HTML 不只把内容“包起来”，还应表达内容之间的关系。正确结构能提供列表项目数、步骤顺序、名称值关联和图注边界。只用段落、圆点字符或一串 `div`，这些关系不会自动出现。

本课不会添加 CSS 布局或真实预约功能。目标是先让无样式页面具有可理解的内容顺序。

## 2. 学习目标

完成本课后，你应能：

- 根据顺序是否重要选择 `ul` 或 `ol`；
- 使用 `li` 建立合法的列表父子关系；
- 解释 `start`、`reversed`、`type` 和 `li[value]` 的语义边界；
- 把子列表放入所属的 `li`，而不是与列表项并列；
- 使用 `menu` 表达命令项目集合，并说明它不自动实现应用菜单键盘模式；
- 使用 `dl`、`dt`、`dd` 表达名称与说明；
- 使用 `figure`、`figcaption` 表达可以独立引用的内容及说明；
- 区分 `blockquote`、`pre`、`div` 和 `hr` 的职责；
- 在 Elements 中确认浏览器实际建立的父子结构；
- 根据新业务内容选择列表、描述列表、表格或分节。

## 3. 预备知识

开始前建议完成：

## 4. 核心理论

### 4.1 先判断“关系”，再选择元素

可以用三个问题快速判断：

```text
这些项目是否属于同一集合？
  ├── 否：可能是多个段落或分节
  └── 是
      ├── 顺序是否改变含义？
      │   ├── 是：ol
      │   └── 否：ul
      └── 它们是否是名称与解释？
          └── 是：dl + dt + dd
```

表格适合按行和列交叉比较；描述列表适合逐项解释名称。不要仅因为两者都能显示“左边名称、右边值”就混用。

### 4.2 `ul`：顺序不改变含义的集合

`ul` 表示无序列表，直接项目使用 `li`：

```html
<h2>商品特点</h2>
<ul>
  <li>灯臂角度可以调节</li>
  <li>开关工作正常</li>
  <li>附带原装电源线</li>
</ul>
```

这里交换三个项目的顺序，不会改变商品事实，所以使用 `ul`。

默认圆点是浏览器样式，不是列表语义的来源。下面的文字看起来有圆点，却不是列表：

```html
<!-- 错误案例：只是三个段落 -->
<p>• 灯臂角度可以调节</p>
<p>• 开关工作正常</p>
<p>• 附带原装电源线</p>
```

辅助技术不会因为出现 `•` 字符就自动报告“列表，共三项”。需要集合关系时，应使用列表元素。

### 4.3 `ol`：顺序参与含义的项目

`ol` 表示有序列表：

```html
<h2>交接流程</h2>
<ol>
  <li>在平台内确认公共交接地点</li>
  <li>当面检查灯罩和电源线</li>
  <li>双方确认后完成交接</li>
</ol>
```

如果先“完成交接”再“检查电源线”，流程含义就变了，因此使用 `ol`。

#### 改变可见编号

`start` 设置整个列表的起始值：

```html
<ol start="4">
  <li>确认交接时间</li>
  <li>检查商品状态</li>
  <li>完成交接</li>
</ol>
```

`reversed` 请求倒序编号：

```html
<ol reversed>
  <li>最后检查：确认没有遗漏配件</li>
  <li>第二项检查：测试开关</li>
  <li>第一项检查：查看电源线</li>
</ol>
```

`li[value]` 调整某一个项目的序号，并影响后续计数：

```html
<ol>
  <li>步骤一</li>
  <li value="4">步骤四：前三步由服务站完成</li>
  <li>步骤五</li>
</ol>
```

编号不是业务 ID。商品 `listing-42` 即使显示为列表第 2 项，刷新排序后仍应保持自己的稳定 ID。

#### `type` 的边界

`ol[type]` 可以选择 `1`、`a`、`A`、`i`、`I` 等编号形式。它表达编号系统，不应只是为了“看起来更漂亮”而改变内容关系。视觉上的编号装饰以后可以交给 CSS。

### 4.4 `li` 与嵌套列表

`li` 必须属于 `ul`、`ol` 或 `menu`。子列表应放在它所解释的父项目中：

```html
<ul>
  <li>
    交接时可以检查
    <ul>
      <li>灯罩划痕</li>
      <li>电源线绝缘层</li>
      <li>开关响应</li>
    </ul>
  </li>
  <li>不提供邮寄</li>
</ul>
```

下面的结构是常见错误：

```html
<!-- 错误案例：子列表没有属于某个 li -->
<ul>
  <li>交接时可以检查</li>
  <ul>
    <li>灯罩划痕</li>
  </ul>
</ul>
```

浏览器可能仍显示缩进，但内容模型已经错误。检查 Elements 时，确认内层 `ul` 的父元素是对应的 `li`。

### 4.5 `menu`：命令项目列表，不是完整应用菜单

`menu` 在当前 HTML 中可以表达命令项目列表：

```html
<menu>
  <li><button type="button">收藏商品</button></li>
  <li><button type="button">分享链接</button></li>
</menu>
```

它通常使用与 `ul` 类似的列表呈现，但不会自动提供：

- 上下方向键在项目间移动；
- 菜单打开和关闭状态；
- 焦点循环；
- 右键菜单；
- ARIA `menu` 复合控件行为。

普通商品操作通常使用按钮列表即可，不要仅因为名称是 `menu` 就套用应用菜单角色。

### 4.6 `dl`、`dt`、`dd`：名称与说明

描述列表适合商品元信息：

```html
<dl>
  <div>
    <dt>价格</dt>
    <dd><data value="3900">39 元</data></dd>
  </div>
  <div>
    <dt>状态</dt>
    <dd>可预约</dd>
  </div>
  <div>
    <dt>交接方式</dt>
    <dd>社区公共地点当面检查</dd>
  </div>
</dl>
```

`dt` 是名称，`dd` 是说明。一个名称可以有多个说明：

```html
<dl>
  <dt>可检查项目</dt>
  <dd>灯罩是否破裂</dd>
  <dd>电源线是否老化</dd>
</dl>
```

多个名称也可以共享一项说明：

```html
<dl>
  <dt>available</dt>
  <dt>可预约</dt>
  <dd>当前没有有效预约，可以发起预约请求。</dd>
</dl>
```

用 `div` 包裹一个完整的 `dt`/`dd` 分组，有助于以后样式布局，但 `div` 不能把一个名称和另一个不相关说明错误拼在一起。

#### `dl` 不是二维数据表

两件商品都要比较“价格、状态、发布时间”时，读者需要沿行和列交叉阅读，更适合使用 `table`。只有一件商品的一组名称和值，通常适合 `dl`。

### 4.7 `figure` 与 `figcaption`

`figure` 表示可作为一个整体引用的内容，内部可以是图片、图表、代码、引用或数据示意。`figcaption` 是这个整体的说明，位于 `figure` 的开头或末尾。

```html
<figure>
  <pre><code>{
  "title": "阅读台灯",
  "priceCents": 3900
}</code></pre>
  <figcaption>商品数据最小示例：价格使用整数分。</figcaption>
</figure>
```

`figcaption` 不是图片 `alt` 的替代：

- `alt` 在图片不可见时替代图片信息；
- `figcaption` 给整个 figure 提供可见说明。

一张纯装饰图不需要为了使用新标签而强行包进 `figure`。

### 4.8 `blockquote` 与引用来源

长引用使用 `blockquote`：

```html
<blockquote cite="https://community.example/rules/handoff">
  <p>交接前应在光线充足的公共地点检查商品状态。</p>
</blockquote>
<p>
  来源：
  <cite>社区闲置物品交接守则</cite>
</p>
```

`blockquote[cite]` 记录来源 URL，但浏览器不会自动把它显示成链接。需要让读者访问来源时，再提供真实 `a[href]`。

`cite` 元素表示作品名称，不是通用的人名标签。

### 4.9 `pre`：保留空白，不停止 HTML 解析

`pre` 保留源文件中的空格和换行，适合代码、日志和字符图：

```html
<pre><code>商品：阅读台灯
价格：3900 分
状态：available</code></pre>
```

它不会让 HTML 语法失效。要显示 `<strong>` 文字，仍需字符引用：

```html
<pre><code>&lt;strong&gt;请检查电源线&lt;/strong&gt;</code></pre>
```

直接写真实 `<strong>` 会创建强调元素，而不是显示标签文本。

### 4.10 `div`：没有更合适语义时的容器

`div` 是无专属语义的流内容容器。它适合：

- 只为布局包裹一组已经拥有内部语义的内容；
- 给脚本或 CSS 提供结构边界；
- 暂时没有更合适语义的普通分组。

不要因为 `div` 容易加 class，就把列表、导航、文章、分节和表格全部替换成 `div`。

```html
<div class="listing-layout">
  <article>...</article>
  <aside>...</aside>
</div>
```

这里 `div` 表达布局容器，内部仍保留文章与补充信息语义。

### 4.11 `hr`：主题转折

`hr` 表示段落层面的主题转折：

```html
<p>以上是商品实际状况。</p>
<hr>
<p>下面是平台统一的安全提醒。</p>
```

如果只想画一条装饰线，应以后使用 CSS 边框或背景，而不是给文档添加不存在的主题转折。

### 4.12 从需求选择结构

| 内容需求 | 推荐结构 | 原因 |
| --- | --- | --- |
| 三个商品特点 | `ul` | 属于集合，顺序不重要 |
| 交接五步 | `ol` | 顺序参与含义 |
| 状态码与解释 | `dl` | 名称和说明 |
| 多商品价格比较 | `table` | 需要行列交叉比较 |
| 一段社区守则原文 | `blockquote` | 外部长引用 |
| 一段 JSON 示例和说明 | `figure` + `pre/code` + `figcaption` | 可独立引用的代码整体 |
| 商品与安全提示的布局包裹 | `div` | 只承担中性布局分组 |

## 5. 元素、属性、API 或配置清单

| 名称 | 作用 | 最小示例 | 常见边界 |
| --- | --- | --- | --- |
| `ul` | 无序集合 | `<ul><li>灯臂可调</li></ul>` | 直接项目使用 `li` |
| `ol` | 有顺序集合 | `<ol><li>检查商品</li></ol>` | 顺序应参与含义 |
| `ol[start]` | 设置起始编号 | `<ol start="4">` | 不是业务 ID |
| `ol[reversed]` | 请求倒序编号 | `<ol reversed>` | 布尔属性，出现即启用 |
| `ol[type]` | 选择编号系统 | `<ol type="A">` | 纯视觉装饰优先 CSS |
| `li[value]` | 设置当前有序项编号 | `<li value="4">` | 会影响后续编号 |
| `menu` | 命令项目列表 | `<menu><li><button>收藏</button></li></menu>` | 不自动实现 ARIA 菜单 |
| `dl` | 名称与说明集合 | `<dl><dt>状态</dt><dd>可预约</dd></dl>` | 不替代二维数据表 |
| `dt` | 名称 | `<dt>价格</dt>` | 放在合法 `dl` 结构中 |
| `dd` | 说明 | `<dd>39 元</dd>` | 与附近名称形成关联 |
| `figure` | 可独立引用的内容整体 | `<figure>...</figure>` | 不只用于图片 |
| `figcaption` | figure 的可见说明 | `<figcaption>价格示意</figcaption>` | 不替代图片 `alt` |
| `blockquote[cite]` | 长引用及来源 URL | `<blockquote cite="...">` | 来源不会自动显示 |
| `pre` | 保留空白 | `<pre><code>...</code></pre>` | 不关闭 HTML 解析 |
| `div` | 中性流内容容器 | `<div class="layout">` | 有明确语义时使用对应元素 |
| `hr` | 主题转折 | `<hr>` | 纯装饰线交给 CSS |

### 6.3 打开方式、预期结果与失败证据

打开方式：

1. 保存文件；
2. 用浏览器打开；
3. 打开 DevTools 的 Elements；
4. 展开最外层 `ul`，找到内层 `ul`；
5. 展开 `dl`、`figure` 和 `blockquote`。

预期结果：

- 商品特点显示为列表；
- “交接时可以检查”下面有三项子列表；
- 交接倒计时使用 `type="I"` 显示 `III`、`II`、`I`；
- 价格、状态和时间形成名称与说明；
- JSON 保留换行；
- 图注出现在代码整体之后；
- 页面无真实预约按钮。

失败证据：

- 商品标题仍位于 `article` 外，导致文章本身没有标题；
- Elements 中的内层 `ul` 与所属 `li` 并列；
- 倒计时没有显示 `III`、`II`、`I`，或首个 `li[value]` 与 `start` 不一致；
- 价格机器值不是 `3900`，或者时间机器值没有使用带 `Z` 的 UTC 字符串。

本页不依赖网络资源。关闭浏览器标签页即可结束观察。

### 6.4 逐步扩展：增加操作命令列表

在 `article` 的 `header` 之后、商品特点之前插入：

```html
  <p>按钮尚未绑定脚本，不会保存状态。</p>
</section>
```

预期出现两个原生按钮。用 Tab 可以聚焦，用 Enter 或空格激活，但因为没有事件脚本，页面不会保存收藏或复制内容。这是“正确元素但尚未实现业务行为”的状态，不是假装功能成功。

### 6.5 故障实验：破坏嵌套关系

把完整案例中的内层列表临时移到父 `li` 后面：

```html
<!-- 错误案例 -->
<ul>
  <li>交接时可以检查</li>
  <ul>
    <li>灯罩边缘的浅划痕</li>
  </ul>
</ul>
```

**现象：**浏览器仍可能显示两个层级。
**证据：**Elements 中内层 `ul` 的父元素是外层 `ul`，不是所属 `li`。
**原因：**列表直接项目应该是 `li`，子列表属于某个具体项目。
**修复：**把内层 `ul` 放回“交接时可以检查”的 `li`。
**复验：**Elements 中父子关系正确，列表含义与可见缩进一致。

## 7. 邻里集市集成案例

本课为邻里集市增加的是“内容关系”，不是新业务状态：

```text
商品
├── 特点集合：ul
├── 商品信息：dl
├── 交接流程：ol
├── 状态词汇：dl
├── 数据示例：figure
└── 社区规则引用：blockquote
```

业务约束仍来自项目契约：

- `priceCents` 使用整数分；
- `available`、`reserved`、`sold` 是状态机器值；
- 交接倒计时使用 `start`、`reversed`、`type` 和 `li[value]` 控制显示编号，但这些编号不是商品或流程记录的稳定 ID；
- 静态文字不能证明服务器真实状态；
- 操作按钮没有脚本和 API 时，不应显示成功消息；
- 引用的 `.example` 地址只用于文档语法，不是可访问的生产资源。

下一阶段会把多件商品放进表格进行行列比较。单件商品的名称值仍保留 `dl`，避免为了视觉布局过早使用表格。

## 8. 常见错误与排查路径

### 8.1 用圆点字符冒充列表

- **现象**：视觉上有三行圆点。
- **证据**：Elements 中只有 `p`，没有 `ul`/`li`。
- **原因**：字符不会创建列表关系。
- **修复**：改为 `ul` 和 `li`。
- **复验**：辅助技术或浏览器 Accessibility 树能识别列表及项目。

### 8.2 子列表与 `li` 并列

- **现象**：缩进似乎正确，但校验或 DOM 结构异常。
- **证据**：内层 `ul` 的父元素是外层列表。
- **原因**：子列表没有属于具体列表项。
- **修复**：移动到对应 `li` 内。
- **复验**：检查 Elements 父子关系。

### 8.3 用 `ol` 表达无顺序特点

- **现象**：商品特点被编号为 1、2、3。
- **证据**：交换项目后内容含义并未改变。
- **原因**：根据默认编号外观选择了元素。
- **修复**：改为 `ul`，以后用 CSS 处理视觉。
- **复验**：解释为什么顺序不参与含义。

### 8.4 用 `dl` 代替多商品表格

- **现象**：每件商品都重复“价格、状态”，难以横向比较。
- **证据**：读者需要在多个名称值组之间来回查找。
- **原因**：把名称值关系误当成二维数据。
- **修复**：多商品交叉比较使用有表头的 `table`。
- **复验**：能沿同一列比较所有价格。

### 8.5 把来源 URL 只写在 `cite` 属性

- **现象**：读者看不到可点击来源。
- **证据**：页面没有链接，只有 DOM 属性。
- **原因**：`cite` 属性记录来源，不负责展示导航。
- **修复**：需要访问时添加有描述文字的 `a[href]`。
- **复验**：键盘可以聚焦并打开来源。

### 8.6 在 `pre` 中直接写未转义标签

- **现象**：标签没有作为代码文字完整显示。
- **证据**：Elements 出现真实子元素。
- **原因**：`pre` 只保留空白，不关闭 HTML 解析。
- **修复**：使用 `&lt;` 和 `&gt;`。
- **复验**：页面显示标签文本，Elements 中没有意外元素。

### 8.7 把显示编号当成业务 ID

- **现象**：倒计时原本显示 `III`、`II`、`I`，把首项改成 `li value="8"` 后却变成 `VIII`、`VII`、`VI`。
- **证据**：Elements 显示 `ol[reversed][start="3"][type="I"]`，但首个 `li[value]` 把后续计数重置为 8。
- **原因**：`start` 给列表设起点，`reversed` 改变计数方向，`type` 改变编号系统，`li[value]` 则从某一项重置计数；这些显示编号都不是稳定业务标识。
- **修复**：恢复 `li value="3"`，或者在无需单项重置时删除 `value`；真实记录 ID 另用稳定数据字段保存。
- **复验**：可见编号恢复为 `III`、`II`、`I`，交换样式不会改变商品或流程记录的身份。

## 9. 课后题

### 9.1 理解题

1. 商品特点与交接步骤为什么使用不同列表？
2. `li[value]` 为什么不能当成商品 ID？
3. `figcaption` 和图片的 `alt` 有什么不同？
4. `blockquote[cite]` 为什么不能替代可见来源链接？
5. `div` 在什么情况下是合理选择？

<details>
<summary>查看理解题答案</summary>

1. 特点的顺序通常不改变含义，使用 `ul`；步骤的顺序参与流程，使用 `ol`。
2. 它只改变当前列表的显示编号，排序或内容变化后编号可能改变；业务 ID 应稳定。
3. `alt` 在图片不可用时替代图片信息，`figcaption` 是整个 figure 的可见说明。
4. 属性不会自动显示或提供导航，读者需要访问时仍需 `a[href]`。
5. 内容只需要中性布局或脚本容器，且没有更准确的语义元素时。

</details>

### 9.2 推理题

下面三组内容分别应使用什么结构？

```text
A：成色、尺寸、颜色
B：填写表单、确认地点、当面检查
C：状态 available 的含义、状态 reserved 的含义
```

<details>
<summary>查看推理答案</summary>

- A 使用 `ul`，它们是无顺序商品属性集合。
- B 使用 `ol`，顺序参与业务过程。
- C 使用 `dl`，它们是状态名称与解释。

</details>

### 9.3 设计题

一个页面要展示三件商品，每件都有价格和状态。请比较：

- 为每件商品建立一个 `dl`；
- 建立一张含“商品、价格、状态”表头的 `table`。

答案标准：如果主要任务是逐件阅读详情，可以使用每件商品的 `dl`；如果主要任务是跨商品比较同一属性，表格更清楚。说明用户任务比默认外观更重要。

## 12. 常见问题

### Q1：去掉列表圆点，列表语义还在吗？

一般情况下，CSS 改变视觉不会修改 DOM 元素。但具体辅助技术对极端样式组合可能存在差异，仍应检查目标环境。语义来源是正确元素，不是圆点。

### Q2：一个 `dl` 中可以有多个 `dt` 和 `dd` 吗？

可以。名称与说明可以形成一对多或多对一关系。关键是让分组关系清楚，不要把无关内容随意放入。

### Q3：每张图片都应该使用 `figure` 吗？

不应该。只有图片、代码或图表作为一个可独立引用的整体，并需要图注或明确边界时才考虑 `figure`。

### Q4：为什么不用 `div` 加 class 模拟所有元素？

class 不会自动提供列表、引用或名称值语义。需要相应关系时使用原生元素，CSS 仍可以改变它们的外观。

### Q5：`menu` 和 `nav` 有什么不同？

`nav` 包含主要导航链接；`menu` 表示一组命令项目。查看商品详情通常是导航，收藏商品通常是命令。

### Q6：`hr` 能不能只用来画线？

它会在文档中表达主题转折。仅为装饰时应由 CSS 实现，避免增加错误语义。

# 第一章：文档、解析与文本

> 从一段卖家消息出发，建立浏览器能够正确解析、人和机器都能理解的商品说明。

## 本章任务

王阿姨发来一段台灯信息：

```text
阅读台灯，39 元。开关正常，灯罩有浅划痕。
周末在社区服务站当面交接。
```

你要把它变成完整 HTML 文档，并能够解释：

- 源文件怎样变成 DOM；
- 浏览器为什么会修复部分错误；
- `head` 中的元信息和资源关系怎样影响页面；
- 标题、段落、强调、时间和修订元素为什么不能只按默认外观选择；
- 价格和时间怎样同时提供机器值与可见文字。

## 学习成果

完成本章后，你将拥有：

- 一份符合现代文档骨架的商品页；
- 一份源文件与 Elements 的解析对照记录；
- 一个能观察脚本加载顺序的页面；
- 一份包含价格整数分、UTC 时间和国际化文字的商品说明；
- 三次错误实验及修复证据。

## 知识依赖图

```text
源文件
  → 解析规则与错误恢复
  → html / head / body 的 DOM
  → head 中的元信息和资源关系
  → body 中的标题、段落与文本语义
  → 商品机器值、国际化与修订记录
```

第一课建立“浏览器实际得到什么”，第 2–7 课再依次讨论合法结构、元信息、资源加载和文本表达。如果不知道 DOM 是否按预期建立，只看页面外观会掩盖结构错误。

## 本章知识地图

### 解析与文档

- 标签、元素、属性、token、节点和 DOM；
- `doctype`、标准模式、`html`、`head`、`body`；
- 空元素、布尔属性、字符引用、注释和空白；
- 内容类别、允许的父子关系和错误恢复。

### 元信息与资源

- `title`、字符编码、视口、描述和 robots；
- `base` 对相对 URL 的文档级影响；
- `link`、`style`、`script`、`noscript`；
- classic、`defer`、`async` 和 module 加载顺序；
- HTML 元信息和真实 HTTP 响应头的边界。

### 文本与国际化

- 标题、段落、换行和主题转折；
- 重要、重音、关键词、引用、术语和代码；
- `time`、`data`、修订记录；
- 语言、文字方向、注音和可选换行。

逐知识点验收位置见 [HTML 教学覆盖矩阵](HTML-COVERAGE.md)。

## 章级综合案例

### 目录

在个人项目中建立：

```text
market-learning/
└── practice/
    └── html-chapter-01/
        ├── index.html
        ├── styles.css
        ├── classic.js
        ├── deferred.js
        └── module.js
```

文件由七篇详细教程逐步完成。本章不在教材仓库提供独立源码。

### 最终页面要求

`index.html` 至少包含：

- 标准文档骨架和 `lang="zh-CN"`；
- UTF-8、viewport、description 和具体 `title`；
- 一个样式表关系；
- 可观察执行顺序的脚本；
- 一个页面主标题和不跳级的分节标题；
- 商品价格的 `data[value]`，值为整数分；
- 发布时间的 `time[datetime]`，机器值使用 UTC；
- 商品状况、安全提醒、型号代码和社区守则引用；
- 一个未知方向的卖家名称；
- 一次交接时间修订记录；
- 明确说明本页不创建真实预约或支付。

## 章级故障演练

按顺序制造并恢复：

1. 在 `p` 中放入块级分节，观察解析器修复；
2. 写入 `disabled="false"`，观察按钮仍禁用；
3. 加入错误 `base`，观察相对链接目标变化；
4. 让 preload 类型与资源不匹配，观察 Network；
5. 用 `strong` 代替标题，比较视觉与文档导航。

每次记录：

```text
现象
源文件
DOM / Network 证据
原因
修复
复验
```

## 本章验收

### 文档与解析

- [ ] 能区分源文件、元素、节点和 DOM；
- [ ] 能解释 `doctype` 与文档骨架；
- [ ] 能指出一个浏览器错误恢复结果；
- [ ] 能解释布尔属性为什么不是字符串布尔值；
- [ ] 能检查内容父子关系。

### 元信息与资源

- [ ] `title` 与页面 `h1` 描述同一主题；
- [ ] 字符编码与文件编码一致；
- [ ] viewport 不禁止缩放；
- [ ] 能预测相对 URL 在 `base` 下的目标；
- [ ] 能画出脚本解析与执行顺序；
- [ ] 不用 meta 冒充所有服务器安全响应头。

### 文本语义

- [ ] 不按粗体或斜体外观选择元素；
- [ ] 标题层级和段落关系清楚；
- [ ] 引用、代码、术语和修订元素用途正确；
- [ ] 价格机器值使用整数分；
- [ ] 时间机器值使用有效 UTC；
- [ ] 未知方向文字不会扰乱附近标点。

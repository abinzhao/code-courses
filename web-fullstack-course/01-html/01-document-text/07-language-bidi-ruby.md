## 4. 核心理论

### 4.1 `lang` 与 `dir`：语言和书写方向是两个维度

根元素上的 `lang="zh-CN"` 声明文档主要语言。局部语言变化应写在最小而完整的片段上：

```html
<html lang="zh-CN">
  ...
  <p>色温模式：<span lang="en">Warm White</span></p>
</html>
```

`lang` 有助于发音、断词、拼写检查和翻译，但不会自动翻译内容，也不会自动决定所有布局方向。

`dir` 声明文字方向：

- `ltr`：从左到右；
- `rtl`：从右到左；
- `auto`：浏览器根据内容中第一个强方向字符判断。

```html
<p lang="ar" dir="rtl">مصباح مستعمل بحالة جيدة</p>
```

语言与方向相关但不是同一个概念。不要用 `lang="ar"` 代替 `dir="rtl"`，也不要用 CSS 的视觉方向设置替代内容本身的方向元数据。

### 4.2 `bdi` 与 `bdo`：隔离未知方向，或明确覆盖方向

用户昵称、商品编号和评论可能来自未知语言。把方向未知的片段直接插入句子，双向文本算法可能让附近的括号、冒号和数字跑到不符合预期的位置：

```html
<p dir="ltr">未隔离：卖家 سارة_88（评分 5）</p>
<p dir="ltr">已隔离：卖家 <bdi>سارة_88</bdi>（评分 5）</p>
```

`bdi` 的意思是“双向隔离”。它默认会根据自身内容判断方向，同时防止内部方向影响外部句子。两行在某些字体和短文本下差异可能不明显，但 DOM 中是否建立隔离边界是稳定证据。对来源未知的用户名，第二种写法更可靠。

`bdo` 是“双向覆盖”，它强制按给定方向呈现内容：

```html
<p>方向覆盖演示：<bdo dir="rtl">ABC-123</bdo></p>
```

它适合确实需要演示或纠正方向的受控文本，不适合未知用户名。把所有 RTL 文字都塞进 `bdo` 会覆盖 Unicode 双向算法，反而可能制造错误。

### 4.3 `ruby`、`rt`、`rp` 与 `wbr`：注音和可选断行

`ruby` 表示带注音或其他短注释的文字，`rt` 放注音，`rp` 为不支持 Ruby 排版的环境提供回退括号：

```html
<p>
  交接地点：
  <ruby>青<rp>（</rp><rt>qīng</rt><rp>）</rp></ruby>
  <ruby>禾<rp>（</rp><rt>hé</rt><rp>）</rp></ruby>
  社区。
</p>
```

现代浏览器通常把 `rt` 排在正文上方或旁边，并隐藏 `rp`；不支持 Ruby 布局时，可退化为“青（qīng）禾（hé）”。`rp` 不是必须显示的普通括号。

`wbr` 是空元素，提供一个“必要时可以在这里换行”的机会：

```html
<p>序列号：NLM-2026-A17<wbr>-QINGHE<wbr>-000104</p>
```

它不会总是产生换行，也不会插入连字符。缩窄窗口后，浏览器才可能在这些位置断开。不要用 `br` 强迫长编号在所有屏幕上固定换行。

## 5. 元素、属性、API 或配置清单

### 5.1 国际化

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `lang` | 声明内容语言 | `lang="zh-CN"` | 不自动翻译，不等于方向 |
| `dir` | 声明文字方向 | `dir="rtl"` | 值为 `ltr`、`rtl` 或 `auto` |
| `bdi` | 隔离未知方向片段 | `<bdi>سارة_88</bdi>` | 用于隔离，不用于强制反转 |
| `bdo[dir]` | 强制覆盖方向 | `<bdo dir="rtl">ABC</bdo>` | 只用于明确、受控的覆盖 |
| `ruby` | 注音容器 | `<ruby>青<rt>qīng</rt></ruby>` | 不代替正文翻译 |
| `rt` | Ruby 注音 | `<rt>qīng</rt>` | 应放在 `ruby` 中 |
| `rp` | Ruby 回退括号 | `<rp>（</rp>` | 支持 Ruby 时通常不显示 |
| `wbr` | 可选换行机会 | `A17<wbr>-000104` | 空元素；不保证换行 |

## 6. 最小可运行案例

### 6.1 文件位置与打开方式

在个人练习目录创建：

```text
practice/
└── html-text/
    └── semantics-contrast.html
```

把下面内容完整保存为 `practice/html-text/semantics-contrast.html`，文件编码选择 UTF-8。双击文件，或在浏览器中选择“打开文件”。地址可以是 `file://`，本例不需要服务器。

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>文本语义对比观察台</title>
  </head>
  <body>
    <h1>文本语义对比观察台</h1>
    <p>不要只看默认大小和粗细，请同时检查 Elements。</p>

    <h2>标题不是粗体文字</h2>
    <h3>商品详情</h3>
    <h4>规格</h4>
    <h5>电源</h5>
    <h6>接口</h6>
    <p><b>这行虽然通常加粗，但仍然只是段落中的注意文字。</b></p>

    <h2>换行不是新段落</h2>
    <p>
      青禾社区服务站<br>
      东门值班室<br>
      周六 14:00～16:00
    </p>
    <p>第一段说明灯罩有轻微划痕。</p>
    <p>第二段说明电源线需要现场检查。</p>

    <h2>重要与视觉注意</h2>
    <p><strong>接电前必须检查线缆。</strong></p>
    <p>分类：<b>家居照明</b>。</p>
    <p><em>仅限当面交接</em>，模式名为 <i lang="en">warm white</i>。</p>
    <p>搜索命中：折叠式<mark>台灯</mark>。</p>

    <h2>旧内容与编辑修订</h2>
    <p>旧展示价：<s>159 元</s>；现价：<data value="12800">128 元</data>。</p>
    <p>
      交接时间：
      <del datetime="2026-10-09T12:00:00Z">工作日 18:00 后</del>
      <ins datetime="2026-10-10T07:00:00Z">周六 14:00～16:00</ins>
    </p>

    <h2>机器时间与可见文字</h2>
    <p>
      发布于
      <time datetime="2026-10-10T08:30:00Z">
        2026年10月10日 16:30（北京时间）
      </time>。
    </p>

    <h2>未知方向用户名</h2>
    <p dir="ltr">未隔离：卖家 سارة_88（评分 5）</p>
    <p dir="ltr">已隔离：卖家 <bdi>سارة_88</bdi>（评分 5）</p>
    <p>方向覆盖演示：<bdo dir="rtl">ABC-123</bdo>。</p>

    <h2>注音与长编号</h2>
    <p>
      地点：
      <ruby>青<rp>（</rp><rt>qīng</rt><rp>）</rp></ruby>
      <ruby>禾<rp>（</rp><rt>hé</rt><rp>）</rp></ruby>
      社区。
    </p>
    <p>编号：NLM-2026-A17<wbr>-QINGHE<wbr>-000104</p>

    <hr>
    <p><small>这是本地教学文件，不接受真实付款或预约。</small></p>
  </body>
</html>
```

### 6.2 预期结果与观察步骤

1. 标签页标题是“文本语义对比观察台”。
2. 页面显示从 `h1` 到 `h6` 的层级演示，但这不表示真实商品必须使用到六级。
3. 地址的三个行分隔位于同一个 `p`，商品状况的两段说明是两个并列 `p`。
4. 旧价格与编辑修订具有不同元素；现价 `data` 的机器值是 `12800`。
5. `time` 的机器值是 UTC，可见文字明确写成北京时间。
6. 两行用户名有“未隔离”和“已隔离”版本；即使当前字体下标点差异很小，也能在 DOM 中确认第二行存在 `bdi`。
7. 缩窄浏览器窗口后，长编号可以在 `wbr` 所在位置换行；它不一定在宽窗口中换行。
8. 在 Elements 搜索 `ruby`，可以看到 `rt` 与 `rp`，而现代浏览器通常不显示回退括号。

### 6.3 失败证据

| 现象 | 优先检查的证据 | 可能原因 |
| --- | --- | --- |
| 页面显示源码 | 地址栏文件名、扩展名 | 文件可能保存成 `.html.txt` |
| 中文或阿拉伯文乱码 | 编辑器编码、`meta charset` | 文件不是 UTF-8 或声明缺失 |
| 标签页仍是旧标题 | 编辑器保存状态、地址栏路径 | 没保存或打开了另一份文件 |
| 长编号始终不换行 | 窗口宽度、Elements 中的 `wbr` | 空间足够，或复制时漏掉 `wbr` |
| 用户名两行看起来相同 | Elements 中是否存在 `bdi` | 短文本的视觉差异可能不明显 |
| 修订时间显示在页面上 | 检查是否另写了可见文字 | 属性值本来不会自动显示 |

关闭标签页即可结束本案例。不要为了制造视觉差异而给页面加入尚未解释的脚本。

## 8. 常见错误与排查路径

### 8.1 错误实验五：移除未知方向用户名的隔离

- **文件路径：**`practice/html-text/fault-bidi.html`。
- **打开方式：**复制集成文件，把 `<bdi>سارة_88</bdi>` 改成普通 `<span>سارة_88</span>`，并在用户名后加入“（评分 5，商品 12）”。缩窄窗口后刷新。
- **预期现象：**不同浏览器、字体和文本组合下，标点与数字顺序可能受用户名方向影响；使用 `bdi` 后外部句子边界更稳定。
- **失败证据：**若肉眼差异不明显，检查 Elements。`span` 没有双向隔离语义，`bdi` 有；不要为了得到夸张截图而改用 `bdo`。

## 12. 常见问题

### Q1：只要页面外观正确，就可以跳过本课语义吗？

不可以。外观只能证明当前样式结果，不能证明 DOM、默认行为、可访问名称、网络状态或机器值正确。

### Q2：开发者工具中的一次成功是否代表所有环境都支持？

不代表。记录浏览器与版本，并把其他浏览器、真实设备、辅助技术或服务器响应列为明确的复测边界。

### Q3：为什么项目案例不在每篇教程中完整复制？

完整应用集中在一篇汇总课中维护。其他课程提交增量和证据，避免多个副本逐渐产生不一致。

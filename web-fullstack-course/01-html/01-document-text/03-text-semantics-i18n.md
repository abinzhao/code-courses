# 03 文本语义与国际化：把卖家留言写成可理解的商品说明

## 任务卡

卖家发来一段消息：“台灯 128，原来 159，周六取，线有点旧，型号 A17，用户 سارة_88。”这些字都能放进网页，但浏览器还不知道哪一部分是标题、价格、警告、时间、引用或用户名。

本课要把这段消息整理成一份有明确含义的邻里集市商品说明。你不仅要让它“看得见”，还要让浏览器、翻译工具、搜索工具和辅助技术获得可以判断的结构。

| 关卡 | 可见成果 | 验收证据 |
| --- | --- | --- |
| 分清层次 | 商品名、分节和段落结构清楚 | Elements 中的 `h1`～`h6` 与 `p` |
| 选择语义 | 重要、重音、旧价格和修订各得其所 | 能解释元素选择而不是只谈外观 |
| 绑定机器值 | 价格使用整数分，时间使用 UTC | `data[value]` 与 `time[datetime]` |
| 处理多语言 | 语言、方向隔离、注音和长编号可读 | `lang`、`dir`、`bdi`、`ruby`、`wbr` |
| 留下变更记录 | 删除和新增内容带有修订元数据 | `del`、`ins` 的 `datetime` 与 `cite` |

建议学习时间为 120～180 分钟。先完成语义对比观察台，再独立写一个不同商品。最终成果是两个能直接由浏览器打开的 HTML 文件，以及一份语义选择记录。

## 1. 任务背景

上一课已经让浏览器获得文档标题、字符编码和资源信息。本课开始处理 `body` 中真正给人阅读的文字。

HTML 不是“给文字套一个默认样式”的工具。浏览器默认把 `h1` 显示得大、把 `strong` 和 `b` 显示得粗，只是为了让没有 CSS 的文档仍然可读；外观可以被 CSS 完全改变，元素表达的含义却仍然存在。

同一句卖家留言至少包含七类信息：

1. “台灯”是商品标题；
2. “128”是给人看的价格，还需要整数分机器值；
3. “原来 159”表示旧价格已不再准确；
4. “周六取”是可见的本地时间说明；
5. “线有点旧”需要提升为安全警告；
6. “A17”是型号代码；
7. `سارة_88` 是方向未知的用户输入，不能让它扰乱周围标点。

如果只用一个 `div` 加粗所有文字，读者也许勉强能看懂，但标题导航、自动提取、翻译和后续程序都缺少可靠线索。本课的完成标准不是“页面像一张商品卡”，而是每段内容都能回答“它为什么使用这个元素”。

## 2. 学习目标

完成本课后，你应能：

- 按内容层级选择 `h1`～`h6`，并解释标题与视觉粗体的区别。
- 用 `p` 表示段落，用 `br` 表示同一段内的必要换行，用 `hr` 表示主题转换。
- 区分 `strong`、`em`、`b`、`i`、`mark`、`small`、`s` 和 `u` 的职责。
- 正确组织 `q`、`blockquote`、`cite`，说明元素 `cite` 与属性 `cite` 的不同。
- 用 `abbr`、`dfn`、`code`、`kbd`、`samp`、`var` 表达缩写、定义和计算机相关文本。
- 用 `time[datetime]` 和 `data[value]` 同时提供可见文字与机器值。
- 区分“不再准确”的 `s` 与“编辑删除”的 `del`，并为 `del`、`ins` 写修订时间和来源。
- 按排版惯例选择 `sub`、`sup`，知道 `span` 不会凭空增加语义。
- 用 `lang`、`dir`、`bdi`、`bdo`、`ruby`、`rt`、`rp`、`wbr` 处理语言、双向文字、注音和换行机会。
- 在 Elements 中检查实际 DOM，并用“现象 → 证据 → 原因 → 修复 → 复验”记录一次错误。

## 3. 预备知识

开始前应完成：

- [文档头、元信息与资源](02-head-metadata-resources.md)：能写出含 `doctype`、`html`、`head`、`body` 的完整文档。

你需要一个纯文本编辑器和现代浏览器。所有练习都放在个人学习目录 `practice/html-text/`，直接打开即可，不需要安装依赖、启动服务器或创建本仓库中的 `labs/`。

本课会让你打开开发者工具的 Elements 面板。若还不会操作：

2. 切到 Elements；

本课不要求掌握 CSS。不要通过字号、颜色或粗细判断语义是否正确；先看内容责任和 DOM 元素名。

## 4. 核心理论

### 4.1 先问“这段内容是什么”

选择文本元素时，按下面的顺序判断：

```text
这段内容是否建立一个新主题？
  ├─ 是：选择与层级相符的 h1～h6
  └─ 否：它是否是一组完整语句？
       ├─ 是：通常用 p
       └─ 否：继续判断它是强调、引用、术语、机器值、修订还是注音
```

不要先问“我想让它多大、加粗还是斜体”。那些是视觉设计问题，后续由 CSS 处理。语义选择错误时，即使页面外观暂时符合预期，也会给标题导航、自动化读取和维护者留下错误信息。

### 4.2 `h1`～`h6`：六级标题不是六种字号

`h1` 到 `h6` 表示标题级别。数字越大，表示相对层级越深，不表示“重要程度百分比”，也不应为了获得较小字体而跳级。

| 元素 | 在一份商品说明中的合理角色 |
| --- | --- |
| `h1` | 页面或商品的主标题，例如“折叠式阅读台灯” |
| `h2` | 商品说明的主要分节，例如“商品状况”“交接信息” |
| `h3` | 某个二级分节下的子主题，例如“电源检查” |
| `h4` | 更深一层的子主题，例如“线缆外皮” |
| `h5` | 只有内容确实继续分层时才使用 |
| `h6` | 六级层次的最深标题，不是普通小字 |

本教材的简单商品页通常只有一个清楚的 `h1`，再从 `h2` 逐级展开。HTML 并没有把“每页只能有一个 `h1`”写成通用语法禁令，但多个主标题会增加初学页面的层级判断成本。浏览器也不会根据 `section` 自动把多个 `h1` 重新计算成理想大纲。

标题与粗体文字的关键差别是：

```html
<h2>商品状况</h2>
<p><b>商品状况</b></p>
```

两者都可能默认加粗，但只有第一行是标题。读屏软件的标题导航、浏览器扩展和文档分析工具可以把 `h2` 当成分节入口；`b` 只让一段文字获得注意，不建立新层级。

观察方法：在 Elements 搜索 `h2`，再把页面默认样式临时关闭。即使视觉差异消失，DOM 中的标题层级仍然不同。

### 4.3 `p`、`br`、`hr`：段落、换行与主题转换

`p` 表示一个段落，也就是围绕同一意思组织的一组语句。开始新的论点、说明新的状况或切换说话内容时，应开始新的 `p`。

`br` 是空元素，表示同一段内容中确实需要换行。例如诗句、歌词或一份需要保留行分隔的简短地址可以使用它：

```html
<p>
  青禾社区服务站<br>
  东门值班室<br>
  周六 14:00～16:00
</p>
```

不要用连续多个 `br` 制造段落间距：

```html
<!-- 错误：两个观点仍被塞在同一段落中 -->
<p>灯罩有划痕。<br><br>电源线需要现场检查。</p>
```

正确做法是：

```html
<p>灯罩有划痕。</p>
<p>电源线需要现场检查。</p>
```

`br` 与 `p` 的区别不只是空白大小。前者仍在同一段落中，后者建立两个独立段落。Elements 会明确显示一个 `p` 加两个 `br`，或两个并列的 `p`。

`hr` 表示段落级别的主题转换，例如从“商品描述”转到“修订记录”。浏览器常把它画成横线，但“画一条装饰线”不是它的语义；纯装饰边框应交给 CSS。

### 4.4 `strong`、`em`、`b`、`i`：意义优先于默认外观

这四个元素最容易因默认粗体或斜体而混淆。

#### `strong` 与 `b`

`strong` 表示重要、严重或紧急：

```html
<p><strong>接电前必须检查破损线缆。</strong></p>
```

`b` 把文字带到读者注意范围内，但不增加重要性，例如摘要中的商品关键词：

```html
<p>分类：<b>家居照明</b></p>
```

它们默认都可能显示为粗体，但“安全警告”与“分类关键词”不是同一种含义。若只是设计稿要求普通文字变粗，不应因此捏造重要性；使用 CSS 设置字重。

#### `em` 与 `i`

`em` 表示语气重音。改变重音位置可能改变一句话想纠正的内容：

```html
<p>本商品<em>只支持当面交接</em>，不提供邮寄。</p>
```

`i` 表示与周围普通叙述不同的声音或文本惯例，例如技术术语、外文短语、分类学名称或内心话：

```html
<p>灯光模式标为 <i lang="en">warm white</i>。</p>
```

默认斜体只是常见呈现。书名应优先考虑 `cite`，重要内容用 `strong`，语气重音用 `em`，不能看到“想要斜体”就一律选择 `i`。

### 4.5 `mark`、`small`、`s`、`u`：四种容易被当成装饰的语义

`mark` 表示在当前上下文中相关、值得标出的内容。搜索“台灯”后的结果可以标出匹配词：

```html
<p>搜索结果：折叠式<mark>台灯</mark></p>
```

若没有搜索、引用比对或当前阅读上下文，单纯为了黄色背景不应使用 `mark`。

`small` 表示旁注、小字条款、版权或免责声明：

```html
<p><small>教学页面不接受真实付款或预约。</small></p>
```

它不等于“任何次要内容”，也不应被当作通用缩小字号工具。

`s` 表示内容已经不再准确或不再相关，但它不是一次文档编辑操作：

```html
<p>旧展示价：<s>159 元</s>；现价：128 元。</p>
```

`u` 表示非文字性的注记，例如中文排版中的专名标记或拼写问题提示。它默认可能带下划线，容易与链接混淆：

```html
<p>交接地点位于<u>青禾社区</u>。</p>
```

只为了下划线装饰应使用 CSS。使用 `u` 时还应确保读者不会误以为它可点击。

### 4.6 `q`、`blockquote`、`cite`：引用内容与作品名称

`q` 用于嵌在句子中的短引用。浏览器会按语言规则生成引号，因此不要再手工把引号写进 `q` 内容：

```html
<p>守则提醒：<q cite="https://market.example/rules/handoff">见面后先验货，再确认交接</q>。</p>
```

`blockquote` 用于独立成块的较长引用，内部通常包含一个或多个段落：

```html
<blockquote cite="https://market.example/rules/handoff">
  <p>请在光线充足的公共地点检查电器外观和线缆。</p>
  <p>确认物品状况后，再决定是否完成交接。</p>
</blockquote>
```

`q` 与 `blockquote` 的 `cite` 属性记录来源 URL，但浏览器不会自动把它显示成可点击链接。若读者需要访问来源，正文中仍应提供链接；链接会在下一章系统学习。

`cite` 元素表示被引用作品的标题，例如规则、文章、书籍、电影或研究报告：

```html
<p>摘自<cite>《邻里集市交接守则》</cite>。</p>
```

不要把普通人名都放进 `cite`。可以写“卖家王阿姨说……”，其中“王阿姨”本身不是作品名称。

### 4.7 `abbr`、`dfn`、`code`、`kbd`、`samp`、`var`：术语与计算机文本

`abbr` 表示缩写。`title` 可以提供完整展开，但鼠标悬停提示不适合触屏和部分辅助技术，所以首次出现时最好在可见正文中同时写出全称：

```html
<p><abbr title="发光二极管">LED</abbr>（发光二极管）是本商品的光源类型。</p>
```

`dfn` 表示当前上下文正在定义的术语，定义应紧邻它：

```html
<p><dfn>整数分</dfn>是用最小货币单位保存价格，例如 128 元写成 12800 分。</p>
```

其余四个元素分别表达不同角色：

```html
<p>价格变量 <var>priceCents</var> 的示例值是 <code>12800</code>。</p>
<p>在 Elements 中按 <kbd>Command+F</kbd>，输入 <kbd>priceCents</kbd>。</p>
<p>找到后会看到类似输出：<samp>&lt;data value="12800"&gt;</samp>。</p>
```

- `code`：计算机代码、文件名中的代码片段或标记片段；
- `kbd`：用户需要输入或按下的内容；
- `samp`：程序或工具产生的示例输出；
- `var`：数学表达式或程序语境中的变量名。

`code` 不会阻止 HTML 解析。要把 `<data>` 当文字显示，仍需写成 `&lt;data&gt;` 之类的字符引用。

### 4.8 `time` 与 `data`：可见文字和机器值各司其职

`time` 用于日期、时间、时长或这些信息的组合。`datetime` 保存标准化机器值，元素内容负责给人阅读：

```html
<time datetime="2026-10-10T08:30:00Z">2026年10月10日 16:30（北京时间）</time>
```

这里 `Z` 表示 UTC。北京时间 UTC+8 的 16:30 与 UTC 08:30 表示同一时刻。这个换算是作者写对的，不是 `time` 元素自动完成的；浏览器不会自动把可见文字转换成读者所在时区。

必须保持机器值与可见文字指向同一时刻。下面是错误示例：

```html
<!-- 错误：机器值是 08:30 UTC，可见文字却写成北京时间 08:30 -->
<time datetime="2026-10-10T08:30:00Z">2026年10月10日 08:30（北京时间）</time>
```

`data` 为任意可见内容附上机器值。邻里集市约定价格机器值使用整数分：

```html
<p>价格：<data value="12800">128 元</data></p>
```

`value="12800"` 只是字符串形式的机器值，HTML 不会检查它是否真的等于 128 元，也不会把它写入数据库。作者或后续程序必须维护单位一致性。日期与时间应优先使用专门的 `time`，而不是通用 `data`。

### 4.9 `del`、`ins` 与 `s`：失效内容不等于编辑记录

商品旧价格只是在当前页面上“不再准确”，适合 `s`。如果要明确记录一次文档修订，例如把“工作日交接”改成“仅周六交接”，应使用 `del` 与 `ins`：

```html
<p>
  交接时间：
  <del
    datetime="2026-10-09T12:00:00Z"
    cite="https://market.example/revisions/listing-104"
  >工作日 18:00 后</del>
  <ins
    datetime="2026-10-10T07:00:00Z"
    cite="https://market.example/revisions/listing-104"
  >仅周六 14:00～16:00</ins>
</p>
```

`datetime` 记录修改时间，`cite` 记录解释此次修改的资源地址；两者都不会自动显示。真实页面若需要让读者看见原因和时间，必须另写可见文字。

对比结论：

| 场景 | 应选元素 | 原因 |
| --- | --- | --- |
| 159 元已经不是当前售价 | `s` | 内容不再准确，没有强调编辑动作 |
| 规则文本从“可邮寄”改为“不可邮寄” | `del` + `ins` | 需要表达删掉与加入的修订 |
| 内容本来就写错，且无需保留历史 | 直接改正 | 不必把所有改字都永久展示成修订 |

### 4.10 `sub`、`sup` 与 `span`：排版惯例和中性容器

`sub` 表示按排版惯例应为下标的内容，`sup` 表示上标：

```html
<p>电池材料标识：LiFePO<sub>4</sub>；占地约 0.18 m<sup>2</sup>。</p>
```

不要用它们单纯缩小或上下移动文字。脚注链接、数学指数和化学式可能适用，但复杂数学应使用更合适的 MathML。

`span` 是没有额外语义的行内容器。当你只需要给一小段文字指定语言、类名或脚本定位点，而没有更准确的语义元素时，可以使用它：

```html
<p>包装上的英文颜色名是 <span lang="en">Warm White</span>。</p>
```

`span` 不会创建段落、标题或强调。若内容本身是重要警告，就应选择 `strong`，不能因为 `span` 容易加样式就放弃语义。

### 4.11 `lang` 与 `dir`：语言和书写方向是两个维度

根元素上的 `lang="zh-CN"` 声明文档主要语言。局部语言变化应写在最小而完整的片段上：

```html
<html lang="zh-CN">
  ...
  <p>色温模式：<span lang="en">Warm White</span></p>
</html>
```

`lang` 有助于发音、断词、拼写检查和翻译，但不会自动翻译内容，也不会自动决定所有布局方向。

`dir` 声明文字方向：

- `ltr`：从左到右；
- `rtl`：从右到左；
- `auto`：浏览器根据内容中第一个强方向字符判断。

```html
<p lang="ar" dir="rtl">مصباح مستعمل بحالة جيدة</p>
```

语言与方向相关但不是同一个概念。不要用 `lang="ar"` 代替 `dir="rtl"`，也不要用 CSS 的视觉方向设置替代内容本身的方向元数据。

### 4.12 `bdi` 与 `bdo`：隔离未知方向，或明确覆盖方向

用户昵称、商品编号和评论可能来自未知语言。把方向未知的片段直接插入句子，双向文本算法可能让附近的括号、冒号和数字跑到不符合预期的位置：

```html
<p dir="ltr">未隔离：卖家 سارة_88（评分 5）</p>
<p dir="ltr">已隔离：卖家 <bdi>سارة_88</bdi>（评分 5）</p>
```

`bdi` 的意思是“双向隔离”。它默认会根据自身内容判断方向，同时防止内部方向影响外部句子。两行在某些字体和短文本下差异可能不明显，但 DOM 中是否建立隔离边界是稳定证据。对来源未知的用户名，第二种写法更可靠。

`bdo` 是“双向覆盖”，它强制按给定方向呈现内容：

```html
<p>方向覆盖演示：<bdo dir="rtl">ABC-123</bdo></p>
```

它适合确实需要演示或纠正方向的受控文本，不适合未知用户名。把所有 RTL 文字都塞进 `bdo` 会覆盖 Unicode 双向算法，反而可能制造错误。

### 4.13 `ruby`、`rt`、`rp` 与 `wbr`：注音和可选断行

`ruby` 表示带注音或其他短注释的文字，`rt` 放注音，`rp` 为不支持 Ruby 排版的环境提供回退括号：

```html
<p>
  交接地点：
  <ruby>青<rp>（</rp><rt>qīng</rt><rp>）</rp></ruby>
  <ruby>禾<rp>（</rp><rt>hé</rt><rp>）</rp></ruby>
  社区。
</p>
```

现代浏览器通常把 `rt` 排在正文上方或旁边，并隐藏 `rp`；不支持 Ruby 布局时，可退化为“青（qīng）禾（hé）”。`rp` 不是必须显示的普通括号。

`wbr` 是空元素，提供一个“必要时可以在这里换行”的机会：

```html
<p>序列号：NLM-2026-A17<wbr>-QINGHE<wbr>-000104</p>
```

它不会总是产生换行，也不会插入连字符。缩窄窗口后，浏览器才可能在这些位置断开。不要用 `br` 强迫长编号在所有屏幕上固定换行。

## 5. 元素、属性、API 或配置清单

### 5.1 内容层次与基础分隔

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `h1`～`h6` | 六级标题层次 | `<h2>商品状况</h2>` | 不按默认字号选级别，不依赖自动大纲 |
| `p` | 一个段落 | `<p>开关正常。</p>` | 不能用多个 `br` 伪造多个段落 |
| `br` | 同一段内的必要换行 | `东门<br>值班室` | 空元素；不负责段落间距 |
| `hr` | 段落级主题转换 | `<hr>` | 空元素；纯装饰线交给 CSS |

### 5.2 强调、注意和注记

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `strong` | 重要、严重或紧急 | `<strong>先断电</strong>` | 不只是视觉粗体 |
| `em` | 语气重音 | `<em>仅限当面</em>` | 不只是视觉斜体 |
| `b` | 吸引注意但不增加重要性 | `<b>家居照明</b>` | 纯字重用 CSS |
| `i` | 不同声音、术语或文本惯例 | `<i lang="en">warm white</i>` | 作品名优先考虑 `cite` |
| `mark` | 当前上下文相关的标记 | `<mark>台灯</mark>` | 纯黄色背景用 CSS |
| `small` | 旁注或小字条款 | `<small>教学数据</small>` | 不表示所有次要内容 |
| `s` | 不再准确或相关 | `<s>159 元</s>` | 编辑记录使用 `del` |
| `u` | 非文字性的注记 | `<u>青禾社区</u>` | 默认下划线可能被误认成链接 |

### 5.3 引用、术语和计算机文本

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `q[cite]` | 行内短引用 | `<q>先验货</q>` | 不要重复手写引号；`cite` 不自动显示 |
| `blockquote[cite]` | 块级长引用 | `<blockquote><p>规则</p></blockquote>` | 不是普通缩进容器 |
| `cite` | 作品标题 | `<cite>《交接守则》</cite>` | 普通人名通常不适用 |
| `abbr[title]` | 缩写 | `<abbr title="发光二极管">LED</abbr>` | 可见正文仍应给出全称 |
| `dfn` | 当前正在定义的术语 | `<dfn>整数分</dfn>` | 定义必须在附近 |
| `code` | 代码片段 | `<code>12800</code>` | 不会自动转义 `<` |
| `kbd` | 用户输入 | `<kbd>Command+F</kbd>` | 不表示程序输出 |
| `samp` | 程序或工具输出 | `<samp>value="12800"</samp>` | 不表示用户按键 |
| `var` | 变量 | `<var>priceCents</var>` | 不只是通用斜体 |

### 5.4 机器值、修订和排版

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `time[datetime]` | 时间及其机器值 | `<time datetime="2026-10-10">10月10日</time>` | 不自动转换时区 |
| `data[value]` | 可见内容及通用机器值 | `<data value="12800">128 元</data>` | 不验证单位，不持久化 |
| `del[datetime][cite]` | 被编辑删除的内容 | `<del datetime="2026-10-10">旧规则</del>` | 旧价格若只是失效可用 `s` |
| `ins[datetime][cite]` | 被编辑加入的内容 | `<ins datetime="2026-10-10">新规则</ins>` | 元数据不会自动可见 |
| `sub` | 下标 | `H<sub>2</sub>O` | 不用来单纯缩小文字 |
| `sup` | 上标 | `m<sup>2</sup>` | 复杂数学优先使用 MathML |
| `span` | 无额外语义的行内容器 | `<span lang="en">White</span>` | 有准确语义元素时不要滥用 |

### 5.5 国际化

| 名称 | 作用 | 最小用法 | 边界 |
| --- | --- | --- | --- |
| `lang` | 声明内容语言 | `lang="zh-CN"` | 不自动翻译，不等于方向 |
| `dir` | 声明文字方向 | `dir="rtl"` | 值为 `ltr`、`rtl` 或 `auto` |
| `bdi` | 隔离未知方向片段 | `<bdi>سارة_88</bdi>` | 用于隔离，不用于强制反转 |
| `bdo[dir]` | 强制覆盖方向 | `<bdo dir="rtl">ABC</bdo>` | 只用于明确、受控的覆盖 |
| `ruby` | 注音容器 | `<ruby>青<rt>qīng</rt></ruby>` | 不代替正文翻译 |
| `rt` | Ruby 注音 | `<rt>qīng</rt>` | 应放在 `ruby` 中 |
| `rp` | Ruby 回退括号 | `<rp>（</rp>` | 支持 Ruby 时通常不显示 |
| `wbr` | 可选换行机会 | `A17<wbr>-000104` | 空元素；不保证换行 |

## 8. 常见错误与排查路径

### 8.1 错误实验一：用粗体冒充标题

- **文件路径：**复制 `semantics-contrast.html` 为 `practice/html-text/fault-heading.html`。
- **打开方式：**把“商品详情”的 `<h3>` 改成 `<p><b>商品详情</b></p>`，保存后直接刷新。
- **预期现象：**文字可能仍然粗，但 Elements 中不再有对应 `h3`；浏览器的标题层级缺少这一项。
- **失败证据：**若仍搜索到旧 `h3`，检查是否保存、是否刷新了 `fault-heading.html`，而不是原文件。

排查链：

```text
现象：看起来仍像标题
→ 证据：Elements 只有 p > b，没有 h3
→ 原因：视觉粗体没有建立标题层级
→ 修复：恢复 h3；视觉外观以后交给 CSS
→ 复验：Elements 再次出现 h3，层级位于 h2 之下
```

### 8.2 错误实验二：用 `br` 伪造段落

- **文件路径：**`practice/html-text/fault-breaks.html`。
- **打开方式：**复制观察台，把两个商品状况段落改成 `<p>第一段<br><br>第二段</p>` 后刷新。
- **预期现象：**屏幕上可能出现一块空隙，但 Elements 只有一个 `p`，其中包含两个 `br`。
- **失败证据：**若看到两个并列 `p`，说明修改未生效或浏览器打开了别的文件。

修复为两个 `p` 后复验：Elements 应显示两个段落兄弟节点，不再依靠连续 `br`。

### 8.3 错误实验三：混淆 `s` 与 `del`

- **文件路径：**`practice/html-text/fault-edits.html`。
- **打开方式：**复制邻里集市文件，把旧价格的 `s` 改成 `del`，并把规则修订的 `del` 改成 `s`。
- **预期现象：**默认外观可能几乎不变，但 DOM 表达的含义正好颠倒。
- **失败证据：**Elements 是主要证据；不能以“都有删除线”判断成功。

修复依据：旧价只是当前已失效，使用 `s`；明确的文档修改保留删除与新增过程，使用 `del` 和 `ins`。

### 8.4 错误实验四：机器时间与可见时间不一致

- **文件路径：**`practice/html-text/fault-time.html`。
- **打开方式：**复制观察台，只把可见文字改成“2026年10月10日 08:30（北京时间）”，保留 `datetime="2026-10-10T08:30:00Z"`。
- **预期现象：**页面不会报错，但机器值与可见文字相差 8 小时。
- **失败证据：**Elements 中的属性与正文同时存在，浏览器没有自动警告，这正是需要人工核对的证据。

修复后应恢复北京时间 16:30，或把机器值改为与 08:30 北京时间对应的 `2026-10-10T00:30:00Z`。二者选其一，关键是同一时刻。

### 8.5 错误实验五：移除未知方向用户名的隔离

- **文件路径：**`practice/html-text/fault-bidi.html`。
- **打开方式：**复制集成文件，把 `<bdi>سارة_88</bdi>` 改成普通 `<span>سارة_88</span>`，并在用户名后加入“（评分 5，商品 12）”。缩窄窗口后刷新。
- **预期现象：**不同浏览器、字体和文本组合下，标点与数字顺序可能受用户名方向影响；使用 `bdi` 后外部句子边界更稳定。
- **失败证据：**若肉眼差异不明显，检查 Elements。`span` 没有双向隔离语义，`bdi` 有；不要为了得到夸张截图而改用 `bdo`。

### 8.6 错误实验六：观察浏览器修复非法段落嵌套

下面代码故意错误：

```html
<p>外层商品说明
  <p>内层商品说明</p>
  外层结尾
</p>
```

- **文件路径：**`practice/html-text/fault-dom.html`，把这段放入一个完整 HTML 的 `body`。
- **打开方式：**保存后直接打开，同时查看“页面源代码”和 Elements。
- **预期现象：**源文件看似有嵌套 `p`，浏览器解析时会提前结束外层段落，实际 DOM 不会保留 `p` 包 `p` 的结构，还可能出现额外空段落。
- **失败证据：**只看页面文字无法证明结构；必须截图或记录源文件与 Elements 的差异。

修复为两个并列 `p`，刷新后复验 DOM。不要通过删除内容逃避结构问题。

## 9. 课后题

先写下自己的判断和依据，再展开答案。

<details>
<summary>题 1：商品分节标题已经通过 CSS 变粗，为什么仍不能只用 `b`？</summary>

`b` 只表示把一段文字带到注意范围，不建立标题层级。分节标题应使用与层级相符的 `h2`～`h6`。CSS 可以让两者外观相同，但 Elements、标题导航和内容分析得到的结构仍然不同。

</details>

<details>
<summary>题 2：“接电前检查线缆”和“家居照明”都想加粗，应分别用什么？</summary>

前者是安全上的重要、严重信息，使用 `strong`；后者只是分类关键词，需要吸引注意但不增加重要性，可使用 `b`。若加粗纯属视觉设计，两者都不应被滥用，应由 CSS 设置字重。

</details>

<details>
<summary>题 3：旧价格 159 元和被删除的“支持邮寄”都用 `s` 可以吗？</summary>

不可以一概而论。旧价格只是不再准确，适合 `s`；如果页面要保留“支持邮寄”被编辑删除的事实，应使用 `del`，并可用 `ins` 表示替换后的内容。默认删除线相似不代表含义相同。

</details>

<details>
<summary>题 4：什么时候用 `br`，什么时候开始新的 `p`？</summary>

同一内容单元内部必须保留的行分隔，例如短地址或诗句，可以用 `br`。开始新的观点、说明或段落时用新的 `p`。判断依据是内容关系，不是想留多少空白。

</details>

<details>
<summary>题 5：`datetime="2026-10-10T08:30:00Z"` 会让页面自动显示北京时间吗？</summary>

不会。`datetime` 给机器读取，元素内容由作者或脚本提供。若正文写北京时间，应自行保证它与 UTC 机器值代表同一时刻，并明确时区。

</details>

<details>
<summary>题 6：未知方向用户名只含拉丁字母时，还需要 `bdi` 吗？</summary>

若用户名来自用户输入，未来可能出现阿拉伯文、希伯来文或混合字符，`bdi` 能建立稳定隔离边界。当前样本只有拉丁字母不代表数据契约永远如此。隔离范围只应包含用户名本身，不应把周围标点和评分一起包入。

</details>

<details>
<summary>题 7：`blockquote cite="..."` 为什么不能代替可点击的来源链接？</summary>

`cite` 属性保存来源 URL 元数据，浏览器不要求把它显示为链接。读者需要访问来源时，页面还应提供可见的 `a[href]`；链接在下一章学习。

</details>

<details>
<summary>题 8：`abbr title="发光二极管"` 是否足以让所有人知道 LED 的含义？</summary>

不足。`title` 常以鼠标悬停方式出现，触屏、键盘和辅助技术体验并不一致。首次出现时应在可见正文写出“LED（发光二极管）”，`title` 只能作为补充。

</details>

**综合推理题：**页面显示“现价 128 元，发布于北京时间 16:30”，但 DOM 是 `data value="128"` 和 `time datetime="2026-10-10T16:30:00Z"`。页面外观是否足以通过验收？

参考答案：不能。项目约定价格使用整数分，128 元应为 `12800`；北京时间 16:30 对应 UTC 08:30，不是 UTC 16:30。两个可见文字都正常，但两个机器值都错误。验收必须同时检查正文、属性、单位和时区。

## 12. 常见问题

**每个页面必须只有一个 `h1` 吗？**

HTML 语法没有把所有多 `h1` 页面判为非法，但浏览器不会可靠地按分节自动重排标题等级。对本课的单商品页，使用一个清楚的 `h1` 和逐级子标题最容易维护和验证。

**`strong` 会让读屏软件一定用更重语气朗读吗？**

不能作普遍保证。语义使工具有机会理解重要性，但具体语音表现取决于辅助技术与设置。选择 `strong` 的理由应是内容重要，而不是期待某一种固定声音。

**`time` 能自动按访问者所在时区显示吗？**

不能。静态 HTML 中可见文字就是作者写入的文字。自动本地化需要后续 JavaScript 或服务端逻辑，并且仍要处理时区和格式。

**`data value="12800"` 会自动显示为 128 元吗？**

不会。`value` 和可见文字由作者分别提供。HTML 不知道项目把价格单位约定为分，也不会自动做除法。

**所有用户输入都要放进 `bdi` 吗？**

重点是可能包含未知方向文字、且会嵌入周围句子的片段，例如用户名和动态标题。是否使用还要看上下文；不要把整段标点和固定标签一并隔离。

**已经写了 `lang="ar"`，还需要 `dir="rtl"` 吗？**

语言和方向是不同元数据。浏览器可能根据字符表现出方向，但作者知道段落方向时应明确声明；混合或未知内容可考虑 `dir="auto"`，嵌入用户名则使用 `bdi` 隔离。

**为什么 `rp` 在页面上看不见？**

现代浏览器支持 Ruby 排版时，`rt` 会被放在正文附近，`rp` 作为回退括号通常隐藏。Elements 中仍可看到它；这正是回退设计。

**能用 `u` 做所有下划线吗？**

不能。`u` 表示非文字性的注记，不是通用装饰。链接也常有下划线，滥用会造成误解；纯装饰应使用 CSS。

**`cite` 元素能放作者姓名吗？**

`cite` 表示作品标题，不是通用署名元素。作者姓名通常写成普通文本；作品名如《邻里集市交接守则》才适合 `cite`。

## 13. 扩展阅读

官方资料核验日期：**2026-10-10**。HTML 与国际化规范会持续更新；核验日期说明本课依据的资料快照，不代表所有旧浏览器都支持完全相同的呈现。

- [WHATWG HTML：章节与标题](https://html.spec.whatwg.org/multipage/sections.html#headings-and-sections)：带着“标题等级如何表达层次、浏览器是否实现自动大纲”阅读。
- [WHATWG HTML：内容分组](https://html.spec.whatwg.org/multipage/grouping-content.html)：核对 `p`、`hr`、`br`、`blockquote` 的内容模型和边界。
- [WHATWG HTML：文本级语义](https://html.spec.whatwg.org/multipage/text-level-semantics.html)：逐项核对强调、术语、机器值、双向隔离、Ruby 与可选断行。
- [WHATWG HTML：编辑记录](https://html.spec.whatwg.org/multipage/edits.html)：比较 `del`、`ins` 的 `cite`、`datetime` 与 `s` 的不同责任。
- [W3C Internationalization：在 HTML 中声明语言](https://www.w3.org/International/questions/qa-html-language-declarations)：核对文档语言和局部语言标记。
- [W3C Internationalization：内联双向文本标记](https://www.w3.org/International/articles/inline-bidi-markup/)：观察混合 LTR/RTL 内容为什么需要隔离边界。
- [Unicode 双向算法 UAX #9](https://www.unicode.org/reports/tr9/)：了解标点和数字顺序不是简单的“字符串反转”；初学阶段先读概述。
- [邻里集市项目契约](../../00-guide/05-project-assessment.md)：复核价格整数分、时间 UTC 与真实业务校验边界。

阅读时持续追问四件事：元素表达什么、允许放在哪里、机器值是什么、怎样在 DOM 中证明。

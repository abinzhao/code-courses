# 11-CSS 盒模型与视觉格式化

## 目标

完成本知识单元后，学员应能够解释“一个元素为什么出现在那个位置、占了多大地方、谁压在谁上面”，并在样式冲突时按规则推导结果，而不是靠反复刷新试数值。学员应能够：

1. 使用行内样式、内部样式表与外部样式表三种方式引入 CSS，说明各自的作用范围、优先级位置与适用场景，并默认选择外部样式表组织项目。
2. 根据目标元素的结构特征选择类型、类、ID、属性、伪类、伪元素选择器以及后代、子代、相邻、兄弟组合器，并准确计算多条规则竞争时的优先级。
3. 用自己的语言描述层叠、来源顺序与 `!important` 的处理规则，面对“样式没生效”问题能定位是优先级、来源、顺序还是拼写问题。
4. 利用继承减少重复声明，识别哪些属性默认继承，并使用 `initial`、`inherit`、`unset` 等通用关键字处理属性。
5. 根据盒模型与 `box-sizing` 计算元素实际占位，解释边框、内边距、外边距对布局的影响以及外边距折叠现象。
6. 区分块级与行内格式化行为，使用五种 `position` 与层叠上下文规则完成定位，处理溢出，并在 px、百分比、em、rem、vw、vh、dvh 等单位间做出合理选择。

## 详细的理论知识讲解和示例伪代码

### 1. CSS 的引入方式与基本语法

#### 1.1 定义

CSS（Cascading Style Sheets，层叠样式表）由规则组成。一条规则包含选择器与声明块，声明块由若干“属性: 值;”声明构成：

```text
选择器 {
  属性: 值;
}
```

引入 CSS 的三种方式：

1. 行内样式：在元素的 `style` 属性中写声明，只影响当前元素。
2. 内部样式表：在 `head` 中的 `<style>` 元素内写规则，只影响当前文档。
3. 外部样式表：把规则写入 `.css` 文件，用 `<link rel="stylesheet">` 引入，可被多个页面复用并被浏览器缓存。

#### 1.2 与 Web 的关系

HTML 负责结构，CSS 负责呈现。浏览器把外部样式表下载、解析后与 DOM 结合生成渲染树。外部样式表实现了“结构与表现分离”：改版式时不必逐页改 HTML，多页共享同一套样式，也利于缓存。行内样式优先级很高且无法被媒体查询等机制复用，除动态设置的个别值外不应大量使用。

#### 1.3 三种引入示例

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <title>引入方式</title>

    <!-- 外部样式表：项目主线 -->
    <link rel="stylesheet" href="./styles/base.css" />

    <!-- 内部样式表：只影响本页 -->
    <style>
      .note {
        color: #555;
      }
    </style>
  </head>
  <body>
    <p class="note">这段文字由内部样式表着色。</p>

    <!-- 行内样式：只影响当前元素，优先级最高的普通来源 -->
    <p style="color: #b3261e">这段文字由行内样式着色。</p>
  </body>
</html>
```

`styles/base.css`：

```css
body {
  font-family: system-ui, -apple-system, sans-serif;
  line-height: 1.6;
  color: #171717;
}
```

#### 1.4 语法要点

- 声明必须以分号结尾；漏掉分号会让相邻声明解析失败。
- 值中的多个单词用空格分隔，如 `border: 1px solid #ccc;`。
- `/* 这是 CSS 注释 */`，CSS 不支持 `//` 注释。
- 未知属性或非法值会被整条忽略，后续规则不受影响——这是“拼写错了却不报错、只是不生效”的原因。

#### 1.5 常见误区

> 行内样式写起来最快，项目可以全用行内。

行内样式无法复用、无法写伪类与媒体查询、维护时要逐元素修改，还会让 HTML 混入表现细节。它只适合由脚本动态计算的个别值。

> CSS 写错时浏览器会报错提示。

CSS 设计上尽量容错：无法识别的声明被静默丢弃。排查要靠开发者工具中该属性是否被划掉或根本未出现。

### 2. 选择器与组合器

#### 2.1 定义

基础选择器：

| 选择器 | 示例 | 匹配对象 |
|---|---|---|
| 类型（元素） | `p` | 所有该标签元素 |
| 类 | `.card` | class 含 card 的元素 |
| ID | `#main` | id 为 main 的唯一元素 |
| 通配 | `*` | 所有元素 |
| 属性 | `input[type="email"]` | 符合属性条件的元素 |

伪类表示元素的特定状态：`:hover`、`:focus`、`:first-child`、`:nth-child(odd)`、`:disabled`、`:checked`。伪元素表示元素的特定部分：`::before`、`::after`、`::first-line`、`::placeholder`，约定使用双冒号。

组合器描述元素间关系：

| 组合器 | 写法 | 含义 |
|---|---|---|
| 后代 | `nav a` | nav 内任意层级的 a |
| 子代 | `.card > h2` | 直接子元素 |
| 相邻兄弟 | `h2 + p` | 紧接其后的一个兄弟 |
| 普通兄弟 | `h2 ~ p` | 之后的所有兄弟 |

#### 2.2 与 Web 的关系

选择器决定“样式落到谁身上”。类选择器可复用、优先级适中，是项目主力；ID 选择器权重高、难以覆盖，除极少数锚点场景外不用于样式。组合器让规则可以表达结构关系，但层级过深（如 `.list .item .wrap a span`）会提高耦合、降低可维护性。

#### 2.3 示例

```css
/* 类选择器：可在多处复用 */
.card {
  border: 1px solid #ddd;
  border-radius: 8px;
  padding: 16px;
}

/* 子代组合器：只影响直接子标题，不影响嵌套卡片中的标题 */
.card > h2 {
  margin-top: 0;
  font-size: 18px;
}

/* 伪类：交互状态 */
.card:hover {
  border-color: #0b5fff;
}

/* 属性选择器：只选中邮箱输入框 */
input[type="email"] {
  border-color: #2e7d32;
}

/* 伪元素：在元素前后插入生成内容 */
.tag::before {
  content: "#";
  color: #888;
}

/* nth-child：斑马纹表格 */
tbody tr:nth-child(even) {
  background: #f7f7f7;
}
```

```html
<article class="card">
  <h2>文章标题</h2>
  <p><span class="tag">前端</span> 标签文字</p>
</article>
```

#### 2.4 选择器使用原则

```text
1. 优先用一个表意清楚的类选中目标，如 .button-primary
2. 需要状态时加伪类，如 :disabled
3. 只在确有结构关系时用组合器，并控制层级深度
4. 不用 ID 写样式，不用 !important 弥补选择器设计问题
```

#### 2.5 常见误区

> `.card > h2` 和 `.card h2` 效果看起来一样，可以混用。

前者只匹配直接子元素，后者匹配任意深度后代。嵌套结构出现后二者结果不同，应按真实关系选择。

> `:nth-child(2)` 表示“同类中的第二个”。

它表示“自身是父元素的第二个子元素且同时满足前面的选择器”。“同类型第二个”应使用 `:nth-of-type(2)`。

### 3. 层叠、优先级与来源

#### 3.1 定义

当多条规则作用于同一元素的同一属性时，浏览器按层叠（cascade）决定最终值，依次比较：

1. 重要性与来源：作者样式（页面写的）、用户样式、浏览器默认样式；`!important` 的声明提升处理，且来源顺序反转。
2. 优先级（选择器权重）。
3. 出现顺序：权重相同时，后出现的声明胜出。

优先级按四个档位计数，可记为 `(行内, ID, 类/伪类/属性, 类型/伪元素)`：

| 选择器示例 | 行内 | ID | 类 | 类型 |
|---|---:|---:|---:|---:|
| `p` | 0 | 0 | 0 | 1 |
| `.card p` | 0 | 0 | 1 | 1 |
| `#main .card` | 0 | 1 | 1 | 0 |
| `style="color:red"` | 1 | 0 | 0 | 0 |

比较时从高档到低档逐档比较，档位数字不进位（1 个 ID 永远压过任意多个类）。

#### 3.2 与 Web 的关系

层叠是 CSS 的核心机制，也是“为什么我写的样式没生效”的根源所在：可能是更高优先级的规则覆盖、同权重时加载顺序靠前者被覆盖、或属性根本不适用于该元素。开发者工具的 Styles 面板会把被覆盖的声明划掉，是定位这类问题的第一现场。

`!important` 会绕过正常权重比较，滥用后层层加 important 互相压制，使样式无法维护。唯一合理的常见用法是工具类（如隐藏工具类）或覆盖完全不受控的第三方内联样式，且应克制。

#### 3.3 优先级计算示例

```css
/* 规则 A */
article .title {
  color: blue;
}

/* 规则 B */
#main .title {
  color: green;
}

/* 规则 C */
article section .title {
  color: orange;
}
```

```html
<main id="main">
  <article>
    <section>
      <h2 class="title">标题颜色是什么？</h2>
    </section>
  </article>
</main>
```

推导：

```text
规则 A 权重 (0,0,1,1)
规则 B 权重 (0,1,1,0)  → 含 1 个 ID，胜出
规则 C 权重 (0,0,2,1)  → 类档位 2 大于 1，但 ID 档位为 0，仍输给 B

最终 color: green
```

#### 3.4 排查“样式不生效”的顺序

```text
1. 元素是否被选择器命中？（Styles 面板中有无该规则）
2. 属性与值是否合法、是否适用于该元素？
3. 是否被更高优先级的规则覆盖？（被划掉的声明上方是谁）
4. 同权重时，样式表加载顺序如何？后加载者胜
5. 是否被 !important 或行内样式压制？
6. 属性是否其实在走继承，而元素上有更靠近的规则？
```

#### 3.5 常见误区

> 选择器写得越长，优先级越高，所以 `.a .b .c p` 一定赢 `.x p`。

长度只影响低档位计数。若对手含 ID 或行内样式，再长的类与类型组合也会输。

> 两个规则权重一样时，写在 HTML 里更靠近元素的那个生效。

普通外部样式之间比较的是样式表中的声明顺序与样式表加载顺序，与 HTML 中元素位置无关。

### 4. 继承

#### 4.1 定义

继承（inheritance）指元素没有显式设置某属性时，取父元素的该属性计算值。默认继承的多为“文字相关”属性：

- `color`
- `font-*`（family、size、weight、style）
- `line-height`
- `text-align`
- `list-style`
- `visibility`

默认不继承的多为“盒子相关”属性：`margin`、`padding`、`border`、`width`、`height`、`display`、`position`、`background`。

通用关键字：

| 关键字 | 含义 |
|---|---|
| `inherit` | 显式取父元素的同属性值 |
| `initial` | 取属性的初始默认值 |
| `unset` | 可继承属性等同 inherit，否则等同 initial |
| `revert` | 回滚到浏览器默认样式表提供的值 |

#### 4.2 与 Web 的关系

继承让“全站字体、正文颜色”只需在 `body` 上声明一次，子元素自动获得，避免重复书写。理解继承也能解释反直觉现象：给 `body` 设置 `color`，链接却不变蓝之外的颜色——因为浏览器默认样式表给 `a` 显式设了颜色，显式声明优先于继承。

#### 4.3 示例

```css
body {
  color: #171717;
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

/* 链接默认色来自浏览器规则，不会继承 body 颜色；如需统一要显式设置 */
a {
  color: #0b5fff;
}

/* 强制按钮继承父级字体，否则按钮默认使用系统控件字体 */
button,
input,
select,
textarea {
  font: inherit;
}

/* 某段说明恢复到属性初始值 */
.reset-spacing {
  margin: initial;
}
```

继承的传递示例：

```html
<div style="color: #2e7d32">
  <p>
    这段文字继承绿色
    <strong>strong 也继续继承绿色</strong>
  </p>
</div>
```

#### 4.4 常见误区

> 在 body 上设置字体后，按钮和输入框里的字也会跟着变。

表单控件默认使用浏览器内置字体，不继承父级字体，需要用 `font: inherit` 显式继承。

> 边框不想要时写 `border: inherit` 就行。

`border` 默认不继承，父级也未必有同值边框；去除边框应写 `border: none` 或 `border: initial`。

### 5. display 与格式化上下文

#### 5.1 定义

`display` 决定元素生成的盒子类型及其参与的格式化方式：

| display | 行为要点 |
|---|---|
| `block` | 独占一行；默认宽度填满父级；可设宽高与上下 margin |
| `inline` | 与相邻行内元素共处一行；宽高设置不生效；上下 margin/padding 不推开行 |
| `inline-block` | 对外像行内（可并排），对内像块（可设宽高、margin） |
| `none` | 元素不生成盒子，不占位，从渲染中移除 |

块级元素参与块格式化上下文（BFC）：盒子在容器内从上到下垂直排列，垂直 margin 相邻时会发生折叠（见第 6 节）。行内元素在行内格式化上下文中从左到右排列，超出容器宽度时按规则换行。

#### 5.2 与 Web 的关系

默认 display 由标签语义决定：`p`、`div`、标题是 block；`span`、`a`、`strong` 是 inline；`img` 是 inline（但具有可替换内容特性）。许多“为什么宽度设了没用”“为什么两个框排不到一行”的问题，本质是没分清元素当前的盒子类型。

现代布局的主力是 Flexbox 与 Grid（下两个单元），`display: flex/grid` 会让元素成为对应容器；`inline-block` 多用于没有布局需求时的简单并排，`display:none` 与 `visibility:hidden` 的区别是前者彻底不占位。

#### 5.3 示例

```css
.block-box {
  display: block;
  width: 200px;
  margin-bottom: 8px;
  background: #e8f0fe;
}

.inline-word {
  display: inline;
  /* 以下对纯行内盒子不会按预期撑开布局 */
  width: 100px;
  margin-top: 20px;
  background: #fde8e8;
}

.pill {
  display: inline-block;
  width: 80px;
  height: 32px;
  margin: 4px;
  text-align: center;
  line-height: 32px;
  border-radius: 16px;
  background: #e8f0fe;
}

.hidden-box {
  display: none;
}
```

```html
<span class="block-box">我被改成块级，独占一行</span>
<span class="inline-word">我仍是行内，宽高与上外边距不推开行</span>
<span class="pill">胶囊一</span>
<span class="pill">胶囊二</span>
<div class="hidden-box">我不占位</div>
```

`display:none` 与 `visibility:hidden`：

| 声明 | 是否可见 | 是否占位 | 读屏器 |
|---|---|---|---|
| `display:none` | 否 | 否 | 不呈现 |
| `visibility:hidden` | 否 | 是 | 默认仍可能不朗读内容 |

#### 5.4 常见误区

> 给行内元素设置 `margin-top` 没看到变化，是浏览器 bug。

行内盒子的垂直 margin、padding 不影响行高方向上的布局（padding 会渲染背景但不推开上下行）。需要垂直间距就改为 inline-block 或块级。

> `display:none` 和 `visibility:hidden` 只是名字不同。

前者脱离布局、不占空间；后者保留位置，只不可见。误用会造成空白区域或内容仍被读出。

### 6. 盒模型与 box-sizing

#### 6.1 定义

每个元素渲染为一个矩形盒子，由四层构成：

```text
┌─────────────────────────────── margin（外边距，透明）
│  ┌─────────────────────────── border（边框）
│  │  ┌─────────────────────── padding（内边距）
│  │  │  ┌─────────────────── content（内容区）
│  │  │  │  文本与子元素
│  │  │  └───────────────────
│  │  └───────────────────────
│  └───────────────────────────
└───────────────────────────────
```

- `content`：内容区，宽高由 `width`/`height` 设置。
- `padding`：内容与边框之间的空间，会显示背景。
- `border`：边框，占据真实空间。
- `margin`：盒子与其他盒子之间的间隔，透明。

`box-sizing` 决定 `width`/`height` 作用的范围：

- `content-box`（默认）：width 只含内容区，实际占位宽 = width + padding + border。
- `border-box`：width 含内容、padding 与 border，实际占位宽就是 width（margin 仍另算）。

#### 6.2 与 Web 的关系

“两个宽度各 50% 的列为什么挤到换行”“设置 width:100% 再加 padding 就溢出”——根因都是 content-box：声明宽度只是内容宽度，padding 和 border 会在其外追加。使用 border-box 后，“这个框占多宽”与声明值一致，做百分比分栏与固定尺寸卡片更直观，因此项目常在全局统一设置。

#### 6.3 占位计算示例

```css
.box {
  width: 200px;
  padding: 20px;
  border: 5px solid #333;
  margin: 10px;
}
```

content-box 下：

```text
实际占据宽度 = 200 + 20×2 + 5×2 = 250px（不含 margin）
含 margin 的布局间隔 = 250 + 10×2 = 270px
```

border-box 下：

```css
.box {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 5px solid #333;
}
```

```text
实际占据宽度 = 200px（内容区被压缩为 200 - 40 - 10 = 150px）
```

全局统一设置：

```css
*,
*::before,
*::after {
  box-sizing: border-box;
}
```

#### 6.4 外边距折叠

块级元素的垂直相邻 margin 会折叠为一个值，取两者中的较大者，常见三种情形：

1. 相邻兄弟：上一个的 margin-bottom 与下一个的 margin-top 折叠。
2. 父元素与第一个/最后一个子元素之间没有 border、padding、行内内容或 BFC 阻隔时，子 margin “穿透”到父元素外。
3. 空块自身的 margin-top 与 margin-bottom 折叠。

注意：水平 margin 不折叠；Flex、Grid 项目的 margin 不折叠；行内盒子不参与。处理方式是改用 padding、阻隔条件或把布局交给 Flex/Grid。

#### 6.5 常见误区

> margin 都是简单相加，两个 20px 间隔应该是 40px。

垂直方向普通块级相邻 margin 折叠取大值，结果仍是 20px。需要更大间隔应在单侧设置。

> 全局 border-box 后，padding 不再占空间。

padding 仍存在，只是从声明的 width 内部扣除，内容区相应变小；margin 永远在 width 之外。

### 7. position、z-index 与层叠上下文

#### 7.1 定义

`position` 的五个值：

| 值 | 定位依据 | 是否脱离常规流 |
|---|---|---|
| `static` | 默认，按正常流 | 否 |
| `relative` | 相对自身原位置偏移，原位置保留 | 否 |
| `absolute` | 相对最近的已定位祖先，否则相对初始包含块 | 是 |
| `fixed` | 相对视口（滚动不移动，特殊祖先 transform 会改变参照） | 是 |
| `sticky` | 正常流中，滚动到阈值时“粘”在指定位置 | 否（保留占位） |

偏移用 `top`、`right`、`bottom`、`left`。`z-index` 只对定位元素（及 Flex/Grid 项目）生效，控制在同一层叠上下文中的前后顺序。

层叠上下文（stacking context）由根元素、定位且 z-index 非 auto 的元素、opacity 小于 1、transform 非 none 等条件形成。其关键规则：子元素的 z-index 只在父上下文内部比较，整体被父上下文的层级决定——这解释了“子元素 z-index:9999 仍压不过另一个面板”。

#### 7.2 与 Web 的关系

定位用于处理常规流无法表达的需求：悬浮按钮、下拉菜单、吸顶导航、角标。滥用绝对定位会让元素脱离文档流、不再占据空间，容易遮挡内容且难以响应式，整页布局应优先 Flex/Grid，定位只负责“局部脱离流”的元素。

#### 7.3 示例

吸顶导航：

```css
.site-header {
  position: sticky;
  top: 0;
  z-index: 10;
  background: #ffffff;
}
```

角标相对卡片定位：

```css
.card {
  position: relative;
}

.card__badge {
  position: absolute;
  top: 8px;
  right: 8px;
  z-index: 2;
  background: #b3261e;
  color: #fff;
  padding: 2px 8px;
  border-radius: 10px;
}
```

返回顶部按钮：

```css
.to-top {
  position: fixed;
  right: 16px;
  bottom: 16px;
  z-index: 20;
}
```

层叠上下文比较示例：

```text
面板 A（z-index:10，形成层叠上下文）
  └─ 内部菜单（z-index:9999）
面板 B（z-index:20）

结果：B 整体压过 A 及其内部任何 z-index 的元素
      因为先比较 A、B 两个上下文：20 > 10
```

#### 7.4 z-index 使用建议

```text
1. 只给真正需要层叠关系的元素设置 z-index，范围尽量小
2. 用分层变量管理，如 10（吸顶）、20（遮罩下按钮）、30（弹窗）
3. 不写 99999 比拼大小，发现压不过时先查层叠上下文归属
4. 定位参照元素自身要 position: relative，避免 absolute 跑到页面顶层
```

#### 7.5 常见误区

> z-index 越大越靠前，所有元素放在一起比较。

比较被限制在各自层叠上下文内。父级层级低，子级写再大也出不了父级的“层级范围”。

> fixed 元素一定相对浏览器视口。

当祖先存在 `transform`、`filter`、`will-change: transform` 等属性时，该祖先会成为 fixed 的包含块，定位参照随之改变。

### 8. 溢出与 CSS 单位

#### 8.1 定义

`overflow` 控制内容超出盒子时的处理：

| 值 | 行为 |
|---|---|
| `visible`（默认） | 内容溢出可见 |
| `hidden` | 裁切溢出内容 |
| `scroll` | 始终显示滚动条 |
| `auto` | 需要时才出现滚动条 |

可分轴设置：`overflow-x`、`overflow-y`。常用单位：

| 单位 | 参照 | 典型用途 |
|---|---|---|
| `px` | 绝对像素 | 边框、细线、已知固定尺寸 |
| `%` | 父元素对应属性 | 分栏宽度、相对容器尺寸 |
| `em` | 当前元素字号 | 组件内部相对自身字号的间距 |
| `rem` | 根元素字号 | 全局间距与字号，可随用户设置缩放 |
| `vw` / `vh` | 视口宽 / 高的百分之一 | 视口比例尺寸 |
| `dvh` | 动态视口高度 | 移动端全屏布局，随浏览器 UI 伸缩 |
| `ch` | 字符 0 的宽度 | 文本行宽与输入框宽度 |

#### 8.2 与 Web 的关系

移动端浏览器地址栏收起会改变视口高度，`vh` 按“大视口”计算时可能让底部按钮被工具栏遮挡；`dvh` 跟随实际可视高度变化，做全屏页面更稳妥（以当前稳定版支持为准，必要时同时声明 vh 作为回退）。rem 配合根字号让整体排版能响应用户的字号偏好；em 在组件内有“随组件字号缩放”的价值，但嵌套时会逐级相乘，需谨慎。

长文本、长 URL、预格式化代码可能撑破容器：可用 `overflow-wrap: break-word`、限制 `max-width`、对代码块使用 `overflow:auto`。

#### 8.3 示例

```css
/* 根字号使用默认设置，rem 以此为基准 */
.panel {
  width: 60ch;
  max-width: 100%;
  padding: 1.5rem;
}

/* 长单词可在必要处断行，避免横向溢出 */
.panel p {
  overflow-wrap: break-word;
}

/* 代码块超出时横向滚动而不是撑破布局 */
pre {
  overflow-x: auto;
}

/* 移动端全屏区：先写 vh 回退，再写 dvh 增强 */
.hero {
  height: 100vh;
  height: 100dvh;
}

/* 裁切容器中的浮层内容 */
.media {
  overflow: hidden;
  border-radius: 12px;
}
```

单位选择决策：

```text
边框、1px 分割线          → px
与容器成比例的分栏         → % 或 fr（Grid 中）
全局字号、间距体系         → rem
组件内随字号缩放的间距     → em
视口相关的全屏、覆盖层     → vw / vh / dvh
限制文本行长               → ch
```

#### 8.4 常见误区

> 用 100vh 做移动端全屏，底部按钮一定完整可见。

部分浏览器中 vh 不计入动态工具栏，按钮可能被遮挡。应以 dvh 实测为准并提供回退。

> overflow:hidden 可以长期用来“强行修一切溢出”。

它只是裁掉症状，溢出的内容可能是交互目标，且会连带裁切定位浮层。应先查明溢出原因（宽度、margin、不可断行内容），再决定是否裁切。

### 强制不通过条件

出现以下任一情况，本次验收不通过；修正后重新验收：

1. 无法计算任一指定元素的优先级或盒模型占位，结论与开发者工具实测冲突。
2. 主体样式依赖多个 !important 互相压制，或使用 ID 选择器书写样式且不愿调整。
3. 不能解释外边距折叠，或把水平 margin、Flex/Grid margin 也当作会折叠。
4. 定位元素参照错误导致浮层错位、遮挡正文，经指出无法定位原因。
5. 对层叠上下文没有概念，认为 z-index 全局可比且用超大数值硬压。
6. 页面存在横向溢出，或移动端全屏高度处理错误且不提供回退。

# 01 Node 运行时与 HTTP：从进程到可停止的接口

## 本章任务

使用 Node.js 24 标准库建立邻里集市的第一个后端边界：先观察模块求值、事件循环与进程信号，
再实现有请求体上限、统一错误和流式响应的 HTTP 接口，最后为超时预算、连接排空与优雅停机负责。

本章产出是**单进程、内存存储的教学 API**。重启后商品会丢失，多副本之间也不共享数据；
它不具备认证、对象授权、数据库事务或生产部署能力。

## 必要前置与边界

- 能阅读 JavaScript ESM、`Promise`、`async`、`await` 和基本异常处理。
- 能在终端运行 `node`、`curl`、`kill`，并能同时使用两个终端。
- 运行时基线为 Node.js 24 LTS；实际补丁版本必须以 `node --version` 记录。
- 所有实验位于读者自己的 `$HOME/code/market-backend-lab/node-http`，不在教材目录创建应用工程。
- HTTP 外部 JSON 在解析与字段校验前一律视为 `unknown`，不能靠注释或 TypeScript 断言变可信。
- 金额只接收非负安全整数分；持久时间形状使用 UTC ISO 8601，显示本地化留给前端。
- 随机 ID、端口占用、时间和信号结果必须记录实际观察，不把本文预期值冒充运行证据。

## 章级邻里集市任务

完成一个最小商品 API：

1. `GET /api/v1/health/live` 返回进程存活状态；
2. `GET /api/v1/listings` 返回固定分页形状；
3. `POST /api/v1/listings` 只接受 JSON 对象和允许字段；
4. `priceCents` 必须是 `0..100000000` 的安全整数；
5. `createdAt` 由服务端生成 UTC ISO 8601；
6. `GET /api/v1/listings.ndjson` 按行输出并尊重背压；
7. 正常创建为 `201`，错误采用 `{code,message,requestId}`；
8. 未知路由为 `404`，坏 JSON 为 `400`，超限正文为 `413`；
9. 收到 SIGTERM 后停止接受新连接，让已接收短请求完成，并在硬截止时间销毁残留连接；
10. 日志只记录允许字段，不记录正文、Cookie、Authorization 或连接字符串。

`ownerId: "demo-user"` 是尚未建立会话前的显式教学替身，绝不能接受请求正文中的 `ownerId`。

## 综合验收证据

| 证据层 | 命令或观察 | 通过标准 |
| --- | --- | --- |
| 运行时 | `node --version` | 输出 `v24.`；保留实际补丁版本 |
| 启动 | `node src/server.mjs` | 仅报告一次监听地址，无未处理拒绝 |
| 正常请求 | `curl -i` 请求健康、列表与创建接口 | 状态分别为 200、200、201，金额保持整数分 |
| 输入边界 | 发送坏 JSON、未知字段、小数金额、超限正文 | 分别得到可解释的 400 或 413，不插入商品 |
| 未知路由 | 请求 `/api/v1/missing` | 404，错误体含与响应头一致的 `requestId` |
| 流式响应 | 请求 `.ndjson` | 每行是完整 JSON；慢客户端不会被无界 `write` 淹没 |
| 阻塞证据 | 运行 `blocking-probe.mjs` | 定时器漂移显著增加；删除忙循环后恢复 |
| 停机 | 后台启动后发送 `kill -TERM` | 不再接收新连接，短请求排空，进程在截止时间内退出 |
| 证据边界 | 重启后再取列表 | 数据清空，明确证明当前仍是内存教学替身 |

每项记录命令、时间、退出码、状态码和实际输出摘要。本文只给出预期，不声称这些命令已在读者机器通过。

## 章级完成标准

- [ ] 能区分模块求值、微任务、计时器、I/O 回调和进程信号。
- [ ] 能用定时器漂移证明同步计算阻塞事件循环。
- [ ] 请求正文按字节累计，并在 JSON 解析后以 `unknown` 进入运行时校验。
- [ ] 路由同时判断方法和规范路径，不用字符串包含关系误匹配。
- [ ] 状态、响应头和正文语义一致；响应结束后不再写入。
- [ ] NDJSON 写入在 `write()` 返回 `false` 时等待 `drain`。
- [ ] 超时、请求体上限和停机截止时间分别承担清楚责任。
- [ ] 信号处理幂等，停机时先停止接流量，再排空，最后才强制断连接。
- [ ] 内存、身份替身、未验证环境和无法复现的输出都已明确标注。
- [ ] 能说明为什么“TypeScript 构建通过”不能证明 HTTP 或停机行为正确。

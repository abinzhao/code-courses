# 02 函数、作用域与可解释错误

## 本章任务

把第 1 章的金额规则从一次性脚本升级为可复用契约：严格解析元文字、格式化整数分、
计算折扣，用闭包拥有独立请求代次，并让失败沿调用栈保留原因。非法价格不得转换为 0，
清理逻辑不得覆盖返回值或异常。

## 产出与前置

完成本章后，你将得到：

- 输入、输出类型、单位和值域明确的金额函数；
- 对空值、负数、指数、尾随文字、三位小数、超范围和 0 分的验证表；
- 两个互不共享状态的闭包计数器；
- 可失效、可释放的请求代次控制器；
- 一份包含错误类型、堆栈、修复和复验的诊断记录。

开始前应完成第 1 章，能够校验非负安全整数分并追踪控制流程。
运行环境仍为 Node.js 24 LTS，无第三方依赖。

## 章级邻里集市任务

在个人 `js-lab/chapter-02/` 中拆分金额能力和运行入口，要求：

1. `parseYuanToCents(input)` 只接收元文字，返回非负安全整数分。
2. `formatCents(cents)` 只接收已验证整数分，不修复坏数据。
3. `applyDiscount(priceCents, discountCents)` 返回支付分，优惠不得超过价格。
4. 三个函数不读取可变全局状态，也不直接输出业务结果。
5. 创建闭包拥有的请求计数器；两个实例必须独立，dispose 后旧 token 失效。
6. 顶层边界分类 TypeError 与 RangeError，finally 只清理，不 return。
7. 用 `node:assert/strict` 或等价精确比较验证合法值与拒绝边界；
   正式 `node:test` 组织方式在第 9 章学习。

不要用 `parseFloat`、真假判断、`Math.abs`、失败返回 0 或双重转换来让案例通过。

## 综合验收证据

必须保留以下结果：

| 输入或场景 | 预期 |
| --- | --- |
| `"19.90"` | 1990 |
| `"0"` | 0 |
| `""`、`"-1"` | 拒绝 |
| `"1e2"`、`"19.90abc"` | 拒绝 |
| `"1.234"` | 拒绝 |
| `"90071992547409.92"` | 拒绝为不安全整数 |
| `"25.00"` 配 3000 分优惠 | 拒绝优惠超过价格 |
| 两个 counter 首次调用 | 分别为 1 |
| 旧请求、dispose 后结果 | 均不能成为当前结果 |

另需提交一次未捕获错误堆栈，指出第一个自己文件帧；一次 inspector 断点记录；
以及“现象、证据、原因、修复、复验”五段诊断。日志不得包含真实身份、Cookie 或密钥。

## 完成本章后

你应能把计算写成可独立验证的函数，用作用域控制谁能修改状态，
并让失败保持失败而不是伪装成合法金额。下一章将处理普通记录、引用共享、
集合变换和外部 JSON 的运行时准入。

# 08 TypeScript 领域设计：从契约到跨层保证

## 本章任务、产出与前置

先完成 TypeScript 核心，能解释 `unknown`、判别联合、泛型和严格配置。
本章为邻里集市建立完整领域契约、逐字段运行时解析器和保存冲突状态机。

最终产出仍位于读者个人 `ts-lab/src/`：`contracts.ts` 定义用途明确的类型与金额构造，
`parsers.ts` 拥有外部数据准入，`state-machine.ts` 表达保存和 409 恢复。
教材仓库不接入真实 API，也不把模拟响应描述成联调通过。

## 保证的所有者

| 保证 | 主要所有者 | 前端不能替代的原因 |
| --- | --- | --- |
| 表单暂存与提示 | 前端表单 | 草稿允许暂时不完整 |
| JSON 字段和值域 | 运行时解析器 | 类型注解执行时已擦除 |
| 金额单位与合法构造 | 领域入口 | 普通 `number` 仍含非法值 |
| 对象授权 | 后端服务 | 客户端按钮和请求体可被修改 |
| 版本原子比较 | 后端事务 | 客户端读到的版本可能已过期 |
| 有效预约唯一 | 数据库约束/事务 | 多个用户和进程可并发写入 |

品牌类型只在可信源码中区分已验证金额；它不替后端校验。解析器只证明本次输入形状
和值域自洽；它不知道当前会话是谁，也不能证明整个数据库没有重复预约。

## 章级邻里集市任务

完成以下闭环：

1. 定义完整 `Listing`、`Page<T>`、`ApiErrorBody`、`Reservation` 和白名单 `ListingPatch`；
2. 从表单文字构造创建命令，服务端字段不进入草稿；
3. 把网络结果保持为 `unknown`，逐字段构造新对象并丢弃未声明额外字段；
4. 标准化合法 UTC 时间，拒绝非法日历日期、重复 ID 和矛盾分页元数据；
5. 保存状态从 `editing → saving → saved/conflict/error` 迁移；
6. 409 保留草稿和服务端当前版本，401/403 不被当成空列表或成功。

## 综合验收证据

- [ ] 完整 Listing 八个字段逐项缺失或类型错误时，错误路径精确到字段。
- [ ] 0 分通过，负数、小数、字符串和超安全整数拒绝。
- [ ] 三种状态全部接受，其他状态拒绝。
- [ ] 合法秒级 UTC 标准化为毫秒，非法日历日期拒绝。
- [ ] 空页、最后一页和超范围空页自洽；超容量、重复 ID 和矛盾总数拒绝。
- [ ] 错误响应缺 `requestId` 时失败，`details` 保持 `unknown`。
- [ ] 201、409、401、403 各进入正确状态；409 不盲目递增版本重试。
- [ ] 能指出 version、权限和预约唯一性各由哪一层拥有。
- [ ] 有效实现没有把断言、禁用按钮或前端类型冒充安全修复。

# 01 值、运算与控制流程

## 本章任务

为邻里集市建立第一条可审计的购物车计算路径：认识运行时值，验证价格与折扣，
遍历多件商品，并保留每次合计变化的轨迹。最终金额只能使用非负安全整数分；
教学种子的持久化时间使用 UTC ISO 8601；表单、JSON 和 API 数据不能因“能转换”就被信任。

## 产出与前置

完成本章后，你将得到：

- 值、类型和显式转换实验；
- 能保留 0 分商品并拒绝非法折扣的决策程序；
- 具有终止条件、溢出保护和逐步轨迹的购物车合计；
- 一份“现象、证据、原因、修复、复验”诊断记录。

开始前只需会保存文件、打开终端并运行 Node。目标环境为 Node.js 24 LTS，
所有实验使用读者个人目录下的 `js-lab/`，不需要安装依赖。

## 章级邻里集市任务

在个人 `js-lab/` 中完成一个 `chapter-01-cart.mjs`，要求：

1. 至少包含 3 件源码内教学商品，字段注明稳定 id、整数分价格、数量、状态和 UTC 创建时间。
2. 每项先检查价格和数量，再判断状态；非法金额必须失败，不得静默跳过。
3. 仅累计 `available` 商品，0 分商品仍计入接纳数量。
4. 折扣必须是非负安全整数分，且不得超过商品合计。
5. 每次乘法、加法和减法后检查安全整数。
6. 输出每轮的下标、id、旧合计、行金额、新合计和最终折后金额。
7. 在代码旁说明：固定数组不是 API 响应，真实外部数据仍需运行时解析。

推荐先在纸上完成状态表，再写代码。不要复制某一篇的最终输出后反推实现。

## 综合验收证据

提交以下可观察证据：

- `node --version` 的实际输出；
- 三篇教程完整文件的 Node 输出；
- 合法购物车的逐步轨迹与最终整数分；
- 折扣超过合计时的明确失败；
- 0 分、负数、小数、字符串、`NaN` 和累计溢出的分类结果；
- 一次 `<=` 越界或漏更新故障的五段诊断；
- 说明 UTC 字符串何时持久化、何时才本地化；
- 说明源码教学种子、表单文字和 API JSON 的信任边界不同。

验收时必须先声明预期输出再运行。只看到“没有报错”不算完成；
删除校验、截断坏输入或最终钳制为 0 都不接受。

## 完成本章后

你应能从值和单位出发推导分支，用循环状态表解释多项累计，
并区分语法成功、类型观察和业务有效性。下一章会把这些规则封装成函数，
用作用域管理状态，并让失败沿调用栈保留可解释证据。
